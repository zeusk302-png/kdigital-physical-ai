# 학생 실습지 · 내 영상으로 판단과 사건 만들기
목적: 단순 박스 표시를 넘어서 자기 영상의 관찰 조건을 사건으로 기록한다. 준비: kit 압축 해제, Python 3.12, CPU 설치, 권한 있는 사진·짧은 영상, 선택 웹캠. 실행 위치는 kit이다. 상세 명령은 kit/README.md를 따른다.

1. 폴더·확장명을 확인하고 환경을 만든다. 예상 결과는 .venv와 runtime/models/yolo11n.pt이며 실제 파일로 확인한다. 설치가 막히면 정확한 명령·마지막 오류를 지원표에 남기고 개념 활동은 계속한다.
2. 사진 한 장을 추론한다. 박스 두 개의 class·score·xyxy와 사람이 본 대상 차이를 적는다. conf를 바꾸기 전 사라질 박스를 예상하고 실행 후 근거를 확인한다.
3. 동영상에서 30프레임만 처리하고 결과를 재생한다. 웹캠이 있으면 0번으로 별도 실행한다. 읽기 실패는 경로·권한·다른 앱 순으로 복구하고 파일 대체 여부를 기록한다.
4. 같은 ID를 연속 세 프레임 찾아 class 번호와 구분해 설명한다. 구역 밖→안→머무름→밖→안 장면을 만들고 entered가 두 번인지 확인한다. 최초 안쪽은 first_seen_inside인지 확인한다.
5. 선 양쪽·여유 영역·ID 소실을 시험한다. tests와 실제 영상 결과를 각각 기록한다. AI에 변경 범위를 events/tests로 한정한 요청을 쓰고 수정 diff와 시험 결과를 확인한다.
6. 목적 하나를 선택해 사건 또는 표시 기능을 수정한다. 소스·설정·시험·설명 중 무엇이 바뀌었는지 남긴다. 새 영상에서 같은 규칙을 확인하고 실패 장면을 찾는다.
7. imgsz 640/320 비교를 같은 입력·conf·클래스·GUI 조건으로 반복한다. FPS와 고정 10프레임의 누락·오검출을 함께 기록하고 선택 이유를 쓴다.
8. 동료가 README만 읽고 실행하게 한다. .gitignore 확인 후 소스만 Git에 기록한다. 가중치·원본 영상·개인정보·전체 자동 결과는 포함하지 않는다. 공개 가능한 결과와 실제 웹캠 미실행 같은 한계를 분명히 적는다.

필수 제출: 소스/설정/시험/README, AI 변경 요청과 diff 설명, 사건 로그 일부와 결과 그림, 두 설정 비교표, 새 영상 실패 분석, 모의·실제추론·웹캠 검증 구분. 원본 영상 제출은 별도 권한 확인 뒤 지정 비공개 경로로 한다. 추가 도전은 퇴장 이벤트 또는 제한 길이 선분 판정이며 기본 과제 평가와 구분한다.

스스로 확인: conf가 높으면 언제 누락이 늘까? 박스가 겹쳤는데 대표점은 밖이면 어떤 결과인가? 소실 뒤 같은 사람이 다른 ID를 받으면 왜 고유 인원 수라고 셀 수 없을까? 저장 영상이 빠르게 재생돼도 실시간 처리라고 말할 수 있을까?
