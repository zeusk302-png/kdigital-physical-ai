# 2026-10-22 · OpenCV + 웹캠 실습

컴퓨터는 사진을 의미가 붙은 사물 목록으로 바로 읽지 않습니다. 이번 수업은 배열의 위치와 색 값에서 시작해, 어떤 조건의 영역을 남겼는지 설명할 수 있는 작은 영상 처리를 만듭니다. 규칙 기반 영상 처리와 학습한 AI 모델의 분류를 혼동하지 않습니다.

## 수업의 출발점

10/8의 데이터 구조와 10/14~15의 변수·조건·반복을 복습합니다. 배열은 줄과 칸으로 값을 담는 방식이며, OpenCV는 이미지 읽기와 변환을 제공하는 라이브러리입니다. import는 그 도구를 코드에서 쓰도록 가져오는 문장이고 설치와 실행은 별도 단계입니다. 파일 입력을 기본으로 사용하며 실제 카메라는 운영 조건이 갖춰진 경우의 선택 경로로 둡니다.

먼저 개념을 읽고 예제의 입력값과 예상 결과를 살펴봅니다. 수업은 50분 × 6교시로 총 300분이며 중식은11:50~13:00입니다. 각 교시에 개념 설명·시연·직접 실습·풀이가 있습니다. 복습·도전 문제는 기본 실습을 마친 뒤 선택하며, 시간이 부족하면 수업 뒤에 이어서 풉니다. 학생 실습에 걸리는 시간은 수업 후 기록합니다.

## A01 · 이미지는 작은 값들의 격자

<!-- enrichment:2026-10-22:P1 -->

### 1교시 필수 개념 보충 · 좌표를 알아야 검사 위치를 정할 수 있다

### 실무 상황과 원리

포장 검사 담당자가 사진 오른쪽 위의 인쇄만 확인하려고 합니다. 사진 파일을 보았다는 사실과 컴퓨터가 그 위치를 읽었다는 사실은 다릅니다. 파일은 저장된 자료이고, 배열은 읽은 뒤 메모리에서 값이 놓인 표입니다. 격자의 한 칸인 픽셀에 번호를 붙이면 위치를 정확히 전달할 수 있습니다. 왼쪽 위를 출발점으로 가로 번호 x, 세로 번호 y가 각각 0부터 시작합니다.

OpenCV 컬러 배열의 shape는 높이, 너비, 채널 수 순서입니다. 높이 3, 너비 4, 채널 3이면 (3,4,3)이며 위치는 12곳, 색 성분은 총 36개입니다. image[y,x]에서 첫 번호는 행이므로 image[1,2]는 x=2, y=1입니다. BGR 값 [0,0,255]는 빨강 성분만 큰 값입니다. RGB 약속을 쓰는 다른 도구로 가져갈 때는 채널 순서를 확인해야 합니다.

완성 예를 종이에 추적합니다. 입력은 shape (3,4,3), 질문은 오른쪽 끝 아래 칸입니다. 처리에서 x의 마지막 번호는 4−1=3, y의 마지막 번호는 3−1=2로 계산합니다. 출력 위치는 image[2,3]입니다. 번호 4와 3을 그대로 쓰면 범위를 벗어납니다. 해상도만으로 실제 물체가 몇 mm인지 계산하지 못하며 촬영 거리와 기준 길이가 필요합니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 높이 5, 너비 8인 새 사진의 왼쪽 아래 픽셀과 전체 위치 수를 직접 작성하세요. 채널이 3일 때 색 성분 수도 별도로 쓰세요.

### 정답과 오답의 이유

정답은 image[4,0], 위치 40곳, 색 성분 120개입니다. image[0,4]는 첫 행의 다섯 번째 위치라서 아래 칸이 아닙니다. 120을 물체 개수로 쓰면 색 성분과 검사 대상을 혼동한 것입니다.

### 확인 질문과 답

1. shape의 첫 값은? → 높이입니다.
2. x=3,y=2의 배열 표기는? → image[2,3]입니다.
3. BGR의 마지막 값은? → 빨강 성분입니다.

픽셀은 이미지에서 한 위치의 색이나 밝기를 담는 최소 단위입니다. 모눈종이의 칸과 비슷하지만 실제 물체의 고정 길이를 뜻하지는 않습니다.

값의 배열을 이해하면 색이 바뀌거나 좌표가 어긋난 이유를 설명할 수 있습니다. 이미지 파일의 이름만으로 내용과 크기를 알 수 없습니다.

### 입력에서 살펴볼 예

가로 4칸, 세로 3칸입니다. 0은 어둡고 255는 밝습니다.
이 예의 배열은 높이 3, 너비 4입니다.

### 구분해야 할 반례

픽셀 한 칸이 현실의 1mm라는 뜻은 아닙니다. 촬영 거리와 렌즈, 해상도에 따라 대응 길이가 달라집니다.

### 2교시 필수 개념 보충 · 잘라내기와 밝기 변환이 바꾸는 정보

### 실무 상황과 원리

작업대 사진에는 부품과 함께 창문 반사가 들어 있습니다. 검사자는 작업대 가운데만 보고 싶습니다. 관심 영역은 전체 사진에서 필요한 작은 구역이며 ROI라고 부릅니다. 잘라내기는 바깥 픽셀을 제외하고, 크기 변경은 새 격자로 값을 다시 배치합니다. 둘을 같은 일이라고 생각하면 검사 위치와 면적 기준이 틀어집니다.

image[20:80,30:130]은 행 20부터 79, 열 30부터 129까지 가져옵니다. 콜론 뒤의 끝 번호는 포함하지 않습니다. 따라서 높이는 80−20=60, 너비는 130−30=100입니다. 잘린 사진의 (0,0)은 원본의 (30,20)입니다. 원본 좌표가 필요하면 잘린 x에 30, y에 20을 더합니다. 가로와 세로를 각각 절반으로 줄이면 같은 물체의 면적은 대략 4분의 1이 됩니다. 정확한 경계 값은 다시 만든 픽셀과 윤곽선에 따라 달라집니다.

회색조는 여러 색 성분을 밝기 하나로 바꿉니다. 세 성분의 단순 평균이 아니라 변환 규칙을 사용합니다. 예제의 순수 빨강 BGR [0,0,255]는 대략 76, 초록 [0,255,0]은 150, 파랑 [255,0,0]은 29입니다. 밝은 부품을 찾기에는 편하지만 같은 밝기의 서로 다른 색은 구분하기 어렵습니다. 완성 흐름은 원본 읽기 → 필요한 영역 자르기 → 회색조 변환 → 높이와 너비 기록입니다. 회색조 결과의 shape는 (60,100)이며 채널 3이 사라집니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

### 01_inspect.py 전체

```python
import cv2
from pathlib import Path
root = Path(__file__).resolve().parent.parent
source = root / "data" / "parts.png"
image = cv2.imread(str(source))
if image is None:
    raise ValueError("이미지를 읽지 못했습니다: " + str(source))
print("shape:", image.shape)
print("BGR:", image[40, 30].tolist())
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
saved = cv2.imwrite(str(root / "work" / "gray.png"), gray)
if not saved:
    raise OSError("출력 파일을 저장하지 못했습니다")
print("gray:", gray.shape)
```

## A06 · 회색조의 얻는 것과 잃는 것

회색조는 색 성분을 밝기 한 값으로 표현한 이미지입니다. 색을 구분하는 문제인지 밝은 영역을 찾는 문제인지에 따라 사용할지 정합니다.

밝기 기준으로 물체 영역을 찾는 이번 예에서는 한 채널 비교가 쉽습니다. 그러나 밝기가 비슷한 빨강과 초록을 구분하려면 색 정보를 보존한 방법이 필요합니다.

### 입력에서 살펴볼 예

BGR: 빨강[0,0,255], 초록[0,255,0], 파랑[255,0,0]
회색조: 76,150,29
별도 색 견본 파일을 비교합니다.

세 채널을 한 밝기로 요약합니다. 빨강·초록·파랑 견본은76·150·29로 변환됩니다.
검출용 parts.png는 처음부터 세 채널 값이 같으므로 변환 전후 외관이 같습니다.

### 구분해야 할 반례

회색조가 모든 영상 문제에서 더 좋은 입력은 아닙니다. 신호등 색을 구별해야 하는 업무에서 밝기만 보면 다른 색을 혼동할 수 있습니다.

### 3교시 필수 개념 보충 · 임계값과 면적 기준은 서로 다른 질문이다

### 실무 상황과 원리

검사 화면에서 밝은 부품 세 개와 작은 먼지 하나가 보입니다. 먼저 밝은 위치를 고르고, 그다음 너무 작은 영역을 제외하려 합니다. 첫 단계는 어떤 픽셀을 남길지 묻고, 두 번째는 남은 덩어리 중 어떤 크기를 셀지 묻습니다. 이 두 질문에 각각 threshold와 min_area라는 설정 이름을 붙입니다.

THRESH_BINARY는 밝기가 임계값보다 클 때 255, 작거나 같을 때 0을 출력합니다. 입력 밝기 [80,100,101,220]과 임계값 100이면 출력은 [0,0,255,255]입니다. 100이 흰색이 되지 않는 이유는 비교가 크거나 같음이 아니라 엄격한 초과이기 때문입니다. 흰색은 조건 통과 위치를 뜻하며 부품 종류나 불량의 의미까지 알려 주지 않습니다.

윤곽선은 남은 영역의 경계입니다. contourArea는 경계 좌표로 계산한 기하학적 면적이며 흰 픽셀 개수를 그대로 센 값과 같다고 보장하지 않습니다. 면적 [25,100,180]에서 최소 면적 100과 비교 조건 >=를 쓰면 두 영역이 남습니다. 첫 밝기 기준의 >와 면적 기준의 >=가 다르다는 점을 코드에서 찾습니다. 붙어 있는 두 부품은 한 윤곽선으로 연결될 수 있어 영역 수와 실제 부품 수가 달라집니다. 완성 예는 회색조 입력 → 이진 마스크 → 외곽 윤곽선 → 면적 필터 → 남은 영역 수 2입니다. 마스크와 박스 그림을 함께 봐야 숫자가 생긴 이유를 설명할 수 있습니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 밝기 [60,90,91,200], threshold=90의 마스크를 작성하세요. 이어서 윤곽선 면적 [49,50,120], min_area=50에서 남는 영역 수를 별도로 판단하세요.

### 정답과 오답의 이유

마스크는 [0,0,255,255], 영역 수는 2입니다. 밝기 90을 남기는 답은 경계 비교 오류이고, 면적 50을 버리는 답은 코드의 >=를 >로 바꿔 읽은 오류입니다. 두 흰 픽셀과 두 영역이 같은 수라는 일반 규칙은 없습니다.

### 확인 질문과 답

1. threshold의 단위는? → 이 예의 8비트 밝기 값입니다.
2. min_area의 역할은? → 작은 윤곽선 영역을 제외합니다.
3. 붙은 부품 둘은 반드시 두 영역인가요? → 아닙니다.

### 짧은 완성 코드로 추적하기

제공 참고 파일 [code/05_threshold_trace.py](examples/course/code/05_threshold_trace.py)은 보존합니다. 예제 `course` 폴더에서 이 파일을 `work/05_threshold_trace.py`에 복사하고 학생 수정본은 work에 저장합니다. 아래는 완결된 전체 코드입니다. 파일·폴더·확장자를 확인한 뒤 같은 course 폴더의 터미널에서 `python -X utf8 work/05_threshold_trace.py`을 실행합니다. 저장과 실행은 별도 행동입니다.

```python

import numpy as np
gray = np.array([[80, 100, 101, 220]], dtype=np.uint8)
used, mask = cv2.threshold(gray, 100, 255, cv2.THRESH_BINARY)
print("threshold:", used)
print("mask:", mask.tolist())
```


1행은 영상 도구 cv2를 가져옵니다. 2행은 배열 도구 numpy를 np라는 짧은 이름으로 가져옵니다. 3행의 대괄호 두 겹은 한 행과 네 칸을 가진 배열이며 dtype=np.uint8은 0~255의 정수로 저장한다는 뜻입니다. 4행은 함수에 입력·기준·최댓값·방식을 전달하고 쉼표로 반환값 두 개를 나눠 받습니다. 5~6행의 괄호는 출력 호출, 점은 도구의 기능을 선택하는 기호입니다. tolist는 배열을 목록으로 보여 줍니다. threshold를 101로 바꾸면 마스크는 [[0,0,0,255]]입니다. cv2 설치 오류는 환경 문제로 기록하고 제공 출력을 비교합니다. 파일 확장자가 .py.txt인지도 확인합니다.




임계값은 값을 나누는 기준이고 마스크는 처리할 영역을 표시한 배열입니다. 출입 기준표처럼 픽셀마다 기준 통과 여부를 정합니다.

THRESH_BINARY에서 밝기가 기준보다 크면 255, 작거나 같으면 0입니다. 결과의 흰색은 조건을 만족한 위치이며 물체의 의미를 이미 알아냈다는 뜻은 아닙니다.

같은 100을 포함하는 쪽을 주의합니다.

### 02_count.py 전체

```python
import cv2
import json
from pathlib import Path
root = Path(__file__).resolve().parent.parent
config = json.loads((root / "work" / "settings.json").read_text(encoding="utf-8"))
source = root / "data" / config["image"]
image = cv2.imread(str(source))
if image is None:
    raise ValueError("입력 이미지를 확인하세요: " + str(source))
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
used, mask = cv2.threshold(gray, config["threshold"], 255, cv2.THRESH_BINARY)
contours, hierarchy = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
kept = []
for contour in contours:
    if cv2.contourArea(contour) >= config["min_area"]:
        kept.append(contour)
preview = image.copy()
for contour in kept:
    x, y, width, height = cv2.boundingRect(contour)
    cv2.rectangle(preview, (x, y), (x + width - 1, y + height - 1), (0, 0, 255), 2)
if not cv2.imwrite(str(root / "work" / "mask.png"), mask):
    raise OSError("mask 저장 실패")
if not cv2.imwrite(str(root / "work" / "detected.png"), preview):
    raise OSError("detected 저장 실패")
report = {"image": config["image"], "threshold": used, "count": len(kept)}
(root / "work" / "report.json").write_text(json.dumps(report, ensure_ascii=False), encoding="utf-8")
print(json.dumps(report, ensure_ascii=False))
```


### 4교시 필수 개념 보충 · 한 조건씩 바꾸고 새 장면으로 시험한다

### 실무 상황과 원리

밝은 작업대에서는 검출이 잘 되는데 조명을 줄이자 부품 하나가 사라졌습니다. 담당자는 숫자가 맞을 때까지 여러 설정을 동시에 바꾸고 싶습니다. 그러나 원인을 설명하려면 비교 조건을 관리해야 합니다. 같은 사진과 같은 크기를 유지하고 threshold만 바꾸는 실험과 min_area만 바꾸는 실험을 나눕니다.

완성 비교표의 기본 행은 파일 P, threshold 100, min_area 100, 관찰 영역 3입니다. 두 번째 행은 같은 P, threshold 150, min_area 100, 관찰 영역 2라는 가상 관찰입니다. 여기서는 밝기 기준 변화의 영향을 비교할 수 있습니다. 세 번째 행에서 파일까지 어두운 D로 바꾸면 두 변화가 섞여 두 번째 행과 같은 근거로 읽지 못합니다. 값이 달라졌다는 관찰과 왜 달라졌다는 설명을 분리합니다.

기본 파일은 규칙을 만들 때 쓰고, 보류 파일은 아직 설정을 맞추지 않은 새 입력으로 씁니다. 새 입력의 기대 결과를 사람이 먼저 기록한 다음 같은 설정을 적용합니다. 기대 영역 4, 관찰 3이면 그 사례는 실패입니다. 바로 기준을 바꾸었다면 새 설정 버전으로 기존 장면도 다시 시험해야 합니다. 빈 사진, 어두운 사진, 붙은 물체 사진은 서로 다른 실패를 드러냅니다. 세 합성 사진 통과를 실제 웹캠 전체 조건의 정확도라고 부르지 않습니다. 각 실행 직후 settings, mask, detected, report를 같은 실험 폴더에 복사하면 뒤 실행이 이전 실험 결과를 덮어쓰는 일을 막을 수 있습니다.

복습 문제: 원본 조건 (100,100)에서 한 팀은 (80,50)으로, 다른 팀은 (80,100)으로 바꾸었습니다. 밝기 기준의 영향만 설명할 수 있는 팀과 이유를 쓰고 새 시험 입력 한 종류를 제안하세요.

두 번째 팀은 면적 기준을 유지했으므로 밝기 기준 비교에 적합합니다. 첫 팀의 결과에는 두 설정 변화가 섞였습니다. 다른 배치나 다른 조명 사진을 제안하되 무엇을 확인하고 무엇을 아직 확인하지 못하는지 적으면 인정합니다.

## A13 · 프레임을 순서대로 처리

### 5교시 필수 개념 보충 · 프레임마다 초기화와 장치 자원 종료

### 실무 상황과 원리

같은 부품이 세 프레임에 계속 보이면 검출 결과가 세 번 나옵니다. 이를 물품 세 개가 지나갔다고 보고하면 수량이 틀립니다. 프레임은 한 시점의 사진이며, 프레임별 영역 수는 그 시점에 보이는 영역 수입니다. 고유 물체의 이동과 통과를 세려면 별도의 추적 규칙과 시험이 필요합니다.

제공 파일 재생 예(code/03_replay.py)의 기본 설정에서 parts.png, empty.png, holdout.png의 장면별 검출 수는 [2,0,3]입니다. 반복마다 count=0을 먼저 만들고 해당 장면의 영역만 더하면 출력은 2,0,3입니다. count를 반복 밖에서 한 번만 만들면 누적은 2,2,5가 됩니다. 누적 합이 필요한 업무라면 누적이 맞을 수 있지만 현재 예의 요구는 장면별 수이므로 초기화 위치가 중요합니다. 이 개수는 해당 입력과 설정에서 얻은 영역 수이며 물품의 실제 수량을 보장하지 않습니다. for는 파일 목록에서 한 이름씩 꺼내고, 들여쓰기는 그 이름을 처리하는 문장 묶음을 표시합니다.

실제 카메라 경로에서는 VideoCapture로 장치를 열고 isOpened로 열기 성공을 확인합니다. read의 ok는 프레임을 받았는지 알리는 값입니다. 장치 열기 성공과 계속 프레임을 받는 성공은 별도입니다. 실패한 프레임에 바로 색 변환을 적용하지 않습니다. finally는 정상 종료와 오류 종료 뒤 모두 자원을 정리할 자리를 제공합니다. release는 카메라 점유를 풀고 destroyAllWindows는 만든 창을 닫습니다. 파일 재생이 완료되어도 권한, 장치 번호, GUI 창, 프레임 지연은 확인하지 않은 상태입니다. 실제 장비가 없으면 장치를 임의로 열지 않고 종료 흐름을 종이에서 설명합니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 프레임의 영역 수가 [2,1,0]일 때 매번 초기화한 출력과 누적 출력의 차이를 직접 쓰세요. 카메라 열기 성공 뒤 read가 실패하면 다음 행동도 판단하세요.

### 정답과 오답의 이유

프레임별 출력은 2,1,0이고 누적은 2,3,3입니다. read 실패이면 처리 반복을 끝내고 자원을 해제합니다. 마지막 정상 프레임을 새 측정처럼 반복 출력하면 관찰 시각이 틀린 보고가 됩니다.

2. count=0 위치는? → 프레임 처리 반복 안입니다.

```python
import cv2
from pathlib import Path
root = Path(__file__).resolve().parent.parent
for name in ["parts.png", "empty.png", "holdout.png"]:
    frame = cv2.imread(str(root / "data" / name))
    if frame is None:
        raise ValueError("프레임을 읽을 수 없습니다: " + name)
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    used, mask = cv2.threshold(gray, 100, 255, cv2.THRESH_BINARY)
    contours, hierarchy = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    count = 0
    for contour in contours:
        if cv2.contourArea(contour) >= 100:
            count = count + 1
    print(name, count)
```

### 04_webcam.py 전체

```python
import cv2
capture = cv2.VideoCapture(0)
try:
    if not capture.isOpened():
        raise RuntimeError("카메라 열기 실패: 권한, 점유, 장치 번호를 확인하세요")
    while True:
        ok, frame = capture.read()
        if not ok:
            print("프레임 읽기 실패: 종료합니다")
            break
        gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
        cv2.imshow("camera-gray", gray)
        if cv2.waitKey(1) & 255 == ord("q"):
            break
finally:
    capture.release()
    cv2.destroyAllWindows()
```

## A16 · 검출 요구를 문장으로 정하기

### 6교시 필수 개념 보충 · 검출 요구와 결과 보고를 연결하기

### 실무 상황과 원리

현장 담당자가 “잘 세어 주세요”라고 요청하면 개발자는 어떤 장면에서 몇 개를 어떻게 셀지 알 수 없습니다. 요구사항은 확인 가능한 입력 조건과 결과의 약속입니다. “분리된 밝은 부품의 외곽 영역을 세고, 입력 파일명과 설정을 함께 저장한다”처럼 관찰 대상과 출력부터 정합니다.

완성 예의 요구 R1은 합성 파일 H에서 사람이 지정한 영역 4개와 프로그램 수를 비교하는 것입니다. 시험 T1의 입력은 H와 설정 (100,100), 기대값은 4입니다. 관찰이 4면 그 시험은 통과이고, 3이면 실패입니다. 실물 카메라 시험 T2는 장치가 없어 미실행이라고 씁니다. R1의 파일 통과가 T2의 미실행을 덮지 않습니다. 숫자 일치 외에 박스가 어떤 영역을 둘렀는지도 살피면 반사와 누락이 우연히 서로 상쇄된 경우를 발견할 수 있습니다.

검출 수를 바르게 해석하려면 가정도 붙입니다. 촬영 크기 고정, 밝은 대상, 대상 사이 간격, 관심 영역, 조명 조건은 제작 가정입니다. 대상이 붙거나 어두워지면 이 단순 규칙이 실패할 수 있습니다. 결과 묶음에는 원본 이미지, 설정, 처리 명령, 마스크, 박스 그림, 수치 보고와 기대값 비교표를 넣습니다. 동료는 같은 파일과 명령으로 수를 다시 얻고 조건을 읽을 수 있어야 합니다. 파일 작성 완료, 로컬 실행 완료, 실물 수용 확인은 서로 다른 상태입니다. 새로운 요구가 들어오면 조건과 기대값을 먼저 바꾸고 시험 결과를 새 버전으로 남깁니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

### 정답과 오답의 이유

예: “고정 크기의 제공 사진 H에서 분리된 밝은 영역 4개를 세고 설정을 기록한다.” 실제 속도와 조명 변화는 미확인입니다. 4개 일치만으로 모든 현장 장면의 정확도를 100%라 쓰면 시험 범위를 확대해 해석한 오답입니다.

## A17 · 새 설정으로 결과 패키지 만들기

결과 패키지는 원본 이름, 설정, 출력, 확인한 사실을 함께 남긴 묶음입니다. 그림 하나만 보내면 어떤 조건으로 만들었는지 재현하기 어렵습니다.

다음 사람이 같은 결과를 확인하려면 입력과 설정이 필요합니다. 오류 입력에서는 그럴듯한 빈 결과를 성공으로 저장하지 않고 실패 이유를 분리해 남깁니다.

### 입력에서 살펴볼 예

종합 입력: holdout.png
threshold=100, min_area=100
추가 시험: missing.png

정상 입력의 기대 count는 3입니다.
없는 파일은 읽기 오류로 종료해야 합니다.

### 구분해야 할 반례

입력을 못 읽은 상태와 정상적으로 물체가 없는 상태는 다릅니다. 둘 다 count0으로 기록하면 센서 장애를 빈 공간으로 오해할 수 있습니다.

스스로 설명할 질문: 입력 실패와 정상 빈장면을 어떤 항목으로 구별할까요?

활동 연결: [입력](examples/course/data/A17_input.md) · [기록 양식](examples/course/work/A17_worksheet.md)

## A18 · 결과를 근거로 설명하기

인수인계는 다음 사람이 작업을 이어갈 수 있도록 입력과 확인 결과, 남은 한계를 전달하는 일입니다. 기능 소개와 실제 검증 결과를 구분해 말합니다.

PPT 장면이나 출력 숫자만 보여 주는 발표보다 어느 조건에서 성공·실패했는지를 설명해야 수정 방향을 정할 수 있습니다. 기록의 날짜와 사용 설정도 함께 남깁니다.

### 입력에서 살펴볼 예

최종 설명3문장
1 입력과 규칙
2 직접 확인한 결과
3 미검증 장비 조건

파일 입력은 실제 실행 근거를 제시합니다.
카메라 촬영·화면 창 표시·현장 성능은 아직 시험하지 않았다고 적습니다.

### 구분해야 할 반례

완성 코드가 있다는 이유로 실시간 품질검사 시스템이 완성됐다고 말하지 않습니다. 교육용 합성 입력과 현장 운영은 검증 범위가 다릅니다.

스스로 설명할 질문: 확인한 사실과 다음 검증을 각각 한 문장으로 말할 수 있나요?

활동 연결: [입력](examples/course/data/A18_input.md) · [기록 양식](examples/course/work/A18_worksheet.md)
