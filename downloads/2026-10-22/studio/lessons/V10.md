# V10 실패 장면과 처리 속도 비교


카메라가 초당 제공하는 프레임 수와 모델이 초당 처리한 프레임 수는 다릅니다. 처리 지연에는 추론뿐 아니라 프레임 읽기·그리기·저장도 영향을 줍니다. 프로그램의 processing_fps는 전체 처리량이고 mean_pipeline_ms는 코드에서 정한 처리 구간의 평균입니다. 화면에 보이는 숫자가 어떤 범위를 잰 것인지 설명합니다.

## 공정하게 비교하기

같은 영상·같은 구역·같은 클래스에서 imgsz만 640과 320으로 바꿉니다. 다음에는 크기를 고정하고 conf만 바꿉니다. fast와 strict 설정은 비교용 출발점이며 둘을 한 번에 비교한 결과만으로 어느 설정 때문에 차이가 났다고 말하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m src.main --source runtime/input/clip.mp4 --config configs/fast.json --output runtime/results/fast01
```

## 수행과 기록

작은 대상·어두운 장면·가림·빠른 움직임을 포함한 자기 입력에서 놓침과 오검출을 적습니다. 동일 영상을 다시 실행해 처리 속도·사건 수·문제 프레임을 비교합니다. 원본 영상은 바꾸지 않고 결과를 별도 폴더에 남깁니다. GPU가 없는 PC에서 CPU로 진행하며 CUDA 설치에 수업 전체를 쓰지 않습니다.

## 확장

프레임을 건너뛰어 처리할 때 방향·진입 사건을 놓칠 수 있는 이유를 설명합니다. 빠르다는 이유만으로 모든 프레임을 버리는 설정을 적용하지 않습니다. ‘몇 FPS 이상’은 현장 PC에서 확인한 값으로 정하고, 측정 전 성능을 보장하지 않습니다.
