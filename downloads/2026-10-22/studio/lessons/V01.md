# V01 · 사진에서 판단하는 프로그램과 프로젝트 폴더

입력·모델·출력의 관계부터 설치와 첫 실행까지


사진을 보고 사람이 있는지 말하는 일과, 프로그램이 사진을 숫자로 받아 박스를 계산하는 일을 연결해 봅시다. 이미지는 작은 색 점인 픽셀의 모음입니다. 색 점의 배열을 입력받아 사물의 위치와 종류를 내놓는 계산을 객체 검출이라고 부릅니다. 사전학습 모델은 여러 사진에서 미리 배운 결과를 가져온 것입니다. 오늘은 학습을 새로 시키는 대신 이미 배운 모델로 새 사진을 판단하는 추론을 실행합니다. 모델이 배운 종류에 없는 안전모·특정 부품을 이름만 바꾸어 검출할 수는 없습니다.

파일 탐색기에서 압축을 풀어 vision-project 폴더를 만듭니다. README.md는 실행 안내, .py는 Python이 읽는 코드, .json은 설정값입니다. 폴더는 자료를 담는 서랍이고 확장자는 서류의 종류 표시라고 생각하세요. 탐색기의 파일 확장명 표시를 켜서 main.py.txt가 되지 않았는지 확인합니다. src 폴더의 코드는 바꾸는 대상이고 runtime 폴더의 모델과 영상은 실행 때 쓰는 재료입니다. 다운로드 파일과 프로그램 소스는 같은 것이 아닙니다.

터미널은 문장으로 컴퓨터에 일을 시키는 창입니다. VS Code에서 kit 폴더를 열고 터미널을 새로 열어 pwd를 입력합니다. 출력 경로의 마지막이 kit인지 확인합니다. 다음 명령은 위에서부터 한 줄씩 실행합니다. 설치가 끝나기 전에 다음 줄을 입력하지 않습니다. .venv는 이 프로젝트만 사용하는 도구 상자입니다. 활성화 권한 문제를 피하려고 Python 실행 파일의 경로를 직접 적습니다.
```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe prepare.py
```
첫 줄의 -m은 설치된 기능을 실행하라는 뜻이고 venv는 도구 상자 생성 기능의 이름입니다. 마지막 줄은 모델 가중치 yolo11n.pt를 runtime/models에 내려받습니다. 인터넷이 필요한 최초 준비 단계입니다. 모델 파일은 사람이 읽는 교안이 아니라 학습된 숫자 묶음입니다. 실행 안내의 인터넷 주소와 파일명을 확인한 뒤 준비합니다.

필수 활동은 설치 경로·Python 버전·가중치 파일 존재를 직접 확인하고 작업 기록에 적는 것입니다. 강사는 정상 PC를 먼저 시연하고, 학생은 자신의 경로를 소리 내어 읽은 다음 실행합니다. 설치가 실패한 학생은 동료 화면에서 검출 개념과 좌표 해석 활동을 함께 하고, 설치 지원 목록에 따로 기록합니다. 설치 실패를 학습 개념 오답으로 처리하지 않습니다. 준비가 끝나면 자기 촬영 또는 사용 권한을 확인한 사진을 runtime/input/photo.jpg에 둡니다. 사진 경로의 띄어쓰기가 있으면 큰따옴표로 감쌉니다.

추가 도전은 새 가상환경을 만든 뒤 같은 requirements.txt로 다시 설치해 버전 차이를 비교하는 것입니다. 필수 수업 중 GPU 설치나 모델 학습을 시도하지 않습니다. 강사는 38명의 다운로드를 동시에 시작하기 전 네트워크와 설치 권한을 확인하고 사전 준비된 모델의 해시를 대조합니다. 준비 가정은 Windows/Python 3.12/인터넷/CPU이며 실제 교실 조건은 점검표로 확인해야 합니다. 질문에 답해 보세요. 코드를 수정하지 않고 모델 파일만 지웠다면 프로그램이 왜 멈출까요? 답은 학습된 숫자 재료가 없어서이며 Python 문법 오류와 구별해야 합니다.
