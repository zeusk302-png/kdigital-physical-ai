# V04 · 추적 ID와 프레임 사이의 기억

검출된 박스 수와 실제 고유 인원 수 구분하기


사진 한 장에서는 사람이 어디에 있는지만 알 수 있습니다. 다음 장에서도 같은 사람인지 이어 붙이는 일이 추적입니다. ByteTrack은 이전 박스와 새 검출의 위치·움직임·점수 등을 이용해 연결하고 임시 ID를 붙입니다. 오늘은 알고리즘 전체를 직접 만들지 않고 검증된 추적기 호출을 이용합니다. 학생이 작성하고 고칠 핵심은 결과 ID를 읽어 상태와 사건을 연결하는 부분입니다. 같은 사람이 화면에 100프레임 나왔다고 100명이 방문했다고 세면 안 됩니다.

src/tracker.py를 열어 model.track와 persist=True를 찾습니다. persist는 연속 프레임의 기억을 유지하겠다는 옵션입니다. 매 프레임 새 YOLO 객체를 만들면 이전 기억이 이어지지 않습니다. 반대로 관련 없는 두 영상은 같은 추적 세션으로 섞지 않습니다. 실행 프로그램을 다시 시작하면 새 세션입니다. tracker='bytetrack.yaml'을 명시해 설치 버전의 기본값이 달라도 수업의 선택을 유지합니다. boxes.id가 없는 첫 검출도 가능하므로 None 검사가 필요합니다.

관찰 정보 Observation에는 track_id, xyxy, class_id, confidence가 들어갑니다. class_id=0은 '사람 종류'이고 track_id=7은 '이번 추적 세션에서 7번으로 연결한 대상'입니다. 둘을 바꾸어 저장하면 사건이 한 종류에 몰립니다. dataclass는 관련 값을 이름으로 묶는 간단한 상자입니다. 예를 들어 item.track_id로 상자 안 번호를 꺼냅니다. 좌표 tuple은 순서가 정해진 값 묶음입니다. zip은 서로 대응하는 박스·ID·종류·점수의 같은 위치 값을 함께 읽습니다.

필수 활동은 결과 영상의 연속 세 프레임에서 같은 사람이 받은 ID를 기록하는 것입니다. 화면 가장자리에서 나갔다 돌아오거나 다른 사람 뒤에 잠시 가려지는 장면도 확인합니다. 같은 사람에게 새 ID가 생길 수 있고, 가까운 두 사람의 ID가 바뀔 수 있습니다. 따라서 서로 다른 ID 개수를 세어 실제 고유 인원 수라고 이름 붙이지 않습니다. 수업 산출물의 이름은 추적 관찰 수 또는 구역 사건 수처럼 무엇을 실제로 계산했는지 드러나야 합니다.

events.jsonl은 프레임마다 한 줄을 남깁니다. 줄의 track_ids에서 [1,2,3]은 그 프레임에 ID를 받은 세 대상을 뜻합니다. 빈 목록은 실제 사람이 없다는 보장보다 '현재 ID를 얻은 검출이 없음'에 가깝습니다. 환경이 어둡거나 사람이 너무 작을 수 있기 때문입니다. 파일을 열고 같은 ID가 얼마나 이어지는지 확인한 뒤 영상 화면과 프레임 번호를 맞춥니다. events 배열이 비어 있어도 track_ids는 있을 수 있습니다. 관찰과 사건이 서로 다른 데이터라는 뜻입니다.

흔한 오류는 프레임 반복문 안에 model=YOLO(...)를 놓는 것, boxes.id가 None인데 바로 정수로 바꾸는 것, 서로 다른 영상의 번호를 같은 사람이라고 묶는 것입니다. AI에 수정 요청을 보낼 때 tracker.py만 읽어 설명하게 한 뒤 허용 파일 범위를 지정합니다. '추적 ID가 없는 검출은 화면에는 남기고 사건에서는 제외하는 이유를 설명해. 모델과 추적기는 교체하지 마.'라고 요청하고 실제 diff를 확인합니다. 추가 도전은 가림이 있는 새 영상에서 ID 교체 장면 하나를 찾아 대체 설명을 적는 것입니다. 강사는 모의 ID 시험이 실제 추적기의 ID 유지 성능을 검증한 것은 아니라는 점을 다시 확인합니다.
