# V05 · 관심 구역 진입과 재진입 사건 만들기

위치 판단과 이전 상태를 연결해 반복 경보 줄이기


창고 바닥의 노란 사각형에 사람이 들어오는 순간을 알려 준다고 생각해 봅시다. 사각형 안에 계속 서 있는 동안 매 프레임 알림을 울리면 같은 사건이 반복됩니다. '안에 있다'는 현재 상태이고 '밖에서 안으로 바뀌었다'는 변화입니다. 오늘은 이 차이를 코드로 표현합니다. 먼저 어떤 점이 구역 안이면 진입으로 볼지 정해야 합니다. 박스 가장자리가 조금 겹치는 규칙과 발 위치가 들어오는 규칙은 다른 결과를 냅니다.

src/zones.py의 bottom_center는 박스 아래쪽 가운데를 대표점으로 고릅니다. (100,50,300,450)의 대표점은 (200,450)입니다. 박스 아래쪽을 발 근처로 보는 제작 선택이며 실제 발 검출은 아닙니다. inside는 left≤x≤right와 top≤y≤bottom을 함께 검사합니다. 경계선 위도 안으로 봅니다. default.json의 zone은 [0.25,0.2,0.75,0.95]입니다. 가로 25~75%, 세로 20~95%의 직사각형이며 영상 크기가 바뀌어도 같은 비율을 유지합니다.

EventEngine은 ID별로 이전 inside와 마지막 관찰 프레임을 states 사전에 기억합니다. 사전은 번호표를 열쇠로 삼아 이전 기록을 찾는 서랍장입니다. 이전 기록이 있고 밖이었다가 현재 안이면 entered를 냅니다. 처음 관찰했는데 이미 안에 있으면 first_seen_inside를 냅니다. 화면이 켜지기 전부터 있던 사람인지 실제 방금 들어온 사람인지 알 수 없기 때문에 이름을 구분합니다. 머무름에는 추가 사건이 없고, 밖으로 나갔다 다시 들어오면 새 entered가 나옵니다.

필수 활동은 네 장면을 가진 짧은 영상을 직접 촬영하거나 권한 있는 영상에서 찾는 것입니다. 장면은 밖·안으로 이동·잠시 머무름·밖으로 나간 뒤 재진입입니다. 실행 전에 어느 프레임 구간에서 사건이 나올지 적고 실제 events.jsonl의 type과 비교합니다. 첫 관찰부터 안에 있는 별도 영상도 확인합니다. 여섯 줄짜리 모의 입력으로 상태 계산을 시험한 결과와 실제 YOLO 영상의 사건 결과를 별도 칸에 기록합니다. 함수가 맞아도 검출 박스가 흔들리면 사건이 잘못 나올 수 있습니다.

중복 ID가 같은 프레임에 두 번 들어오면 엔진은 duplicate_id 경고를 남기고 두 번째 관찰을 건너뜁니다. 이는 추적기 문제를 숨기지 않으면서 같은 프레임 사건 중복을 막습니다. max_gap=15는 15프레임보다 더 오래 관찰되지 않은 ID의 기억을 지우는 기준입니다. 프레임 기준이므로 10FPS와 30FPS에서 실제 시간은 다릅니다. 소실 뒤 같은 번호가 다시 나타나도 최초 관찰로 처리하며 진입을 확정하지 않습니다. 짧은 가림은 기억을 유지하므로 안에 있던 객체가 다시 보여도 사건이 반복되지 않습니다.

수정 과제는 config 복사본에서 구역 왼쪽을 0.25에서 0.4로 바꾸고 대표점이 들어오는 시점 차이를 확인하는 것입니다. 숫자 하나만 바꾸는 활동 다음에는 학생이 직접 상황을 설계합니다. 예를 들어 통로보다 좁은 구역이 누락을 만들거나 사람이 큰 박스로 잡힐 때 발 위치가 부정확해지는 장면을 재현합니다. 강사 풀이에서는 entered는 추적된 대표점의 상태 전이이며 실제 위험 사건의 공식 판정이 아니라는 점을 설명합니다. 추가 도전은 퇴장 이벤트를 별도 type으로 구현하고 진입·머무름·퇴장·재진입 시험을 추가하는 것입니다.
