# V08 · 내 영상 프로그램 완성과 AI·Git 인수인계

새 영상에서 재현하고 다음 대시보드에 넘기기


오늘의 최종 작품은 자기 목적을 가진 영상 인식 프로그램입니다. 안전 구역 접근 알림, 이동 방향 기록, 선택 사물의 구역 출입 관찰 중 하나를 고릅니다. 사람이 실제로 보고 판단해야 하는 장면을 먼저 한 문장으로 씁니다. '사람을 검출한다'보다 '통로에 접근한 추적 대상이 있을 때 담당자가 영상을 확인하도록 진입 사건을 남긴다'가 출력의 쓰임을 설명합니다. 실제 안전 설비의 대체나 엄밀한 고유 인원 집계라고 이름 붙이지 않습니다.

프로젝트의 파일 역할을 설명할 수 있어야 합니다. detector는 사진 판단, tracker는 ID 연결, zones는 좌표 계산, events는 이전 상태에 따른 변화, drawing은 화면 표시, main은 전체 순서와 파일 저장을 담당합니다. configs는 자주 바꾸는 숫자, tests는 규칙 검사, docs는 사용법과 실험 근거입니다. 파일을 나누는 이유는 오류가 생긴 역할을 찾고 제한된 변경을 검토하기 위해서입니다. 모든 코드를 main 한 파일에 합치면 지금은 열기 쉽지만 다음 수정 범위와 시험 대상을 찾기 어려워집니다.

필수 구현은 설정 하나 이상의 목적 있는 변경과 사건 규칙 또는 표시 기능 하나의 수정입니다. 예를 들어 구역 진입 후 화면에 안내 문구를 일정 프레임 동안 유지하거나 사건 종류별 표시를 바꿀 수 있습니다. 단순히 색만 바꾼 결과로 전체 기능을 완성했다고 평가하지 않습니다. 수정 전 행동·원하는 행동·바꿀 파일·보존할 필드·시험을 AI 프롬프트에 씁니다. AI가 제안한 설명을 읽고 자신이 이해한 줄에만 동의합니다. 모르는 새 패키지를 무조건 설치하거나 요구하지 않은 업로드 기능을 추가하지 않습니다.

kit 폴더에서 git status로 현재 변경을 확인합니다. 새 독립 저장소를 만드는 경우에만 git init을 한 번 실행합니다. 제공 키트를 기존 프로젝트 안에서 작업 중이면 상위 저장소 여부를 확인하고 중첩 저장소를 만들지 않습니다. git add src configs tests docs README.md AGENTS.md requirements.txt .gitignore로 공개 가능한 파일만 골라 준비한 뒤 git diff --cached로 내용과 영상·가중치 포함 여부를 확인합니다. 적절한 메시지 예는 feat: add zone entry notice입니다. commit은 로컬 기록이며 GitHub 공개 게시와 다릅니다.

가중치 .pt, 가상환경 .venv, 원본 영상, 얼굴이 찍힌 결과, 누적 로그는 runtime 아래 두고 추적에서 제외합니다. .gitignore는 새 파일을 제외할 뿐 이미 추적한 자료를 자동 삭제하지 않습니다. git check-ignore runtime/models/yolo11n.pt로 규칙을 확인하고 git ls-files로 이미 포함된 파일을 확인합니다. 실수로 포함한 경우 원본 파일을 지우기 전에 추적 해제 방법과 공개 이력을 강사와 확인합니다. 공개 전에는 본인 개인정보뿐 아니라 촬영 대상의 사용 권한도 검토합니다.

동료 검증에서는 다른 학생이 README만 읽고 같은 입력을 준비해 실행합니다. 실제 입력 파일은 공개 저장소에 올리지 않아도 이름·해시·준비 절차로 식별할 수 있습니다. 새 영상에서 진입·머무름·재진입·소실·선 통과를 다시 확인하고 결과가 다르면 수정 이력을 남깁니다. 다음 10/29 수업에는 events.jsonl을 API 입력으로 변환할 수 있습니다. 프레임마다 빈 events도 존재하므로 실제 사건 배열만 전송하고 세션·프레임·배열 위치로 사건 식별자를 만듭니다. observed_at은 처리 시각이고 video_seconds는 영상 안 시각이며 둘을 혼동하지 않습니다. 제출을 마칠 때 실행 성공·모의 시험·실제 웹캠 여부·남은 한계를 자기 말로 정리합니다.
