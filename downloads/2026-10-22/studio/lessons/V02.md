# V02 · 첫 YOLO 추론과 박스·클래스·신뢰도

결과 그림을 코드에서 다룰 수 있는 값으로 읽기


객체 검출 결과의 네모를 바운딩 박스라고 부릅니다. 박스는 사물의 윤곽선이 아니라 사물을 감싸는 직사각형입니다. 사진의 왼쪽 위를 원점으로 두고 오른쪽으로 갈수록 x, 아래로 갈수록 y가 커집니다. xyxy는 왼쪽 위 x·y와 오른쪽 아래 x·y를 순서대로 담습니다. 예를 들어 (100,50,300,450)은 폭 200, 높이 400인 박스입니다. 두 번째 y가 큰 것은 바닥 방향이기 때문입니다. 좌표가 cm나 실제 거리라고 생각하면 안 됩니다.

클래스는 모델이 붙인 종류 이름입니다. 이 수업의 COCO 사전학습 모델에서 0은 person입니다. ID 0이라는 숫자는 사람 개체의 번호가 아니라 종류 번호입니다. 신뢰도는 해당 예측이 얼마나 강한지 나타내는 모델 점수입니다. 0.9라고 해서 안전 사건을 90% 확률로 증명하거나 모든 사진에서 90% 정확하다고 보장하는 뜻은 아닙니다. 오검출은 없는 것을 잡거나 잘못 이름 붙인 것이고 누락은 실제 사물을 놓친 것입니다. 점수를 높이면 두 문제가 모두 사라진다는 보장은 없습니다.

kit 폴더 터미널에서 아래 명령을 실행합니다. --source 뒤는 입력 사진이고 --image는 한 장 모드입니다. --output 뒤는 결과를 둘 폴더이며 원본을 덮어쓰지 않습니다.
```powershell
.\.venv\Scripts\python.exe -m src.main --image --source runtime/input/photo.jpg --output runtime/results/photo1
```
실행 후 image.jpg를 열어 원본과 나란히 놓습니다. 터미널에는 detections와 classes, scores가 나옵니다. detections가 0일 수 있으며 실행 실패와 다릅니다. 클래스 필터는 사람만 남기도록 설정되어 있으므로 사진 속 버스가 보이더라도 박스가 없을 수 있습니다. 원본에 사람이 정말 없는지, 작게 가려져 있는지, 필터에서 제외됐는지를 차례대로 확인합니다.

src/detector.py의 load_model은 가중치 존재를 검사하고 모델을 엽니다. detect 함수의 model.predict는 새 사진을 판단합니다. 괄호 안 frame은 입력 이미지, conf는 남길 점수 기준, imgsz는 내부 계산 크기, classes는 종류 번호 목록입니다. 마지막 [0]은 반환된 결과 목록 중 첫 결과를 고릅니다. 점 .은 객체 안의 기능이나 값을 찾는 기호이고 쉼표는 서로 다른 인수를 나눕니다. 대괄호는 목록 또는 목록의 위치를 나타냅니다. 이 파일을 열고 함수 이름과 입력값을 색연필처럼 구분해 보세요.

필수 활동은 같은 사진에서 박스 두 개를 골라 종류·점수·좌표를 표로 기록하고, 사람이 눈으로 판단한 실제 대상과 비교하는 것입니다. 다음으로 default.json을 복사한 photo-high.json에서 conf만 0.35에서 0.65로 바꿉니다. 실행 전에 어떤 박스가 사라질지 예상하고 --config configs/photo-high.json으로 다시 실행합니다. 예상과 실제가 다르면 점수 값을 근거로 설명합니다. JSON의 숫자에는 따옴표를 붙이지 않고 항목 사이 쉼표를 유지합니다. 파일 읽기 오류는 문법 오류부터 고치고 모델의 인식 실패와 혼동하지 않습니다.

추가 도전은 classes를 [0,2]로 바꾸고 사람과 자동차를 함께 비교하는 것입니다. 새 종류를 추가하기 전에 모델 names에서 번호를 확인합니다. 사진마다 모델 파일을 새로 로드하면 준비 비용이 반복됩니다. 함수 바깥에서 한 번 로드한 객체를 다음 호출에도 넘기는 이유를 자신의 말로 설명하세요. 강사 풀이의 핵심은 가중치 읽기와 사진 판단을 분리하는 것입니다. 최종 제출에는 개인정보 없는 결과 그림 한 장과 누락 또는 오검출 설명을 넣습니다.
