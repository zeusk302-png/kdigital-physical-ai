# V03 · 프레임·동영상·웹캠을 같은 흐름으로 처리하기

입력 읽기와 종료·저장·재생을 따로 확인하기


동영상은 빠르게 이어지는 사진 묶음입니다. 한 장을 프레임이라고 부르고 초당 30장을 재생하면 입력 FPS가 30인 영상입니다. OpenCV는 카메라나 영상 파일에서 프레임을 가져오고 화면에 그림을 그리거나 결과 파일을 저장하는 도구입니다. YOLO는 가져온 한 장을 판단합니다. 따라서 입력 읽기→판단→사건 처리→그리기→저장의 순서를 반복해야 합니다. 이것을 반복 처리 흐름이라고 부릅니다. 전체 영상을 한 번에 메모리에 쌓지 않아도 한 장씩 처리할 수 있습니다.

먼저 사용 권한이 있는 짧은 동영상을 runtime/input/clip.mp4에 둡니다. 영상에는 학생 얼굴이나 개인정보가 찍히지 않도록 촬영 범위를 정합니다. 웹캠이 없는 경우 이 파일 경로로 검출·추적·구역 사건을 모두 수행할 수 있습니다. 웹캠 0은 첫 번째 카메라라는 장치 번호이며 파일 이름 '0'과 구분하기 위해 main에서 숫자로 바꿉니다. 다른 앱이 카메라를 쓰고 있으면 먼저 그 앱을 종료한 뒤 다시 엽니다.
```powershell
.\.venv\Scripts\python.exe -m src.main --source runtime/input/clip.mp4 --output runtime/results/video1 --show
.\.venv\Scripts\python.exe -m src.main --source 0 --output runtime/results/camera1 --show
```
화면 창을 클릭하고 q를 누르면 종료합니다. 창 표시가 어려운 환경은 --show를 빼고 저장 결과를 확인합니다. 첫 명령을 충분히 확인한 뒤 두 번째 명령을 시도합니다. 웹캠 미보유 학생은 그 사실과 사용한 영상 경로를 기록하며 카메라 성공으로 보고하지 않습니다.

capture.read()는 성공 여부와 이미지 두 값을 돌려줍니다. ok가 False이면 파일 끝이거나 읽기 실패입니다. while은 같은 일을 반복하고 break는 반복을 빠져나옵니다. try와 finally는 중간에 오류가 생겨도 마지막 정리 작업을 수행하도록 묶습니다. capture.release는 카메라를 돌려주고 writer.release는 저장 중인 영상 파일 끝 정보를 마무리합니다. 이 과정을 생략하면 다음 프로그램이 카메라를 열지 못하거나 영상 재생이 안 될 수 있습니다. 코드를 읽을 때 가장 먼저 입력을 여는 줄, 반복을 끝내는 줄, 자원을 닫는 줄을 찾아봅니다.

화면 좌표는 원본 크기에 따라 달라지므로 프로그램은 좌표를 0~1 비율로 바꾸어 사건 계산에 사용합니다. 가로가 1280인 영상에서 x=640은 0.5입니다. 가로 640인 영상의 x=320도 0.5입니다. 이 덕분에 관심 구역을 화면 중앙 25~75%처럼 정할 수 있습니다. 반면 실제 세계의 길이나 이동 속도는 원근·렌즈·카메라 위치에 따라 달라집니다. 화면 좌표 변화만으로 실제 이동 거리를 단정하지 않습니다.

필수 활동은 입력 영상 길이·입력 FPS와 처리된 프레임 수를 기록하고 annotated.mp4를 실제로 재생하는 것입니다. 소리가 없는 것은 이 예제의 정상 범위입니다. 영상 저장 코드는 화면 프레임만 쓰며 원본 오디오는 복사하지 않습니다. 저장 영상이 원래 재생 속도로 보이더라도 처리에 걸린 시간은 더 길 수 있습니다. 강사는 10초 파일을 처리하고 벽시계 시간을 비교하는 시연을 합니다. 학생은 --limit 30으로 첫 30프레임만 실행한 뒤 예상 저장 길이를 계산합니다. 입력 30FPS라면 약 1초 분량이지만 처리 시간은 환경에 따라 다릅니다. 추가 도전은 파일 끝과 카메라 읽기 실패가 각각 어떤 메시지를 만드는지 확인하는 것입니다.
