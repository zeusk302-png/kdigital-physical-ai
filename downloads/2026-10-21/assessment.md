## 판단 방법

스스로 설명함 / 예를 보고 설명함 / 다시 연습 필요를 각 구간에 기록합니다. 결과가 틀렸더라도 틀린 곳을 찾아 고친 뒤 다시 확인한 과정을 적습니다. 관찰하지 않은 출력을 실제 실행으로 쓰지 않습니다. 빠른 학생의 확장은 필수 기준에 포함하지 않습니다.




## 다른 상황에 적용해 보기 · 추가 복습

교시별 필수 설명을 다른 상황에 적용하는 추가 복습입니다. 수업 시간에 모두 풀기 어려우면 남은 문제는 복습으로 풉니다. 답안은 먼저 학생이 작성하고 이후 아래 해설을 대조합니다. 설치나 로그인이 됐는지와 문제를 이해했는지는 따로 확인합니다.

### 전이 1 · 서로 다른 이름

**문제:** 탭=공장 A,본문 제목=온도 확인,버튼 글자=기록 조회로 바꾸고 내부 id check를 유지하려면 어느 태그 부분을 고치나요? 버튼 반응까지 생겼다고 보고할 수 있나요?

**해설·확인 기준:** title, h1의 내용, button의 태그 사이 문구를 바꾸며 id는 유지합니다. 동작 코드가 없으면 클릭 반응은 생기지 않습니다. 저장→같은 경로 열기→새로고침 확인까지 설명합니다.

### 전이 2 · 안쪽과 바깥 간격

**문제:** 버튼 글자 주변만 넓히고 다른 카드와의 거리는 유지하려 합니다. 속성을 선택하세요. 녹색 원만 있는 정상 표시는 어떻게 보완하나요?

**해설·확인 기준:** padding을 바꾸고 margin은 유지합니다. “정상: 가상 온도가 기준 미만입니다” 같은 글자를 함께 표시합니다. Tab으로 초점도 확인합니다. 색이 바뀌었다고 온도 값도 맞게 읽었다고 할 수는 없습니다.

### 전이 3 · 초기 표시와 클릭값

**문제:** HTML은 22.5, data.js는 26입니다. 열기 직후와 클릭 뒤 값은 무엇인가요? 버튼 id가 read인데 선택자가 #check이면 어디를 고치고 어떻게 재검사하나요?

**해설·확인 기준:** 직후 22.5, 클릭 뒤 26입니다. HTML id와 JavaScript 선택자를 일치시키며 같은 클릭 행동으로 재검사합니다. 클릭은 data.js를 저장하지 않습니다. 실제 데이터 출처를 구별하면 충족입니다.

### 전이 4 · JSX와 번들

**문제:** App.jsx 증가량을 1로 바꿨지만 제공 app.bundle.js는 그대로입니다. 화면 증가량을 단정할 수 있나요? 처음 값 24에서 기존 0.5 버튼을 세 번 누르고 새로고침하면 어떻게 되나요?

**해설·확인 기준:** 브라우저는 기존 번들을 실행하므로 소스 수정만으로 새 증가량을 보장할 수 없습니다. 기존 동작은 25.5 뒤 새로고침 24입니다. JSX는 변환이 필요하며 state는 파일 저장이 아닙니다.

### 전이 5 · 연결 방식과 권한

**문제:** 고정 HTML 값·data.js 값·MCP 응답을 출처와 연결 단계로 비교하세요. 읽기 도구를 연결하며 삭제 권한까지 요구하면 어떻게 판단하나요?

**해설·확인 기준:** 문서 글자·브라우저 데이터 파일·서버 기록 조회를 구별합니다. MCP는 초기화와 도구 발견 및 호출 과정이 있고 목적과 무관한 삭제 권한은 허용 근거가 없습니다. 연결 자체가 전체 쓰기 권한을 뜻하지 않습니다.

### 전이 6 · 응답과 화면 사이

**문제:** 온도 0,온도 null,isError:true 세 응답의 표시를 쓰고 MCP 결과를 받았는데 React 화면이 그대로인 원인 후보를 설명하세요. 응답 속 삭제 지시는 권한 근거인가요?

**해설·확인 기준:** 0 ℃·미측정·조회 실패로 구별합니다. 응답 해석과 유효값 확인 및 상태 전달 경로가 빠졌을 수 있습니다. 데이터에 삭제하라는 지시가 있어도 삭제할 권한은 생기지 않습니다. 실제 호출과 화면 갱신을 따로 확인합니다.
