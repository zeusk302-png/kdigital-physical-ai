# W06 JavaScript로 메뉴와 문의 검사 연결

JavaScript는 사용자의 행동을 받아 화면이나 데이터를 바꾸는 언어입니다. 문서의 버튼을 찾고, 클릭 사건을 기다린 뒤, 상태를 바꾸는 순서로 생각합니다. DOM은 브라우저가 HTML을 읽어 만든 요소들의 구조입니다. document.querySelector('#menu-button')은 그 구조에서 id가 menu-button인 첫 요소를 찾습니다. const는 다시 다른 값을 대입하지 않을 이름을 만들고, 등호는 오른쪽 결과를 왼쪽 이름에 저장합니다. 세미콜론은 문장의 끝입니다. HTML의 id를 바꾸면 JS에서 찾는 이름도 맞춰야 합니다.

addEventListener('click', 함수)는 지금 함수를 실행하는 대신 클릭 때 실행할 일을 등록합니다. 괄호 안의 첫 값은 사건 이름이고 두 번째는 할 일입니다. 중괄호 안의 코드가 함수의 본문입니다. 메뉴의 aria-expanded 값을 문자열 'true'와 비교해 현재 열림을 읽습니다. ===는 두 값이 같은지 비교하고 !는 참과 거짓을 뒤집습니다. setAttribute는 접근성 상태를 바꾸고 classList.toggle은 CSS에 쓸 클래스를 붙이거나 뗍니다. 화면만 열리고 aria-expanded가 그대로면 보조 기술에 잘못된 상태가 전달됩니다.

FAQ는 details와 summary라는 HTML 기본 요소로 먼저 구현합니다. 별도 JS 없이 키보드로 열고 닫을 수 있다는 장점이 있습니다. 모든 상호작용에 JS를 작성할 필요는 없습니다. React판에서는 state 학습을 위해 같은 내용을 버튼과 조건부 표시로 다시 만듭니다. 두 방식의 목적을 구별해 설명합니다. 메뉴는 실제 이동 링크를 포함하고, 작은 화면에서 링크를 고르면 메뉴를 닫습니다. 닫힌 메뉴의 링크가 Tab 순서에 남아 있는지도 확인합니다.

문의 폼은 label과 입력칸을 연결하고 이름, 이메일, 내용을 검사합니다. 예제는 서버로 전송하지 않으며 성공 문구도 ‘입력 확인 완료, 전송하지 않았습니다’라고 표시합니다. trim()은 양끝 공백을 제거하므로 공백만 입력한 이름은 빈 값이 됩니다. if는 조건이 참일 때 다른 결과를 돌려주고 return은 함수 결과를 정합니다. 이메일 검사는 공백 없는 간단한 형식 확인이며 실제 주소가 존재하는지는 보장하지 않습니다. submit 사건의 preventDefault()는 페이지가 새로 이동하는 기본 동작을 멈춥니다.

필수 직접 구현은 빈 이름이면 안내하는 분기를 읽고, 내용 최소 길이를 10에서 20으로 바꾸며, 19자와 20자를 비교하는 것입니다. 메뉴 버튼 동작을 한 줄씩 자기 말로 설명합니다. 오류는 개발자 도구 Console에서 첫 줄부터 읽습니다. null에 메서드를 호출했다면 요소 이름이나 스크립트 실행 위치를 확인합니다. script의 type="module"은 모듈로 읽고 문서 해석 뒤 실행하게 돕습니다. 따옴표 한 쌍을 지운 오류를 만든 뒤 되돌려 복구합니다. 추가 도전은 오류 메시지를 해당 입력칸 가까이 두고 첫 오류 입력칸으로 초점을 옮기는 것입니다.

## 확인과 합류

필수: 본문에서 지시한 한 기능을 직접 작성하고 예상과 실제 결과를 docs/checks.md에 남깁니다. 막힌 학생은 완성 예제에서 해당 부분을 찾아 먼저 실행한 후 자기 문구로 수정합니다. 설치 실패는 개념 미성취로 처리하지 않습니다. 짝은 수정 위치와 이유를 묻고 대신 입력하지 않습니다.
