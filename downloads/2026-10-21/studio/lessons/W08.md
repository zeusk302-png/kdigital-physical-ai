# W08 state로 화면을 바꾸고 폼 비교하기

상태는 화면이 기억해야 하는 현재 값입니다. FAQ가 열려 있는가, 메뉴가 열려 있는가, 입력 안내가 무엇인가처럼 시간이 지나며 바뀌는 값이 해당합니다. 일반 변수만 바꾸면 React가 다시 그려야 한다는 사실을 알지 못합니다. useState는 값과 값을 바꾸는 함수를 한 쌍으로 제공합니다. const [open, setOpen] = useState(false)에서 대괄호는 두 결과를 각각 이름에 담는 문법입니다. false는 처음 닫혀 있다는 뜻입니다. Hook은 컴포넌트 함수의 맨 위에서 호출하며 조건문 안에서 호출하지 않습니다.

버튼의 onClick={() => setOpen(!open)}은 클릭 때 현재 값의 반대로 상태를 바꿉니다. 화살표 함수는 나중에 실행할 일을 짧게 쓰는 표현입니다. onClick={setOpen(true)}로 적으면 그리는 도중 함수를 호출하므로 같은 의미가 아닙니다. 상태 변경 요청 뒤 React가 컴포넌트를 다시 실행하고 새 값으로 JSX를 계산합니다. DOM 요소를 직접 찾아 textContent를 바꾸는 코드와 React state를 같은 영역에 섞으면 화면의 기준이 둘이 됩니다. 오늘 React 부품 안에서는 state를 기준으로 그립니다.

aria-expanded={open}은 열림 상태를 버튼의 접근성 속성에 전달합니다. hidden={!open}은 닫혔을 때 내용을 숨깁니다. 삼항 연산자 open ? '닫기' : '열기'는 참일 때와 거짓일 때 다른 글을 선택합니다. 화면에서 보이는 말과 실제 상태를 함께 확인합니다. 첫 클릭 전에 닫힘, 첫 클릭 뒤 열림, 두 번째 클릭 뒤 닫힘이라는 순서를 표로 예측한 뒤 실제 결과와 비교합니다. 키보드 Enter와 Space로도 같은 상태 변화를 확인합니다.

Contact 컴포넌트는 form의 submit 사건에서 FormData로 입력값을 읽고 공유 함수 validateContact에 넘깁니다. FormData는 폼의 name 속성을 기준으로 값을 모읍니다. label의 htmlFor는 id와 연결되고 name은 값 수집용이므로 서로 다른 역할입니다. e.currentTarget은 사건이 연결된 폼이며 e.preventDefault는 기본 이동을 멈춥니다. 이 수업은 모든 키 입력을 state로 저장하는 제어 입력을 필수로 삼지 않습니다. 결과 안내만 state로 보관해 개념을 작게 유지합니다. 서버 전송은 여전히 하지 않습니다.

필수 활동은 FAQ의 초기값을 true로 바꾸고 첫 화면이 어떻게 달라질지 설명한 뒤 실행하는 것입니다. 다음은 같은 FAQ 컴포넌트를 두 번 놓아 서로 독립적으로 열리는지 확인합니다. 문의 내용 최소 길이는 공유 JS 함수를 고쳐 HTML판과 React판에 같은 기준을 적용합니다. 예상과 실제가 다르면 어느 원본과 주소를 열었는지 먼저 확인합니다. 추가 도전은 한 질문만 열리도록 부모에서 열린 id를 관리하는 것입니다. 이때 자식마다 따로 가진 state를 부모 하나로 올리는 이유를 ‘한 가지 진실한 기준이 필요해서’라고 설명할 수 있어야 합니다.

## 확인과 합류

필수: 본문에서 지시한 한 기능을 직접 작성하고 예상과 실제 결과를 docs/checks.md에 남깁니다. 막힌 학생은 완성 예제에서 해당 부분을 찾아 먼저 실행한 후 자기 문구로 수정합니다. 설치 실패는 개념 미성취로 처리하지 않습니다. 짝은 수정 위치와 이유를 묻고 대신 입력하지 않습니다.

강사 피드백: 화면만 보여 달라고 하지 않고 원본 파일, 바꾼 줄, 예상, 실행 주소를 함께 확인합니다. 추가 도전은 필수 완료 뒤 선택합니다.
