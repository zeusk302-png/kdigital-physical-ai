# W01 방문자와 목적부터 기획하기

랜딩페이지는 방문자가 처음 도착해 무엇을 하는 곳인지 이해하고 다음 행동을 고르는 한 장의 웹페이지입니다. 가게 안내판에 모든 업무 자료를 붙이지 않듯, 첫 화면에도 가장 중요한 한 가지 메시지를 둡니다. 오늘의 예시는 동네 산책 모임 ‘걸음’을 소개하고 참여 전 궁금증을 확인하는 페이지입니다. 학생은 포트폴리오, 제품 소개, 취미 모임 중 자기 주제로 바꿉니다. 예시와 색만 똑같이 만드는 것이 목표는 아닙니다.

먼저 kit/docs/brief.md를 엽니다. ‘누가 방문하는가’, ‘그 사람의 문제는 무엇인가’, ‘어떤 약속을 할 것인가’, ‘무엇을 누르기를 바라는가’를 한 문장씩 작성합니다. 방문자를 ‘모든 사람’으로 적으면 글과 버튼을 고르기 어렵습니다. ‘주말에 동네를 걷고 싶지만 혼자 나가기 어려운 직장인’처럼 상황을 적습니다. 주요 행동을 CTA라고 부릅니다. 여기서는 ‘모임 알아보기’ 버튼이 페이지 아래 문의 영역으로 이동합니다. 서버 없는 예제의 버튼을 ‘결제하기’로 바꾸고 결제한 것처럼 안내해서는 안 됩니다.

레퍼런스는 MDN 학습 페이지, React Learn, GitHub Pages 소개처럼 실제 열리는 홈페이지 세 곳을 각자 관찰합니다. 같은 디자인을 복제하기 위한 수집이 아닙니다. 첫 화면 제목이 몇 줄인지, 설명 다음에 어떤 버튼이 오는지, 본문 폭이 어디서 멈추는지, 휴대전화 폭에서 메뉴가 어떻게 바뀌는지를 기록합니다. 이미지나 로고는 허락 없이 내려받아 쓰지 않습니다. 예제에는 직접 만든 SVG 삽화를 포함했습니다. 본인 사진으로 교체할 때도 공개할 권리를 먼저 확인합니다.

종이에 위에서 아래로 헤더, 히어로, 장점 세 개, 소개 또는 사례, FAQ, 문의, 푸터 상자를 그립니다. 히어로는 첫 화면의 큰 소개 영역을 가리킵니다. 장점은 ‘최고의 서비스’ 같은 평가보다 ‘매주 토요일 60분’, ‘처음 온 사람도 함께’처럼 확인할 수 있는 내용을 씁니다. 예시는 교육용 가상 모임이며 회원 정보를 수집하지 않습니다. 수치나 후기는 가상의 성과를 실제처럼 제시하지 않고 본인 프로젝트 설명으로 교체합니다.

예시의 방문자와 버튼을 확인하고 docs/brief.md의 첫 문장을 고칩니다. 학생은 자기 주제의 제목·설명·버튼 문구 세 개를 직접 새로 씁니다. 다음에는 짝이 기획서를 30초 읽고 ‘누구를 위한 무엇이며 어디를 눌러야 하는지’를 자기 말로 설명합니다. 예상과 다른 답이면 문구를 먼저 고칩니다. 추가 도전은 두 제목 후보를 비교하고 선택 이유를 기록하는 것입니다. 아직 CSS를 작성하지 않아도 완료할 수 있습니다.

## 확인과 합류

필수: 본문에서 지시한 한 기능을 직접 작성하고 예상과 실제 결과를 docs/checks.md에 남깁니다. 막힌 학생은 완성 예제에서 해당 부분을 찾아 먼저 실행한 후 자기 문구로 수정합니다. 설치 실패는 개념 미성취로 처리하지 않습니다. 짝은 수정 위치와 이유를 묻고 대신 입력하지 않습니다.
