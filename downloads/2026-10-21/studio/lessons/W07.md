# W07 React를 처음 만나는 사람을 위한 부품과 JSX

React는 사용자 인터페이스를 작은 부품으로 나누고 데이터와 함께 그리는 JavaScript 라이브러리입니다. 기존 HTML을 지워야만 React를 배울 수 있는 것은 아닙니다. 오늘은 완성 HTML판과 실행 가능한 React판을 나란히 열고 Header, Hero, FeatureCard를 대응시킵니다. HTML판은 index.html의 내용을 고치고 React판은 src/App.jsx와 components 안의 파일을 고칩니다. 두 화면은 같은 주제를 다루지만 서로 다른 원본이므로 한쪽 수정이 다른 쪽에 자동 복사되지는 않습니다.

컴포넌트는 화면 일부를 돌려주는 함수입니다. function Hero() { return (...); }에서 function은 할 일을 묶는 선언, Hero는 이름, 괄호는 입력 자리, return은 그릴 내용을 돌려주는 말입니다. React 컴포넌트 이름은 대문자로 시작합니다. JSX는 JavaScript 안에서 태그와 비슷하게 화면을 표현하는 문법입니다. HTML과 닮았지만 class 대신 className, label의 for 대신 htmlFor를 쓰며, 형제 요소를 돌려줄 때 하나의 부모나 Fragment로 감쌉니다. 브라우저는 JSX를 그대로 읽지 못하므로 Vite가 변환합니다.

main.jsx는 문서의 root 요소를 찾아 createRoot로 React를 연결하고 App을 그립니다. import는 다른 파일이 내보낸 기능을 가져옵니다. './App.jsx'의 점은 현재 파일이 있는 폴더 기준입니다. export는 다른 파일에서 가져갈 수 있게 표시합니다. 파일을 components/Hero.jsx로 옮기면 import 경로도 고칩니다. 흰 화면이면 저장 여부, 터미널 변환 오류, Console의 경로 오류를 차례로 봅니다. .jsx 파일을 더블클릭하는 것은 실행 방법이 아닙니다.

props는 부모가 부품에 전달하는 입력입니다. <FeatureCard title="함께 걷기" text="처음이어도 괜찮아요" />에서 title과 text가 입력 이름입니다. 함수가 받은 { title, text }는 객체 안에서 두 값을 꺼내는 문법입니다. JSX 안의 {title}는 글자 그대로 title을 쓰는 대신 변수 값을 넣습니다. 중괄호와 따옴표의 차이를 비교합니다. 카드 세 개를 데이터 배열에서 map으로 그릴 때 각 카드의 key는 서로 구별되는 안정된 id입니다. 배열 위치 번호를 습관적으로 key로 쓰지 않습니다.

함께 따라 하기는 Hero의 제목을 자기 문구로 바꾸고 /react.html에서 결과를 확인하는 것입니다. 개별 활동은 카드 하나를 새 내용으로 추가하고 props가 들어가는 경로를 그립니다. HTML판의 section과 React 컴포넌트 파일이 대응하는 표를 만듭니다. 학생이 전체 페이지를 처음부터 전환할 필요는 없습니다. 필수 기준은 작동하는 골격에서 부품 하나를 직접 수정·재사용하고 빌드 결과에도 반영하는 것입니다. 추가 도전은 FAQ 항목을 객체 배열로 분리해 다른 질문에도 재사용하는 것입니다. ‘React가 자동으로 반응형을 만든다’는 설명은 틀립니다. 배치는 여전히 CSS로 정합니다.

## 확인과 합류

필수: 본문에서 지시한 한 기능을 직접 작성하고 예상과 실제 결과를 docs/checks.md에 남깁니다. 막힌 학생은 완성 예제에서 해당 부분을 찾아 먼저 실행한 후 자기 문구로 수정합니다. 설치 실패는 개념 미성취로 처리하지 않습니다. 짝은 수정 위치와 이유를 묻고 대신 입력하지 않습니다.
