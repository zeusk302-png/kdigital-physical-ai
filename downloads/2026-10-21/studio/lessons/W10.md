# W10 Git·빌드·배포와 독립 요구 변경

Git은 작업 원본의 변경 이력을 남기는 도구입니다. 공유할 원본과 다시 만들 수 있는 산출물을 구별합니다. src, index.html, react.html, public의 허가된 이미지, package.json, package-lock.json, README, AGENTS, docs는 기록합니다. node_modules는 설치한 도구의 복사본이며 dist는 빌드 결과입니다. 둘은 크고 다시 만들 수 있어 .gitignore로 제외합니다. 실제 .env, 비밀키, 개인 문의 자료도 저장소에 넣지 않습니다. .gitignore는 이미 기록된 파일을 지워 주는 기능이 아니므로 커밋 전 상태를 직접 확인합니다.

kit 안에서 git status를 실행하고 이 폴더가 이미 큰 저장소 안에 있는지 먼저 확인합니다. 학생 개인 작업은 ZIP을 별도 폴더에 풀어 사용합니다. 남의 저장소 안에서 무작정 git init을 실행하지 않습니다. 독립 폴더에서 git init, git add ., git status, git commit -m "feat: create landing page" 순으로 진행합니다. status에 node_modules가 있으면 .gitignore 위치를 확인합니다. git diff --cached로 실제 기록할 내용을 읽습니다. 작성자 이름·이메일 설정은 지난 수업을 기억한다고 가정하지 않고 오류 메시지에 따라 설정합니다.

npm.cmd run build는 소스와 의존성을 읽어 dist에 브라우저용 결과를 만듭니다. npm.cmd run preview는 그 결과를 로컬에서 확인합니다. dev 성공과 build 성공은 다르며, preview 성공과 공개 배포 성공도 다릅니다. vite.config.js의 base: './'는 하위 폴더에서도 생성 자산을 상대경로로 읽게 합니다. React판은 dist/react.html입니다. 소스 JSX를 수정한 뒤 build를 다시 하지 않고 예전 dist를 올리면 이전 화면이 보입니다. dist 파일만 고치면 다음 빌드 때 사라지므로 원본을 고칩니다.

본인 GitHub 계정과 공개 권한이 준비된 학생은 새 저장소에 원본을 푸시합니다. kit/docs/deploy.md의 Actions 예제는 push 때 npm ci, build, Pages artifact 업로드, 배포를 실행합니다. Settings → Pages에서 Source를 GitHub Actions로 선택합니다. 저장소 공개 여부와 이미지 권리를 본인이 확인하고 본인 작업만 게시합니다. Actions의 성공 표시 뒤 표시된 공개 URL을 열고 이미지, CSS, /react.html, 메뉴, 문의 안내를 다시 확인합니다. 실패한 상태를 URL만 적어 제출하지 않습니다.

마지막 독립 과제는 ‘제목이 두 배 길어지고 장점이 네 개이며 문의 내용은 20자 이상이어야 한다’는 새 요구를 반영하는 것입니다. 기획서, HTML 또는 React 원본, CSS, 공유 검사 함수를 각각 어디까지 고칠지 먼저 표시합니다. 수정 후 정상·경계·실패 입력을 비교하고 모바일 캡처와 검수 기록을 제출합니다. 외부 배포를 못 했으면 로컬 주소와 이유를 적고 공개 완료로 쓰지 않습니다. 추가 도전은 짝의 새 문구와 이미지로도 구조가 유지되는지 검토하는 것입니다. 강사는 화면 완성도와 설치·인증 문제를 분리해 평가합니다.

## 확인과 합류

필수: 본문에서 지시한 한 기능을 직접 작성하고 예상과 실제 결과를 docs/checks.md에 남깁니다. 막힌 학생은 완성 예제에서 해당 부분을 찾아 먼저 실행한 후 자기 문구로 수정합니다. 설치 실패는 개념 미성취로 처리하지 않습니다. 짝은 수정 위치와 이유를 묻고 대신 입력하지 않습니다.

강사 피드백: 화면만 보여 달라고 하지 않고 원본 파일, 바꾼 줄, 예상, 실행 주소를 함께 확인합니다. 추가 도전은 필수 완료 뒤 선택합니다.
