# W09 AI에게 작업을 나눠 맡기고 변경 확인하기

## 코드와 팀 문서의 역할

코드는 GitHub 저장소에, 팀의 의견과 결정은 Notion에 둡니다. 저장소는 파일의 변경을 추적하고 Notion은 팀원이 함께 읽을 작업 내용을 정리합니다. GitHub Pages는 방문자가 보는 완성 화면입니다. 같은 프로젝트라도 세 장소의 역할이 다릅니다. Notion에 글을 썼다고 홈페이지가 바뀌지는 않습니다.

에이전트는 요청에 따라 파일을 읽거나 수정하는 도구입니다. 먼저 목적·현재 파일·유지할 조건·완료 확인을 알려 줍니다. 오늘 만든 HTML판은 index.html, React판은 src/App.jsx와 components 폴더가 원본입니다. 화면 전체를 한 번에 다시 만들게 하지 말고 한 문제씩 요청합니다.

## 작업 전 상태를 남기기

VS Code에서 kit 폴더를 연 상태로 Terminal → New Terminal을 선택합니다. 아래 명령은 현재 프로젝트 터미널에 한 줄씩 입력합니다. git status에서 저장소 밖이라고 나오면 W10의 초기 설정부터 진행합니다.

```powershell
git status
git diff
```

수정 중인 파일을 먼저 확인하고 정상 작동하는 시점을 커밋합니다. AI 수정 뒤에는 VS Code Source Control에서 바뀐 파일을 눌러 이전 내용과 비교합니다. 빨간 줄은 빠진 내용, 초록 줄은 추가한 내용입니다. 작업과 관계없는 제목·색·파일 삭제까지 섞였다면 해당 변경을 받지 않고 범위를 다시 설명합니다.

## 복사할 요청문

```text
docs/brief.md와 docs/design.md, src/styles/layout.css를 읽어.
390px 화면에서 제목과 메뉴가 겹치는 문제를 해결하려고 해.
원인을 설명하고 수정할 파일·확인 방법부터 제안해.
내 문구·이미지·데스크톱 배치는 유지해.
이번에는 관련 CSS만 수정하고 새 패키지를 추가하지 마.
수정 뒤 모바일과 데스크톱에서 확인한 사실을 보고해.
```

계획을 읽은 뒤 수정 범위를 승인하고 실행합니다. AI가 화면 확인 도구를 쓰지 않았다면 ‘화면 확인 완료’라는 문장만 믿지 않고 직접 브라우저에서 확인합니다. 빌드 성공은 화면의 모든 기능이 정상이라는 뜻이 아닙니다.

## 직접 해보기

긴 제목 때문에 줄바꿈이 어색한 문제를 하나 고릅니다. 예상한 원인, 변경 파일, 수정 전후 결과를 docs/checks.md에 적습니다. 다음에는 팀원이 적은 피드백을 같은 형식의 작업 요청으로 바꿉니다. 모든 의견을 그대로 구현하지 말고 지금 페이지의 목적과 맞는지 먼저 판단합니다.
