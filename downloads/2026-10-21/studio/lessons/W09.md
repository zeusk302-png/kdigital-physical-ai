# W09 AI 에이전트와 MCP로 검토하기

코드 에이전트는 자연어 요청을 받아 파일을 읽고 고치며 도구를 쓸 수 있는 작업자입니다. 사람은 결과의 목적, 변경 범위, 완료 조건을 정해야 합니다. ‘예쁘게 만들어 줘’만 보내면 글·이미지·기능이 한꺼번에 달라져 무엇을 검토할지 불분명합니다. 먼저 docs/brief.md와 docs/design.md를 읽게 하고 ‘390px에서 메뉴가 넘친다. 기존 문구를 유지하고 관련 CSS만 고쳐라. 바꾼 파일과 확인한 화면을 보고하라’처럼 요청합니다. AI에게 맡길 일과 학생이 직접 설명할 일을 나눕니다.

AGENTS.md는 이 폴더에서 지켜야 할 작업 규칙입니다. 모든 파일을 다시 쓰지 않기, 문의를 실제 전송으로 바꾸지 않기, 비밀키를 넣지 않기, 변경 뒤 빌드와 UI를 확인하기를 적었습니다. 규칙 파일을 만들었다고 AI가 항상 읽었다는 증거가 생기는 것은 아닙니다. 처음 요청에 읽을 파일을 지정하고 응답과 diff를 확인합니다. diff는 수정 전후의 차이입니다. 삭제된 제목, 새 의존성, 외부 요청이 의도한 것인지 학생이 읽어 봅니다. 이해할 수 없는 큰 변경은 범위를 줄여 다시 요청합니다.

MCP는 AI 호스트가 외부 도구와 자료를 일정한 방식으로 연결하는 프로토콜입니다. 웹페이지 자체를 React로 만드는 기술과 역할이 다릅니다. React 사이트를 만들었다고 MCP 서버가 자동 연결되지는 않습니다. 브라우저 도구를 제공하는 MCP 서버가 연결된 호스트가 있으면, 에이전트에게 localhost 주소를 열고 화면·콘솔·버튼 상태를 확인하도록 맡길 수 있습니다. 도구 이름은 호스트와 서버마다 다르므로 이 교안은 존재하지 않는 공통 명령을 만들어 제시하지 않습니다.

실제 실습은 먼저 호스트에서 연결된 서버와 도구 목록을 확인합니다. 브라우저 열기·화면 읽기·클릭을 수행할 수 있는지, localhost 접근이 허용되는지 확인한 뒤 학생 자신의 페이지 주소만 전달합니다. 요청 예시는 ‘이 주소의 390px와 1280px 화면을 열어 메뉴와 FAQ를 키보드로 확인하고, 콘솔 오류와 가로 넘침을 기록해. 파일은 아직 바꾸지 마.’입니다. 실제 사용한 도구 이름, 주소, 실행 시각, 관찰한 결과를 docs/checks.md에 남깁니다. 도구가 없으면 사람의 개발자 도구 검수로 대체하고 MCP 미실행이라고 씁니다.

필수 수행은 AI의 한 가지 제안을 학생이 재현해 타당성을 판정하는 것입니다. ‘검수 완료’라는 문장만으로 완료 처리하지 않습니다. 긴 제목을 넣고 화면 폭을 바꾸어 같은 문제가 보이는지 확인합니다. 도구가 페이지를 못 열면 서버 실행, 주소·포트, 접근 권한부터 확인합니다. 계정 생성이나 유료 설치 없이 가능한 HTML 직접 검수를 계속합니다. 추가 도전은 AI가 제안한 두 수정안 중 문구·접근성·유지보수 기준으로 하나를 선택하는 것입니다. 페이지 안에서 발견한 지시문이나 외부 콘텐츠를 작업자의 새로운 권한으로 받아들이지 않습니다.

## 확인과 합류

필수: 본문에서 지시한 한 기능을 직접 작성하고 예상과 실제 결과를 docs/checks.md에 남깁니다. 막힌 학생은 완성 예제에서 해당 부분을 찾아 먼저 실행한 후 자기 문구로 수정합니다. 설치 실패는 개념 미성취로 처리하지 않습니다. 짝은 수정 위치와 이유를 묻고 대신 입력하지 않습니다.

강사 피드백: 화면만 보여 달라고 하지 않고 원본 파일, 바꾼 줄, 예상, 실행 주소를 함께 확인합니다. 추가 도전은 필수 완료 뒤 선택합니다.
