# W04 CSS의 선택자·박스·색과 글자

CSS는 이미 놓인 내용에 모양과 공간 규칙을 붙입니다. .hero { padding: 3rem; }에서 점은 class 이름을 찾으라는 뜻이고 중괄호는 그 대상에 적용할 규칙의 묶음입니다. padding은 테두리 안쪽 여백, 콜론은 속성과 값 사이, 세미콜론은 규칙 끝을 나타냅니다. .hero와 HTML의 class="hero"가 정확히 맞아야 적용됩니다. #hero는 id를 찾으므로 점과 샵을 바꾸어 쓰지 않습니다. CSS는 보통 뒤에 나온 같은 우선순위 규칙이 앞의 규칙을 덮으므로 덧붙이기만 반복하면 원인을 찾기 어려워집니다.

모든 요소를 상자로 생각합니다. 내용의 폭에 padding, border, margin이 연결됩니다. margin은 상자 바깥의 간격이고 padding은 안쪽 공간입니다. box-sizing: border-box는 지정 폭 안에 padding과 border를 포함해 계산하기 쉽게 합니다. width: 100%만 주고 큰 padding을 더하면 설정에 따라 화면 밖으로 밀릴 수 있습니다. 개발자 도구에서 요소를 선택하고 Computed의 박스 그림을 보면 실제 공간을 읽을 수 있습니다. ‘왜 떨어졌지?’를 감으로 고치지 말고 어느 공간인지 먼저 확인합니다.

src/styles/tokens.css의 :root에는 --ink, --paper, --accent, --space 같은 이름이 있습니다. 이것은 여러 곳에서 다시 쓸 CSS 사용자 지정 속성입니다. var(--accent)는 해당 이름의 값을 가져옵니다. 오늘은 본문색, 배경색, 강조색을 세 가지로 정하고 제목 크기와 본문 줄 간격을 일정하게 맞춥니다. 글자를 작게 하여 모든 내용을 첫 화면에 넣는 것보다 문단을 줄이고 순서를 고치는 편이 읽기 좋습니다. rem은 기본 글자 크기를 기준으로 하므로 확대 설정과 함께 검토할 수 있습니다.

강사는 배경색 하나를 바꾸기 전에 어떤 영역이 바뀔지 묻고 실제 결과와 비교합니다. 학생은 강조색, 본문 line-height, 카드 padding을 각각 한 번씩 독립적으로 바꿉니다. 세 값을 한 번에 바꾸면 무엇 때문에 달라졌는지 알기 어렵습니다. 변경 후 200% 확대에서도 글자와 버튼이 겹치지 않는지 확인합니다. 색만으로 의미를 구별하지 않고 버튼에는 행동을 적습니다. :focus-visible 규칙은 Tab으로 이동할 때 현재 위치를 보여 줍니다. 보기 싫다는 이유로 outline을 제거하지 않습니다.

오류 복구는 CSS 파일 연결, 선택자 철자, 닫는 중괄호, 적용 순서 순으로 진행합니다. Network에서 CSS가 404이면 내용보다 경로 문제입니다. Styles에서 규칙에 취소선이 있으면 더 강하거나 뒤의 규칙이 덮은 것입니다. 필수 산출물은 docs/design.md의 색 세 가지와 간격 기준, 수정 전후 캡처입니다. 추가 도전은 본문 길이가 두 배가 되었을 때 카드 높이를 고정하지 않고도 정돈되어 보이게 만드는 것입니다. 실제 제목과 본문을 읽으며 검토해야 색 견본만 바꾸는 활동에서 벗어날 수 있습니다.

## 확인과 합류

필수: 본문에서 지시한 한 기능을 직접 작성하고 예상과 실제 결과를 docs/checks.md에 남깁니다. 막힌 학생은 완성 예제에서 해당 부분을 찾아 먼저 실행한 후 자기 문구로 수정합니다. 설치 실패는 개념 미성취로 처리하지 않습니다. 짝은 수정 위치와 이유를 묻고 대신 입력하지 않습니다.

강사 피드백: 화면만 보여 달라고 하지 않고 원본 파일, 바꾼 줄, 예상, 실행 주소를 함께 확인합니다. 추가 도전은 필수 완료 뒤 선택합니다.
