# W13 배포 오류를 고치고 수정본 다시 공개하기

## 오류 위치부터 나누기

내 PC의 dev 화면, build 결과의 preview, GitHub Actions, 공개 URL은 서로 다른 단계입니다. 문제가 난 단계부터 확인하면 같은 코드를 계속 다시 만드는 일을 줄일 수 있습니다. 화면이 안 보인다는 말 대신 주소·작업 단계·첫 오류를 적습니다.

| 상황 | 확인 위치 | 해결 방향 |
|---|---|---|
| npm ci에서 실패 | 터미널 또는 Actions의 해당 단계 | Node 버전·잠금 파일·네트워크 확인 |
| npm test에서 실패 | 실패한 시험 이름과 기대값 | 변경한 요구와 코드·시험의 일치 확인 |
| npm run build에서 실패 | 첫 구문·import 오류 | 파일명 대소문자·경로·JSX 문법 수정 |
| Pages 설정을 못 찾음 | 저장소 Settings·내 권한 | 본인 저장소인지와 관리 권한 확인 |
| 배포 작업에서 404 | Pages Source와 배포 로그 | GitHub Actions 선택 뒤 재실행 |
| 공개 주소 전체가 404 | 계정명·저장소명·Actions 상태 | Code 주소 대신 Pages URL 열기 |
| 글만 보이고 CSS·이미지 없음 | 개발자 도구 Network | 저장소 하위 경로·상대 주소·대소문자 확인 |
| React 화면만 흰색 | 공개 /react.html의 Console | 번들 경로·소스 오류 확인 |
| 수정했는데 예전 내용 | 최근 커밋·Actions·브라우저 | 저장·commit·push·배포 성공 여부 순서 확인 |

브라우저에서 F12 또는 우클릭 검사로 개발자 도구를 엽니다. Network에서 새로고침하고 빨간 요청의 Status와 URL을 확인합니다. 404는 그 주소에 파일이 없다는 뜻입니다. Console의 첫 오류를 확인하고, 화면에 보인 마지막 오류만 복사하지 않습니다.

## 의도한 오류 두 가지

먼저 정상 화면을 커밋합니다. 오류는 하나씩 만들고 바로 복구합니다.

1. 이미지 파일명을 HTML에서만 다른 대소문자로 바꿉니다. 실제 파일명과 요청 주소를 비교합니다. 로컬에서 재현되지 않으면 공개 Linux 환경과 대소문자 처리 차이를 설명하고, 복구한 뒤 게시합니다. 고장 난 버전을 계속 공개해 둘 필요는 없습니다.
2. 로컬 원본 제목을 바꾸고 preview를 새로고침합니다. build 전이라 이전 제목이 남는지 확인합니다. npm.cmd run build 후 preview를 다시 확인합니다. 원본과 dist의 차이를 자기 말로 설명합니다.

경로 추가 도전은 vite.config.js의 base를 '/'로 바꾸고 하위 저장소 경로에서 생길 요청 주소를 예상하는 것입니다. 복구는 './'입니다. 이 설정을 바꾼 채 무작정 여러 번 배포하지 말고 요청 URL이 왜 달라지는지 먼저 확인합니다.

## 수정하고 재배포

프로젝트 터미널에서 아래를 한 줄씩 실행합니다. test나 build가 실패하면 다음 push를 하지 말고 오류를 해결합니다. git add 뒤의 경로는 실제 수정 파일에 맞춰 고릅니다.

```powershell
npm.cmd test
npm.cmd run build
git status
git diff
git add index.html src docs
git diff --cached
git commit -m "fix: apply team review feedback"
git push
git log -1 --oneline
```

Actions가 마지막 커밋으로 성공했는지 확인한 뒤 공개 URL을 엽니다. Ctrl+F5로 다시 읽고 수정 항목과 기존 메뉴·링크·폼을 함께 시험합니다. 새 기능만 확인하면 기존 기능이 고장 난 것을 놓칠 수 있습니다.

## 팀원이 최종 확인

수정한 사람이 직접 설명하기 전에 팀원이 같은 단계로 문제를 다시 재현해 봅니다. 해결됐다면 Notion의 해당 피드백 상태를 ‘확인 완료’로 바꾸고 확인한 URL·환경을 적습니다. 여전히 발생하면 ‘진행 중’으로 남기고 다음 수정 범위를 정합니다. 완료 상태와 실제 결과를 맞추는 것도 협업의 일부입니다.

## 제출할 것

대표 공개 URL, GitHub 저장소 URL, 마지막 배포 커밋, 모바일 화면, 팀 피드백 ID, 수정 전후 설명, MCP 도구 호출 확인 결과를 kit/docs/release.md에 정리합니다. 로컬 경로·localhost는 공개 URL 대신 제출하지 않습니다. 계정 문제로 공개하지 못한 경우에는 미완료 단계와 로컬 실행 결과를 나눠 적습니다.

원본 ZIP을 제출할 때 node_modules·dist·실제 .env·인증 정보는 제외합니다. Notion MCP 설정에는 공식 서버 주소만 남깁니다. Notion 팀 문서를 인터넷 전체에 공개해야 제출할 수 있는 것은 아니며 수업 안에서 접근 가능한 공유 방식으로 확인합니다.
