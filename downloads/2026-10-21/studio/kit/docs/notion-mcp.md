# W11 Notion 팀 문서 만들고 MCP 연결하기

## MCP가 하는 일

브라우저로 Notion을 열어 글을 읽는 일은 사람이 합니다. MCP를 연결하면 AI가 Notion에서 제공하는 도구로 문서를 읽거나 수정할 수 있습니다. AI 대화창이 작업을 요청하는 쪽인 클라이언트, Notion이 도구를 제공하는 쪽인 서버입니다. 연결은 통로를 여는 일이며 자동으로 팀 문서를 찾거나 홈페이지를 수정하지는 않습니다.

오늘 목표는 팀 문서를 실제로 한 번 읽고, 그 내용을 근거로 수정 작업을 정리하는 것입니다. Notion AI를 켜는 기능과 외부 에이전트의 Notion MCP 연결은 구별합니다. 홈페이지 JavaScript에서 Notion 비밀키를 사용하는 실습도 아닙니다.

## 1. 팀 공간부터 만들기

38명은 5명 팀 6개와 4명 팀 2개, 총 8팀으로 구성합니다. 팀 번호는 T01~T08입니다. 각자 홈페이지와 저장소는 유지하고 검수 문서만 함께 사용합니다. 팀에서 진행·기록·검수·실행 확인 역할을 나누고 다음 활동에는 역할을 바꿉니다. 5명 팀은 검수를 두 명이 나눕니다.

Notion 계정으로 로그인한 뒤 수업용 공간에서 New page로 ‘T01 랜딩페이지 검수’ 같은 문서를 만듭니다. kit/docs/team-review-template.md 내용을 복사해 붙여넣습니다. 웹 공개(Publish)가 아니라 Share에서 팀원의 이메일을 초대하거나 기관이 준비한 팀 공간을 사용합니다. 편집이 필요한 팀원에게만 편집 권한을 줍니다. 워크스페이스 요금제·게스트 한도·기관 초대 정책에 따라 초대가 막히면 팀 대표 계정으로 문서를 운영하고 나머지 팀원은 기록을 모아 대표에게 전달합니다. 공동 암호를 만들지 않습니다.

브라우저에서 팀원 한 명이 문서를 열고 검수 행 한 개를 작성할 수 있는지 먼저 확인합니다. 문서 소유자는 Share 메뉴에서 Copy link로 페이지 주소를 복사합니다. 학교·회사 기존 업무 자료를 수업에 섞지 말고 수업용 계정·공간을 사용합니다. OAuth 연결은 선택한 워크스페이스에서 본인이 접근 가능한 자료를 사용할 수 있으므로, 요청문에 페이지 URL을 지정하는 것만으로 접근 권한이 그 페이지에 한정되는 것은 아닙니다.

## 2. VS Code의 AI 기능 확인

기본 경로는 VS Code와 GitHub Copilot입니다. Extensions(Ctrl+Shift+X)에서 Microsoft/GitHub 공식 게시자의 GitHub Copilot 관련 확장이 설치·활성화되어 있는지 확인합니다. 계정 아이콘 또는 Copilot 안내로 본인 GitHub 계정에 로그인하고 Chat을 엽니다. Agent 모드를 사용할 수 있는지 확인합니다. 계정의 사용량 한도·요금제·기관 정책에 따라 도구 실행이 제한될 수 있습니다. 이 실습 때문에 유료 가입을 바로 진행하지 않습니다.

다른 확장의 채팅창을 켰다면 아래 설정이 그 확장에 자동 적용된다고 가정하지 않습니다. MCP 서버 목록을 관리하는 클라이언트가 무엇인지 먼저 확인합니다. [VS Code 공식 MCP 안내](https://code.visualstudio.com/docs/agent-customization/mcp-servers)를 함께 열어 메뉴가 달라졌는지 확인할 수 있습니다.

## 3. 서버 주소 등록

VS Code에서 kit를 열고 왼쪽 탐색기에서 .vscode/mcp.json을 찾습니다. ZIP에 아래 설정이 이미 들어 있습니다. 비밀키가 아니라 공식 서버 주소만 담긴 파일입니다. 같은 이름의 설정이 있으면 통째로 덮어쓰지 말고 servers 안에 notion 항목을 합칩니다.

```json
{
  "servers": {
    "notion": {
      "type": "http",
      "url": "https://mcp.notion.com/mcp"
    }
  }
}
```

servers는 서버 목록, notion은 이 연결의 이름, type: http는 네트워크 연결 방식, url은 연결할 주소입니다. 따옴표와 쉼표를 임의로 지우지 않습니다. JSON에는 설명용 # 주석을 넣지 않습니다. 위 설정은 VS Code용이며 Cursor 설정의 mcpServers와 모양이 다릅니다.

파일을 직접 만들려면 탐색기에서 .vscode 폴더를 만들고 그 안에 mcp.json을 저장합니다. 또는 Ctrl+Shift+P → MCP: Add Server → HTTP → 위 주소 → 이름 notion → Workspace로 추가할 수 있습니다. 두 방법을 중복 실행해 같은 서버를 두 개 만들지는 않습니다.

## 4. 시작하고 Notion 로그인

Ctrl+Shift+P로 명령 팔레트를 열고 MCP: List Servers를 검색합니다. notion을 선택해 Start Server 또는 시작 항목을 실행합니다. 설정 파일 위의 Start 링크가 보이는 버전은 그 링크로 시작해도 됩니다. 서버 신뢰와 로그인 안내가 나오면 주소가 공식 Notion인지 확인합니다.

브라우저 인증 화면에서 본인의 Notion 계정과 수업용 워크스페이스를 선택하고 요청되는 접근 권한을 확인한 뒤 승인합니다. 인증을 마치면 VS Code로 돌아옵니다. 암호·토큰을 채팅이나 mcp.json에 붙여넣지 않습니다. 로그인 정보는 클라이언트가 관리합니다. 이 설정 파일을 다른 팀원에게 전달해도 그 사람의 로그인까지 대신 되지는 않습니다.

## 5. 첫 번째 읽기 호출

Chat을 Agent 모드로 열고 도구 목록에서 notion 서버 도구가 켜져 있는지 확인합니다. 메뉴는 버전에 따라 Configure Tools 또는 Chat의 도구 선택으로 표시될 수 있습니다. 아래 TEAM-PAGE-URL을 팀 페이지의 실제 주소로 바꿉니다.

```text
Notion MCP 도구를 사용해서 이 팀 문서를 읽어 줘.
문서: TEAM-PAGE-URL
페이지 제목과 ‘팀 확인 문장’을 그대로 알려 줘.
사용한 문서 링크도 함께 적어 줘.
다른 문서를 검색하거나 내용을 수정하지 마.
```

먼저 팀 문서에 ‘팀 확인 문장: T01 오늘은 우리 페이지를 검수합니다’처럼 팀 고유 문장을 적습니다. AI 대화에서 도구 호출을 펼쳐 notion 도구가 실행됐는지, 올바른 페이지 내용이 반환됐는지, 답변이 그 문장과 맞는지 확인합니다. ‘연결했습니다’라는 답변만으로 통과하지 않습니다. 사용 가능한 도구 이름은 서버 버전에 따라 달라질 수 있으므로 실제 목록과 호출을 확인합니다.

## 6. 연결 오류를 고치는 순서

| 보이는 문제 | 먼저 할 일 | 성공 확인 |
|---|---|---|
| MCP 명령이 없음 | VS Code·AI 확장 활성화와 현재 클라이언트 확인 | 서버 목록 명령이 열림 |
| JSON 빨간 밑줄 | 괄호·쉼표·servers 키와 저장 경로 확인 | 구문 오류가 사라짐 |
| 로그인 반복 | 선택한 Notion 계정·워크스페이스 확인 후 서버 재시작 | 인증 후 도구 목록 표시 |
| 문서를 못 찾음 | 같은 계정의 브라우저에서 정확한 URL 열기·공유 권한 확인 | 브라우저와 도구 모두 같은 문서 읽음 |
| 도구가 안 불림 | Agent 모드와 notion 도구 선택 확인 | 실제 호출과 반환 내용 표시 |
| 사용량·관리자 제한 | 계정 한도·기관 정책 확인 | 허용된 계정에서 실행 또는 대표 실행 |

연결이 막히면 팀 대표의 실제 호출을 함께 확인하고 각자 ‘개인 연결’과 ‘팀 대표 호출 확인’을 구분해 기록합니다. 단순 복사·붙여넣기를 MCP 실행이라고 적지 않습니다. 계정 연결을 해결하는 동안 나머지 팀원은 브라우저 검수와 피드백 작성을 계속합니다.
