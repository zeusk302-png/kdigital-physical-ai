# 개인 홈페이지와 팀 검수 실습

## 준비

자료 ZIP을 풀고 kit를 VS Code로 엽니다. GitHub·Notion 본인 계정, Git·Node·VS Code, 인터넷을 준비합니다. GitHub Pages는 개인 공개 사이트, Notion은 수업 안에서 공유하는 팀 문서입니다. Notion 문서를 웹 전체에 공개할 필요는 없습니다.

## 필수 활동 8개

1. **내 페이지 기획**: 주제·방문자·핵심 문장·버튼 목적을 docs/brief.md에 적습니다. 기대 결과는 남의 예제 문구를 바꾼 자기 소개입니다.
2. **자기 화면 제작**: 제목·소개·장점·이미지를 수정합니다. CSS의 콘텐츠 폭·간격·모바일 배치를 조절하고 390px·1280px에서 확인합니다.
3. **동작과 React 비교**: 메뉴·FAQ·입력 검사를 실행하고 한 기능을 수정합니다. React판의 Hero 또는 FeatureCard를 고쳐 HTML판과 원본 위치를 비교합니다.
4. **처음 배포**: W10 순서로 test·build·preview → Git commit·push → Pages Source 설정 → Actions → 공개 URL을 확인합니다. .github/workflows/pages.yml은 kit에 포함돼 있습니다.
5. **팀 문서와 의견 작성**: W11의 팀 문서 양식을 복사하고 팀원이 직접 열어 편집할 수 있는지 확인합니다. 서로 다른 학생에게 재현 가능한 의견을 두 개 이상 남깁니다.
6. **Notion MCP 실제 읽기**: .vscode/mcp.json → 서버 시작 → OAuth → 팀 확인 문장 조회를 실행합니다. 호출 서버·문서·반환 내용을 기록합니다. 팀 대표 실행을 확인했다면 개인 연결 성공과 구분합니다.
7. **피드백 선택과 수정**: W12 요청으로 자기 의견만 정리하고 원문과 비교합니다. 한 문제를 선택해 범위를 정하고 원본 코드 수정·diff·직접 실행을 확인합니다.
8. **재배포와 팀 확인**: W13 순서로 시험·빌드·커밋·push·Actions를 확인합니다. 팀원이 공개 URL에서 같은 문제를 다시 시험하고 docs/release.md에 결과를 남깁니다.

## 오류 해결

ENOENT는 현재 폴더, 이미지 404는 경로와 대소문자, 배포 실패는 Actions의 실패 단계부터 확인합니다. Notion 조회 실패는 같은 계정으로 브라우저에서 팀 문서를 열 수 있는지 먼저 확인합니다. 계정·요금제·관리자 제한이 있으면 대표 호출을 함께 확인하고 개인 수행 여부를 구분해 적습니다. 수동으로 복사한 문장을 MCP 조회 성공으로 기록하지 않습니다.

## 더 해보기

React판 전체를 자기 콘텐츠로 전환하기, FAQ 한 개만 열리게 만들기, 첫 오류 입력칸으로 초점 이동하기, 다른 팀 검수 받기, MCP로 확인한 수정 결과를 팀 문서의 자기 영역에 추가하기입니다. 쓰기 요청은 대상과 추가할 문장을 확인한 뒤 실행합니다.

## 제출

공개 URL·저장소·배포 커밋·팀 피드백 ID·수정 전후·모바일 화면·MCP 실행 구분을 release.md에 적습니다. 공개하지 못했다면 정확히 멈춘 단계와 실행 결과를 적습니다. 원본 제출에서 node_modules·dist·비밀값·로그인 정보는 제외합니다.
