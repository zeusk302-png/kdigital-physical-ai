# 나의 랜딩페이지 공개와 팀 검수

각자 주제를 정해 홈페이지 하나를 만들고 GitHub Pages 공개 주소를 갖습니다. 팀원에게 피드백을 받은 뒤 Notion MCP로 의견을 읽고, 한 가지 이상을 고쳐 다시 배포합니다. 홈페이지는 개인별, 검수 문서는 팀별입니다.

## 오늘의 흐름

| 시간 | 할 일 | 남길 결과 |
|---|---|---|
|10:00–10:50|8팀 구성·주제·방문자·첫 실행|기획과 실행 화면|
|11:00–11:50|HTML·CSS·모바일 배치|자기 콘텐츠와 반응형 페이지|
|11:50–13:00|중식|—|
|13:00–13:50|메뉴·입력 검사·React 부품 비교|작동하는 기능과 JSX 수정|
|14:00–14:50|Git 기록·GitHub Pages 배포|개인 공개 URL|
|15:00–15:50|Notion 팀 문서·MCP 설정·로그인·읽기|실제 문서 조회 결과|
|16:00–16:50|팀 검수·의견 정리·수정·재배포|개선한 공개 페이지|

각 수업 사이 10분 휴식, 16:50–17:00 저장·종료 준비입니다. 설치·로그인이 길어지면 시작 골격을 활용하고 페이지 전체를 React로 옮기는 작업은 더 해보기로 이어갑니다.

## 필수 경로

자기 제목·소개·장점·주요 버튼 작성 → 모바일과 메뉴 확인 → 개인 Pages 배포 → 팀 문서 작성 → Notion 도구로 읽기 → 피드백 한 건 수정 → 재배포입니다. W01~W13은 모두 목차에 있습니다. React 전체 전환·고급 상태 관리·실제 문의 접수 서버는 추가 도전입니다. 처음부터 두 개의 홈페이지를 새로 만드는 대신 제공 HTML판을 완성하고 React판의 부품·상태를 비교합니다.
