# 학생 실습지

## 목적과 준비
나만의 방문자·메시지·주요 행동을 담은 랜딩페이지를 만듭니다. kit 폴더 전체, 에디터, 브라우저를 준비합니다. 폴더를 연 뒤 README의 실행 경로를 선택합니다. 필수와 추가 도전을 구별하며 실제 회원 접수는 하지 않습니다.

## 단계
1. docs/brief.md에 주제·방문자·문제·약속·버튼을 작성합니다. 공식 사이트 세 곳에서 제목·CTA·여백·모바일 메뉴를 관찰해 docs/design.md에 적습니다. 예상 결과: 종이 와이어프레임과 자기 문장.
2. index.html에서 h1과 장점 세 개를 자기 글로 쓰고 내 소개 section을 추가합니다. contact 내부 링크를 연결합니다. 확인: 버튼 클릭 뒤 문의 영역으로 이동하고 제목 순서가 h1→h2인가?
3. tokens.css의 색과 layout.css의 여백을 바꾸고 이유를 적습니다. 카드 네 개를 배치합니다. 확인: 390/768/1280에서 읽히는가? 고정폭을 한 번 넣어 실패를 재현하고 원인 규칙을 복구합니다.
4. vanilla.js에서 메뉴의 현재 상태 읽기→뒤집기→화면 적용을 설명합니다. validate.js에서 내용 최소 길이를20으로 바꿉니다. 빈 값, 잘못된 이메일,19자,20자 입력을 비교합니다. 정상 문구는 전송하지 않았다고 안내해야 합니다.
5. /react.html을 열고 Hero 제목과 FeatureCard 하나를 직접 수정합니다. FAQ 초기 state를 true로 바꾼 뒤 첫 화면을 예상합니다. 같은 부품 두 개가 독립적으로 동작하는지 확인합니다. HTML 원본과 JSX의 차이 세 가지를 적습니다.
6. 긴 제목·네 번째 장점·20자 검사를 반영합니다. 에이전트에게 문제 원인과 최소 수정안을 요청하고 diff를 읽습니다. MCP가 연결되었으면 실제 도구·주소·관찰을 기록하고 없으면 수동 검수라고 적습니다. build→preview 확인 뒤 Git에 원본을 기록합니다. 본인 공개 권한이 준비되면 deploy.md에 따라 게시하고 실제 URL에서 재확인합니다.

## 오류 해결
화면 그대로: 저장 파일·주소·dev/preview 구분부터 확인합니다. CSS 미적용: 링크 경로와 선택자 철자를 확인합니다. 이미지 깨짐: 경로 대소문자와 Network404를 확인합니다. 흰 화면: 터미널 변환 오류와 Console 첫 오류를 읽습니다. npm ENOENT: pwd와 package.json을 확인합니다. 설치 불가: 정적 대체본으로 합류하고 React를 성공 처리하지 않습니다.

## 제출
기획·디자인·checks를 포함한 원본 ZIP( node_modules/dist/실제.env 제외), 모바일 화면, 검수표, 공개 URL 또는 미배포 사유를 냅니다. 추가 도전은 FAQ 하나만 열기, 첫 오류 입력칸으로 초점 이동, 타인의 새 문구에도 레이아웃 유지입니다.
