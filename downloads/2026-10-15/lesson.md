## A01 · 같은 업무를 함수로 묶는 이유

<!-- enrichment:2026-10-15:P1 -->

### 사례로 이해하기 · 함수가 받을 값과 돌려줄 결과 정하기

먼저 강사의 예를 보고 같은 순서로 함께 확인합니다. 추가 문제는 필수 활동을 마친 뒤 풀어 보세요.

안내 데스크는 방문자 이름을 받아 같은 환영 문장을 만듭니다. 이름마다 문장을 복사하면 한 문구를 고칠 때 여러 곳을 찾아야 합니다. 함수는 공통 절차를 이름 붙여 묶는 방법입니다. 코드를 적기 전에 ‘이름 문자열을 받아 환영 문장 문자열을 돌려준다’라는 규칙을 적습니다. 입력은 호출자가 건네는 값, 처리는 문장을 만드는 일, 결과는 호출자가 다시 사용할 값입니다. 이 세 역할이 분명해야 함수를 어디까지 묶을지 판단할 수 있습니다.

매개변수는 받을 값의 자리 이름이고 인자는 실제 호출에서 건네는 값입니다. 신청서의 이름 칸과 그 칸에 적는 민수라는 글의 관계로 생각합니다. 아래 완결 예를 work/E01_greeting.py라는 새 파일로 저장하고 course 폴더에서 `python -X utf8 work/E01_greeting.py`를 실행합니다.

```python
def make_greeting(name):
    return "안녕하세요, " + name
first = make_greeting("민수")
second = make_greeting("지아")
print(first)
print(second)
```

첫 줄의 def는 작업을 정의하고 괄호 안 name은 받을 자리입니다. 콜론 뒤 들여쓴 둘째 줄은 호출 때 문자열을 연결하고 return으로 돌려줍니다. 셋째 줄은 “민수”를 주고 받은 문장을 first에 연결합니다. 넷째 줄은 별도 호출에 “지아”를 주고 second에 연결합니다. 마지막 두 줄은 각 결과를 표시합니다. 예상 출력은 ‘안녕하세요, 민수’와 ‘안녕하세요, 지아’ 두 줄입니다. 정의 자체에서는 인사가 출력되지 않습니다.

두 호출은 같은 작업을 쓰지만 다른 입력으로 다른 결과를 얻습니다. 함수 안 name이 항상 민수라고 외우면 둘째 호출을 잘못 읽습니다. 들여쓰기가 빠지면 함수 본문의 경계가 깨져 오류가 날 수 있으므로 둘째 줄 앞 공백을 확인합니다. 이름을 숫자로 주면 문자열 연결이 실패할 수 있으므로 오늘 함수는 문자열만 받도록 정했습니다. 실제 계정 조회나 메시지 전송은 하지 않습니다.

### 혼자 풀어 볼 문제

복습·도전: 물품 라벨에 상품명과 보관함을 받아 ‘장갑 / B02’처럼 한 문자열을 만드는 작업을 설계하세요. 입력 자리 두 개, 반환할 종류, 순서를 바꿨을 때 생길 문제를 문장으로 쓰세요. 첫 입력은 장갑/B02, 둘째 입력은 마스크/A01입니다. 이 두 호출의 결과를 예상하세요.

### 정답과 오답의 이유

입력은 상품명·보관함 문자열, 결과는 두 내용을 순서대로 연결한 문자열입니다. 장갑/B02와 마스크/A01의 결과는 각 입력에 따라 달라집니다. 순서를 바꾸면 B02 / 장갑처럼 업무 양식이 달라집니다. 컴퓨터가 이름의 뜻을 추측해 입력 위치를 고쳐 준다는 답은 오답입니다.

### 다시 확인할 질문 세 가지

1. **정의하면 바로 실행되나요?** 본문은 해당 함수를 호출했을 때 실행됩니다.

2. **매개변수와 인자는 같은 이름인가요?** 매개변수는 받을 자리, 인자는 호출에서 준 실제 값입니다.

3. **어떤 코드를 함수로 묶나요?** 공통 작업과 입력·결과 규칙이 분명한 부분을 먼저 묶습니다.


**개념.** 함수는 한 가지 일을 이름 붙여 묶은 코드입니다. 매번 같은 안내 절차를 읽는 대신 ‘온도 상태 확인’이라는 작업을 정해 두고 필요한 값으로 부를 수 있습니다. 무엇을 입력하고 무엇을 결과로 돌려줄지 먼저 정합니다.

**왜 필요한가.** 같은 조건식을 여러 곳에 복사하면 한 곳만 수정하고 다른 곳을 놓칠 수 있습니다. 반복되는 규칙을 모으면 변경 위치를 찾기 쉽습니다. 첫 코드부터 모든 줄을 함수로 만들 필요는 없습니다.

**함께 보는 예.** 온도 22.5·25.0·24.0을 각각 24.0과 비교합니다. 공통 작업은 비교하여 상태를 정하는 과정이며 달라지는 것은 입력 온도입니다. 같은 업무 이름에 다른 입력을 줄 수 있습니다.

**헷갈리는 경우.** 이름이 check라고 해서 검증을 모두 수행하는 것은 아닙니다. 본문이 실제로 어떤 조건을 보는지 읽어야 합니다. 함수 이름은 약속을 설명하지만 정확성을 보장하지 않습니다.

### 제공 입력


```text
세 업무: 22.5와24.0 비교 / 25.0과24.0 비교 / 24.0과24.0 비교.
답칸: 공통 작업 / 달라지는 입력 / 결과 / 이름 제안.
```


### 학생 적용

1. 같은 부분과 다른 값을 구별합니다.
2. 공통 작업에 temperature_status라는 이름을 붙입니다.
3. 받을 값과 결과의 뜻을 문장으로 씁니다.
4. 기준 변경 때 수정할 위치를 비교합니다.

예상 결과: 공통 규칙·온도 입력·상태 결과를 구별합니다.

확인 질문: 줄 수가 짧으면 함수가 필요 없다고 단정할 수 있나요?

## A02 · def로 정의하고 이름으로 호출하기

**개념.** def는 함수를 정의하는 문장입니다. 이름 뒤 괄호와 콜론을 쓰고 들여쓴 줄을 함수 본문으로 묶습니다. 정의만 하면 본문은 아직 실행되지 않으며 이름을 괄호와 함께 불러야 합니다.

**왜 필요한가.** 위에서 아래로 읽는 원리는 유지하지만 함수 본문은 호출할 때 실행됩니다. 정의 위치와 실제 실행 시점을 나누어 보면 출력 순서가 이해됩니다.

**함께 보는 예.** show_notice를 정의한 뒤 준비를 출력합니다. 함수 호출 때 안내가 나오고 호출에서 돌아온 뒤 끝이 나옵니다. 함수 본문의 줄 번호가 위에 있다고 가장 먼저 출력되는 것은 아닙니다.

**헷갈리는 경우.** show_notice라고 이름만 적는 것과 show_notice()로 호출하는 것은 다릅니다. 괄호는 실제 작업을 요청하는 표기입니다.

### 전체 코드


```python
def show_notice():
    print("점검을 시작합니다")
print("준비")
show_notice()
print("끝")
```

### 각 줄의 뜻

| 줄 | 코드 | 뜻 |
| --- | --- | --- |
| 1 | `def show_notice():` | 안내하는 작업을 정의합니다. |
| 2 | `    print("점검을 시작합니다")` | 호출할 때 실행할 출력입니다. |
| 3 | `print("준비")` | 바깥에서 준비를 출력합니다. |
| 4 | `show_notice()` | 정의한 함수를 호출합니다. |
| 5 | `print("끝")` | 돌아온 뒤 끝을 출력합니다. |


```text

```

작은 수정: `show_notice()

```text

점검을 시작합니다
점검을 시작합니다

```


### 학생 적용

1. 정의와 호출을 표시합니다.
2. 실제 출력 순서를 씁니다.
3. 호출을 한 번 더 넣어 예상합니다.
4. 정의 횟수와 본문 실행 횟수를 설명합니다.

예상 결과: 정의 한 번·호출 두 번이면 안내 출력 두 번.

## A03 · 매개변수와 실제 인자

**개념.** 매개변수는 받을 값의 이름이고 인자는 호출할 때 실제로 주는 값입니다. 양식의 ‘장소’ 칸과 거기에 넣는 ‘입구’라는 내용의 관계에 비유할 수 있습니다.

**왜 필요한가.** 고정 값을 함수 안에서 매번 바꾸는 대신 호출값을 달리해 같은 작업을 사용합니다. 함수 안 이름이 어디서 값을 받는지 알아야 전달한 값을 추적할 수 있습니다.

**함께 보는 예.** sensor_id와 value는 받을 이름입니다. 첫 호출에서 S01·22.5가 연결되고 다음 호출에서는 S02·25.0이 연결됩니다. 각 호출은 서로 다른 값으로 같은 본문을 사용합니다.

**헷갈리는 경우.** 인자의 순서를 바꾸어도 컴퓨터가 업무 의미를 추측해 바로잡지 않습니다. 센서명 위치에 숫자를 주면 잘못된 위치의 값이 출력될 수 있습니다.

### 전체 코드


```python
def show_temperature(sensor_id, value):
    print(sensor_id, value)
show_temperature("S01", 22.5)
show_temperature("S02", 25.0)
```

### 각 줄의 뜻

| 줄 | 코드 | 뜻 |
| --- | --- | --- |
| 1 | `def show_temperature(sensor_id, value):` | 센서명과 값을 받는 함수를 정의합니다. |
| 2 | `    print(sensor_id, value)` | 이번 호출에서 받은 값을 출력합니다. |
| 3 | `show_temperature("S01", 22.5)` | 첫 센서와 온도를 전달합니다. |
| 4 | `show_temperature("S02", 25.0)` | 둘째 센서와 온도를 전달합니다. |

### 실행과 예상 출력

현재 위치가 압축을 푼 course 폴더일 때 실행합니다.


```text

```

수정한 작업본은 다음 명령으로 실행합니다.


```text

```

원본 코드의 예상 출력:


```text

S02 25.0
```

작은 수정: `show_temperature("S02", 25.0)`를 `show_temperature("S03", 0.0)`로 바꿉니다.

수정 후 예상 출력:


```text
S01 22.5
S03 0.0
```

# 2구간 · 함수 입력과 반환

## A04 · print와 return의 차이

<!-- enrichment:2026-10-15:P2 -->

### 사례로 이해하기 · 화면 표시와 다음 계산의 반환값 구별하기

먼저 강사의 예를 보고 같은 순서로 함께 확인합니다. 추가 문제는 필수 활동을 마친 뒤 풀어 보세요.

청구서 담당자는 수량 3과 단가 1200원으로 상품 금액을 계산한 뒤 배송비 2000원을 더합니다. 첫 계산이 화면에 3600을 보여 주었다고 다음 계산에서 그 값을 사용할 수 있는 것은 아닙니다. 화면 표시는 사람에게 보여 주는 행동이고 반환은 함수를 부른 곳에 결과 값을 보내는 행동입니다. 전자계산기에서 값을 읽는 것과 그 값을 다음 식의 입력으로 전달하는 것을 구별합니다. 필요한 최종 결과를 먼저 쓰면 print와 return의 역할이 선명해집니다.

이 함수는 단가와 수량을 정수로 받아 상품 금액을 정수로 돌려줍니다. 수업용 처리 규칙은 단가×수량이며 세금이나 할인은 넣지 않습니다. 호출에서 1200과 3을 주면 함수 안에서 3600을 만들고 return으로 보냅니다. 호출한 쪽은 받은 값에 2000을 더해 최종 5600원을 얻습니다. 손 추적표는 입력 1200·3 → 함수 계산 3600 → 반환 3600 → 배송비 포함 5600 순서입니다. 화면에 무엇이 보이는가와 변수에 무엇이 연결되는가를 다른 칸으로 적습니다.

print만 하는 함수는 3600을 화면에 보이게 해도 별도 return이 없으면 호출 결과가 None입니다. None에 2000을 더하면 숫자 계산이 되지 않습니다. 오류를 피하려고 None을 0으로 바꾸면 상품 금액이 사라져 잘못된 청구서가 됩니다. 결과를 계산하는 함수에 return을 두고 필요한 표시를 호출한 쪽에서 맡기는 구조를 생각합니다. 또한 return을 만나는 즉시 그 호출은 끝납니다. 그 아래 줄은 같은 호출에서 이어서 실행되지 않습니다. 조건이 여러 갈래인 함수라면 각 갈래가 무엇을 반환하는지 읽어야 합니다. 한 갈래에서만 반환하면 나머지 입력에서 뜻밖의 None이 생길 수 있습니다.

### 혼자 풀어 볼 문제

복습·도전: 배송 준비 함수는 포장비 500원을 화면에 표시하지만 반환문이 없습니다. 호출 결과를 fee에 연결한 뒤 총액 3000에 더하려 합니다. 화면값·fee 값·다음 계산을 분리해 설명하고 올바른 역할 배치를 문장으로 설계하세요.

### 정답과 오답의 이유

화면에는 500이 보이지만 fee는 None이며 다음 덧셈은 TypeError가 날 수 있습니다. 함수가 500을 반환하고 호출자가 총액에 더한 뒤 표시하도록 설계합니다. 화면에 500이 보이므로 fee도 500이라는 답은 표시와 반환을 혼동한 것입니다.

### 다시 확인할 질문 세 가지

1. **print의 결과가 자동 저장되나요?** 표시와 반환은 별도이며 호출 결과를 보려면 return을 확인합니다.

2. **return 뒤 안내가 실행되나요?** 같은 호출은 return에서 끝나므로 아래 줄까지 가지 않습니다.

3. **None을 0으로 고쳐도 되나요?** 업무 결과가 누락된 원인을 고쳐야 하며 임의 0은 계산 의미를 바꿉니다.


**개념.** print는 값을 화면에 보여 주고 return은 함수를 부른 위치로 값을 돌려줍니다. 화면에 결과가 보였다는 사실과 다음 계산에 사용할 결과를 받았다는 사실은 다릅니다.

**왜 필요한가.** 결과를 JSON에 저장하거나 집계하려면 함수가 값을 돌려줘야 합니다. 화면 글자를 다른 코드가 저절로 변수에 담지는 않습니다.

**함께 보는 예.** add_offset은 받은 두 수를 더해 반환합니다. result가 23.5를 받고 다음 계산에서 사용합니다. 더하는 값은 수업 계산 예이며 실제 장비 교정값으로 사용하지 않습니다.

**헷갈리는 경우.** return 없이 print만 하는 함수의 반환값은 None입니다. 그 값을 숫자처럼 더하려고 하면 오류가 날 수 있습니다. 화면만 보지 말고 return의 역할을 확인합니다.

### 전체 코드


```python
def add_offset(value, offset):
    return value + offset
result = add_offset(22.5, 1.0)
print(result)
print(result + 1)
```

### 각 줄의 뜻

| 줄 | 코드 | 뜻 |
| --- | --- | --- |
| 1 | `def add_offset(value, offset):` | 두 값을 받는 작업을 정의합니다. |
| 2 | `    return value + offset` | 합을 호출한 곳으로 돌려줍니다. |
| 3 | `result = add_offset(22.5, 1.0)` | 돌아온 결과를 result에 연결합니다. |
| 4 | `print(result)` | 받은 결과를 출력합니다. |
| 5 | `print(result + 1)` | 결과를 다음 계산에 사용합니다. |

## A05 · 조건을 담은 상태 함수

**개념.** 함수 안에서도 if를 사용할 수 있습니다. 입력을 받아 조건에 맞는 상태 문자열을 돌려주는 규칙을 만듭니다. return을 만나면 그 호출은 결과를 돌려주고 끝납니다.

**왜 필요한가.** 상태 규칙과 출력 위치를 나누면 같은 결과를 화면이나 파일에 사용할 수 있습니다. 함수가 입력값을 바꾸는지 새 결과만 만드는지도 설명합니다.

**함께 보는 예.** None이면 미측정,24.0 초과면 확인,나머지는 정상입니다. 앞의 return을 실행한 호출은 아래 비교로 다시 내려가지 않습니다.

**헷갈리는 경우.** 함수로 묶었다고 자료형 규칙이 없어지는 것은 아닙니다. None을 먼저 숫자와 비교하면 TypeError가 나므로 값 없음의 처리를 앞에 둡니다.

### 전체 코드


```python
def temperature_status(value):
    if value is None:
        return "미측정"
    if value > 24.0:
        return "확인"
    return "정상"
print(temperature_status(22.5))
print(temperature_status(None))
print(temperature_status(25.0))
```

### 각 줄의 뜻

| 줄 | 코드 | 뜻 |
| --- | --- | --- |
| 1 | `def temperature_status(value):` | 값을 받는 함수를 정의합니다. |
| 2 | `    if value is None:` | 값 없음을 먼저 확인합니다. |
| 3 | `        return "미측정"` | 미측정으로 반환하고 끝냅니다. |
| 4 | `    if value > 24.0:` | 숫자의 기준 초과를 묻습니다. |
| 5 | `        return "확인"` | 초과 상태를 반환합니다. |
| 6 | `    return "정상"` | 나머지 상태를 반환합니다. |
| 7 | `print(temperature_status(22.5))` | 정상 입력을 확인합니다. |
| 8 | `print(temperature_status(None))` | 미측정 입력을 확인합니다. |
| 9 | `print(temperature_status(25.0))` | 초과 입력을 확인합니다. |

```text

```

작은 수정: `temperature_status(25.0)`를 `temperature_status(24.0)`로 바꿉니다.

수정 후 예상 출력:


```text
정상
미측정
정상
```


### 학생 적용

## A06 · 예상 사례표로 함수 확인하기

**개념.** 검증 사례는 입력과 기대 결과를 미리 적어 실제 결과와 비교하는 한 경우입니다. 정상값뿐 아니라 경계와 값 없음의 사례도 포함합니다.

**왜 필요한가.** 프로그램이 보여 준 결과를 그대로 정답으로 적으면 잘못된 코드도 통과합니다. 실행 전에 업무 규칙에서 기대값을 정해야 합니다.

**헷갈리는 경우.** 다섯 사례를 통과했다고 모든 입력을 확인한 것은 아닙니다. 글자와 범위 밖 숫자는 아직 검사하지 않았다는 한계를 남깁니다.

# 3구간 · 파일을 읽고 결과 저장

## A07 · 파일 경로와 텍스트 읽기

<!-- enrichment:2026-10-15:P3 -->

### 사례로 이해하기 · 읽은 텍스트에서 값으로, 값에서 저장 파일로

먼저 강사의 예를 보고 같은 순서로 함께 확인합니다. 추가 문제는 필수 활동을 마친 뒤 풀어 보세요.

점검 담당자는 CSV 입력에서 온도를 읽고 요약 JSON을 남깁니다. 파일은 디스크에 저장된 내용이고 읽어 온 값은 프로그램이 처리하는 내용입니다. 화면에 요약을 출력했다는 사실만으로 결과 파일이 저장되지는 않습니다. 흐름을 파일 주소 → 읽은 원문 → 해석한 값 → 결과 묶음 → 저장 주소 순서로 그립니다. 같은 내용처럼 보이는 단계도 역할과 저장 종류가 달라지므로 경계를 하나씩 확인합니다. 원자료와 결과 파일은 서로 다른 주소로 정합니다.

예를 들어 헤더 `sensor_id,temperature_c` 아래 `S08,20.5` 한 행이 있습니다. DictReader 같은 CSV 읽기 도구는 헤더를 이름표로 삼고 기본 셀값을 문자열로 읽습니다. 원문 “20.5”를 실수 20.5로 해석한 다음 요약의 측정수 1과 평균 20.5를 만듭니다. JSON으로 표현한 완성 예는 `{"count":1,"average":20.5}`입니다. 숫자에 따옴표를 붙이지 않았으므로 JSON에서는 숫자값입니다. 원문 CSV에 숫자처럼 적혀 있다는 사실과 읽은 Python 값의 종류를 구별합니다.

경로는 파일의 주소이며 현재 터미널 위치와 코드 파일 위치가 같다고 가정하지 않습니다. 기존 예제는 코드 위치를 기준으로 data와 work를 찾습니다. 폴더 배치가 바뀌면 입력 주소가 맞는지 먼저 확인합니다. FileNotFoundError는 파일 이름·주소·압축 해제 상태를 확인하는 단서이고 KeyError는 실제 헤더와 찾는 이름표를 비교하는 단서입니다. 파일은 찾았지만 “뜨거움”을 숫자로 읽으려 하면 ValueError 단계가 됩니다. 세 오류가 같은 화면에 보여도 해결할 경계가 다릅니다. 저장 후에는 결과 파일을 다시 열어 count와 average가 기대값인지 확인합니다. 이전 실행 파일이 남아 있을 수 있으므로 입력명과 실행 시각도 기록합니다.

### 혼자 풀어 볼 문제

복습·도전: 입력 헤더는 device_id,value이고 한 행은 D09,0입니다. 프로그램은 temperature_c를 찾다가 실패했습니다. 파일 열기·헤더 찾기·숫자 변환 중 어느 단계인지 판단하고 원문을 보존한 수정 계획과 올바른 JSON 수치 표현을 쓰세요.

### 정답과 오답의 이유

헤더 찾기 단계의 문제입니다. 입력 열 이름이 value로 정해져 있다면 코드에서 찾는 키도 value로 맞춥니다. 고치기 전에 정해 둔 열 이름과 실제 헤더를 확인합니다. 수치 0은 실제 값이므로 JSON에서는 0이며 null이 아닙니다. 주소 수정이나 0 삭제는 현재 증거에 맞는 해결이 아닙니다.

### 다시 확인할 질문 세 가지

1. **CSV 값은 숫자로 자동 읽히나요?** 기본 읽기는 문자열이므로 의미에 맞는 해석 단계를 둡니다.

2. **출력했으면 저장도 끝났나요?** 화면 표시와 파일 쓰기·재읽기 확인은 다른 작업입니다.

3. **오류 종류를 왜 나누나요?** 파일·구조·값의 어느 경계에서 실패했는지 좁혀 올바른 부분을 고치기 위해서입니다.


**개념.** 경로는 파일의 저장 주소입니다. 현재 터미널 폴더와 코드 폴더는 다를 수 있습니다. Path(__file__)로 코드 위치를 찾으면 그 위치를 기준으로 자료 주소를 만들 수 있습니다.

**왜 필요한가.** 터미널을 다른 곳에서 열어도 같은 자료를 읽도록 준비합니다. 긴 준비 줄을 외우기보다 code·work·data의 상대 배치를 이해하는 것이 목적입니다.

**함께 보는 예.** course/code 또는 course/work의 코드에서 parent.parent는 course입니다. 그 아래 data/notice.txt를 읽습니다. UTF-8은 한글을 글자로 해석하는 인코딩 약속입니다.

**헷갈리는 경우.** FileNotFoundError는 주소와 이름의 문제를 먼저 확인해야 합니다. 아직 파일을 읽지 못했는데 숫자 변환을 수정해도 원인을 해결하지 못합니다.

### 전체 코드


```python
from pathlib import Path
base = Path(__file__).resolve().parent.parent
source = base / "data" / "notice.txt"
text = source.read_text(encoding="utf-8")
print(text.strip())
```

### 각 줄의 뜻

| 줄 | 코드 | 뜻 |
| --- | --- | --- |
| 1 | `from pathlib import Path` | 파일 주소 도구를 가져옵니다. |
| 2 | `base = Path(__file__).resolve().parent.parent` | 코드의 두 상위 폴더 course를 찾습니다. |
| 3 | `source = base / "data" / "notice.txt"` | 입력 파일 주소를 만듭니다. |
| 4 | `text = source.read_text(encoding="utf-8")` | UTF-8 텍스트를 읽습니다. |
| 5 | `print(text.strip())` | 앞뒤 공백과 줄바꿈을 정리해 출력합니다. |

## A08 · CSV를 이름표가 있는 행으로 읽기

**개념.** csv.DictReader는 헤더를 키로 삼아 각 데이터 행을 딕셔너리로 읽습니다. 기본 셀값은 문자열이므로 온도 계산 전에 의미에 맞는 해석이 필요합니다.

**왜 필요한가.** 열 번호를 외우기보다 temperature_c라는 이름으로 읽으면 처리할 항목이 드러납니다. 실제 헤더가 약속과 맞아야 같은 이름으로 읽을 수 있습니다.

**함께 보는 예.** 입력은 S01의 22.5,S02의 25.0,S03의 빈 온도,S04의 0.0 네 건입니다. 첫 온도의 화면 모양은 숫자 같지만 type은 str입니다.

**헷갈리는 경우.** 헤더를 temperature로 바꾸면 temperature_c라는 키가 저절로 생기지 않습니다. DictReader가 업무상 비슷한 단어를 연결하지 않습니다.

### 전체 코드


```python
import csv
from pathlib import Path
source = Path(__file__).resolve().parent.parent / "data" / "readings.csv"
with source.open(encoding="utf-8", newline="") as file:
    rows = list(csv.DictReader(file))
print(len(rows))
print(rows[0]["sensor_id"])
print(rows[0]["temperature_c"], type(rows[0]["temperature_c"]).__name__)
```

## A09 · JSON 결과를 새 파일로 저장하기

**개념.** json.dumps는 프로그램 값을 JSON 텍스트로 표현합니다. 그 텍스트를 경로에 써야 결과 파일이 생깁니다. 입력 읽기와 결과 저장은 별도 작업입니다.

**왜 필요한가.** 화면 출력만 있으면 다음 사람이 결과를 재사용하기 어렵습니다. 입력 원자료를 덮어쓰지 않도록 work의 결과 경로를 명확히 정합니다.

**함께 보는 예.** 건수 4와 미측정 1을 JSON으로 저장합니다. ensure_ascii=False는 한글을 읽기 쉬운 모양으로 남기고 indent=2는 들여쓰기를 넣습니다. 저장한 파일을 다시 읽어 값이 같은지 봅니다.

## A10 · 미측정과 잘못된 숫자의 구별

<!-- enrichment:2026-10-15:P4 -->

### 사례로 이해하기 · 미측정·잘못된 글자·실제 0의 세 갈래

먼저 강사의 예를 보고 같은 순서로 함께 확인합니다. 추가 문제는 필수 활동을 마친 뒤 풀어 보세요.

수업용 측정 파일에 빈 문자열, “0”, “추움” 세 원문이 있습니다. 검사를 통과시키려고 모두 0으로 바꾸면 세 기록이 실제 0℃로 합쳐집니다. 빈 문자열은 이번 데이터 사전에서 미측정이고, “0”은 측정한 숫자 표현이며, “추움”은 숫자 칸에 온 다른 종류의 내용입니다. 먼저 원문을 보존하고 어떤 갈래에 속하는지 정합니다. 오류 처리는 숨기는 행동이 아니라 분류와 후속 확인을 기록하는 행동입니다.

해석 절차의 첫 질문은 원문이 빈 문자열과 정확히 같은지입니다. 같으면 None으로 반환해 미측정을 보존합니다. 아니면 숫자로 변환합니다. “0”은 0.0이 되지만 “추움”은 ValueError가 납니다. 이 예에서는 ValueError를 잡아 장치번호와 원문을 이슈로 남깁니다. 처리할 수 없는 숫자 글자 오류를 잡는 것과 주소 오류까지 무조건 숨기는 것은 다릅니다. except ValueError는 해당 변환·규칙 오류만 맡고 파일이 없다는 오류의 해결은 별도입니다.

완성 분류표는 R01/빈 문자열/미측정, R02/“0”/수치 0.0, R03/“추움”/이슈입니다. 수치 평균을 계산한다면 R02만 대상으로 하므로 평균은 0.0입니다. R01을 0으로 채워 평균에 넣으면 대상 수가 늘고 미측정 사실이 사라집니다. R03을 None으로 바꾸면 잘못 적힌 내용이 있었다는 근거가 사라집니다. 오류 원문을 보존한 후 담당자에게 어떤 입력을 의도했는지 묻습니다. 공백 한 칸 “ ”도 빈 문자열과 그대로는 다르며 이 수업의 규칙에는 자동 공백 정리가 없습니다. 새 정리 규칙이 필요하면 먼저 원문과 변경 이유를 기록하고 별도 약속으로 정해야 합니다.

### 혼자 풀어 볼 문제

복습·도전: 수량 칸 원문이 빈 문자열, “0”, “여섯”, “ ”입니다. 이 문제의 규칙은 정확한 빈 문자열만 미확인으로 보고, 숫자만 계산 대상으로 정합니다. 네 갈래의 분류와 담당자에게 남길 이슈 원문을 작성하세요.

### 정답과 오답의 이유

빈 문자열은 미확인, “0”은 수치 0, “여섯”과 공백 한 칸은 현재 규칙으로 숫자로 읽을 수 없는 입력입니다. 두 이슈 원문을 그대로 남깁니다. 공백을 자동 삭제해 미확인으로 합치는 답은 명시되지 않은 정리 규칙을 추가한 것입니다.

### 다시 확인할 질문 세 가지

1. **미측정도 오류인가요?** 규칙에서 허용한 빈값과 잘못된 입력을 구별합니다.

2. **예외를 잡으면 실제 값을 알게 되나요?** 아닙니다. 실패한 입력값을 그대로 남겨 무엇을 더 확인할지 알 수 있습니다.

3. **0을 평균에서 빼나요?** 실제 수치 0은 포함하고 값 없음만 제외합니다.


**개념.** 빈값 규칙과 숫자 변환은 다른 단계입니다. 이 자료의 빈 온도는 미측정이므로 None으로 보존하고 숫자가 아닌 글자는 잘못된 입력으로 알립니다.

**왜 필요한가.** 모든 변환 실패를 None으로 바꾸면 누락과 잘못된 기록을 구별하지 못합니다. 원문과 실패 이유를 남겨야 확인 요청을 할 수 있습니다.

**함께 보는 예.** 빈 문자열은 None, "0.0"은 숫자 0.0, "뜨거움"은 ValueError입니다. 먼저 빈 문자열인지 확인하고 나머지에 숫자 변환을 적용합니다.

**헷갈리는 경우.** 빈 문자열을 0으로 대신 채우면 미측정을 실제 0℃로 바꿉니다. 계산을 편하게 하려고 확인되지 않은 값을 보충하지 않습니다.

### 전체 코드


```python
def parse_temperature(raw):
    if raw == "":
        return None
    return float(raw)
print(parse_temperature("22.5"))
print(parse_temperature(""))
print(parse_temperature("0.0"))
```

### 각 줄의 뜻

| 줄 | 코드 | 뜻 |
| --- | --- | --- |
| 1 | `def parse_temperature(raw):` | 원문 온도를 해석하는 함수를 정의합니다. |
| 2 | `    if raw == "":` | 빈 문자열 여부를 확인합니다. |
| 3 | `        return None` | 계약에 따라 None을 반환합니다. |
| 4 | `    return float(raw)` | 나머지를 숫자로 변환합니다. |
| 5 | `print(parse_temperature("22.5"))` | 일반 숫자를 확인합니다. |
| 6 | `print(parse_temperature(""))` | 미측정을 확인합니다. |
| 7 | `print(parse_temperature("0.0"))` | 실제 0을 확인합니다. |

## A12 · try와 except로 예상 오류 기록

**개념.** try에는 실패할 수 있는 작업을 쓰고 except에는 특정 예외가 났을 때 할 일을 씁니다. 오류를 처리하는 일은 문제를 없던 일로 만드는 것이 아니라 기록과 다음 행동을 정하는 일입니다.

**왜 필요한가.** 한 값이 잘못되어도 원문과 이유를 남길 수 있습니다. 다룰 오류 종류를 좁히면 예상하지 못한 문제를 숨기지 않습니다.

**함께 보는 예.** ‘뜨거움’을 float로 읽으면 ValueError가 납니다. 그때 원문과 확인 필요 메시지를 출력합니다. 정상값 24.0을 주면 숫자를 출력합니다.

**헷갈리는 경우.** except: pass로 모든 오류를 무시하면 어떤 기록이 사라졌는지 모릅니다. 이 코드는 ValueError만 다루며 모든 오류를 복구한다고 설명하지 않습니다.

### 전체 코드


```python
raw = "뜨거움"
try:
    value = float(raw)
    print(value)
except ValueError:
    print("숫자 확인 필요:", raw)
```

### 각 줄의 뜻

| 줄 | 코드 | 뜻 |
| --- | --- | --- |
| 1 | `raw = "뜨거움"` | 수치로 읽을 원문입니다. |
| 2 | `try:` | 실패 가능 작업을 시작합니다. |
| 3 | `    value = float(raw)` | 숫자로 해석합니다. |
| 4 | `    print(value)` | 성공한 숫자를 출력합니다. |
| 5 | `except ValueError:` | 변환 오류의 처리 묶음입니다. |
| 6 | `    print("숫자 확인 필요:", raw)` | 문제 원문을 포함해 메시지를 남깁니다. |

## A13 · 범위 규칙을 함수에서 확인하기

### 사례로 이해하기 · 허용 범위의 바깥과 경계를 검사하기

먼저 강사의 예를 보고 같은 순서로 함께 확인합니다. 추가 문제는 필수 활동을 마친 뒤 풀어 보세요.

접수 시스템은 물품 수량을 0개부터 20개까지 받습니다. 21은 숫자로 바꿀 수 있지만 정해 둔 수량 범위에는 맞지 않습니다. 숫자로 바꿀 수 있는지와 허용 범위 안인지는 따로 검사합니다. 먼저 “스물”은 숫자 표현이 아니라 변환에서 멈추고, 21은 숫자로 읽힌 뒤 범위에서 멈춥니다. 0은 실제 수량이 없다는 뜻이며 이번 규칙에서는 허용합니다. 같은 ValueError라는 결과가 나올 수 있어도 어떤 규칙과 원문 때문에 실패했는지 기록합니다.

0≤수량≤20을 수직선으로 그리면 두 끝점이 포함됩니다. 바깥은 ‘0보다 작음 또는 20보다 큼’입니다. or는 둘 중 하나라도 참이면 참이고 and는 둘 다 참이어야 참입니다. 완성 검수표는 -1 거부, 0 허용, 10 허용, 20 허용, 21 거부입니다. 경계 0과 20을 보지 않으면 <와 <=를 바꾼 실수를 놓칠 수 있습니다. ‘0보다 작고 동시에 20보다 큼’이라는 and 조건은 한 숫자에 성립하지 않아 범위 밖을 놓칩니다.

20이 재고 한도인지 주문 수량 한도인지도 규칙에 적어야 합니다. 같은 숫자 20을 모든 업무의 기준으로 재사용하지 않습니다. 21을 자동으로 20으로 잘라 저장하면 검사 대신 원자료 변경을 수행한 것입니다. 담당자의 확인 없이 실제 수량을 고치지 않고 거부 사유와 원문을 남깁니다. 수정 검증은 실패 입력 한 건만 다시 보는 것이 아닙니다. 기준 비교를 바꿨다면 정상·양쪽 경계·양쪽 바깥의 다섯 사례를 다시 봅니다. 통과한 사례 수와 검사하지 않은 종류를 구별해서 보고합니다. 이 예제는 정수 개수를 받습니다. 1.5개 같은 값을 허용할지는 따로 정해야 합니다. 범위 통과만으로 정수 조건이나 실물 재고의 정확성이 증명되지는 않습니다.

### 혼자 풀어 볼 문제

복습·도전: 수업용 배터리 기록의 허용 충전율은 0~100%입니다. -0.1, 0, 50, 100, 100.1의 기대 결과와 바깥을 찾는 논리 문장을 쓰세요. 100.1을 100으로 자동 변경해도 되는지 근거를 설명하세요.

### 정답과 오답의 이유

양 끝 -0.1·100.1은 거부, 0·50·100은 허용입니다. ‘0 미만 또는 100 초과’가 바깥입니다. 자동 변경은 원문을 바꾸므로 현재 검사 규칙에서는 허용하지 않습니다. and로 쓰면 두 바깥 조건을 동시에 만족하는 값이 없어 오류를 놓칩니다.

### 다시 확인할 질문 세 가지

1. **변환 성공이 허용 성공인가요?** 숫자 표현과 업무 범위·정수 조건은 별도 검사입니다.

2. **범위 밖에 왜 or를 쓰나요?** 아래쪽이나 위쪽 중 하나만 벗어나도 거부해야 하기 때문입니다.

3. **통과가 실제 정확성을 뜻하나요?** 입력 규칙에 맞았다는 뜻이며 실제 측정·기록 정확성은 따로 확인합니다.


**개념.** 숫자로 변환할 수 있다는 것과 허용 범위 안에 있다는 것은 다른 검사입니다. 값이 0~50인지 확인하고 벗어나면 이유를 예외로 알립니다.

**왜 필요한가.** 51.0은 숫자이므로 float는 성공하지만 실습 입력 규칙에는 맞지 않습니다. 변환과 규칙 검사를 분리하여 읽어야 합니다.

**함께 보는 예.** 23.5는 반환하고 51.0은 범위 확인 필요를 알립니다.0과 50은 허용 경계입니다. 이 범위는 실습의 입력 약속이며 실제 장비 안전 기준이 아닙니다.

**헷갈리는 경우.** 51.0을 자동으로 50으로 자르면 원자료를 바꿉니다. 실제값을 모르면 원문을 보존하고 확인 요청을 남깁니다.

# 6구간 · 로그 검사기와 사용 안내

## A16 · 로그 검사기 전체 흐름

<!-- enrichment:2026-10-15:P6 -->

### 사례로 이해하기 · 분류 건수와 평균 분모를 보존하기

먼저 강사의 예를 보고 같은 순서로 함께 확인합니다. 추가 문제는 필수 활동을 마친 뒤 풀어 보세요.

로그 검사기를 넘겨받은 사람이 요약의 accepted를 실제 숫자 수라고 읽었습니다. 그러나 기존 검사기에서 accepted는 수치와 미측정을 합한 수락 건수입니다. 이름만 보고 뜻을 짐작하지 말고 각 항목의 정의와 계산 코드를 확인해야 합니다. 합성 원문 다섯 건은 “10”, 빈 문자열, “20”, “오류”, “0”입니다. 수치는 세 건, 미측정은 한 건, 이슈는 한 건입니다. 입력 전체와 분류된 부분이 빠짐없이 맞는지 검산합니다.

이 프로그램의 관계는 input=accepted+issues, accepted=numeric+missing입니다. 다섯 건 사례에서는 5=4+1, 4=3+1입니다. 평균은 숫자 세 건의 합 10+20+0=30을 숫자 건수 3으로 나누어 10입니다. 수락 건수 4로 나누면 7.5가 되어 미측정을 0처럼 처리합니다. 이슈 건수까지 포함해 5로 나누면 6이 됩니다. 같은 원문에서 분모만 바꿔도 업무 의미가 바뀌므로 평균 대상과 건수를 함께 보고합니다.

한 행의 추적은 원문→해석→분류→누적 순서입니다. 잘못된 글자가 나오면 이슈 목록에 원문을 남기고 continue로 다음 행으로 넘어갑니다. 문제 행이 수치 목록에도 들어가면 중복 분류가 되어 두 검산 관계가 깨질 수 있습니다. 모든 수치가 없을 때 평균은 None입니다. 0이라고 쓰면 실제 평균 0을 계산했다는 오해가 생깁니다. 헤더만 있는 입력은 전체 0건이고 모든 값이 빈 입력은 전체 기록은 있으나 수치가 0건입니다. 둘 다 평균이 없지만 같은 자료는 아닙니다. 결과 안내에는 입력 파일명·명령·실제 출력·미확인 범위·변경 이유를 남깁니다. 현재 검사는 합성 온도값 규칙을 확인하며 모든 필드나 센서의 실제 성능을 보증하지 않습니다.

### 혼자 풀어 볼 문제

복습·도전: 원문은 “5”, “15”, 빈 문자열, “뜨거움”, 빈 문자열, “0”입니다. 전체·수치·미측정·이슈·수락 건수와 평균을 구하고 두 검산식을 쓰세요. 수치가 전혀 없는 경우의 평균 표현도 적으세요.

### 정답과 오답의 이유

전체 6, 수치 3, 미측정 2, 이슈 1, 수락 5입니다. 6=5+1, 5=3+2이고 평균은 20÷3을 소수 둘째 자리로 반올림한 6.67입니다. 수치가 없으면 None입니다. 수락 5를 분모로 쓰면 4가 되어 미측정을 포함한 잘못된 평균입니다.

### 다시 확인할 질문 세 가지

1. **수락 건수는 수치 건수인가요?** 이 검사기에서는 수치와 미측정을 합하므로 결과의 각 항목이 무엇을 세는지 확인합니다.

2. **continue가 필요한 이유는?** 이슈로 분류한 행을 정상 처리로 보내지 않고 다음 행으로 넘어갑니다.

3. **평균 None과 0은 같은가요?** None은 계산할 수치가 없음이며 0은 실제 수치 평균이 0이라는 값입니다.


**개념.** 검사기는 한 행씩 온도를 해석하여 정상 수치·미측정·이슈를 나눕니다. 함수는 한 값의 규칙을 담당하고 반복문은 여러 행에 같은 규칙을 적용합니다.

**왜 필요한가.** 함수·파일·예외를 하나의 업무에 연결합니다. 긴 코드는 준비·정의·행 처리·집계·저장으로 나눠 추적합니다. 전체를 암기하거나 빈 편집기에서 다시 작성하는 것이 목표는 아닙니다.

**함께 보는 예.** 실제 수치는 22.5·25.0·0.0으로 합 47.5,개수 3,평균 15.83입니다. 빈 온도 1건은 미측정,뜨거움과 51.0은 원문 이슈로 남깁니다.0도 실제 측정이므로 평균에 포함합니다.

**헷갈리는 경우.** 평균이 낮아 보인다는 이유로 0을 빼지 않습니다. 입력 원문과 정해 둔 처리 규칙을 확인합니다. 이 프로그램은 온도 규칙에 집중하며 모든 필드와 실제 측정의 진위를 검사하지 않습니다.

### 전체 코드


```python
import csv
import json
from pathlib import Path

def parse_temperature(raw):
    if raw == "":
        return None
    value = float(raw)
    if value < 0 or value > 50:
        raise ValueError("범위 확인 필요")
    return value

base = Path(__file__).resolve().parent.parent
source = base / "data" / "bad_readings.csv"
with source.open(encoding="utf-8", newline="") as file:
    rows = list(csv.DictReader(file))
numbers = []
issues = []
missing = 0
for row in rows:
    try:
        value = parse_temperature(row["temperature_c"])
    except ValueError:
        issues.append({"sensor_id": row["sensor_id"], "raw": row["temperature_c"]})
        continue
    if value is None:
        missing = missing + 1
    else:
        numbers.append(value)
average = None
if len(numbers) > 0:
    average = round(sum(numbers) / len(numbers), 2)
summary = {"input": len(rows), "accepted": len(numbers) + missing,
           "missing": missing, "issues": len(issues), "average": average}
(base / "work" / "check_summary.json").write_text(
    json.dumps(summary, ensure_ascii=False, indent=2), encoding="utf-8")
(base / "work" / "check_issues.json").write_text(
    json.dumps(issues, ensure_ascii=False, indent=2), encoding="utf-8")
print(summary["input"], summary["accepted"], summary["missing"], summary["issues"])
print(summary["average"])
```

## A18 · 검사기 사용 안내와 근거 전달

**개념.** 사용 안내는 다음 사람이 같은 입력으로 같은 결과를 확인할 수 있도록 쓰는 문서입니다. 파일·명령·기대 결과·이슈의 뜻·미확인 범위를 함께 전달합니다.

**왜 필요한가.** 작성자가 없어도 검사 범위를 오해하지 않게 해야 합니다. ‘검증 완료’보다 온도 변환·범위·미측정 구별을 검사했다고 구체적으로 씁니다.

**함께 보는 예.** 안내에는 course의 실행 명령, source가 읽는 입력명, work 결과 두 개, 이슈 원문을 확인하는 방법을 씁니다. 확정 근거가 있으면 작업 사본만 고치고 재확인합니다.

**헷갈리는 경우.** 모든 필드를 검사하거나 실제 센서 정확도를 보장한다고 주장하지 않습니다. 오늘은 로컬 합성 파일의 처리이며 외부 서비스로 전송하지 않습니다.

### 제공 입력


```text
작성칸: 목적 / 필요한 파일 / 명령 / 입력 선택 / 결과 위치 / 이슈 해석 / 수정 근거 / 미확인 범위.
```


### 학생 적용

1. work/usage.md에 실행 안내를 씁니다.
2. 짝이 입력 하나의 결과를 설명하게 합니다.
3. 빠진 파일 위치와 입력·결과 규칙을 추가합니다.
4. 코드·입력·요약·이슈·사례표를 함께 제출합니다.

예상 결과: 다음 사람이 파일을 찾아 같은 명령을 실행하고, 결과와 검사한 범위를 확인할 수 있는 안내.

확인 질문: 이슈 0건이라는 결과만 남기면 무엇이 부족한가요?

막혔을 때: 처음 실행 순서와 오류 확인 순서를 나눠 씁니다. 미확인 사실을 확정하지 않습니다.
