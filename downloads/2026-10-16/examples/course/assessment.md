# Git/GitHub 확인과 평가

**18활동의 작성·예상·실제 확인을 분리해 봅니다. 속도나 설치 성공만 평가하지 않습니다.**

| 기준 | 확인할 증거 | 보완이 필요한 경우 |
| --- | --- | --- |
| 개념 | 입력·처리·출력 또는 변경 단계의 역할 설명 | 결과 이름만 외우고 근거를 말하지 못함 |
| 수정 | 지정한 위치와 변경 전후를 연결 | 여러 곳을 바꾸어 원인을 설명하지 못함 |
| 확인 | 정상·경계·오류 사례의 예상과 실제 구별 | 실행 성공을 내용 정확성으로 단정 |
| 전달 | 파일·명령·결과·남은 질문을 재현 가능하게 기록 | 어느 파일을 사용했는지 불명확 |

각 기준은 ‘독립 설명 가능 / 힌트 후 가능 / 다시 연습’으로 기록합니다. 개인 실행 여부는 별도 체크하며 미실행을 실패한 개념 이해로 간주하지 않습니다.

## 구간별 확인 질문

1. status를 열 번 실행하면 커밋이 생기나요?
2. 커밋 해시가 교안과 달라지면 실패인가요?
3. .gitignore가 과거 커밋의 파일을 지우나요?
4. 브랜치를 만들면 GitHub PR도 자동으로 생기나요?
5. PR 본문에 ‘모든 테스트 통과’라고 쓰면 그대로 믿어도 되나요?
6. clean 상태이면 원격도 최신이라고 단정할 수 있나요?

## 제출

work의 활동 노트와 수정 파일, 마지막 종합 작업, 확인한 명령·출력 또는 수동 추적 기록을 제출합니다. 기관 제출 위치는 미확인입니다. 정답 폴더를 학생 결과에 복사하지 않습니다.
