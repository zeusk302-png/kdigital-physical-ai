# Git/GitHub · 변경을 비교하고 기록하기

2026-10-16 · Git/GitHub

파일 저장과 Git 기록을 구별하고 연습용 README의 한 변경을 상태·비교·스테이징·커밋으로 추적합니다. 로컬 공유 저장소로 보내기·받기를 확인하고 GitHub 리뷰는 계정 없는 제공 자료로 연습합니다.

**360분 상세 운영을 위한 제작 배정이며 실제 학습자 리허설 전입니다.** 원본을 보존하고 work의 지정한 부분을 수정합니다. 계정이나 실제 장비 없이 합성 자료로 진행합니다.

## A01 · 파일 저장과 변경 기록

**목적:** 최종·진짜최종 같은 파일명을 계속 만들면 어떤 변경이 어느 목적이었는지 찾기 어렵습니다. 같은 파일의 변경을 기록하면 이전 내용과 현재 내용을 비교할 수 있습니다.

**준비:** 원자료와 작업 파일을 나란히 엽니다. 원본은 보존하고 work 파일에 기록합니다. 실행 환경이 없으면 같은 입력·코드·출력으로 수동 추적합니다.

- [A01_input.md](data/A01_input.md)
- [A01_notes.md](work/A01_notes.md)

**단계**

1. 카드를 순서대로 놓고 각 행동의 결과를 씁니다.
2. 저장만 한 경우와 커밋한 경우를 구별합니다.
3. 오늘 수정할 README의 목적을 읽습니다.
4. 현재 컴퓨터와 공유 저장소의 역할을 다른 칸에 적습니다.

**예상 결과:** 저장과 커밋, 로컬 기록과 공유를 구별합니다.

**확인 방법:** 인터넷이 끊겨도 로컬 커밋을 만들 수 있나요?

**오류 해결:** Git과 GitHub가 섞이면 내 컴퓨터의 기록 도구와 웹 서비스라는 역할부터 나눕니다.

## A04 · 작업 변경과 diff의 기준

**목적:** 기록하기 전에 의도한 변경만 있는지 검토해야 합니다. 상태는 파일 수준을, diff는 줄 수준의 차이를 보여 줍니다.

**준비:** 원자료와 작업 파일을 나란히 엽니다. 원본은 보존하고 work 파일에 기록합니다. 실행 환경이 없으면 같은 입력·코드·출력으로 수동 추적합니다.

- [A04_input.md](data/A04_input.md)
- [A04_notes.md](work/A04_notes.md)

**단계**

1. 각 카드의 비교 대상 두 상태를 적습니다.
2. 추적되지 않은 파일과 추적 파일을 구별합니다.
3. 삭제·추가 기호를 최종 문장으로 재구성합니다.
4. 의도한 한 문장 변경만 있는지 검토합니다.

**예상 결과:** 상태와 diff를 함께 읽고 비교 기준을 설명합니다.

**확인 방법:** 기본 diff는 항상 마지막 커밋과 비교하나요?

**오류 해결:** 변경이 안 보이면 status와 --staged 여부를 확인합니다. 같은 파일명의 다른 복사본을 고쳤는지도 봅니다.

## A06 · commit과 변경 이력

**목적:** 무엇을 왜 바꿨는지 나중에 확인할 수 있도록 기록합니다. 파일 저장→선택→기록의 세 단계를 직접 수행합니다.

**준비:** 원자료와 작업 파일을 나란히 엽니다. 원본은 보존하고 work 파일에 기록합니다. 실행 환경이 없으면 같은 입력·코드·출력으로 수동 추적합니다.

**단계**

**예상 결과:** 첫 커밋 한 개. 남은 변경이 없으면 상태가 깨끗합니다.

## A08 · 현재 내용과 과거 커밋 비교

**목적:** 파일을 현재 상태로 복구하지 않고도 과거 내용을 읽을 수 있습니다. 조회와 변경을 구별하면 필요한 정보를 안전하게 확인할 수 있습니다.

**단계**

1. 현재 파일을 열어 문구를 확인합니다.
2. 이전 내용을 조회하되 파일이 바뀌지 않았는지 봅니다.
3. 두 커밋의 차이를 자신의 말로 설명합니다.
