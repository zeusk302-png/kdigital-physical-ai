# G04 · 파일 저장과 변경 기록은 어떻게 다를까요?

이 단원에서는 인터넷에 연결하지 않고 내 컴퓨터에 연습 저장소를 만듭니다. GitHub 계정은 필요 없습니다. Git 설치와 Git Bash 실행이 먼저 끝나 있어야 합니다. 결과물은 `git-class-lab` 폴더의 `README.md`와 첫 커밋 한 개입니다. **필수 활동**은 폴더 확인→작성자 설정→파일 만들기→상태 확인→선택→첫 기록입니다.

## 1. 개념 정의 · 세 가지 저장을 구별하기

파일은 이름이 붙은 내용 묶음입니다. 폴더는 파일을 넣는 장소입니다. `README.md`에서 README는 이름, `.md`는 Markdown 문서임을 나타내는 확장자입니다. 이 파일에는 프로그램 사용법이나 프로젝트 소개를 적습니다. `.md`라고 해서 실행되는 프로그램이 되는 것은 아닙니다.

편집기의 저장은 **현재 파일 내용**을 컴퓨터에 남깁니다. Git의 커밋은 **선택한 파일 내용과 변경 이유**를 이력에 남깁니다. GitHub 등에 보내는 push는 **이미 만든 커밋**을 다른 저장소에 전송합니다. 따라서 Ctrl+S, commit, push는 목적과 도착지가 다릅니다. 오늘은 첫 두 단계까지만 수행합니다.

Git 저장소는 프로젝트 파일과 이력을 관리하는 공간입니다. 보통 프로젝트 폴더 안의 숨김 폴더 `.git`에 Git 관리 정보가 있습니다. 이 폴더를 수동으로 고치거나 지우는 활동은 하지 않습니다. GitHub 웹에서 저장소를 만드는 것과 내 PC에서 `git init`으로 저장소를 시작하는 것도 다른 행동입니다.

## 2. 일상 비유 · 오늘 낼 과제 묶음

책상 위에서 보고서를 고치는 모습을 떠올려 보세요. 책상 위 원고가 작업 폴더, 제출할 원고를 고르는 자리가 스테이징 영역, 제출한 묶음에 번호와 이유를 붙여 보관하는 일이 커밋입니다. 글을 고쳤다고 곧바로 제출한 것은 아니고, 제출할 종이를 골랐다고 제출을 마친 것도 아닙니다.

이 비유에서 실제 파일이 다른 폴더로 이동하는 것은 아닙니다. 스테이징은 Git 내부에서 **다음 커밋에 담을 파일 내용**을 고르는 단계입니다. 영어로 staging area 또는 index라고 부릅니다. 파일을 여러 번 저장해도 직접 커밋하기 전까지는 커밋 이력 수가 늘지 않습니다.

## 3. 구성요소 · 어디에서 무엇을 보나요?

| 이름 | 쉬운 뜻 | 이번 실습에서 확인할 것 |
|---|---|---|
| 작업 폴더, working tree | 내가 파일을 열고 고치는 곳 | 탐색기에서 보이는 README.md |
| 스테이징 영역, index | 다음 기록에 넣을 내용을 고른 상태 | git add 이후의 status |
| 커밋, commit | 선택 내용을 이유와 함께 남긴 기록 | git commit 뒤의 짧은 ID |
| 브랜치 main | 현재 따라가는 기록 흐름의 이름 | status의 On branch main |
| 작성자 이름과 이메일 | 커밋에 적히는 작성자 표시 | 저장소 안의 user.name/user.email |

작성자 설정은 GitHub 로그인이나 본인 인증이 아닙니다. 다른 사람 이름을 넣는다고 그 계정의 권한이 생기지 않습니다. 여기서는 **현재 연습 저장소에만 적용하는 `--local`**을 사용합니다. 사용자 전체 기본값을 바꾸는 `--global`은 사용하지 않습니다. 예시 이메일 `learner@example.invalid`는 연습용이며 메일을 받는 주소가 아닙니다. 이 커밋을 온라인에 공개하기 전에 본인 GitHub Settings → Emails에서 확인한 noreply 주소로 바꾸세요. 나중에 설정을 바꾸어도 이미 만든 커밋의 이메일이 자동 변경되지는 않습니다.

## 4. 준비 · G03의 연습 폴더를 이어 쓰기

**G03을 마쳤다면 아래 준비 코드 상자 전체를 건너뛰고 5절로 이동합니다.** 현재 위치가 이미 git-class-lab 안입니다. `pwd`와 `ls`로 위치와 내용만 확인하세요. `mkdir git-class-lab`과 `cd git-class-lab`을 다시 입력하지 않습니다. 이미 README.md가 있으면 아래 printf로 덮어쓰지 말고 내용을 읽고 이어 씁니다. G03에서 Git 저장소까지 시작했다면 `git status`로 상태를 확인하고 init도 건너뜁니다. 첫 커밋이 이미 있다면 새 파일을 만드는 대신 문장 하나를 추가해 add·commit 단계를 연습합니다.

G03을 하지 않고 **새로 시작하는 경우에만** 파일 탐색기에서 기존 과제나 실제 프로젝트가 없는 연습용 부모 폴더를 만드세요. 예를 들어 문서 안에 `GitPractice`를 만들 수 있습니다. 그 빈 폴더에서 우클릭하여 Git Bash를 엽니다. 메뉴 위치는 Windows와 설치 옵션에 따라 다를 수 있습니다. Git Bash를 실행한 뒤 폴더로 이동해도 됩니다. 검은 창의 색은 설정에 따라 달라질 수 있으며 Git 자체의 기능은 아닙니다.

아래 명령은 **Git Bash용**입니다. PowerShell에 그대로 넣지 않습니다. `$`는 입력을 기다리는 표시인 프롬프트 예시이며 아래 명령에는 포함하지 않았습니다. 한 줄을 입력하고 Enter를 누른 뒤 결과를 확인하세요. 주석인 `#` 뒤의 글은 설명입니다. 코드 상자 전체를 한 번에 실행하지 말고 한 명령씩 수행합니다.

```bash
# 지금 창이 어느 폴더를 보고 있는지 주소를 확인합니다.
pwd
# 현재 폴더의 파일과 폴더 이름을 봅니다.
ls
# 새 연습 폴더를 만듭니다. 이미 있다는 오류가 나면 아래 복구 안내를 읽습니다.
mkdir git-class-lab
# 방금 만든 연습 폴더 안으로 들어갑니다.
cd git-class-lab
# 현재 위치 끝이 git-class-lab인지 다시 확인합니다.
pwd
```

`pwd`는 현재 위치를 보여 주는 명령, `ls`는 목록을 보여 주는 명령, `mkdir`는 폴더 만들기, `cd`는 위치 이동입니다. Windows의 `C:\Users\...`가 Git Bash에서는 `/c/Users/...`처럼 보일 수 있습니다. **폴더 이름이 같다는 것만 보지 말고 전체 주소가 내가 만든 연습 위치인지 확인**합니다. `mkdir`와 `cd`는 Git 명령이 아니라 창에서 사용하는 기본 명령입니다.

## 5. 복사 명령 · 첫 커밋 만들기

```bash
# 이 폴더를 Git 저장소로 만들고 첫 브랜치 이름을 main으로 정합니다.
git init -b main
# 이 저장소의 새 커밋에 적힐 작성자 이름을 정합니다.
git config --local user.name "Git Learner"
# 이 저장소에만 연습용 작성자 이메일을 정합니다.
git config --local user.email "learner@example.invalid"
# 이름 설정을 조회합니다. 값이 없으면 빈칸 대신 설정 단계를 확인합니다.
git config --local --get user.name
# 이메일 설정을 조회합니다. 이 값은 로그인 비밀번호가 아닙니다.
git config --local --get user.email
# 연습 문서 두 줄을 새로 만듭니다. 이 폴더에 README가 없는 첫 실행에서만 사용합니다.
printf '# My Git Practice\nFirst record.\n' > README.md
# 파일의 현재 내용을 읽습니다.
cat README.md
# 아직 기록되지 않은 파일이 무엇인지 확인합니다.
git status
# README.md의 현재 내용을 다음 커밋 대상으로 고릅니다.
git add README.md
# 선택 전후에 표시가 어떻게 달라졌는지 확인합니다.
git status
# 선택한 내용을 이유와 함께 첫 기록으로 남깁니다.
git commit -m "Add practice README"
# 기록 후 남아 있는 변경이 있는지 확인합니다.
git status
```

`git` 뒤에 행동 이름이 붙습니다. `init`은 시작, `config`는 설정, `status`는 상태 확인, `add`는 선택, `commit`은 기록입니다. `-b main`의 `-b`는 첫 브랜치 이름을 지정하는 옵션입니다. `-m`은 커밋 설명을 명령 뒤에 바로 적겠다는 옵션이고, 큰따옴표는 공백이 있는 설명을 하나로 묶습니다. 따옴표를 뺀 여러 단어를 아무렇게나 붙이지 않습니다.

`printf`는 글을 출력하는 기본 명령입니다. 작은따옴표 안의 내용은 문서에 넣을 글이고 `\n`은 줄바꿈입니다. `>`는 출력 결과를 파일에 저장하되 기존 파일이 있으면 덮어씁니다. 따라서 위 명령은 README가 없는 **새 연습 폴더에서 한 번만** 실행합니다. `cat`은 파일을 읽어 보여 줍니다. 출력과 명령을 혼동하여 `First record.`를 다시 명령으로 입력하지 않습니다.

## 6. 예상 출력 · 문장보다 상태의 뜻 보기

처음 `git status`에서는 다음과 비슷한 뜻을 확인합니다.

```text
On branch main
No commits yet
Untracked files:
        README.md
```

main에서 작업 중이며 아직 커밋이 없습니다. `Untracked`는 Git이 아직 관리 대상으로 기록하지 않은 새 파일이라는 뜻입니다. 파일이 없다는 뜻이 아닙니다. `git add README.md` 후에는 `Changes to be committed`와 `new file: README.md`가 보일 수 있습니다. 이제 다음 기록에 넣을 내용이 준비되었습니다.

커밋 후에는 `[main (root-commit) 1a2b3c4] Add practice README`처럼 보일 수 있습니다. `root-commit`은 첫 기록이고 뒤의 문자와 숫자는 기록을 구별하는 ID입니다. 예시 ID를 외우거나 똑같이 만들 필요는 없습니다. 마지막에는 `nothing to commit, working tree clean`과 비슷한 뜻의 문장을 확인합니다. 기록할 변경이 없다는 뜻이며 인터넷 업로드 완료라는 뜻은 아닙니다. 언어 설정에 따라 영어·한국어·중국어 등 출력 언어와 줄 수가 달라도 **현재 브랜치, 선택된 파일, 남은 변경**을 확인합니다.

`git add`와 `git config`는 성공해도 아무 출력 없이 다음 입력줄이 나올 수 있습니다. 아무 말이 없다는 이유로 같은 명령을 계속 반복하지 말고 조회나 `git status`로 결과를 확인합니다.

## 7. 변경 실습 · 저장과 기록을 나누어 보기

필수 실습입니다. 메모장이나 편집기에서 현재 연습 폴더의 README.md를 엽니다. 마지막에 `I am learning Git.` 한 줄을 추가하고 Ctrl+S로 저장하세요. 먼저 상태를 예상해 말한 뒤 `git status`를 실행합니다. 이번에는 새 파일이 아니라 수정된 파일로 표시됩니다. `git add README.md` 후 상태를 다시 보고, `git commit -m "Describe my learning"`으로 두 번째 기록을 만듭니다. 마지막 상태가 깨끗한지 확인합니다.

강사 시연을 본 뒤 같은 순서를 함께 수행하고, 자기 문장으로 한 번 더 바꾸어 보세요. **어느 순간 파일이 바뀌었고 어느 순간 이력이 생겼는지** 짝에게 말합니다. 한 값 수정만 반복하지 말고 저장된 파일 내용과 Git 기록의 역할 차이를 설명하는 것이 목표입니다.

## 8. 흔한 오류와 복구

- `not a git repository`: 현재 위치가 저장소 밖일 수 있습니다. `pwd`와 `ls`를 보고 본인이 만든 git-class-lab로 이동합니다. 실제 프로젝트에서 무작정 init을 실행하지 않습니다.
- `mkdir: ... File exists`: 같은 이름의 폴더가 이미 있습니다. 삭제하거나 덮어쓰지 말고 탐색기로 내용을 확인합니다. 이전 연습을 이어갈 폴더라면 들어가서 status부터 확인하고, 새 연습이 필요하면 강사와 다른 빈 부모 폴더를 고릅니다.
- `Author identity unknown`: 로그인 실패와 다릅니다. 이 저장소 안에서 위 `--local` 이름·이메일 설정을 확인한 뒤 커밋을 다시 시도합니다.
- `pathspec 'README.md' did not match`: 파일 이름과 현재 위치를 확인합니다. 탐색기에서 확장명을 표시하고 README.md.txt로 저장한 것은 아닌지 봅니다.
- `nothing to commit`: 편집기에서 저장했는지, 같은 폴더 파일을 고쳤는지 확인합니다. 이미 기록이 끝난 경우에는 새 커밋을 억지로 만들 필요가 없습니다.

## 9. 확인 질문과 풀이

1. 저장만 했는데 커밋 수가 늘었을까요? → 늘지 않습니다. 저장은 작업 파일을 바꾸며 커밋은 별도 행동입니다.
2. add하면 README가 다른 폴더로 옮겨지나요? → 아닙니다. 다음 커밋에 넣을 파일 내용을 Git 내부에서 고릅니다.
3. 작성자 이메일을 넣었으니 GitHub에 로그인됐나요? → 아닙니다. 커밋 작성자 표시와 서비스 인증은 다릅니다.
4. 마지막 status가 깨끗하면 웹에서도 보이나요? → 아직 원격을 연결하거나 push하지 않았으므로 웹 게시 여부를 뜻하지 않습니다.
5. Git이 기록하지 않는 숨김 파일을 직접 고치면 더 편할까요? → `.git` 관리 정보는 직접 고치지 않고 Git 명령으로 다룹니다.
