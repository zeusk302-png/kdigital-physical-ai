# G01 · 파일을 고친 기록에서 Git·GitHub의 역할까지

## 목적과 준비

오늘은 “어느 파일이 최신이지?”라는 문제를 해결하는 방법을 배웁니다. 코드를 먼저 외우지 않습니다. 파일 탐색기와 메모장을 열 수 있으면 시작할 수 있습니다. 이 단원은 설명·분류·예상 활동이며 계정 생성이나 공개 게시를 수행하지 않습니다. Windows PC를 예로 들며 다른 PC에서는 폴더 이름과 화면이 다를 수 있습니다.

## 1. 파일·폴더·저장·실행을 먼저 구별하기

파일은 이름을 붙여 보관한 내용입니다. 자기소개 글, 사진, Python 프로그램이 모두 파일입니다. 폴더는 파일을 모아 두는 공간입니다. `intro.txt`의 `.txt`는 일반 글 파일임을 나타내는 확장자이고, `main.py`의 `.py`는 Python 코드 파일의 확장자입니다. 이름만 바꾼다고 내용이 다른 형식으로 변하는 것은 아닙니다.

메모장의 저장은 지금 작성한 내용을 파일에 적는 행동입니다. Python 실행은 코드의 지시를 Python 프로그램이 수행하는 행동입니다. 저장했다고 프로그램이 자동 실행되거나 인터넷에 공개되지는 않습니다. 파일 탐색기의 주소창에 나오는 `C:\Users\학생\GitPractice`는 PC의 폴더 위치입니다. 브라우저의 `https://github.com/…`은 웹 주소입니다. 두 주소를 서로의 주소창에 넣어 같은 일을 할 수 있다고 생각하지 마세요.

### 함께 해 보기

1. 메모장에서 “오늘은 파일 변경을 배웁니다.”를 적습니다.
2. 강사가 지정한 개인 연습 위치에 `intro.txt`로 저장합니다. 기존 파일을 덮어쓰지 않습니다.
3. 파일 탐색기에서 그 파일을 찾고 다시 엽니다. 내용이 남아 있으면 파일 저장은 된 것입니다.
4. 끝에 “두 번째 문장입니다.”를 추가하고 저장합니다.
5. 지금 파일만 보고 처음 문장이 무엇이었는지, 누가 언제 왜 바꿨는지 모두 알 수 있는지 생각해 봅니다.

예상 결과: 현재의 두 문장은 보이지만 이 파일만으로 모든 과거 변경 이유를 알 수는 없습니다. 저장 성공과 이력 관리 성공은 서로 다른 확인입니다.

## 2. 버전 관리는 무엇인가요?

발표자료를 `발표_최종`, `발표_진짜최종`, `발표_수정2`로 복사해 본 적이 있나요? 복사본이 늘면 무엇을 바꿨는지 비교하기 어렵습니다. 버전 관리는 파일의 변화를 기록하고 이전 상태와 비교하는 방법입니다. Git은 파일을 무조건 매초 기록하지 않습니다. 내가 선택한 변경을 설명과 함께 기록하는 행동을 **커밋(commit)**이라고 합니다.

예를 들어 첫 기록에는 “자기소개 추가”, 다음 기록에는 “학습 목표 추가”라고 적습니다. 나중에 어느 줄을 왜 바꿨는지 확인할 수 있습니다. 기록 전에 사라진 모든 내용이 저절로 복구되는 것은 아닙니다. 이력에 남긴 범위와 아직 기록하지 않은 범위를 구별해야 합니다. PC가 망가지면 PC 안 기록도 잃을 수 있으므로 별도의 보관과 공유도 필요합니다. Git을 설치한 것만으로 백업이 자동 완성되지는 않습니다.

**저장소(repository)**는 관련 파일과 그 변경 이력을 관리하는 프로젝트 단위입니다. 일반 폴더를 만든 직후에는 아직 Git 저장소가 아닙니다. 다음 단원에서 만들 `git-class-lab`도 처음에는 빈 연습 폴더입니다. [G04](G04.md)에서 Git 이력 관리를 시작합니다.

## 3. 이름이 비슷한 도구를 지도처럼 나누기

| 이름 | 쉬운 설명 | 주로 여는 곳 | 하는 일의 예 |
|---|---|---|---|
| Git | PC에서 변경 기록을 관리하는 도구 | 터미널 또는 이를 이용하는 앱 | 변경 비교, 커밋, 과거 기록 보기 |
| Git Bash | Git 명령과 폴더 명령을 글자로 입력할 환경 | Windows의 Git Bash 창 | 현재 폴더 확인 후 Git 실행 |
| GitHub | 저장소를 웹에서 보관·공유·검토하는 서비스 | 브라우저 | 파일 읽기, 변경 제안과 검토 |
| GitHub Desktop | Git 작업을 버튼과 목록으로 다루는 앱 | Windows에 설치한 앱 | 변경된 줄 확인, 커밋, 보내기 |
| GitLab | Git 저장소와 협업 기능을 제공하는 다른 서비스 | 브라우저, 기관 서버 등 | 저장소 관리, 변경 제안과 검토 |

GitHub Desktop은 PC의 저장소를 다룹니다. 브라우저에서 GitHub 파일을 보는 것과 같은 화면이 아닙니다. Git 명령과 Desktop은 같은 폴더의 같은 이력을 다룰 수 있으므로 한 도구에서 만든 커밋을 다른 도구에서도 볼 수 있습니다. 그러나 서로 다른 폴더를 열었다면 같은 이름이어도 내용이 다를 수 있습니다. 항상 폴더 위치를 확인합니다.

GitHub와 GitLab은 별도 서비스입니다. GitHub 계정으로 모든 GitLab 사이트에 자동 로그인되는 것은 아닙니다. 회사가 자체 주소로 GitLab을 운영할 수도 있습니다. Git의 기본 기록 개념을 익히면 다른 서비스를 이해하는 데 도움이 되지만 화면과 권한은 각각 확인해야 합니다. GitHub에서 변경을 합치자고 제안하는 이름은 Pull Request(PR), GitLab에서는 Merge Request(MR)입니다. 이름만 외우기보다 “변경을 비교하고 검토하는 제안”이라는 목적을 기억하세요.

## 4. PC 이름·Git 작성자·웹 계정은 무엇이 다를까요?

학교 PC 사용자 이름이 `student01`, GitHub 사용자 이름이 `mina-lab`, Git 기록의 작성자 이름이 `김민아`여도 가능합니다. 세 이름은 사용하는 곳이 다릅니다.

- PC 사용자: Windows에서 어떤 사용자로 작업하는지 나타냅니다. 개인 폴더 위치에도 영향을 줄 수 있습니다.
- Git 작성자 이름·이메일: 커밋에 “누가 작성했는가”를 적는 정보입니다. 로그인 비밀번호가 아닙니다.
- GitHub 계정: 웹 서비스에서 내가 누구인지 인증하고 저장소 접근 권한을 확인하는 계정입니다.

Git 작성자 이름에 다른 사람 이름을 적는다고 그 사람의 저장소 수정 권한이 생기지 않습니다. GitHub에 로그인했다고 모든 터미널의 작성자 설정이 자동으로 올바른지도 보장되지 않습니다. [G02](G02.md)에서 앱 로그인을 확인하고, 저장소를 만든 뒤 [G04](G04.md)에서 작성자 설정을 별도로 확인합니다. 예제 이름과 이메일을 그대로 본인 정보처럼 사용하지 않습니다.

## 5. 인터넷이 끊겨도 무엇을 할 수 있나요?

이미 Git이 설치되고 PC에 저장소가 있으면 파일 수정, 변경 비교, 커밋, PC에 있는 이력 확인은 인터넷 없이 할 수 있습니다. 반면 인터넷의 GitHub에 로그인하기, 원격 저장소를 처음 받기, 새 기록을 보내기, 다른 사람의 새 기록을 가져오기는 연결이 필요합니다. GitHub 서비스에 연결하지 못해도 PC의 파일 저장까지 실패한 것은 아닙니다.

파일 저장 → 변경 선택 → PC에 커밋 → 원격에 보내기는 서로 다른 단계입니다. **push**는 PC의 커밋을 원격 저장소로 보내는 작업입니다. **pull**은 원격 변경을 가져와 현재 작업에 통합하는 작업입니다. 단순한 자동 파일 동기화와 같다고 생각하지 마세요. 뒤 단원에서 각 단계의 전후 상태를 직접 확인합니다.

## 한 값 바꾸기와 예상 비교

위 자기소개 활동에서 두 번째 문장을 “센서 데이터를 배우고 싶습니다.”로 바꿉니다. 저장한 뒤 예상과 실제를 비교합니다. 예상: 메모장과 다시 연 파일 내용이 바뀝니다. GitHub 웹은 이 행동만으로 바뀌지 않습니다. 짝에게 “어디에 저장했고, 어떤 기록이나 공유는 아직 하지 않았는가”를 설명하세요.

## 막혔을 때

파일이 없으면 파일 탐색기의 실제 저장 위치와 이름을 확인합니다. 메모장에서 저장하지 않고 닫았다면 Git이 그 내용을 기록했다고 추정하지 않습니다. 브라우저에서 파일을 찾고 있었다면 PC 파일 탐색기로 돌아갑니다. 앱이 여러 개면 창의 제목과 주소를 먼저 읽고 지금 PC를 보는지 웹을 보는지 구별합니다.

## 확인 문제와 풀이

1. Git을 설치하면 GitHub 계정도 생기나요? **아니요.** PC 도구 설치와 서비스 가입은 별개입니다.
2. 인터넷이 끊기면 이미 받은 저장소의 커밋 이력도 못 보나요? **아니요.** PC에 있는 이력은 로컬에서 확인할 수 있습니다.
3. 저장 후 웹 파일이 그대로면 무조건 저장 실패인가요? **아니요.** PC 저장과 원격에 보내기는 별도입니다.
4. Git 작성자 이름을 바꾸면 다른 사람 계정으로 로그인되나요? **아니요.** 기록의 이름과 인증은 다릅니다.
5. 짝이 GitLab을 쓴다면 Git을 처음부터 다른 도구로 바꿔 배워야 하나요? **Git의 기본 개념은 이어집니다.** 서비스 화면·계정·권한은 다시 확인합니다.
