# G15 · 실제 화면을 함께 둘러보는 순서

## 세 창을 같은 저장소로 맞춥니다

기능 이름만 듣는 것보다 같은 파일을 세 화면에서 찾아보면 역할을 구별하기 쉽습니다. Git Bash는 명령과 상태, Desktop은 변경과 기록, GitHub는 공유된 파일과 협업을 보여 줍니다. 아래 순서로 각 창에서 같은 README.md와 커밋을 찾아봅니다.

개인 저장소가 아니라 **공개해도 되는 연습 저장소**를 사용하세요. 화면 공유 전에 다른 프로젝트, 인증 코드, 비공개 주소와 개인 파일을 닫습니다. GitLab은 공개 프로젝트를 읽는 방식으로도 둘러볼 수 있습니다.

## 1. Git Bash · 현재 위치에서 첫 기록까지

1. Windows 시작에서 Git Bash를 엽니다. 프롬프트의 사용자명·현재 폴더·브랜치·`$`를 찾습니다.
2. `pwd`와 `ls`로 현재 폴더와 파일을 확인합니다. 같은 폴더를 탐색기에서도 찾습니다.
3. G04의 연습 폴더로 들어가 `git status`를 읽습니다.
4. README를 수정·저장합니다. `git diff`에서 바뀐 줄을 찾습니다.
5. `git add README.md` 뒤 `git diff --staged`를 읽습니다. 커밋할 문장이 맞는지 말해 봅니다.
6. 메시지를 적어 커밋하고 `git --no-pager log --oneline -3`으로 결과를 확인합니다.

**여기서 설명할 말:** “파일 저장과 이력 기록은 다릅니다. 방금 기록은 아직 내 PC에 있습니다.”

## 2. GitHub Desktop · 같은 커밋 찾기

1. Current repository와 Show in Explorer로 같은 연습 폴더인지 확인합니다.
2. Current branch가 Git Bash의 브랜치와 같은지 봅니다.
3. History에서 방금 만든 제목과 바뀐 줄을 찾습니다.
4. 다른 문장을 하나 더 고치고 Changes를 봅니다. 이번에는 Desktop으로 커밋합니다.
5. Git Bash의 log에서도 두 번째 커밋이 보이는지 확인합니다.

**확인 질문:** 두 도구의 기록이 다른가요, 같은 저장소를 다른 화면으로 보는 건가요?

**풀이:** 같은 폴더·같은 브랜치를 열었다면 같은 기록입니다.

## 3. GitHub · 공유 결과와 업무 기능 찾기

1. 준비한 연습 저장소 주소를 브라우저에서 엽니다. PC 폴더 경로와 웹 주소가 다르다는 점을 확인합니다.
2. Code에서 README와 파일 목록, 현재 브랜치, Commits를 찾습니다.
3. Desktop에서 push한 뒤 웹의 최신 커밋 제목과 파일 내용을 비교합니다.
4. 웹에서 README 한 문장을 고쳐 커밋한 뒤 Desktop으로 fetch·pull합니다. 이번에는 웹에서 PC로 이동했습니다.
5. 자기 작업 브랜치의 PR에서 base·compare, 바뀐 파일, 댓글 위치를 찾습니다. 병합 뒤 main을 다시 받아옵니다.
6. Issues는 해야 할 일과 문제, Projects는 진행 상태, Actions는 자동 작업, Releases는 버전 배포, Pages는 정적 웹 게시, Security는 보안 점검 정보를 다루는 곳임을 각 메뉴에서 확인합니다.

메뉴를 찾는 것과 기능을 켜거나 게시하는 것은 다릅니다. 저장소에 없는 메뉴도 있습니다. 모든 기능을 켜기 위해 권한·요금·공개 범위를 바꾸지 않습니다. G09~G12에서 기능별 조건과 가벼운 관찰 과제를 확인하세요.

## 4. GitLab · 같은 Git, 다른 협업 화면

공개 예시인 [GitLab 개발 프로젝트](https://gitlab.com/gitlab-org/gitlab)를 엽니다. 저장소의 파일과 Commits, Issues, Merge requests를 찾아봅니다. 읽기만 해도 GitHub와 비교할 수 있습니다.

| 비교 질문 | 찾아볼 내용 |
|---|---|
| 파일은 어디에 있나요? | Repository의 파일·브랜치 |
| 변경 제안 이름은 무엇인가요? | GitHub의 Pull request, GitLab의 Merge request |
| 자동 실행은 어디에 있나요? | GitHub Actions, GitLab CI/CD의 파이프라인 |
| 프로젝트를 어디서 운영하나요? | GitLab.com 또는 조직이 운영하는 Self-Managed 환경 등 |

## 마무리 · 주소와 결과를 설명해 봅니다

완성한 캡처를 많이 모으는 것보다 작업의 방향을 설명할 수 있는지가 중요합니다.

- **한 줄 수정은 어디에 저장됐나요?** 작업 폴더의 README.md.
- **어떤 변경을 기록했나요?** add 또는 Desktop에서 선택해 확인한 내용.
- **PC 이력은 어디서 확인하나요?** Git log 또는 Desktop History.
- **상대방도 볼 수 있나요?** 공유 주소·접근 권한·브랜치·push 결과 확인.
- **다른 사람이 올린 변경은 어떻게 받나요?** fetch로 확인하고 상황에 맞게 pull.
- **합치기 전에 어디서 의견을 나누나요?** GitHub PR 또는 GitLab MR.

이 순서는 새로운 제출 과제가 아닙니다. 각자 실습을 설명하거나 강사의 화면 시연을 따라 확인하는 점검 목록입니다.
