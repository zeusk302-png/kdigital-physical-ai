# G11 · PR·Fork·Review로 수정 제안 이해하기

**학습 경로: 연습.** 본인 소유의 연습 저장소와 브랜치를 사용합니다. 강사 예시를 본 뒤 자기 작품의 README 한 문장을 수정해 제안합니다. PR 제출과 병합은 실제 저장소에 기록을 남기므로 연습 대상으로 안내된 저장소에서만 진행합니다. 다른 학생이나 외부 프로젝트에 PR·댓글을 임의로 보내지 않습니다.

## PR은 “이 수정안을 함께 확인해 주세요”

Pull request를 줄여 PR이라고 합니다. 한 브랜치의 변경을 다른 브랜치에 합치자고 제안하는 기능입니다. 파일을 첨부한 일반 메시지보다 바뀐 줄을 비교하기 쉬우며, 의견과 수정 기록을 같은 곳에서 확인할 수 있습니다. Issue는 고칠 일이고 PR은 파일을 어떻게 고쳤는지를 보여 주는 제안입니다.

진입 위치: 저장소의 Pull requests 탭 → New pull request입니다. Desktop에서도 브랜치를 원격으로 보낸 뒤 Create Pull Request 등으로 브라우저의 작성 화면을 열 수 있습니다. Desktop에서 버튼을 눌렀다는 사실과 웹에서 PR 제출을 마쳤다는 사실은 다릅니다.

PR에서 base는 변경을 받아들일 대상, compare는 제안할 변경이 있는 출발 브랜치입니다. 편지의 받는 곳과 보내는 곳처럼 먼저 방향을 확인합니다. `base: main`, `compare: readme-guide`라면 readme-guide의 변경을 main에 넣자는 방향입니다. 기본 브랜치 이름이 다르면 화면의 실제 이름을 사용합니다.

## 따라 하기 · README 설명 한 문장 제안

1. Desktop의 Current repository가 내 작품인지, 경로가 clone한 폴더인지 확인합니다. 아직 저장하지 않은 수정이 있으면 현재 작업부터 확인하고 강사에게 알립니다.
2. 기본 브랜치를 바탕으로 `readme-guide`라는 새 브랜치를 만듭니다. 브랜치는 별도의 수정 흐름입니다. 파일 탐색기에 같은 프로젝트 폴더가 하나 더 생기는 방식은 아닙니다.
3. README에 `실행 전 main.py가 있는 폴더를 엽니다.`라는 안내를 추가합니다. 실제 실행 파일이 다르면 그 이름으로 바꿉니다. 저장하고 Desktop Changes에서 내가 의도한 한 문장인지 확인합니다.
4. `README에 실행 위치 안내 추가`라는 설명으로 커밋합니다. 새 브랜치를 Publish branch 또는 push로 원격에 보냅니다. 버튼 이름은 현재 상태에 따라 달라질 수 있습니다.
5. 브라우저에서 PR 작성 화면을 열어 base와 compare를 확인합니다. Files changed에서 README의 안내 문장만 바뀌었는지 봅니다. 개인정보나 다른 파일이 보이면 제출 전에 돌아가 원인을 확인합니다.
6. 제목에 바뀐 일을 쓰고, 본문에 `이유: 처음 받는 사람이 실행 위치를 찾도록 보완`, `확인: 파일 목록과 README의 파일명 대조`를 적습니다. 실제 확인한 범위만 적고 PR을 만듭니다.

![수정 전후 비교 예시](../git-starter/assets/live/07-diff.jpg)

예상 결과: 내 저장소의 PR 주소가 생기고 Files changed에서 안내 문장이 보입니다. 아직 기본 브랜치에 합쳐지지 않았을 수 있습니다. PR 생성과 merge는 별도 행동입니다. “비교할 차이가 없다”면 base와 compare가 같은지, 커밋이 올바른 브랜치에 있는지, push를 했는지 순서대로 확인합니다.

![같은 브랜치 비교 상태를 점검하는 예시](../git-starter/assets/live/08-compare-branches.jpg)

## Review는 바뀐 내용과 근거를 확인하는 일

Review는 검토입니다. PR의 Conversation에서 이유를 읽고 Files changed에서 실제 변경을 봅니다. 줄 옆의 의견 기능이나 Review changes가 보일 수 있습니다. 읽기·댓글·승인·병합의 권한은 다르며 저장소 규칙도 적용됩니다. 자기 PR에 자신이 승인 평가를 내리는 방식으로 연습을 완료하지 않습니다.

가벼운 짝 활동: 각자 자기 PR을 화면으로 보여 줍니다. 짝은 게시하지 않고 말로 `좋은 점 1개`, `확인할 점 1개`를 전달합니다. 예를 들어 “실행 명령이 생겨 좋다. 실제 파일명도 main.py인지 확인하자”라고 합니다. 작성자는 파일 목록과 대조하고 필요한 수정이 있으면 같은 브랜치에서 저장→커밋→push합니다. 같은 브랜치를 사용하는 PR에는 이후 변경도 반영됩니다.

예상 결과: 검토 의견과 수정 근거가 연결됩니다. 초록색 검사 표시나 Approve 한 번이 모든 오류가 없다는 뜻은 아닙니다. 실행하지 않았다면 실행 확인으로 적지 않습니다. 이번 자료만으로 외부 저장소 병합을 수행하지 않으며, 본인 연습 PR의 merge는 수업의 별도 병합 안내와 권한을 확인해 진행합니다.

## Fork는 내 계정 쪽에 만드는 관련 저장소

Fork는 다른 저장소를 바탕으로 내 계정 또는 허용된 위치에 관련 저장소를 만드는 기능입니다. 남의 저장소를 직접 바꿀 권한이 없어도 자신의 fork에서 수정한 뒤 원본에 PR을 제안하는 흐름에 사용합니다. clone은 내 PC로 작업 저장소를 가져오는 일이므로 fork와 위치가 다릅니다. fork를 만들었다고 내 PC 폴더가 자동으로 생기지 않습니다.

진입 위치: 저장소 위쪽 Fork 버튼입니다. 이 단원에서는 버튼 위치만 봅니다. 공개 저장소를 fork할 수 있는 경우에도 라이선스·이용 조건은 별도로 확인해야 합니다. 비공개 저장소는 조직 정책·권한·허용 설정에 따라 fork가 제한될 수 있습니다. 버튼이 없거나 막히면 우회하지 않습니다.

마무리 확인: `branch는 수정 흐름`, `fork는 관련된 별도 저장소`, `clone은 PC로 가져오기`, `PR은 합치기 제안`, `review는 검토`를 각자 자기 말로 설명합니다. 오늘 필수 연습은 본인 저장소 브랜치의 PR이며 fork 생성은 요구하지 않습니다.
