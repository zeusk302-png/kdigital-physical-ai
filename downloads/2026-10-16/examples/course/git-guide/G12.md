# G12 · Actions·Releases·Pages·Security·Settings 둘러보기

**학습 경로: 둘러보기.** 준비된 화면을 읽고 기능을 구별합니다. 작업 실행, 서비스 활성화, 게시, 보안 검사 설정, 결제 설정을 진행하지 않습니다. 개인·조직·공개 여부·요금제에 따라 보이는 화면과 사용 범위가 다릅니다. 탭이 없으면 강사 예시로 확인합니다.

## Actions · 정해 둔 일을 자동으로 수행하기

파일이 바뀔 때마다 사람이 같은 명령으로 검사하면 빠뜨릴 수 있습니다. Actions는 정해 둔 조건에 따라 검사나 파일 만들기 같은 작업을 실행하는 기능입니다. 예를 들어 PR이 올라오면 Python 검사 명령을 실행하도록 만들 수 있습니다. 무엇을 언제 실행할지는 workflow라는 작업 정의에 적습니다.

진입 위치: 저장소의 Actions 탭에서 실행 목록을 보고 항목 하나를 누릅니다. 실행 아래에는 job이라는 작업 묶음과 실제 명령 단계가 있을 수 있습니다. 이 단원은 이미 끝난 예시만 봅니다. Enable workflows나 Run workflow는 누르지 않습니다.

가벼운 따라가기: 강사 화면에서 성공 또는 실패 표시, 실행한 브랜치, 실패 단계의 메시지를 찾습니다. `파일을 찾을 수 없음`이라면 테스트 대상 파일명·경로와 관련된 단서입니다. 빨간 표시만 보고 전체 프로그램을 지우는 식으로 반응하지 않습니다.

예상 결과: push 성공과 자동 검사 성공이 별개임을 설명합니다. 검사가 통과해도 사람이 실제 요구를 확인해야 합니다. 비용은 저장소 공개 여부와 실행 환경·사용량·요금제 등에 따라 달라지므로 무제한 무료라고 생각하지 않습니다. 수업에서는 새 runner나 비밀키를 등록하지 않습니다.

## Releases · 특정 버전을 받는 안내

Releases는 “이번에 받을 버전과 바뀐 점”을 안내하는 곳입니다. Git 태그와 연결되며 설명과 배포 파일을 붙일 수 있습니다. 커밋은 작업 기록 하나하나이고 Release는 사용자가 선택할 버전을 설명하는 데 쓰입니다.

진입 위치: 보통 저장소 Code 화면의 Releases 영역 또는 release 목록 링크입니다. 상단에 다른 탭과 같은 모양으로 늘어선다고 외우지 않습니다. 릴리스가 하나도 없을 수 있습니다.

가벼운 따라가기: 준비된 release에서 버전 이름, 변경 설명, Assets의 파일 이름을 읽습니다. Source code ZIP은 소스 묶음입니다. Windows 실행 파일이 따로 준비되어 있다면 파일명을 구별합니다. Release를 만들었다고 `.exe`가 자동 생성되는 것은 아닙니다.

예상 결과: 내가 받을 것이 실행 파일인지 직접 실행할 소스인지 README와 함께 판단합니다. 개발 중인 최신 브랜치와 마지막 release가 다를 수 있습니다. release 작성·수정에는 적절한 권한이 필요하므로 남의 저장소에서는 읽기만 합니다.

## Pages · 정적 웹페이지를 공개하는 공간

Pages는 HTML·CSS·JavaScript 같은 파일을 웹사이트로 제공하는 기능입니다. 우리 수업 홈페이지처럼 주소를 열어 안내와 자료 링크를 볼 때 사용합니다. Code 화면은 파일을 살피는 곳이고 Pages 주소는 완성된 웹 화면을 보는 곳입니다.

진입 위치: 설정 권한이 있는 저장소에서는 Settings → Pages에서 구성 정보를 확인합니다. 이미 공개된 사이트는 README나 저장소의 웹사이트 링크로 열 수 있습니다. 권한이 없으면 Settings가 보이지 않을 수 있습니다. 이번에는 공개 사이트 주소만 읽습니다.

가벼운 따라가기: 수업 홈페이지와 GitHub 저장소 주소를 각각 열어 주소와 화면을 비교합니다. 한쪽은 학습 페이지, 다른 쪽은 파일과 변경 기록입니다. 내 Python 파일을 Code에 올려도 Pages가 그 Python 프로그램을 서버에서 실행해 주지는 않습니다.

예상 결과: 소스 공개와 웹사이트 게시를 구별합니다. GitHub Free에서는 공개 저장소의 Pages를 사용할 수 있으며 비공개 저장소의 사용은 적합한 플랜 조건을 확인해야 합니다. 저장소가 비공개라는 사실만으로 Pages 사이트까지 비공개라고 가정하지 않습니다. 공개 범위는 별도로 확인합니다.

## Security · 공개하기 전에 살필 보안 기능

Security는 저장소의 보안 안내와 검사 관련 기능을 모아 보는 입구입니다. 알려진 취약한 의존성, 실수로 포함한 비밀정보 등과 관련한 기능이 있지만 모든 저장소에 모든 검사가 같은 조건으로 제공되지는 않습니다. 일부 기능은 별도 활성화·요금제·제품 조건을 요구합니다.

진입 위치: 저장소의 Security 또는 보안과 품질 관련 탭입니다. 표시 이름과 접근 가능한 항목은 현재 화면을 기준으로 합니다. 이 단원에서는 강사 예시의 항목 이름만 읽고 검사 활성화 버튼은 누르지 않습니다.

가벼운 따라가기: 가상 파일 목록 `main.py / README.md / password.txt`를 보고 마지막 파일을 공개하면 안 되는 이유를 말합니다. 예시에는 실제 비밀번호를 넣지 않습니다. 실제 키가 이미 공개되었다면 현재 파일에서 지우는 것만으로 과거 기록이 없어지지 않으며 해당 키 폐기·교체 등 필요한 대응을 확인해야 합니다.

예상 결과: “보안 탭이 있으니 아무 파일이나 올려도 안전하다”는 생각을 버리고 commit 전에 Changes에서 파일과 내용을 확인합니다. 경고가 없다는 사실이 비밀정보가 전혀 없다는 증명은 아닙니다.

## Settings · 저장소 운영 방식을 정하는 곳

Settings는 공개 범위·접근 권한·기능·연결 같은 운영 설정을 다룹니다. 자기 PC의 Git 작성자 이름을 바꾸는 설정과 저장소의 웹 설정은 위치와 효과가 다릅니다. Settings가 보이지 않으면 권한이 없는 경우가 있습니다.

진입 위치: 저장소 상단 Settings이며 화면 폭에 따라 메뉴 안에 들어갈 수 있습니다. 이 단원은 위치와 역할만 확인합니다. 공개/비공개 전환, 저장소 삭제·이전, 권한 추가, 기능 활성화는 하지 않습니다.

마무리 확인: “자동 검사 결과 / 버전 받기 / 웹 화면 / 보안 정보 / 운영 설정”을 각 기능에 연결합니다. 이 단원 완료의 기준은 설정 변경이 아니라 목적에 맞는 위치를 찾는 것입니다.
