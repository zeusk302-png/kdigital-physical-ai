# G10 · Issues·Projects·Wiki·Discussions 둘러보기

**학습 경로: 둘러보기.** 기능이 마련된 공개 예시 또는 강사 화면을 읽고 용도를 고릅니다. 새 게시물·댓글·보드·위키를 만들 필요가 없습니다. 탭이 없으면 기능이 꺼져 있거나 저장소에서 제공하지 않는 경우도 있습니다. 설정을 바꾸어 탭을 만들어 내지 않습니다.

## Issues · 구체적인 할 일을 남기는 곳

구두로 “프로그램이 이상해요”라고만 말하면 어떤 상황인지 다시 물어야 합니다. Issue는 해결할 일과 확인한 사실을 한곳에 적는 메모입니다. 오류 신고뿐 아니라 새 기능 요청, 문서 보완, 해야 할 작업을 적을 수 있습니다. 파일의 이력을 저장하는 커밋과는 다른 기록입니다.

진입 위치: 저장소 위쪽 Issues 탭입니다. 열려 있는 항목의 제목을 눌러 본문·상태·댓글을 읽습니다. Open은 아직 열려 있다는 표시이고 Closed는 닫혔다는 표시입니다. 닫혔다고 반드시 프로그램 수정으로 해결됐다는 뜻은 아닙니다. 중복이거나 더 진행하지 않기로 정해 닫을 수도 있으므로 사유를 읽습니다.

가벼운 따라가기: 강사가 보여 주는 예시를 다음 세 칸으로 나눠 종이나 메모장에 적습니다. `해 본 일: 이름을 비워서 실행`, `실제 결과: 아무 안내도 없음`, `원하는 결과: 이름을 입력해 달라고 안내`. 재현 절차와 바라는 결과가 있으면 다른 사람도 같은 상황을 확인하기 쉽습니다. 실제로 실행하지 않았다면 “직접 확인”이라고 쓰지 않습니다.

예상 결과: Issue를 읽고 고쳐야 할 일이 무엇인지 설명합니다. 흔한 오해는 Issue를 만들면 코드가 자동으로 바뀐다는 것입니다. 파일 수정은 별도이며, 수정 제안인 PR에 Issue를 연결하면 작업 이유를 따라가기 쉬워집니다.

## Projects · 여러 할 일의 진행을 보는 판

팀이 종이 메모를 `할 일 / 진행 중 / 완료` 칸에 붙이는 장면을 떠올려 보세요. Projects는 Issue나 PR 등을 표·보드·일정 형태로 모아 진행을 살피는 기능입니다. Git 저장소는 파일과 이력의 단위이고, Projects는 업무를 계획하고 추적하는 공간입니다.

진입 위치: 저장소의 Projects 탭이 연결되어 있으면 그곳에서 보거나, 사용자·조직의 Projects에서 봅니다. Projects는 사용자 또는 조직 수준에서 관리되므로 저장소 하나에 파일처럼 들어 있는 기능으로만 이해하지 않습니다. 보드가 비공개면 읽기 권한이 필요하고 항목을 바꾸려면 편집 권한이 필요합니다.

가벼운 따라가기: 화면의 카드 하나를 골라 제목·상태·연결된 Issue를 찾아봅니다. 카드를 옮기지는 않습니다. 메모장에 `실행 방법 보완 → 진행 중 → README 변경 후 새 폴더 실행으로 확인`이라고 적습니다. 단순히 완료 칸으로 옮겼다고 실제 실행 확인이 끝난 것은 아닙니다.

예상 결과: 해야 할 일의 설명과 현재 진행 상태를 구별합니다. 모든 팀이 같은 칸 이름과 절차를 쓰지는 않습니다. 수업에서는 보드 생성이나 자동화 설정까지 수행하지 않습니다.

## Wiki · 여러 쪽으로 나눠 쓰는 설명서

README가 현관의 짧은 안내판이라면 Wiki는 사용법·설치·문제 해결을 여러 페이지로 정리한 설명서입니다. README만으로 충분한 작은 작품이라면 Wiki를 꼭 만들 필요는 없습니다. 문서가 어디에 있는지 일관되게 안내하는 것이 먼저입니다.

진입 위치: 저장소의 Wiki 탭입니다. 페이지 목록에서 설치나 사용법을 찾습니다. 공개 저장소의 Wiki를 읽을 수 있어도 편집 권한이 자동으로 생기는 것은 아닙니다. GitHub Free의 공개 저장소에서 Wiki를 제공하며, 비공개 저장소 Wiki는 적합한 유료 플랜 조건이 적용될 수 있습니다. 탭이 없으면 강사 예시로 확인합니다.

가벼운 따라가기: `작품 소개 3문장`, `오류별 해결법 10개`라는 두 자료를 README와 Wiki 중 어디에 두면 찾기 쉬울지 말합니다. 정답 하나를 외우기보다 방문자가 어디서 출발해 필요한 정보를 찾을지 설명하세요.

예상 결과: 문서가 많을 때 여러 페이지가 필요한 이유를 설명합니다. Wiki 페이지에 Python 코드를 적는 것과 실행 가능한 `.py` 파일을 저장소에 두는 것은 다릅니다.

## Discussions · 질문과 의견을 나누는 공간

Discussions는 프로젝트와 관련한 질문·아이디어·공지 등을 주제로 대화하는 공간입니다. “어떤 기능이 있으면 좋겠나요?”처럼 아직 구체적인 작업으로 정하지 않은 이야기를 나누는 데 쓰입니다. Issue도 대화를 포함하므로 둘의 구분은 해당 팀의 운영 규칙을 함께 봅니다.

진입 위치: 기능을 켠 저장소 또는 조직의 Discussions입니다. 모든 저장소에 보이지는 않습니다. 읽을 수 있는 범위는 공개 여부와 접근 권한에 따르며, 참여에는 로그인과 게시 권한 등 조건이 적용됩니다. 우리 연습에서는 게시하지 않고 주제와 분류를 읽습니다.

가벼운 따라가기: `이 줄의 파일명이 틀렸어요`는 구체적인 Issue 후보, `작품을 어떤 주제로 확장할까요`는 Discussion 후보로 나눠 봅니다. `설치 방법이 어디 있나요`는 우선 README·Wiki를 찾고 팀의 질문 규칙을 따릅니다.

마무리 확인: “할 일 설명 / 진행 현황 / 긴 설명서 / 열린 대화” 네 문구를 네 기능에 연결합니다. 이번 둘러보기의 결과는 기능을 구별하는 것이며 게시물 개수로 평가하지 않습니다.
