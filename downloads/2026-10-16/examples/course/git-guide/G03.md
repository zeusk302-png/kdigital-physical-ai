# G03 · 검은 창을 읽고 내 연습 폴더 찾아가기

## 목적 → 준비

검은 창에 글자를 입력해도 겁내지 않고 현재 위치와 명령 결과를 읽는 연습입니다. Windows에서 Git Bash가 열려 있으면 시작합니다. 이 단원은 폴더 만들기와 이동까지만 합니다. **Git 저장소 생성은 G04에서 진행합니다.** 인터넷과 GitHub 로그인이 없어도 이 폴더 연습은 가능합니다. 기존 작품 폴더가 아닌 새 빈 폴더 `git-class-lab`을 사용합니다.

필수 활동은 입력줄 읽기, 현재 위치 확인, 폴더 목록 읽기, 새 연습 폴더 만들기, 이동 후 확인입니다. 공백 이름 폴더는 선택 도전입니다. 현재 창의 폴더가 어디인지 모르면 먼저 아래 `pwd` 확인부터 합니다. 원래 폴더를 삭제하면서 새로 시작하지 않습니다.

## 1. 터미널과 셸은 무엇인가요?

터미널은 글자로 지시하고 결과를 보는 창입니다. 셸은 그 지시를 읽고 프로그램을 실행해 주는 도구입니다. 식당에서 주문서를 적는 공간이 터미널이라면 주문을 읽어 전달하는 역할이 셸에 가깝습니다. Git Bash는 Windows에서 Bash 방식으로 명령을 사용할 수 있게 하는 환경입니다. PowerShell은 다른 문법을 사용하는 셸입니다. 둘 다 Git을 실행할 수 있지만 폴더 주소와 일부 명령 해석은 다릅니다.

검은 배경은 화면 색일 뿐입니다. 검은 창이라고 모두 Git Bash는 아닙니다. 창 제목과 입력줄을 확인합니다. `PS C:\Users\…>`가 보이면 PowerShell일 가능성이 높습니다. 이 단원의 폴더 명령은 **Git Bash**에서 따라 합니다. Windows 시작 메뉴에서 Git Bash를 검색해 엽니다.

## 2. 프롬프트와 명령·출력을 구별하기

창에 다음처럼 보일 수 있습니다. 이 상자는 화면 예시이므로 통째로 입력하지 않습니다.

```text
student@CLASS-PC MINGW64 ~
$ pwd
/c/Users/student
```

`student@CLASS-PC`는 PC 사용자와 컴퓨터 이름을 보여 주는 부분입니다. `MINGW64` 같은 표시는 Git for Windows 환경에 관한 표시이며 그대로 입력하는 명령이 아닙니다. `~`는 현재 사용자의 홈 폴더를 짧게 나타냅니다. 새 줄의 `$`는 “여기서 명령을 입력할 수 있습니다”라는 표시인 **프롬프트**입니다. 설정에 따라 모양·색·줄 수가 달라도 됩니다.

위에서 사람이 입력한 것은 `pwd` 세 글자뿐입니다. `$`와 `/c/Users/student`는 입력하지 않습니다. 마지막 줄은 프로그램이 보여 준 **출력**입니다. 출력 다음에 새 프롬프트가 나타나면 다음 명령을 받을 준비가 된 것입니다. 나중에 저장소 안으로 들어가면 프롬프트에 `(main)` 같은 브랜치 이름이 보일 수도 있습니다. 아직 그런 표시가 없다고 고장난 것은 아닙니다.

### 첫 입력 따라 하기

커서가 있는 곳에 아래 명령만 입력하고 Enter를 누릅니다. 주석은 설명이며 입력하지 않아도 됩니다.

```bash
# 현재 작업 폴더의 전체 위치를 출력합니다. 파일을 만들거나 바꾸지 않습니다.
pwd
```

예상 출력은 `/c/Users/본인PC사용자` 같은 위치입니다. 남과 경로가 달라도 괜찮습니다. pwd는 “지금 내가 어느 폴더에 있는가”를 묻습니다. 글자를 쓴 뒤 Enter를 안 누르면 아직 실행 전입니다. 영문 입력 모드를 확인하고 `pwd`를 소문자로 입력합니다.

## 3. 입력할 때 필요한 키와 기호

| 상황 | 행동 | 뜻 |
|---|---|---|
| 아직 실행 전 오타 | Backspace로 고치기 | 입력줄 글자만 지움 |
| 실행하기 | Enter | 입력줄을 셸에 전달 |
| 이전 명령 재사용 | 위쪽 방향키 | 이전 입력을 불러옴. Enter 전 수정 가능 |
| 명령 중단 또는 덜 쓴 입력 취소 | Ctrl+C | 진행 중인 작업에 중단을 요청하거나 현재 입력을 취소 |
| 긴 기록 전용 화면에서 나가기 | q | less 같은 페이지 보기 도구가 열렸을 때 원래 입력줄로 복귀 |
| 붙여넣기 | 창의 우클릭 메뉴 Paste 또는 Shift+Insert | Git Bash 터미널 설정에 따라 방법이 다를 수 있음 |

Ctrl+C는 이 창에서 보통 복사가 아닙니다. 붙여넣은 글에 Enter가 포함되면 바로 실행될 수 있으므로 처음에는 한 줄씩 확인합니다. 프롬프트까지 붙이지 않습니다. q는 모든 프로그램을 종료하는 공통 키가 아닙니다. 보통 입력줄에서 q를 치면 q라는 프로그램을 찾다가 오류가 납니다. 프롬프트와 긴 내용 전용 화면을 구별하세요. 창 전체를 닫는 것은 오른쪽 위 X로 할 수 있지만 진행 중인 작업이 있다면 먼저 상태를 확인합니다.

주석 표시 `#`는 셸에서 설명을 적을 때 씁니다. 다음 상자처럼 줄 맨 앞에 사용한 설명은 실행하지 않습니다. 폴더 이름 앞에 마음대로 붙이는 기호가 아닙니다. 명령과 대상 사이에는 한 칸 이상 띄웁니다. `cdGitPractice`와 `cd GitPractice`는 다릅니다.

## 4. 홈 폴더로 가서 목록 읽기

명령은 한 줄씩 실행하고 결과를 확인한 뒤 다음 줄로 넘어갑니다.

```bash
# ~는 현재 사용자의 홈 폴더를 뜻합니다. cd는 그 위치로 이동합니다.
cd ~
# 지금 홈 폴더에 있는지 전체 경로로 확인합니다.
pwd
# 현재 폴더 안의 파일과 폴더 이름을 목록으로 봅니다. 내용을 바꾸지 않습니다.
ls
```

`cd`는 change directory, 즉 작업 폴더를 바꾸는 명령입니다. `ls`는 현재 위치의 목록을 보여 줍니다. 출력에는 `Desktop`, `Documents`, `Downloads` 등이 있을 수 있고 PC마다 다릅니다. 이름이 없다고 새로 만들 필요는 없습니다. 아무것도 없는 폴더에서는 ls의 출력이 비어 있을 수도 있습니다. 명령이 실패했다는 뜻은 아닙니다.

`cd`가 성공하면 보통 “이동 완료” 문장은 나오지 않습니다. 프롬프트의 위치가 달라지거나 뒤의 pwd로 확인합니다. 터미널에서 이동해도 이미 열린 파일 탐색기 창이 자동으로 같은 위치로 바뀌지는 않습니다. 탐색기도 해당 폴더를 따로 열어 비교합니다.

## 5. 새 연습 폴더 만들기: 필수 함께 따라 하기

아래 시작 위치는 홈 폴더입니다. mkdir는 make directory, 즉 폴더를 만드는 명령입니다. 새 파일을 만드는 명령이 아닙니다.

```bash
# 홈 폴더로 돌아갑니다. 시작 위치를 일정하게 맞추기 위한 단계입니다.
cd ~
# 홈 폴더 바로 아래 GitPractice라는 연습용 폴더를 만듭니다.
mkdir GitPractice
# 방금 만든 폴더 안으로 이동합니다.
cd GitPractice
# 위치가 /c/Users/본인/GitPractice로 끝나는지 확인합니다.
pwd
# 현재 위치 바로 아래 git-class-lab이라는 새 폴더를 만듭니다.
mkdir git-class-lab
# Git 실습에 사용할 그 폴더 안으로 이동합니다.
cd git-class-lab
# 최종 위치가 GitPractice/git-class-lab으로 끝나는지 확인합니다.
pwd
# 새 폴더가 비어 있는지 일반 목록을 확인합니다.
ls
```

`GitPractice`는 부모 폴더, `git-class-lab`은 그 안에 있는 자식 폴더입니다. 하이픈 `-`도 이름의 일부입니다. `git class lab`처럼 공백으로 바꾸지 않습니다. 폴더를 만들기만 해서는 그 안으로 이동하지 않으므로 mkdir 다음 cd가 따로 필요합니다.

### 예상 결과

마지막 pwd 예시는 `/c/Users/student/GitPractice/git-class-lab`입니다. 본인 이름 부분은 다릅니다. 마지막 ls는 새 빈 폴더이면 아무 목록 없이 다음 입력줄로 넘어갑니다. 이 시점에는 아직 커밋·GitHub 저장소·원격 공유가 생기지 않았습니다.

`mkdir GitPractice`에서 `File exists`가 나오면 이미 같은 이름의 대상이 있다는 뜻입니다. 먼저 ls로 그것이 연습 폴더인지 확인합니다. 기존 수업 연습 폴더가 맞으면 해당 mkdir 한 줄만 건너뛰고 cd로 들어갑니다. 다만 `git-class-lab`까지 이미 있고 그 안에 파일이나 예전 Git 이력이 있다면 새 빈 폴더라는 시작 조건과 다릅니다. 지우지 말고 강사와 다른 개인 연습 위치를 정합니다. 준비된 기존 프로젝트나 이 교안의 실제 원본 폴더 안에서 Git 저장소를 새로 만들지 않습니다.

## 6. 한 단계 올라갔다가 다시 들어가기

실행하기 전에 pwd가 `git-class-lab`으로 끝나는지 확인합니다.

```bash
# ..은 바로 위 부모 폴더입니다. git-class-lab에서 GitPractice로 이동합니다.
cd ..
# 부모 폴더로 이동했는지 확인합니다.
pwd
# git-class-lab이 목록에 보이는지 확인합니다.
ls
# 다시 자식 폴더 안으로 들어갑니다.
cd git-class-lab
# 원래 연습 위치로 돌아왔는지 확인합니다.
pwd
```

`..`의 점 두 개는 “부모 폴더”이고 한 개 `.`는 “현재 폴더”입니다. 점 두 개 사이에는 공백이 없습니다. 이 활동은 파일을 바꾸지 않고 작업 위치만 바꿉니다. 탐색기의 뒤로 가기 버튼과 달리 cd ..은 방문 기록이 아니라 폴더 구조의 위쪽으로 갑니다.

짝에게 “지금은 어디이며, cd ..을 하면 어디인가”를 예상해 말한 뒤 실제 pwd와 비교합니다. 두 경로의 마지막 폴더 이름이 어떻게 달라졌는지 찾아보세요.

## 7. C:\ 와 /c/는 왜 다르게 보일까요?

Windows 탐색기는 보통 `C:\Users\student\GitPractice`처럼 드라이브 글자와 역슬래시를 씁니다. Git Bash에서는 같은 위치를 `/c/Users/student/GitPractice`처럼 표현할 수 있습니다. `/c/`는 C 드라이브 쪽을 가리키는 Git Bash의 경로 표현입니다. 탐색기 주소창이 틀린 것이 아닙니다. 표시 규칙이 다릅니다.

Git Bash에서는 `C:/Users/student/GitPractice`처럼 드라이브 글자와 슬래시를 쓰는 표현도 사용할 수 있지만, 여기서는 `/c/…`로 통일합니다. `c:/`는 드라이브 글자와 콜론이 있는 표현이고 `/c/`는 Bash 환경의 경로 표현입니다. `c/`처럼 콜론과 맨 앞 슬래시를 모두 빼면 현재 폴더 아래의 c라는 이름으로 해석될 수 있어 뜻이 달라집니다. 예시 student를 내 PC 사용자 이름으로 바꾸지 않고 복사하면 남의 경로를 찾게 됩니다.

다음 두 명령은 같은 홈 아래 연습 폴더로 돌아오는 예입니다. 첫 번째만 실행해도 충분합니다.

```bash
# ~ 뒤의 경로로 내 홈 폴더 아래 연습 위치에 한 번에 갑니다.
cd ~/GitPractice/git-class-lab
# 실제 도착 위치를 출력합니다. 본인 PC 경로와 비교합니다.
pwd
```

이렇게 전체 위치를 기준으로 정한 경로와 달리 `cd git-class-lab`은 현재 폴더 안에서 이름을 찾습니다. 지금 위치가 다르면 같은 명령도 성공하거나 실패할 수 있습니다. 명령 전에 pwd를 읽는 이유입니다.

## 8. 한 값 바꾸기: 공백 있는 폴더 이름 (선택 도전)

필수 연습 폴더가 빈 상태인지 확인한 다음 잠시 부모 GitPractice로 이동해 추가 활동을 합니다. 필수 git-class-lab 안에는 파일을 만들지 않습니다.

```bash
# git-class-lab의 부모 GitPractice로 이동합니다.
cd ..
# 큰따옴표 안의 전체 글자를 하나의 폴더 이름으로 묶어 만듭니다.
mkdir "my notes"
# 공백이 있는 하나의 폴더 이름을 큰따옴표로 묶어 이동합니다.
cd "my notes"
# 마지막이 my notes인지 확인합니다.
pwd
# 다시 부모로 나옵니다.
cd ..
# 필수 실습용 빈 폴더로 돌아갑니다.
cd git-class-lab
# 다음 G04를 시작할 위치를 확인합니다.
pwd
```

예상: `my notes`는 한 폴더입니다. 큰따옴표는 이름에 포함되는 글자가 아니라 띄어쓰기를 포함한 하나의 대상으로 묶는 기호입니다. 곧은 영문 큰따옴표 `"`를 사용합니다. `mkdir my notes`처럼 따옴표를 빼면 my와 notes라는 두 대상을 만들 수 있습니다. 실수했더라도 지우는 명령을 시험하지 말고 ls로 실제 생긴 것을 확인합니다. `cd my notes`는 cd에 대상이 여러 개 주어졌다는 오류가 날 수 있습니다.

한 값 수정 활동: 아직 해당 이름을 만들지 않았다면 위 예시의 `my notes` 세 곳을 `study notes`로 모두 맞춰 바꿉니다. 예상: 폴더 이름과 pwd 마지막 부분만 바뀝니다. 이동 명령의 이름을 그대로 두면 다른 이름을 찾아 실패합니다. 기존 이름이 있는 경우 같은 폴더인지 확인하고 mkdir를 건너뜁니다.

## 9. 자주 막히는 입력과 복구

| 화면 또는 상황 | 뜻과 복구 |
|---|---|
| `$: command not found` | 프롬프트의 $까지 입력했는지 확인합니다. 다음 줄에는 명령만 입력합니다. |
| `pwwd: command not found` | 프로그램 이름 오타입니다. 위 방향키로 불러와 pwd로 수정 후 Enter를 누릅니다. |
| `cd: …: No such file or directory` | 현재 위치와 폴더 이름 확인: pwd → ls → 실제 이름으로 cd. 폴더를 지우지 않습니다. |
| `mkdir: …: File exists` | 같은 이름이 이미 있습니다. ls로 확인하고 새 빈 폴더 조건을 강사와 맞춥니다. |
| `Permission denied` | 쓰기 권한이 없는 위치일 수 있습니다. pwd 확인 후 개인 홈 연습 위치를 사용합니다. 기관 정책을 따릅니다. |
| `>`만 보이며 다음 줄을 기다림 | 따옴표를 닫지 않았을 수 있습니다. Ctrl+C로 취소하고 양쪽 따옴표를 맞춰 한 줄로 다시 입력합니다. |
| 긴 화면 아래 `(END)` | 페이지 보기 도구라면 q로 나옵니다. q를 일반 프롬프트에서 실행하지 않습니다. |
| PowerShell처럼 `PS …>`가 보임 | 이 단원은 Git Bash를 엽니다. PowerShell 오류를 Bash 오류와 섞어 해석하지 않습니다. |

PowerShell에서는 경로를 `C:\Users\…`처럼 표시하고 `pwd`·`ls`가 비슷해 보여도 별칭으로 다른 명령에 연결될 수 있습니다. Bash의 `~`·따옴표 예제가 모든 셸에서 완전히 같은 결과라는 뜻은 아닙니다. Git 명령이 양쪽에서 가능하다는 점과 셸의 폴더 문법이 같다는 주장은 구별합니다.

## 확인 문제와 풀이

1. `$ pwd` 화면에서 내가 입력할 글은? **pwd**입니다. $는 프롬프트 예시입니다.
2. mkdir가 성공하면 새 폴더 안에 있나요? **아니요.** cd로 이동하고 pwd로 확인합니다.
3. ls가 아무것도 안 보여 주면 실패인가요? **빈 폴더일 수 있습니다.** 오류 문장과 현재 경로도 확인합니다.
4. GitPractice/git-class-lab에서 cd ..의 목적지는? **GitPractice**입니다.
5. `cd "my notes"`의 큰따옴표가 필요한 이유는? **공백을 포함한 전체 이름을 하나의 대상으로 전달하기 위해서입니다.**
6. `git-class-lab` 폴더를 만들었으니 GitHub에도 생겼나요? **아니요.** PC에 폴더만 만든 상태입니다.
7. 작업 중 Ctrl+C와 긴 기록 화면에서 q는 같은가요? **아니요.** 전자는 중단 요청, 후자는 해당 페이지 보기 종료에 사용합니다.

마지막 도착점은 pwd가 `GitPractice/git-class-lab`으로 끝나고 해당 폴더가 새 빈 폴더인 상태입니다. “내가 만든 폴더와 지금 명령이 실행되는 폴더가 같다”를 경로로 설명하세요. 이어서 [G04](G04.md)에서 이 폴더를 Git 저장소로 만들고 작성자 설정과 첫 기록을 배웁니다.
