# G14 · 오류를 읽고 되돌리는 방법

## 먼저 현재 위치와 상태를 읽습니다

Git의 오류는 무엇을 하려 했는지와 현재 상태가 맞지 않는다는 안내인 경우가 많습니다. 같은 명령을 반복하기 전에 **현재 폴더 → 현재 브랜치 → 남은 변경 → 연결한 원격** 순서로 확인합니다. 아래 명령은 상태를 읽으며 파일을 지우지 않습니다.

```bash
# Git Bash에서 현재 폴더를 봅니다.
pwd

# 현재 폴더의 파일과 숨김 항목을 봅니다. .git도 확인할 수 있습니다.
ls -a

# 현재 브랜치, 기록할 변경, 아직 선택하지 않은 변경을 봅니다.
git status

# 원격 이름과 주소를 확인합니다. 주소를 외부에 공유하기 전 내용을 확인합니다.
git remote -v
```

`git status`부터 실패한다면 `git diff`나 `git push`로 넘어가지 않습니다. 아직 저장소 밖에 있을 수 있습니다.

## 자주 만나는 메시지

| 메시지·증상 | 무슨 뜻인가요? | 확인하고 할 일 |
|---|---|---|
| `git: command not found` 또는 ‘git을 인식할 수 없습니다’ | 이 창에서 Git을 찾지 못함 | 설치 여부를 확인하고 새 Git Bash를 열어 `git --version` 확인 |
| `not a git repository` | 현재 위치에서 Git 저장소를 찾지 못함 | `pwd` 확인 후 실제 연습 저장소로 이동. 문제를 덮으려고 아무 폴더에서 init하지 않기 |
| `Author identity unknown` | 커밋에 쓸 작성자 정보가 없음 | G04의 `git config --local` 설정과 조회 확인. GitHub 비밀번호 입력 문제가 아님 |
| `nothing to commit, working tree clean` | 현재 변경할 내용이 없음 | 편집기 저장·파일 위치·이미 커밋했는지 확인 |
| `no changes added to commit` | 바꾼 파일이 기록 대상으로 선택되지 않음 | diff를 읽고 해당 파일만 add |
| `pathspec ... did not match` | 적은 파일 또는 브랜치를 찾지 못함 | `ls`, `git branch`로 철자·확장자·현재 위치 확인 |
| `repository not found` | 주소가 틀리거나 접근 권한이 없음 | 주소·계정·저장소 공개 범위를 확인. 새 저장소를 계속 만들지 않기 |
| `non-fast-forward` 또는 `rejected` | 공유 쪽에 내 PC에 없는 기록이 있음 | fetch 후 이력을 비교. G07처럼 충돌 여부를 판단하고 받아오기 |
| `CONFLICT` | 같은 부분의 변경을 자동으로 합칠 수 없음 | G06에서 표식과 의도를 읽고 해결하거나 병합 중단 |
| `would be overwritten` | 내 미커밋 변경을 덮어쓸 수 있음 | 현재 작업을 먼저 보관·기록하고 다시 판단 |
| `(END)` 또는 화면 아래 `:` | 긴 출력을 읽는 화면이 열림 | `q`로 빠져나오기. 명령이 실패한 것이 아님 |

메시지의 줄바꿈·언어·기본 브랜치명은 PC마다 다를 수 있습니다. 의미를 보고 판단하세요.

## 취소도 단계에 따라 다릅니다

| 지금 상태 | 원하는 일 | 방법과 남는 것 |
|---|---|---|
| 편집 중·미저장 | 방금 타이핑만 취소 | 편집기의 실행 취소. Git 명령이 아님 |
| 저장했지만 미커밋 | 이번 커밋 대상에서만 빼기 | `git restore --staged README.md` — 파일 수정은 남음 |
| 저장했지만 미커밋 | 파일의 수정을 버리기 | 별도 복사 후 `git restore README.md` — 작업 파일이 스테이징 내용으로 바뀜 |
| 이미 커밋 | 그 변경을 상쇄하는 새 기록 만들기 | `git revert 커밋ID` — 기존 이력을 남기고 취소 커밋 추가 |
| 병합 중 충돌 | 병합 시도 중단 | `git merge --abort` — 시작 전 상태 복구 시도. 시작 전 미커밋 변경이 있으면 복구가 어려울 수 있음 |

**파일 수정 버리기는 되돌릴 기록이 없을 수 있습니다.** 원본을 복사해 두고 새 연습 저장소에서만 확인합니다. 처음에는 전체 초기화나 강제 push로 문제를 덮지 않습니다.

## 직접 해보기 · 선택만 취소하기

G05처럼 이미 첫 커밋이 있는 `git-class-lab`에서 진행합니다. README.md에 한 줄을 적고 저장한 뒤 아래를 한 줄씩 실행합니다.

```bash
# 먼저 추가된 줄을 읽습니다.
git diff

# README.md의 현재 내용을 기록 대상으로 고릅니다.
git add README.md

# 작업 파일을 지우지 않고, 기록 대상 선택만 취소합니다.
git restore --staged README.md

# staged가 아니라 Changes not staged for commit으로 돌아왔는지 확인합니다.
git status
git diff
```

**예상 결과:** 글은 파일에 그대로 남아 있습니다. 스테이징 취소는 편집 취소와 다릅니다. 아직 첫 커밋이 없는 저장소에서는 이 예제를 그대로 진행하지 말고 G04를 먼저 마치세요.

## 추가 연습 · 한 기록을 취소하는 기록

이 연습은 원격에 공유하지 않은 별도 저장소에서 합니다. README.md에 시험 문장을 추가해 `Add trial sentence`라는 커밋을 하나 남깁니다. 다음으로 가장 최근 커밋의 제목을 확인합니다.

```bash
# HEAD는 지금 선택한 브랜치의 현재 커밋을 가리킵니다.
git --no-pager log --oneline -1

# 가장 최근 커밋이 방금 만든 시험 문장 커밋일 때만 실행합니다.
# --no-edit는 자동으로 만들어진 취소 메시지를 사용한다는 옵션입니다.
git revert --no-edit HEAD

# 원래 커밋과 취소 커밋이 모두 남았는지 봅니다.
git --no-pager log --oneline -3
```

**예상 결과:** 시험 문장이 없어지고 취소 커밋이 하나 더 생깁니다. 원래 커밋을 이력에서 지운 것이 아닙니다. 다른 변경과 겹치면 revert도 충돌할 수 있으므로 메시지를 읽고 강사에게 현재 상태를 보여 주세요.

## 원격 동기화에서 하면 안 되는 추측

‘push가 안 되니 새 저장소를 만든다’, ‘강제로 보내면 된다’, ‘.git을 지우면 해결된다’는 방법을 먼저 선택하지 않습니다. 공유 쪽에 누군가의 기록이 있거나, 주소가 틀렸거나, 권한이 없는 등 원인이 다를 수 있습니다. 오류 문장과 `status`, 현재 브랜치, 마지막 기록을 함께 확인합니다. 비밀번호·토큰·인증 코드는 캡처나 질문 글에 넣지 않습니다.

## 명령 빠른 찾기

| 목적 | 명령 | 바뀌는 것 |
|---|---|---|
| 위치·파일 보기 | `pwd`, `ls` | 조회만 |
| 상태 읽기 | `git status` | 조회만 |
| 미선택 변경 보기 | `git diff` | 조회만 |
| 선택한 변경 보기 | `git diff --staged` | 조회만 |
| 기록 대상으로 선택 | `git add README.md` | 스테이징 |
| PC 기록 | `git commit -m "메시지"` | 로컬 커밋 |
| 최근 기록 | `git --no-pager log --oneline -5` | 조회만 |
| 작업 흐름 만들기 | `git switch -c docs-improve` | 브랜치·작업 위치 |
| 원격 변경 확인 | `git fetch origin` | 원격 추적 정보 |
| 빠른 전진으로 받아오기 | `git pull --ff-only` | 로컬 브랜치와 작업 파일; 갈라진 이력이면 중단 |
| 내 기록 보내기 | `git push` | 공유 저장소 |

**질문:** 스테이징에서 파일을 빼면 파일 자체도 삭제되나요?

**풀이:** 아닙니다. `restore --staged`는 기록 대상 선택을 바꿉니다. 파일 편집은 남습니다. 작업 파일 내용까지 바꾸는 명령과 구별해야 합니다.

## 나중에 만날 기능도 이름을 알아둡니다

지금은 아래 명령을 한꺼번에 실행하지 않습니다. 기본 기록과 협업이 익숙해지면 필요한 목적에 맞춰 공식 예제를 읽습니다.

| 기능 | 어떤 상황에 쓰나요? | 먼저 구별할 점 |
|---|---|---|
| `.gitignore` | 캐시·가상환경·개인 설정처럼 기록하지 않을 파일 지정 | 이미 추적 중인 파일은 규칙을 추가해도 자동으로 이력에서 빠지지 않음 |
| `git tag` | 특정 커밋에 v1.0 같은 버전 이름 붙이기 | 브랜치처럼 새 커밋에 따라 계속 이동하는 이름과 다름 |
| `git stash` | 미커밋 변경을 잠시 치워 다른 작업 하기 | 커밋·백업·원격 공유를 대신하지 않음. 다시 적용할 때도 충돌 가능 |
| `git show` | 특정 커밋의 내용과 변경 보기 | 파일 편집이나 실행을 하는 명령이 아님 |
| `git cherry-pick` | 다른 흐름의 특정 변경을 현재 흐름에 적용 | 단순 파일 복사와 다르며 새 커밋·충돌이 생길 수 있음 |
| `git rebase` | 커밋을 다른 시작점 위에 다시 적용해 이력 정리 | 공유한 이력을 바꿀 수 있어 팀 규칙 확인이 먼저 |
| `git reflog` | 내 PC에서 참조가 이동했던 기록 찾아보기 | 모든 파일과 모든 원격 기록을 영구 보관하는 백업은 아님 |
