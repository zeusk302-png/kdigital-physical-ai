# G02 · Windows에서 설치하고 첫 연결 확인하기

## 목적 → 준비

이 단원의 목적은 Git Bash에서 Git 버전을 확인하고, GitHub Desktop에서 본인 계정 연결을 확인하는 것입니다. 설치 파일을 받았다는 사실, Git 실행 성공, 웹 로그인 성공, Desktop 연결 성공을 각각 확인합니다.

Windows PC, 프로그램 설치 권한, 공식 사이트에 접속할 인터넷이 필요합니다. GitHub 가입·인증에는 본인이 확인할 수 있는 이메일이 필요합니다. PC의 Windows 버전·CPU 종류·기관 설치 정책은 화면에서 확인합니다. 설치 화면과 버튼 이름은 버전에 따라 달라질 수 있습니다.

## 1. 설치 전에 기존 상태 확인하기

Windows 시작 버튼을 누르고 `Git Bash`와 `GitHub Desktop`을 각각 검색합니다. 검색 결과에 있다고 곧바로 재설치하지 않습니다. Git Bash가 있으면 실행한 뒤 아래 버전 명령을 먼저 시도합니다. Desktop이 있으면 앱을 열어 계정 상태를 확인합니다. 다른 사람의 계정이 보이면 그 계정으로 실습을 이어가지 않고 강사에게 알립니다.

설치 권한이 없는 기관 PC라면 관리자 비밀번호를 추측하거나 보안 기능을 끄지 않습니다. 강사에게 “다운로드 불가”, “실행 불가”, “설치 권한 필요” 중 어느 단계인지 알립니다. 설치가 막힌 학생도 G01의 역할 구별과 G03의 입력·출력 읽기 문제는 종이 또는 교안으로 할 수 있습니다. 이것을 설치 성공으로 표시하지는 않습니다.

## 2. Git for Windows 설치하기

1. 브라우저에서 [Git 공식 Windows 설치 안내](https://git-scm.com/install/windows)를 엽니다. 검색 광고의 유사 다운로드 버튼 대신 공식 안내의 연결을 사용합니다.
2. PC에 맞는 설치 파일을 선택합니다. 종류가 헷갈리면 Windows 설정의 시스템 정보를 강사와 확인합니다.
3. 내려받은 파일을 실행하고 표시된 프로그램 이름과 게시자를 확인합니다. 기관의 설치 정책을 따릅니다.
4. 설치 위치와 구성 요소는 기관 지정이 없다면 기본 제안을 우선 사용합니다. 수업에 없는 추가 옵션을 임의로 바꾸지 않습니다.
5. 기본 편집기를 묻는 화면에서는 실제 설치된 VS Code 등 사용할 편집기를 선택할 수 있습니다. 목록에 보인다고 그 편집기가 반드시 설치된 것은 아닙니다. 모르면 기본값으로 두고 강사에게 확인합니다. 이 단원에서는 메시지를 직접 적는 방식으로 진행하므로 편집기 사용법을 먼저 외울 필요가 없습니다.
6. 명령을 사용할 환경(PATH)을 묻는 화면에서는 외부 터미널에서도 Git을 사용할 수 있게 하는 권장 항목을 확인합니다. Git Bash 전용으로 제한하면 PowerShell에서 Git을 못 찾을 수 있습니다. 이미 기관 기준이 있으면 그 기준을 따릅니다.
7. 나머지 항목도 설명을 읽고 기본 제안으로 진행합니다. Install 후 완료 메시지를 확인합니다.
8. 이전부터 열려 있던 터미널은 닫고 Windows 시작 검색에서 Git Bash를 새로 엽니다.

Git for Windows는 Windows에서 Git을 사용하게 하는 배포판이며 Git Bash를 포함합니다. 설치 완료 후 Git Bash 창이 열렸다고 GitHub 로그인까지 끝난 것은 아닙니다.

## 3. 버전 확인: 어디에 무엇을 입력하나요?

실행 위치는 **Git Bash 창의 커서가 깜박이는 입력줄**입니다. 브라우저 주소창이나 메모장에 입력하면 실행되지 않습니다. 아래 상자의 첫 줄은 설명인 주석입니다. `#` 뒤 글은 Bash가 명령으로 실행하지 않습니다. 둘째 줄만 직접 입력해도 됩니다. 입력 뒤 Enter를 한 번 누릅니다.

```bash
# 설치된 Git 프로그램의 버전을 화면에 표시합니다. 설정이나 파일은 바꾸지 않습니다.
git --version
```

`git`은 실행할 프로그램 이름, 한 칸 띄우기는 이름과 옵션의 경계, `--version`은 버전을 보여 달라는 옵션입니다. 하이픈 두 개는 키보드의 일반 `-`를 두 번 입력합니다. 교안의 문장 부호 `—` 하나로 바꾸면 다른 글자가 됩니다.

예상 출력 예시는 다음과 같습니다. 숫자는 PC마다 달라도 됩니다.

```text
git version 2.xx.x.windows.x
```

`2.xx.x`는 예시 자리표시이며 직접 입력할 명령이 아닙니다. 실제 화면에 `git version`으로 시작하는 버전 문장이 나오고 다음 입력줄이 생기면 설치된 Git이 실행된 것입니다. 아무 말도 안 하고 오래 멈춘 것처럼 보이면 아직 Enter를 안 눌렀는지 확인합니다. GitHub 비밀번호를 입력할 단계가 아닙니다.

## 4. GitHub 계정 가입 또는 웹 로그인

이미 계정이 있으면 새 계정을 만들지 않고 로그인합니다. [GitHub](https://github.com/)에서 Sign in을 선택합니다. 처음이라면 Sign up에서 본인 이메일, 사용할 username, 비밀번호를 화면 안내에 따라 정합니다. username은 주소에 쓰이는 계정 이름입니다. 표시 이름과 다를 수 있습니다.

인증 메일이나 코드는 본인이 메일함에서 확인합니다. 약관·필수 동의·인증·보안 설정은 내용을 읽고 본인이 결정하고 진행합니다. 비밀번호나 복구 코드를 강사에게 제출하거나 실습지에 적지 않습니다. 유료 구독이나 Copilot 결제는 이 실습에 필요하지 않습니다. 인증이 요구되면 화면 안내를 따르고, 이메일이 없으면 주소 오타·스팸함·재발송 여부를 확인합니다.

로그인 후 프로필 메뉴에서 본인 username을 확인합니다. 브라우저에 다른 사람 계정이 남아 있다면 계정을 바꾸기 전에 공용 PC 운영 지침을 확인합니다. 브라우저 로그인 완료를 Desktop 로그인 완료로 표시하지 않습니다.

## 5. GitHub Desktop 설치와 연결

1. [Desktop 공식 다운로드](https://desktop.github.com/)에서 Windows용 설치 파일을 받습니다. 이미 설치되어 있다면 앱을 엽니다.
2. 설치 프로그램을 실행해 앱이 열릴 때까지 기다립니다. 지원되지 않는 PC 환경 또는 기관 차단이면 메시지를 기록해 강사에게 알립니다.
3. Desktop의 `Sign in to GitHub.com`을 선택합니다. 브라우저가 열리는 것은 정상 연결 흐름입니다.
4. 브라우저 프로필이 본인 계정인지 다시 확인합니다. Desktop 연결을 허용하는 인증 화면의 대상과 내용을 읽고 본인이 진행합니다.
5. 앱을 열겠다는 브라우저 안내에서 GitHub Desktop으로 돌아갑니다. 인증이 끝나면 Desktop에서 본인 계정 연결을 확인합니다.
6. Windows 메뉴의 `File → Options → Accounts`에서 연결된 계정을 확인합니다. 창 구성에 따라 초기 안내와 설정 화면이 다를 수 있습니다.
7. Git 작성자 설정 화면이 나오면 이름·이메일을 검토합니다. 이메일 공개가 걱정되면 GitHub Settings의 Emails에서 본인에게 제공된 noreply 주소를 확인합니다. 다른 사람의 예시 주소를 그대로 복사하지 않습니다.

Desktop은 자체 Git 구성 요소를 이용하므로 Desktop이 켜진다는 사실과 별도로 설치한 명령줄 Git의 성공은 구별합니다. Desktop 로그인을 했다고 Git Bash의 모든 설정이 자동 검증되는 것도 아닙니다. Git 작성자 설정은 G04에서 현재 연습 저장소 기준으로 확인합니다.

## 6. 한 값 바꿔서 확인하기

Git Bash에서 다음을 입력합니다. 버전 옵션 대신 도움말 옵션으로 한 항목을 바꾸는 활동입니다. 명령을 이해하기 위한 선택 활동이며 설치 확인은 앞의 버전 출력으로 끝낼 수 있습니다.

```bash
# Git 명령의 기본 도움말을 표시합니다. --version과 달리 버전 한 줄 대신 사용 안내가 나옵니다.
git --help
```

예상: `usage: git`으로 시작하는 사용법과 대표 명령 목록이 나옵니다. PC의 도움말 설정에 따라 표시 방식이 다를 수 있습니다. 내용이 길다고 전부 외우지 않습니다. 옵션을 바꾸자 출력의 목적이 버전 확인에서 사용 안내로 바뀌었다고 설명하면 됩니다.

## 오류 해결

| 보인 것 | 확인 순서 |
|---|---|
| `git: command not found` | 철자 확인 → Git Bash인지 확인 → 창을 닫고 새로 열기 → 설치 완료 확인 |
| PowerShell에서 Git을 찾지 못함 | PowerShell 새로 열기 → Git Bash의 버전 확인과 구별 → PATH 설치 선택을 강사와 확인 |
| 버전은 나오는데 Desktop 로그인 실패 | Git 설치 성공은 유지하고 브라우저 계정·인증 흐름·네트워크를 별도로 확인 |
| 브라우저 인증 후 앱으로 안 돌아옴 | 앱 실행 허용 안내 확인 → Desktop 창 확인 → 공식 인증 안내와 대조 |
| 이메일 인증이 안 옴 | 본인 이메일 철자·스팸함·재발송 확인. 계정을 계속 새로 만들지 않기 |
| 다른 사람 계정이 표시됨 | 작업을 멈추고 강사와 공용 PC 계정 지침 확인 |

## 도착점과 확인 문제

개인 메모에 `Git 버전 확인 / 웹 계정 확인 / Desktop 계정 확인`을 각각 완료·막힘으로 적습니다. 비밀번호는 적지 않습니다. 설치 문제 때문에 늦었다면 실패 화면과 현재 단계를 알리고, G03에서는 강사의 화면으로 경로와 입력줄을 설명하는 활동에 먼저 합류합니다.

1. 버전 문장이 나오면 GitHub 인증도 끝났나요? **아니요.** Git 실행 확인만 끝났습니다.
2. 웹의 username과 PC 사용자 이름이 달라도 되나요? **됩니다.** 서로 다른 대상입니다.
3. 작성자 이메일은 로그인 비밀번호인가요? **아니요.** 커밋에 남는 작성 정보입니다.
4. Git Bash와 Desktop은 둘 다 설치가 성공했다고 한 항목으로 적어도 되나요? **각각 확인합니다.** 한쪽만 가능한 경우를 구별해야 합니다.
5. 가입·인증이 막혔을 때 유료 구독을 하면 해결되나요? **그렇게 판단하지 않습니다.** 현재 오류 단계부터 확인합니다.
