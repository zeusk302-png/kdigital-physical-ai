# Git/GitHub · 변경을 비교하고 기록하기

2026-10-16 · Git/GitHub

파일의 변경을 비교하고 Git으로 기록합니다. 로컬 저장소 실습과 제공된 GitHub 리뷰 사례로 협업 흐름을 익힙니다.

원본은 그대로 두고 work 폴더의 지정한 파일을 수정하세요. 계정 없이 사용할 수 있는 연습용 저장소로 진행합니다.

## 오늘의 연결

지금까지 만든 파일의 변경을 비교하고 이전 상태를 기록하는 방법을 배웁니다.

## 먼저 구별할 화면

- 파일 탐색기는 저장한 파일의 위치를 찾습니다.
- 텍스트 편집기는 코드와 데이터를 읽고 고칩니다.
- 터미널은 명령을 입력하고 실제 실행 결과를 확인합니다.
- 웹 교안은 설명·원문·출력 예를 제공합니다. Git 명령을 실행하는 터미널은 아닙니다.

## 참여 순서

1. 압축을 일반 폴더에 풀고 data·code·work의 위치를 유지합니다.
2. lesson의 개념을 읽고 activity-guide의 해당 활동 입력을 엽니다.
3. work의 답칸에 예상과 이유를 먼저 쓰고 지정한 값을 수정합니다.
4. 저장 후 정확한 work 파일을 실행하거나 강사 출력·제공 예와 수동 비교합니다.
5. 확인 방식을 기록합니다. 개인 실행을 하지 않았으면 실행 성공으로 적지 않습니다.

## 도구를 준비하지 못했을 때

설치 문제로 수업을 멈추지 말고 제공한 전체 코드·출력과 동일 입력을 사용해 줄별 값을 직접 추적합니다. 종이에도 같은 답칸을 작성합니다. 개인 실행은 강사가 환경을 준비한 뒤 확인합니다.

## 수업 전, 이 세 가지부터 확인하세요

앞선 수업을 기억하지 못해도 아래 질문과 풀이부터 다시 읽으면 됩니다. 먼저 자기 말로 답한 뒤 풀이와 비교하세요.

### 저장과 기록

질문: 파일을 저장하면 Git 이력도 자동으로 생기나요?

풀이: 저장은 작업 파일을 바꿉니다. 변경 확인, add, commit을 거쳐 기록을 남기는 절차는 별개입니다.

### 내 컴퓨터와 공유 위치

질문: 로컬 commit 후 다른 사람도 바로 그 내용을 받나요?

풀이: 원격 저장소에 보내는 과정은 별도입니다. 로컬 기록과 원격 반영을 구별해 확인합니다.

### 충돌

질문: 두 사람이 같은 줄을 바꾸면 최신 파일로 덮으면 될까요?

풀이: 두 변경의 의도를 비교해 결과를 결정하고 검증해야 합니다. 단순 덮어쓰기는 필요한 변경을 잃을 수 있습니다.
