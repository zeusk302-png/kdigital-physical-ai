## 구간별 확인 질문

1. 오류 줄 번호가 마지막 줄을 가리키면 그 줄만 보면 충분할까요?
2. 오류가 사라졌다는 것만으로 올바른 수정이라고 할 수 있나요?
3. 코드가 종료 코드 0으로 끝났다면 평균의 업무 의미도 보장되나요?
4. None에 직접 > 24.0을 적용하면 어떻게 될까요?
5. 한 번의 print인데 세 항목을 검사할 수 있는 이유는 무엇인가요?
6. 내일 파일에서 읽은 "24.0"을 그대로 이 코드에 넣으면 무엇이 추가로 필요할까요?

## 다른 사례로 연습하기

아래 여섯 문제는 추가 복습용입니다. 풀이를 보기 전에 답과 그렇게 생각한 이유를 적으세요. 프로그램 설치 여부와 별개로 내용을 이해했는지 확인하는 문제입니다.

### 문제 1 · 편집 화면·저장 파일·실행 결과의 세 상태

복습·도전: 편집기는 work/check.py에 ‘검사 B’를 보여 줍니다. 실행 명령은 code/check.py를 가리키고 출력은 ‘검사 A’입니다. 확인된 사실 세 가지와 다음 확인 동작 두 가지를 적으세요. 새 설치나 임의 파일 삭제는 필요하지 않습니다.

**정답·해설:** 편집한 파일과 실행한 파일의 위치가 다르며 화면에는 A가 나왔습니다. work 파일을 저장했는지 확인하고 같은 work 주소를 실행합니다. 파일이 다르다는 증거는 있지만 저장 여부는 아직 미확인입니다. ‘Python 고장’은 증거 없는 원인 단정입니다.

### 문제 2 · 재고 갱신을 한 줄씩 추적하기

복습·도전: 물 12병을 준비하고 4병을 배부한 뒤 현재 수량을 안내합니다. 다시 6병을 받아 최종 수량을 안내합니다. 두 안내값과 세 번의 대입 뒤 현재 수량을 표로 작성하고, 두 print를 어디에 놓을지 판단하세요.

**정답·해설:** 대입 뒤 현재 값은 12→8→14이고 안내값은 8과 14입니다. 배부 직후와 추가 입고 직후에 출력해야 합니다. 모든 대입 뒤에 같은 이름을 두 번 출력하면 14·14가 되어 중간 안내를 잃습니다.

### 문제 3 · 운송비 계산에서 문자열과 숫자 나누기

복습·도전: 판매표의 주문번호 “0009”, 단가 “1500”, 수량 “3”을 보고 총액과 각 항목의 저장 계획을 쓰세요. 단가는 원 단위의 정수이고, 수량은 개수로 정했습니다. 배송비 2000원을 포함한 최종액도 계산하세요.

**정답·해설:** 주문번호는 문자열 유지, 단가와 수량은 정수로 해석합니다. 상품 총액 1500×3=4500원, 최종액 6500원입니다. “1500”+“3”의 문자열 연결은 “15003”으로 금액 계산이 아닙니다. 주문번호를 정수 9로 바꾸면 앞 0을 잃습니다.

### 문제 4 · 이상과 초과를 업무 문장으로 읽기

복습·도전: 대여 정책은 ‘잔여 수량이 5개 이하이면 보충 요청’입니다. 4, 5, 6, 미확인 네 입력의 결과와 비교 기호를 정하세요. 미확인은 보충 확정 대신 확인 요청으로 처리합니다.

**정답·해설:** 기호는 <=이며 4와 5는 보충 요청, 6은 요청 없음, 미확인은 확인 요청입니다. <를 고르면 경계 5를 놓칩니다. 미확인을 0으로 채우면 수량을 실제 관찰한 것처럼 처리하는 오답입니다.

### 문제 5 · 목록의 위치와 반복 누적을 함께 추적하기

복습·도전: 주문별 수량 목록은 3, 0, 7, 2입니다. 총수량과 2개 초과 주문 수를 각각 손 추적표로 구하세요. 길이와 마지막 위치 번호, 빈 목록일 때 두 결과도 적으세요.

**정답·해설:** 총수량은 12개이고 초과 주문은 3과 7 두 건입니다. 길이 4, 마지막 번호 3입니다. 빈 목록은 초기 합계 0·건수 0을 유지합니다. 0을 오류라고 임의 삭제하거나 수량 합 12를 주문 건수로 쓰면 서로 다른 질문을 혼동한 것입니다.

### 문제 6 · 한 기록의 이름표를 지키며 상태표 만들기

복습·도전: 세 물품 P01 수량 0, P02 수량 미확인, P03 수량 2를 대상으로 ‘2개 이하이면 주문 요청’ 상태표를 새로 설계하세요. 물품번호와 수량의 이름표, 미확인 갈래를 먼저 정하고 세 줄을 작성하세요.

**정답·해설:** 이름표는 예를 들어 product_id와 quantity입니다. P01·P03은 주문 요청, P02는 수량 확인입니다. 0은 실제 수량이라 포함하고 None은 비교 전에 처리합니다. temperature_c 키를 그대로 쓰는 답은 새 업무의 항목 뜻을 맞추지 못한 것입니다.
