# 빠른 디자인 · 학생 선택 경로와 강사 시연

## 1. Claude로 스케치를 화면 후보로

1. Claude에 로그인하고 새 대화를 엽니다. 자신의 화면에서 디자인 출력 또는 Artifacts의 Design 경로를 사용할 수 있는지 확인합니다. 메뉴가 안 보이면 일반 대화에서 디자인 초안을 요청합니다. 계정·조직·사용량 조건은 달라질 수 있습니다.
2. 자신의 스케치 이미지와 `CLAUDE-DESIGN-HANDOFF.md`를 첨부합니다. 첫 요청은 화면 배치 두 안과 선택 이유입니다. 실측 자료를 아직 연결하지 않았다고 명시합니다.
3. ‘조명 판단을 먼저 하는 안’과 ‘환경 변화 관찰을 먼저 하는 안’을 비교합니다. 배경색만 다른 안은 다시 요청합니다. 핵심값·최근 변화·제어·연결 상태를 찾습니다.
4. 선택 후 ‘센서 실패와 USB 끊김, 명령 응답 대기 모습도 추가해 줘’라고 요청합니다. 글자·버튼 크기, 좁은 화면의 배치를 봅니다.
5. 실제 구현 때 기존 HTML/CSS/JS 세 파일을 줍니다. 로컬 파일을 수정할 수 있는 코드 에이전트라면 현재 폴더를 지정하고, 채팅만 쓴다면 반환된 파일을 원본 사본 옆에 저장해 비교합니다. 디자인 미리보기 안에서 내 USB가 자동 연결된다고 가정하지 않습니다.
6. 연습 모드에서 화면을 확인하고, 실제 연결은 공개/localhost 예제를 Chrome·Edge에서 열어 다시 확인합니다.

요청 예: ‘작업실 조명 화면을 만들고 싶어. 사용자와 상황은 첨부 문서에 있어. 밝기 원시값과 LED 상태 중심 / 온습도와 변화 중심 두 안을 비교해 줘. 값은 예시라고 써 줘. 구현할 때 기존 DOM id와 data-command, P01 통신을 유지해 줘.’

[Claude 공식 현재 시작 안내](https://support.claude.com/en/articles/14604416-get-started-with-claude-design), 확인일 2026-10-28. 실제 메뉴와 계정 조건은 수업 전 강사 계정에서 확인합니다. 학생 구매·가입은 필수가 아닙니다.

## 2. Figma MCP · 강사 사전 준비가 된 경우 소개

MCP는 에이전트가 Figma 파일의 디자인 정보를 도구로 읽고 쓰는 연결입니다. 디자인을 읽어 코드로 만드는 방향과, 코드를 캔버스로 가져오는 방향을 구별합니다. 이번 소개는 **내 프레임 → 기존 대시보드 코드**입니다.

1. 강사는 접근 가능한 Figma 파일에 작은 대시보드 프레임을 준비합니다. 카드 이름·단위·정상/실패 상태를 넣고 프레임 링크를 복사합니다.
2. 지원 클라이언트에서 Figma 공식 플러그인·MCP 연결과 계정 인증을 수업 전에 끝냅니다. Claude Code의 공식 권장 설치 예는 터미널에서 다음을 실행하는 것입니다. 이미 연결되어 있으면 다시 설치하지 않습니다.

```text
claude plugin install figma@claude-plugins-official
```

이 명령은 **설치된 Claude Code용**이며 일반 Claude 웹 채팅에 입력하는 명령이 아닙니다. Claude Code 재시작 후 `/plugin`의 Installed에서 Figma 연결·로그인을 확인합니다. 조직 정책이 설치를 막거나 계정·파일 권한·호출 한도가 다르면 수업 중 우회 설치하지 않고 스크린샷으로 설명합니다.

3. 요청: ‘이 프레임 링크의 디자인 정보를 읽고 현재 index.html/style.css에 반영해 줘. 기존 요소 id·data-command·dashboard.js 통신 계약은 유지해 줘. 글자·여백·카드 배치가 어떻게 달라졌는지 설명해 줘.’
4. 수정 전후와 정상·실패 화면을 확인합니다. 예쁜 화면 생성과 실제 장치 성공은 따로 확인합니다.

[Figma 공식 연결 안내](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/) · [권한·요금제별 한도](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/). 실제 계정에 대한 설치·인증·과금 작업은 이 자료 제작에서 수행하지 않았습니다.

## 도구가 없어도 같은 목표

제공 예제의 HTML 카드 순서, 제목, CSS 색·글자·여백을 수정합니다. 스케치와 두 화면 후보를 그림판·슬라이드로 비교해도 됩니다. 평가 대상은 도구 보유보다 사용자 목적·정보 의미·제어 피드백입니다.
