# 정보·단위·색·피드백의 원칙


## 사례에서 원칙으로

대시보드를 읽는 순서는 ‘지금 연결되었나 → 현재 상태가 어떤가 → 어떤 변화가 있었나 → 무엇을 조작할까 → 결과가 왔나’로 잡을 수 있습니다. 모든 작품의 정답 배치라는 뜻은 아닙니다. 사용할 사람의 질문을 기준으로 순서를 정합니다.

1. **정보의 우선순위**: 조명 작품이면 밝기·LED 상태를 앞에, 온도·습도를 보조 정보로 둡니다. 같은 크기의 카드 20개를 놓지 않습니다.
2. **이름과 단위**: `24.3 °C`, `습도 48 %`, `밝기 입력 320 / 1023`처럼 씁니다. CdS 원시값을 lux로 이름만 바꾸면 측정 의미가 달라집니다.
3. **현재와 이력**: 카드는 최근 정상 수신값, 그래프는 시간에 따른 기록입니다. 평균이 필요하면 장치·측정 종류·시간 범위를 먼저 정합니다. 서로 다른 단위의 값을 한 평균으로 섞지 않습니다.
4. **색과 글자**: 초록색 점만 놓지 말고 ‘정상 수신’, ‘연결 끊김’처럼 상태 이름도 씁니다. 경고색을 모든 버튼에 쓰면 중요한 이상이 묻힙니다.
5. **동작과 응답**: 버튼을 누른 순간 ‘성공’으로 바꾸지 않습니다. 전송 중 → 해당 요청번호의 보드 응답 → 보드 보고 상태를 구별합니다. 물리 LED 점등은 눈으로 따로 확인합니다.
6. **모름을 표시**: 센서 실패 `null`과 숫자 0은 다릅니다. 실패는 ‘— / 센서값 없음’, 연결 중단은 ‘마지막 정상 수신 14:22:10’처럼 보여 줍니다.

## 강사 시연 · 같은 값으로 두 화면 비교

[교재의 비교 그림](../kit/uno-dashboard/design-comparison.svg)을 봅니다. 왼쪽은 학습용 문제 화면, 오른쪽은 같은 상황을 읽기 쉽게 정리한 제작 예입니다. 외부 제품의 평가·공식 인증 결과가 아닙니다. 단위 누락, 값의 출처 누락, 의미 없는 색, 명령 응답 없는 성공 문구를 먼저 찾습니다.

## 직접 고쳐 보기

잘못된 문구 `밝기 320 lux / 온도 0 / LED 성공`을 고쳐 적습니다. 센서 실패·명령 미응답이라는 조건을 줍니다. 예상 답은 `밝기 원시값 320 / 온도 — 센서값 없음 / LED 적용 여부 미확인`입니다. 원칙 설명을 들은 뒤 자신의 답을 다시 읽고 이유를 한 문장 적습니다.

## 확인과 오류 복구

값이 작을수록 어둡다는 판단은 P01의 CdS 위치와 분압 배선에 따릅니다. 다른 배선에서는 반대일 수 있으므로 숫자만 외우지 않습니다. 글자가 작거나 그래프가 모호하면 센서를 늘리기 전에 이름·단위·시간 범위부터 고칩니다. 채팅에는 가장 큰 문제 하나와 고친 문구를 올립니다.
