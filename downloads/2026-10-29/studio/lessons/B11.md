# B11 팀 검수·Notion MCP·실행과 배포 범위


10/21의 Notion 팀 검수 방식을 그대로 사용하되 이번에는 실제 연동 경로를 기록합니다. 팀 문서에 입력 장치·실행 PC·서버 주소·장치 ID·측정 종류·필드·단위·새 기록 주기를 적습니다. localhost는 각자의 PC를 뜻하므로 다른 학생의 localhost를 내 브라우저에서 열어 같은 서버가 나올 것으로 생각하지 않습니다.

## 팀 검수 순서

수집기 실행자·서버 실행자·화면 검수자·기록자를 나누고 역할을 바꿉니다. 한 PC에서 전체 경로를 먼저 완성합니다. 여러 PC 연결은 네트워크·기관 정책·접근 통제 준비가 된 뒤 확장합니다. 기본 서버는 127.0.0.1에만 열어 둡니다.

## MCP 작업 지시

```text
Notion MCP로 우리 팀의 정확한 검수 문서 URL을 읽어.
그중 내 대시보드의 연결 상태 문제만 정리해.
원문·재현 단계·기대 결과를 유지하고 문서에 없는 문제를 만들지 마.
다음으로 frontend/src/main.jsx와 api.js를 읽어 수정 범위를 제안해.
서버 중단과 센서 수집 중단을 따로 시험할 방법을 적어.
지금은 문서나 코드를 바꾸지 마.
```

확인 뒤 코드를 고치고 API·단위시험·브라우저에서 각각 검증합니다. 팀원의 PC에서 README만 보고 실행하게 합니다. 키·원본 영상·실행 DB는 Git에 올리지 않고 requirements·잠금 파일·스키마·코드·실행 안내를 남깁니다.

## 배포 범위

정적 프런트만 GitHub Pages에 올리면 로컬 FastAPI와 DB가 생기지 않습니다. 공개 서버를 연결하려면 HTTPS·인증·CORS·운영 저장소가 필요하므로 이번 공통 경로는 로컬입니다. 공개 강의 홈페이지에서 교안과 ZIP을 제공하는 것과 학생 대시보드 서버 운영을 구분합니다. 로봇 원격 명령은 정지·명령 유효시간·연결 중단·실제 장치 응답을 갖춘 뒤 별도 확장합니다.
