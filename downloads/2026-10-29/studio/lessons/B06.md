# B06 · 실제 원천 연결과 사건 어댑터

원천의 필드 이름을 바꾸기 전에 그 값이 뜻하는 것을 확인합니다.

## 어댑터의 역할

YOLO가 내보내는 사건과 로봇이 내보내는 상태는 같은 형식이 아닐 수 있습니다. 어댑터는
이 둘의 의미를 API 계약으로 옮깁니다. 원천 코드를 무조건 고쳐 모든 이름을 맞추기보다
송신 경계에서 변환을 분리하면 기존 프로그램을 유지하기 쉽습니다.

## YOLO 연결

검출 프레임마다 박스 수를 반복해서 더하면 같은 객체를 새 사람으로 셉니다. 이 수업의
YOLO 로그는 프레임과 사건 목록을 구분하므로 실제 entered/crossed 같은 사건만 전달합니다.
관찰 시각과 영상 안의 재생 시각도 다릅니다. 장시간 과거 영상을 다시 보내면 그 시각을
보존할지 재생 시각으로 바꿀지 표시하고, 실제 지금 발생한 사건처럼 설명하지 않습니다.

## 로봇 연결

명령 발행과 실행 확인을 다른 kind로 구분할 수 있습니다. 모의 실행은 장치 ID나 설명에
모의임을 표시합니다. PC에서 HTTP 요청을 했다고 실제 모터가 움직였다고 기록하지 않습니다.
하드웨어 어댑터는 실제 로봇에서 검증한 인터페이스만 사용합니다.

## 직접 수행

한 사건을 원천 로그 → 어댑터 → API 응답 → DB → 표에서 찾습니다. event_id로 추적하고
입력 시각·장치·종류가 유지됐는지 대조합니다. 다음에는 자동으로 발생한 여러 사건을
연속 수집하고 전송 실패 후 재시도에서 중복이 쌓이지 않는지 봅니다.

## 전송 실패와 형식 오류

서버 중단은 같은 줄 재시도가 가능하지만 잘못된 형식은 고치기 전 계속 실패합니다.
전송기는 실패 줄을 조용히 건너뛰지 않습니다. 저장 기록을 먼저 보존하고 원인에 따라
송신·계약·검사 중 수정할 위치를 정합니다.

## 실제 파일과 연결해서 읽기

아래는 파일 앞부분입니다. 실행은 전체 파일로 합니다. 생략한 코드를 그대로 실행하지 마세요.

```python
"""실제 프로그램이 기록한 표준 사건 JSONL을 API로 전송합니다. 임의 가짜 자료를 만들지 않습니다."""
import argparse,json,time
from pathlib import Path
from urllib.request import Request,urlopen
from urllib.error import URLError,HTTPError

def send(url,event):
    request=Request(url,data=json.dumps(event,ensure_ascii=False).encode('utf-8'),
                    headers={'Content-Type':'application/json'},method='POST')
    with urlopen(request,timeout=5) as response:
        return json.loads(response.read())

def main():
    parser=argparse.ArgumentParser()
    parser.add_argument('path',type=Path,help='실제 수집한 표준 사건 JSONL')
    parser.add_argument('--url',default='http://127.0.0.1:8895/api/events')
    parser.add_argument('--follow',action='store_true',help='새 줄을 기다림. Ctrl+C로 종료')
    args=parser.parse_args()
    with args.path.open(encoding='utf-8') as stream:
        while True:
            position=stream.tell();line=stream.readline()
            if not line:
                if not args.follow:break
                time.sleep(.25);continue
            if not line.endswith('\n') and args.follow:
                stream.seek(position);time.sleep(.25);continue
            try:
                event=json.loads(line);result=send(args.url,event)
                print('수신 확인',result,flush=True)
            except HTTPError as error:
                if 400 <= error.code < 500:
                    raise SystemExit('요청 형식을 고친 뒤 같은 사건 ID로 다시 보내세요: '+error.read().decode('utf-8'))
                stream.seek(position);time.sleep(2)
            except (URLError,OSError) as error:
                # 실패 줄을 건너뛰지 않고 같은 위치부터 재시도합니다.
                print('전송 실패, 같은 줄 재시도:',error,flush=True)
                stream.seek(position);time.sleep(2)
            except (ValueError,TypeError) as error:
```

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
