# B07 · 장애 주입·복구·자동 시험

정상 요청만 통과하는 화면이 아니라 중단을 알아차리는 화면을 만듭니다.

## 시험의 세 층

함수 시험은 입력과 계산을, API 시험은 요청·DB·응답을, 브라우저 시험은 표시와 사용자
조작을 확인합니다. 하나를 통과했다고 나머지까지 성공했다고 말하지 않습니다. kit의
test_api.py는 임시 DB를 만들므로 실제 수업 자료를 지우지 않습니다.

## 실행하고 예상과 비교

README의 unittest 명령을 실행하고 시험 이름과 조건을 읽습니다. 정상 수신, 숫자0,
null, 같은 사건 재전송, ID 충돌, 잘못된 형식, 과거 사건의 늦은 도착, 재시작 복원을
확인합니다. 시험을 일부러 실패하게 할 때는 자기 복사본에서 한 조건만 제거하고
어떤 시험이 잡는지 확인한 뒤 복구합니다.

## 실제 장애 주입

첫째 송신기만 멈춥니다. 서버 조회는 성공하지만 새 기록이 없다는 상태여야 합니다.
둘째 서버를 멈춥니다. 화면은 조회 실패를 알리고 마지막 성공 기록을 남깁니다.
셋째 재실행합니다. 연결이 복구되고 DB 기록이 유지돼야 합니다. 넷째 오래된 기록을
늦게 보냅니다. 최신값이 과거로 돌아가지 않는지 봅니다.

## 직접 추가할 시험

같은 장치에 서로 다른 종류를 보낸 뒤 지표가 섞이지 않는지 시험을 추가합니다. 빈
결과·긴 장치 이름·범위 전환·느린 응답도 브라우저에서 확인합니다. 결과에는 입력,
기대, 실제, 실행 명령 또는 화면을 남깁니다.

## 완료 설명

정상·실패·미실행을 나누고 운영 전 남은 조건을 한 문장으로 적습니다. 실제 장치가
없을 때 제공 영상 재생으로 확인한 부분을 실물 연결 성공으로 바꾸어 적지 않습니다.

## 실제 파일과 연결해서 읽기

[전체 파일 받기](../kit/backend/test_api.py)

아래는 파일 앞부분입니다. 실행은 전체 파일로 합니다. 생략한 코드를 그대로 실행하지 마세요.

```python
"""실제 강의 DB 대신 임시 폴더에서 API와 DB 계약을 시험합니다."""
import tempfile,unittest
from pathlib import Path
from datetime import datetime,timezone,timedelta
from fastapi.testclient import TestClient
from app.main import create_app

class ApiTests(unittest.TestCase):
    def setUp(self):
        self.tmp=tempfile.TemporaryDirectory();self.addCleanup(self.tmp.cleanup)
        self.db=Path(self.tmp.name)/"events.sqlite3"
        self.client=TestClient(create_app(self.db))
        self.event={"event_id":"one","device_id":"robot-a","kind":"speed",
                    "value":0,"occurred_at":datetime.now(timezone.utc).isoformat(),"level":"info"}

    def test_empty(self):
        body=self.client.get('/api/events').json()
        self.assertEqual(body['count'],0);self.assertIsNone(body['average'])

    def test_zero_and_persistence(self):
        self.assertEqual(self.client.post('/api/events',json=self.event).status_code,201)
        other=TestClient(create_app(self.db))
        body=other.get('/api/events').json()
        self.assertEqual(body['count'],1);self.assertEqual(body['average'],0)

    def test_duplicate_and_conflict(self):
        self.client.post('/api/events',json=self.event)
        self.assertFalse(self.client.post('/api/events',json=self.event).json()['created'])
        self.assertEqual(self.client.post('/api/events',json={**self.event,'value':4}).status_code,409)
        self.assertEqual(self.client.get('/api/events').json()['count'],1)

    def test_invalid(self):
        for change in [{'value':True},{'value':'3'},{'device_id':' '},
                       {'occurred_at':'2026-01-01T00:00:00'}, {'extra':'bad'}]:
            self.assertEqual(self.client.post('/api/events',json={**self.event,**change}).status_code,422)

    def test_null_not_zero(self):
        self.client.post('/api/events',json={**self.event,'value':None})
```

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
