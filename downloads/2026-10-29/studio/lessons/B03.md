# B03 · SQLite 저장·중복·시간 범위

서버를 다시 실행해도 기록이 남도록 저장과 조회의 책임을 나눕니다.

## 테이블과 키

SQLite는 이 실습에서 파일 한 개로 사용할 수 있는 관계형 DB입니다. events 테이블의
각 행은 한 사건입니다. event_id는 기본 키로 같은 사건이 두 번 저장되는 것을 막습니다.
목록에 append만 하는 메모리 저장은 서버 종료 후 사라집니다. 저장 코드가 있다는
설명만 믿지 말고 실제 파일과 재시작 조회로 확인합니다.

## 같은 ID가 두 번 왔을 때

같은 내용이면 재전송으로 보고 created:false를 반환합니다. 같은 ID인데 값이 다르면
409 충돌입니다. 다른 사건에 같은 ID를 계속 사용하면 새 자료를 잃으므로 송신기에서
새 사건과 재시도를 구분합니다. INSERT를 무조건 REPLACE로 바꾸면 원본을 덮어쓸 수
있으므로 요구사항을 확인해야 합니다.

## 직접 따라 하기

서버를 실행하고 실제 기록을 넣은 뒤 종료합니다. runtime/events.sqlite3를 지우지 않고
재실행해 이전 사건을 조회합니다. 다른 시각의 기록을 보내고 최신값이 도착 순서가 아닌
occurred_at로 결정되는지 봅니다. 잘못된 과거 자료를 최신값으로 선택하는 오류를
tests에서 재현하고 고칩니다.

## 코드의 의미

SQL의 ?는 전달할 값의 자리입니다. 사용자 입력을 SQL 문자열에 직접 붙이지 않습니다.
with는 처리 성공 때 commit·실패 때 rollback을 도우며, 연결 자체의 close도 별도로
보장해야 합니다. 제공 Store는 contextmanager에서 이 둘을 분리해 파일 잠금을 막습니다.

## 직접 작성할 기능

장치와 시간 범위 조회를 읽고 사건 종류 필터를 서버에 추가해 보세요. 조회 조건·화면
요청·자동 시험을 같이 바꿉니다. 운영 DB를 Git에 올리는 대신 테이블 생성 코드와
비식별 시험 자료, 재현 방법을 올립니다.

## 실제 파일과 연결해서 읽기

[전체 파일 받기](../kit/backend/app/store.py)

아래는 파일 앞부분입니다. 실행은 전체 파일로 합니다. 생략한 코드를 그대로 실행하지 마세요.

```python
"""SQLite 저장·중복·시간 조회. SQL 값은 문자열 붙이기가 아닌 ?로 전달합니다."""
import sqlite3
from pathlib import Path
from contextlib import contextmanager

class Store:
    def __init__(self,path):
        self.path=Path(path)
        self.path.parent.mkdir(parents=True,exist_ok=True)
        with self.connect() as db:
            db.execute("""CREATE TABLE IF NOT EXISTS events(
                event_id TEXT PRIMARY KEY, device_id TEXT NOT NULL,
                kind TEXT NOT NULL, value REAL, occurred_at REAL NOT NULL,
                received_at REAL NOT NULL, level TEXT NOT NULL)""")
            db.execute("CREATE INDEX IF NOT EXISTS event_time ON events(occurred_at)")

    @contextmanager
    def connect(self):
        db=sqlite3.connect(self.path)
        db.row_factory=sqlite3.Row
        try:
            with db:
                yield db
        finally:
            db.close()

    def append(self,event,received_at):
        values=(event.event_id,event.device_id,event.kind,event.value,
                event.occurred_at.timestamp(),received_at,event.level)
        with self.connect() as db:
            old=db.execute("SELECT * FROM events WHERE event_id=?",(event.event_id,)).fetchone()
            if old:
                # 같은 ID·다른 내용은 충돌입니다. 재전송과 구분합니다.
                if tuple(old)[0:5]+tuple(old)[6:] != values[0:5]+values[6:]:
                    raise ValueError("같은 event_id의 내용이 다릅니다.")
                return False
            db.execute("INSERT INTO events VALUES(?,?,?,?,?,?,?)",values)
        return True
```

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
