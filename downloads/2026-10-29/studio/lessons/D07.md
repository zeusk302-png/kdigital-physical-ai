# 값과 명령을 읽고 화면을 고치기

## 화면 안의 자료 이해

보드의 한 줄 `{"v":1,"type":"state","profile":"P01","request":0,"ms":5000,"pot_raw":512,"light_raw":320,"button_pressed":false,"led":0,"auto":false,"lcd_ready":true,"temperature_c":24.3,"humidity_pct":48}`는 JSON입니다. 중괄호는 한 묶음, 따옴표 안 이름은 항목 이름, 콜론 뒤는 값, 쉼표는 항목 구분입니다. `true/false`는 상태이고 `null`은 값을 얻지 못했음을 나타냅니다. 문자열 `"null"`이나 숫자 0과 다릅니다.

`1 LED 1`은 요청번호 1로 LED 켜기를 요청한 것입니다. 첫 1은 통신 식별자이고 마지막 1은 켜짐 값입니다. 보드가 같은 request의 ACK를 보내면 프로그램 적용 응답으로 보여줍니다. 버튼을 눌렀다는 사실만으로 성공하지 않습니다. 응답이 없으면 적용 여부 미확인이고 자동 재전송하지 않습니다.

## 짧은 완성 예 · 왜 null을 따로 처리하나

이 코드는 브라우저 동작을 설명하는 작은 예이며 USB 전체 코드는 제공 파일을 사용합니다.

```javascript
const temperature = null;
const text = temperature === null ? '센서값 없음' : temperature + ' °C';
console.log(text);
```

`const`는 이름을 붙여 값을 보관하고, `=`는 값을 넣습니다. `===`는 같은지 비교합니다. `?` 앞이 참이면 첫 문구, 아니면 `:` 뒤 문구를 고릅니다. `+`는 값 뒤에 단위 글자를 붙입니다. `console.log`는 확인 문구를 콘솔에 출력합니다. 개발자 도구 Console에 세 줄을 함께 입력하면 ‘센서값 없음’이 나옵니다. 첫 줄을 `const temperature = 24.3;`으로 바꿀 때는 새 콘솔 실행 범위에서 실행하거나 페이지를 새로고침해 같은 이름 재선언 오류를 피합니다. 예상 문구는 ‘24.3 °C’입니다.

## 개인 수정

ZIP의 HTML 제목을 자기 작품명으로 바꾸고 저장 후 새로고침합니다. CSS의 강조색을 하나 바꿉니다. 그런 다음 가장 중요한 카드가 먼저 오게 HTML의 article 순서를 바꿉니다. id가 중복되거나 빠지면 값 연결이 끊기므로 각 id는 하나씩 유지합니다. `dashboard.js`의 프로토콜은 변경하지 않습니다.

## 확인

수정 전후 값의 의미가 같은지, 색 외의 상태 문구가 남는지, LED 명령의 응답 표시가 작동하는지 확인합니다. 제목만 바꾼 결과와 사용자 목적에 맞게 정보 순서·기능을 바꾼 결과는 구별해서 기록합니다. 값이 사라지면 먼저 파일 저장·새로고침·id·스크립트 경로를 점검합니다.

## 짧은 코드로 화면 연결의 원리 확인

[짧은 화면 예제](../kit/uno-dashboard/mini-display.html)는 USB 없이 HTML 글자와 JavaScript 값의 관계를 보는 독립 예제입니다. 열면 ‘밝기 입력:320/1023’, 버튼을 누르면 ‘센서값 없음’으로 바뀝니다. 같은 폴더의 [줄별 설명](../kit/uno-dashboard/CODE-WALKTHROUGH.md)을 함께 봅니다.

이 예제의 목적은 ‘값을 읽어 특정 자리에 표시한다’를 이해하는 것입니다. 실제 연결 예제 dashboard.js 전체를 처음부터 작성할 필요는 없습니다. 복사한 코드에서 어떤 파일이 글·꾸밈·동작을 맡는지와, 바꾼 값이 어떤 결과를 만드는지 설명합니다.

### 직접 수행 세 가지

1. 원본을 사본으로 보관하고 처음 값320을600으로 바꿉니다. 예상 숫자를 적고 저장·새로고침합니다.
2. HTML 표시 이름을 ‘밝기 입력’에서 ‘CdS 원시값’으로 바꿉니다. 숫자의 단위나 센서 성능은 바뀌지 않았음을 설명합니다.
3. 버튼을 눌러 값이 없을 때0과 어떻게 다른지 설명합니다. `null`을 문자열 `'null'`로 바꾸면 동일한 비교가 아니라는 점을 줄별 설명과 확인합니다.

예제가 안 바뀌면 저장했는지, 올바른 파일을 열었는지, 확장자가.html인지, 요소 id와 getElementById 안 글자가 같은지 순서대로 확인합니다.
