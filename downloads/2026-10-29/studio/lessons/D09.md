# 자기 점검·고장 상황·복구

## 목적과 준비

자신의 작품을 사용자의 입장에서 점검합니다. 짝 검수 대신 자기 점검표를 사용하고 강사는 필요한 화면을 함께 봅니다. 배선 변경은 전원을 끈 뒤 합니다. 센서 실패를 만들기 위해 통전 중 선을 무작정 뽑지 않습니다. 제공 연습 모드는 12회마다 온습도를 null로 만들므로 화면 처리 확인에 쓸 수 있습니다.

## 확인 시나리오

| 상황 | 예상 표시·행동 | 증거 |
| --- | --- | --- |
| 시작 전 | —, 입력 없음, 제어 비활성 | 초기 화면 |
| P01 정상 수신 | 수신 중, 최근 시각, 올바른 이름·단위 | USB 화면과 입력 변화 |
| 가변저항·CdS 변화 | 입력 변화가 카드·그래프에 반영 | 동작 전후 또는 짧은 영상 |
| LED 켜기·끄기 | 전송 중→같은 요청 응답→보고 상태, 실제 LED 별도 확인 | 통신 기록+물리 관찰 |
| 자동 모드 | 아래 경계 켜짐, 위 경계 꺼짐, 중간 이전 상태 | 관측 raw·기준·출력표 |
| 온습도 null | 0 대신 — / 값 없음 | 연습 모드 실패 화면, 모드 표기 |
| USB 수신 종료·4초 미수신 | 현재값 숨김·오래됨, 과거 그래프·수신 시각 남김 | 중단 화면 |
| 명령 응답 없음 | 적용 여부 미확인, 자동 재전송 없음 | 재현 시 기록, 못 했으면 미확인 |
| 키보드·좁은 화면 | Tab 이동 표시, 버튼 조작, 글자 겹침 없음 | 확인 메모 |

USB를 뽑으면 보드 전원이 끊길 수 있습니다. 별도 전원이 있는 보드의 연결 해제는 STOP과 같지 않습니다. 이번 P01은 통신 종료 자동 정지를 보장하지 않으므로 연결된 동안 STOP과 실제 출력을 먼저 확인합니다. 고장 상황 재현을 위해 외부전원을 새로 연결하지 않습니다.

## 기록의 예

`실제 USB / CdS 가림 / raw 280 < 켜짐350 / LED 켜짐 관찰 / 정상`처럼 씁니다. 연습 모드 확인은 `연습 / null / 온도 — / 화면 처리 정상, 실제 DHT 고장 시험 아님`이라고 적습니다. ACK가 왔어도 LED를 보지 못했다면 ‘보드 적용 응답 있음, 실제 출력 미확인’입니다.

## 풀이와 복구

작동하지 않은 항목은 원인 후보와 다음 확인을 적습니다. 포트가 잠겼으면 시리얼 모니터·다른 탭을 닫고, 카드만 안 바뀌면 DOM id·단위 매핑을 확인합니다. 시계열이 사라졌다면 새로고침으로 메모리 기록이 초기화된 것인지 먼저 봅니다. 이력 영구 저장을 구현하지 않았다면 DB에 남는다고 설명하지 않습니다.

## 예측·실제·확인 경로를 남기는 빈 표

[자기 확인표 MD](../kit/uno-dashboard/SELF-CHECK.md)를 내려받거나 [개인 작성지](../kit/uno-dashboard/workbook.html)의 결과 칸을 사용합니다. 기능별로 `예측 / 실제 / 연습 또는 USB / 못 한 것`을 적습니다. 확인하지 않은 칸을 자동으로 정상으로 채우지 않습니다.

### 자동 경계의 새 입력 문제

켜짐 기준350, 꺼짐 기준450이고 시작 LED는꺼짐입니다. 입력이300→400→500이면 각 단계 LED는 어떻게 될까요? 다음으로 시작 LED가켜짐일 때 입력400은 어떨까요? 단일 기준 하나만 쓰는 방식과 두 경계 방식의 차이를 말해 봅니다. 제공 P01은 `raw<켜짐`과 `raw>꺼짐`에서만 상태를 바꾸므로 정확히350·450일 때는 이전 상태를 유지합니다.

### 실패 처리 문제

온습도만null인데 밝기는정상입니다. 화면 전체를 ‘USB 연결 끊김’으로 표시하면 어떤 정보가 사라질까요? 반대로 수신이 오래 멈췄는데 온도24.3을 계속 현재값으로 보여주면 무슨 문제가 있을까요? 실패한 센서와 연결 전체의 상태를 나누어 설명합니다.

장비가 준비되지 않았다면 같은 문제를 디자인 비교실의 상태 전환으로 확인할 수 있습니다. 그 결과는 화면·설계 확인이며 실제 센서 고장·USB·LED 확인과 구별합니다.
