# B02 · API 요청·검사·실제 프로그램 연결

송신 성공 문구보다 서버가 받은 값과 응답을 확인합니다.

## 요청과 응답

브라우저·YOLO·로봇은 서로 다른 프로그램입니다. HTTP 요청은 어느 주소의 기능을
사용할지와 보낼 내용을 정합니다. 이 실습의 POST /api/events는 사건을 받으며 GET은
선택한 범위를 읽습니다. JSON은 전달 형식입니다. 작은 자료를 손으로 채우는 것이
목표가 아니라 실제 발생한 사건이 이 약속을 따라 전달되는지 확인합니다.

## 실행 위치

kit에서 README의 가상환경 명령을 수행하고 uvicorn을 실행합니다. 이 터미널은 서버가
돌아가는 동안 유지합니다. 브라우저에서 http://127.0.0.1:8895/docs를 열면 요청 형식과
응답을 시험할 수 있습니다. Python 패키지 설치 실패와 서버 실행 오류를 구분합니다.
PC의127.0.0.1은 그 PC 자신이며 로봇에서 쓰는 같은 주소는 로봇 자신입니다. 다른 장치
연결은 네트워크와 서버 접근 주소를 확인한 뒤 별도 설정합니다.

## 먼저 예측할 입력

event_id는 사건을 구분하고 재전송 때 유지합니다. device_id는 장치, kind는 사건 종류,
occurred_at는 발생 시각, level은 info/warning입니다. value가 없으면 null이고 실제0은
숫자0입니다. 문자열"0"이나 True를 측정 숫자로 받지 않습니다.

## 직접 구현

docs/api.md를 보고 자기 원천의 필드가 계약 어디에 대응하는지 표로 적습니다. 없는
측정값을 새로 만들어 채우지 않습니다. 새 필드가 꼭 필요하면 화면·모델·DB·시험에서
함께 바뀔 부분을 먼저 정합니다. 불필요한 필드는 보내지 않고 잘못된 요청의422 응답을
확인하세요. 요청이 실패했는데 송신기만 성공으로 기록하지 않도록 처리합니다.

## 복구

연결 거절은 서버·주소·포트부터,422는 본문과 자료형부터 확인합니다. 모든 오류를
네트워크 문제라고 생각하고 서버만 다시 실행하지 않습니다.

## 실제 파일과 연결해서 읽기

[전체 파일 받기](../kit/backend/app/models.py)

아래는 파일 앞부분입니다. 실행은 전체 파일로 합니다. 생략한 코드를 그대로 실행하지 마세요.

```python
"""네트워크에서 받을 한 사건의 형식입니다. 값 누락과 0을 구분합니다."""
from datetime import datetime, timezone, timedelta
from typing import Literal
from pydantic import BaseModel, ConfigDict, Field, field_validator

class Event(BaseModel):
    # 알 수 없는 필드를 조용히 버리지 않고 잘못된 요청으로 안내합니다.
    model_config = ConfigDict(extra="forbid")
    event_id: str = Field(min_length=1,max_length=120)
    device_id: str = Field(min_length=1,max_length=80)
    kind: str = Field(min_length=1,max_length=80)
    value: float | None = None
    occurred_at: datetime
    level: Literal["info", "warning"] = "info"

    @field_validator("event_id", "device_id", "kind")
    @classmethod
    def nonblank(cls, value):
        value=value.strip()
        if not value:
            raise ValueError("빈 식별자는 사용할 수 없습니다.")
        return value

    @field_validator("value", mode="before")
    @classmethod
    def numeric(cls,value):
        # bool은 숫자처럼 보일 수 있으나 측정값 True를 허용하지 않습니다.
        import math
        if value is not None and (type(value) not in (int,float) or not math.isfinite(value)):
            raise ValueError("측정값은 유한한 숫자 또는 null이어야 합니다.")
        return value

    @field_validator("occurred_at")
    @classmethod
    def with_timezone(cls,value):
        if value.tzinfo is None:
            raise ValueError("시각에는 시간대가 필요합니다.")
```

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
