# 좋은 대시보드는 어떤 판단을 돕나


## 목적과 준비

대시보드는 여러 값을 한 화면에 모아 **상태를 판단하고 필요한 행동을 선택하게 하는 화면**입니다. 수치를 예쁘게 모으는 것만으로 목적이 완성되지는 않습니다. 오늘은 각자의 키트를 연결해 개인 작품을 만듭니다. 짝·팀 검수는 하지 않습니다. 사례는 강사가 화면 공유하고 학생은 채팅과 개인 메모로 참여합니다.

## 사례 1 · Grafana Play

[Grafana 공식 체험 화면](https://play.grafana.org/)을 열고 Dashboards에서 예제를 하나 선택합니다. 설치하지 않고 사례를 읽는 시간입니다. 강사는 수업 전에 열리는 예제를 하나 정해 즐겨찾기해 둡니다. 실시간 체험 내용은 바뀔 수 있으므로 페이지 제목·관찰 시각을 기록합니다. [공식 대시보드 구성 안내](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/)도 함께 봅니다.

강사 질문: ‘이 화면을 보는 사람은 누구일까요? 지금 숫자와 지난 1시간 그래프는 어떤 다른 질문에 답할까요?’ 학습자는 **현재값·시간 범위·단위·변화·이상 표시** 중 실제 화면에서 찾은 항목을 적습니다. 기능이 없는 화면에 기능이 있다고 추정하지 않습니다. 서버 지표를 우리 온도·밝기 값으로 바꿔 생각해 봅니다.

## 사례 2 · Home Assistant

[Home Assistant 공식 대시보드 소개](https://www.home-assistant.io/dashboards/)의 실제 화면·편집 예시를 봅니다. 조명 상태를 보고 같은 화면에서 제어하는 구성이 오늘 과제에 가깝습니다. 강사가 상태 표시와 조작 영역을 짚고, 학생은 ‘전등을 켜려면 어디를 누르는가? 켜졌다는 것을 무엇으로 아는가?’를 설명합니다. 이 수업에서 Home Assistant를 설치하거나 모든 예시 장비를 구매하지 않습니다.

## 직접 수행

노트에 ‘사례 / 사용자 / 가장 먼저 알아야 할 정보 / 가능한 행동 / 내 작품에 가져올 원칙’ 다섯 칸을 만듭니다. 두 사례 각각 한 줄을 작성합니다. 채팅에는 `사례 이름: 내가 가져올 원칙 한 가지`만 보냅니다. 강사는 공통 답 두 개와 다른 답 하나를 골라 왜 도움이 되는지 설명합니다.

## 완성 예와 확인

`조명 화면 / 혼자 공부하는 나 / 어두움과 LED 상태 / 켜기·끄기 / 제어 뒤 상태를 다시 보여주기`처럼 씁니다. 화면 전체를 복제하기보다 판단 흐름을 가져옵니다. 사례가 열리지 않으면 다음 단원의 교재 자체 비교 그림을 사용합니다. 로그인·사이트 장애를 학습 성취와 구별합니다.

## 사례를 읽는 네 가지 질문 · 메모를 남기며 보기

사례 화면을 연 뒤 ① 사용자가 해야 할 일 ② 첫 시선이 가는 정보 ③ 시간·단위 ④ 조작 후 바뀌는 상태를 차례로 찾습니다. 실제 화면에 없는 장치나 기능은 써 넣지 않습니다. 이미 잘 만들어진 화면이라도 사용자가 달라지면 좋은 배치가 달라질 수 있습니다.

| 볼 곳 | Grafana에서 찾을 것 | Home Assistant에서 찾을 것 | 내 P01 작품으로 옮기면 |
| --- | --- | --- | --- |
| 첫 정보 | 어느 패널·숫자가 먼저 눈에 들어오는가 | 어느 방·장치 상태가 먼저 보이는가 | 조명 작품이면 밝기와 LED 상태 |
| 시간 | 표시 기간·마지막 값·변화의 범위 | 지금 상태와 이력을 구별하는가 | 현재 카드와 최근 60개 그래프 |
| 의미 | 숫자 옆 단위·이름·축 | 조명 이름과 현재 상태 | raw와 °C, %를 분리 |
| 행동 | 기간·필터 등 실제 가능한 조작 | 상태 확인 뒤 가능한 장치 조작 | LED 켜기·끄기와 응답 |

### 강사 시연 → 개인 읽기

강사가 첫 패널 하나를 읽는 모습을 보여 준 뒤, 학생은 다른 패널·카드 하나를 골라 같은 질문에 답합니다. 관찰한 정보와 자신의 해석을 나눠 씁니다. 예를 들어 ‘그래프 옆에 1h라고 보였다’는 관찰이고, ‘최근 한 시간 변화를 판단하게 하려는 것 같다’는 해석입니다.

### 예상과 비교

화면을 보기 전 ‘조명 작품이면 켜기 버튼이 제일 중요하다’고 예상했더라도, 실제 사례에서 장치 연결 여부가 먼저 보여야 한다고 느낄 수 있습니다. 예상·실제·바뀐 생각을 한 줄씩 적습니다. ‘예뻐서’ 대신 ‘어떤 판단이 쉬워졌기 때문인지’를 씁니다.

### 질문이 막힐 때

사용자를 ‘모든 사람’으로 두면 필요한 정보가 정해지지 않습니다. ‘집에서 책상에 앉은 나’나 ‘작업실을 점검하는 담당자’처럼 한 상황으로 좁혀 봅니다. 공식 사례가 열리지 않으면 [교재 디자인 A/B 비교실](../kit/uno-dashboard/design-studio.html)에서 같은 질문을 적용합니다.
