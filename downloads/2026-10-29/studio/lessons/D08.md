# 개인 제작 · 내 목적의 화면 완성

## 목적과 필수 범위

공통 연결을 바탕으로 스케치에서 정한 자기 작품을 만듭니다. 제작이 끝나면 자기 점검·화면 공유·제출로 이어집니다. 완전 자유 주제여도 핵심은 **실제 입력 두 종류 이상 표시, 목적에 맞는 정보 배치, 출력 제어 하나, 상태·오류 표시**입니다. 실제 연결이 막힌 경우 연습 모드로 같은 화면 동작을 만들고 증거 범위를 구별합니다.

## 제작 흐름과 매 구간 결과

| 단계 | 직접 할 일 | 남길 결과 |
| --- | --- | --- |
| 1단계 | 스케치와 파일 보존, 사용자·핵심 동작 다시 정하기 | 작품명·완료 목표·원본 사본 |
| 2단계 | 제목·정보 순서·색·글자·간격·반응형 배치 수정 | 초안 화면, 정상값 표시 |
| 3단계 | 입력 변화·LED 수동 제어·명령 피드백 확인 | 첫 왕복 확인, 미완료 오류 한 가지 |
| 4단계 | 두 경계 자동 모드 또는 목적에 맞는 설명 기능 추가 | 조건·예상·실제 비교표 |
| 5단계 | null·연결 중단·좁은 화면·키보드 점검 | 고친 오류와 전후 화면 |
| 6단계 | 실행 순서·제한·코드 정리 | 개인 README, 제출 ZIP 초안 |

중간 점검에서는 채팅으로 `완료한 기능 / 지금 막힌 한 가지 / 다음 할 일`을 받습니다. 학생마다 짝을 배정하지 않습니다. 화면 공유는 도움이 필요한 학생·희망자 중심으로 하고, 다른 학생은 자기 작업을 계속합니다.

## 선택 확장과 범위

가장 먼저 사용자 판단을 돕는 문구, 표시 단위, 기준 변경, 변화 설명을 완성합니다. 추가 도전으로 그래프 표시 구간 선택이나 CSV 내보내기를 만들 수 있습니다. 아직 없는 기능이므로 AI에게 구현·검증을 함께 요청합니다. P02 RGB·P03 키패드 확장은 배선 프로파일과 파서를 별도로 바꾸는 도전입니다. 기본 P01 예제를 그대로 사용하면 자동 지원되지 않습니다. P04 모터는 외부전원 없이 구동하지 않습니다.

## AI 사용과 확인

한 번에 ‘전부 만들어 줘’보다 스케치·필드·기존 파일·완료 조건을 줍니다. 디자인 수정과 통신 수정은 변경 범위를 적어 요청합니다. 받은 코드의 실제 실행 위치와 바꾼 파일을 기록하고, 연습 데이터인지 USB인지 화면에 표시합니다. 그럴듯한 랜덤 숫자만 나오는 작품은 실제 연결 작품과 구별합니다.

## 중간 합류와 오류 복구

공통 연결이 늦은 학생은 새 폴더에 원본 예제를 다시 풀어 연습 모드부터 합류합니다. 포트 오류가 계속되면 화면 제작을 먼저 계속하고 강사가 개별 확인합니다. 핵심 동작이 완성되면 기능 수를 늘리기 전에 실패 상태를 점검합니다.

## 개인 제작 과제 A/B/C · 하나를 고르거나 변형

### A · 집중 공간 조명

목적: 공부하는 사람이 조명이 필요한지 판단하고 LED로 동작을 표현합니다. 필수: 밝기·LED가 앞에 보임, 온습도 또는 가변저항 보조값, 수동 제어, 두 경계 자동 모드, 연결·명령 상태. 완료 예: 밝기를 가렸을 때 raw280<350로 LED켜짐, 다시 밝아져 raw600>450으로 꺼짐을 기록. 실제 경계를 넘지 않으면 자신의 관측값으로 기준을 조정합니다.

### B · 작업실 환경 관찰

목적: 작업실의 현재값과 변화를 확인합니다. 필수: 온도·습도·밝기의 단위 구별, 현재 카드와 밝기 이력 분리, 마지막 정상 수신, LED 수동 확인, null 표시. 도전: 화면에 사용하는 기록이 최근60개임을 명확히 설명하거나 사용자가 남기는 관찰 메모 추가. 장기 DB 저장이나 안전 판정을 구현하지 않았다면 있다고 설명하지 않습니다.

### C · 센서 입력 실험판

목적: 손으로 바꾼 입력과 화면 변화를 비교합니다. 필수: 가변저항·CdS 원시값, 바꾸기 전 예상/후 실제 메모, LED 수동 제어, 버튼 현재 상태·연결 상태. 도전: 입력 두 값을 같은 단위라고 평균내지 않고 각각의 변화 범위를 설명하는 안내 추가. 버튼은1초 현재 상태이므로 누적 횟수처럼 만들지 않습니다.

### 필요한 AI 요청 범위

제목만 바꾸는 데서 끝내지 않고 첫 정보·조작 순서·실패 안내 중 적어도 두 가지를 자기 목적에 맞게 바꿉니다. ‘A안 스타일을 기존 파일에 적용하되 통신은 유지’처럼 파일과 범위를 지정합니다. 필수 완료 후에만 새로운 데이터 내보내기나 어댑터를 추가합니다.

### 진행 메모

[진행·실행 확인표](../kit/uno-dashboard/SELF-CHECK.md)에 구간별 결과를 남깁니다. 만들기→오류→복구→재확인을 작업의 일부로 포함합니다. 자꾸 새 기능이 생기면 스케치의 오늘 범위로 돌아갑니다.
