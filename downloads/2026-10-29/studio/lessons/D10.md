# 개인 제출과 다음 프로젝트로 연결


## 목적

다른 사람이 파일을 보고 다시 실행할 수 있게 정리합니다. 오늘은 개인 작품입니다. 팀 Notion이나 짝의 확인을 제출 조건으로 두지 않습니다. 다음 프로젝트 수업에는 오늘의 사용자·문제·입출력·미완성 기능을 기획 재료로 가져갑니다.

## 제출 폴더 예

```text
홍길동_작업실조명/
  README.md
  index.html
  style.css
  dashboard.js
  sketch.png
  evidence/
    normal.png
    disconnected.png
    checks.md
```

폴더는 파일을 묶는 상자이고 확장자는 파일 종류를 구별합니다. 탐색기의 파일 확장명 표시를 켜 `index.html.txt`처럼 잘못 저장하지 않았는지 봅니다. `.png`는 화면·스케치 이미지, `.md`는 글로 쓴 실행 안내입니다. ZIP은 제출 폴더를 하나로 압축한 파일이며, 받는 사람이 압축을 풀어야 합니다. 실제 업로드한 보드 코드도 바꿨다면 해당 .ino/.h를 함께 넣고, 원본 P01 그대로면 버전·핀을 README에 적습니다.

## README에 쓸 내용

작품명·사용자·상황 한 문장, 실제 부품·핀, 실행 위치와 순서, 핵심 버튼, 정상·실패 예상 결과, 실제 확인한 범위와 못 한 범위, AI로 바꾼 파일, 다음 기능 하나를 적습니다. 설치된 전체 라이브러리 폴더·.venv·개인 API 키·로그인 정보는 넣지 않습니다. 브라우저 USB 권한은 파일에 포함되지 않으므로 다른 PC에서는 다시 선택해야 합니다.

## 개인 설명 예

‘밝기를 가장 크게 둔 이유는 사용자가 조명을 켤지 먼저 판단하기 때문입니다. 320은 lux가 아닌 원시값입니다. LED 버튼은 전송 중과 보드 응답을 구별합니다. 연습 데이터에서 null을 처리했고 실제 USB에서는 가변저항 변화와 LED를 확인했습니다. 장기 기록 저장은 구현하지 않았습니다.’

## 마지막 30분 운영

처음 10분은 D09 자기 점검, 다음 10분은 희망자 일부 화면 공유와 강사 피드백, 마지막 10분은 README·증거·ZIP 제출입니다. 학생 수가 미확인이므로 전원 발표 시간을 전제로 하지 않습니다. 제출 장소는 강사가 Zoom 채팅으로 안내합니다. 새 접수 서버나 임의의 공개 게시를 요구하지 않습니다.

## 확인 질문과 평가

‘이 화면의 첫 정보는 왜 이것인가?’, ‘수신 실패와 숫자0은 어떻게 다른가?’, ‘누름·명령 응답·실제 출력은 각각 어떻게 확인했나?’를 자기 말로 답합니다. 화면의 화려함이나 부품 개수보다 목적·의미·실행·복구 근거를 평가합니다. 계정·장비 문제는 별도 기록하고 설계·코드 성취와 구별합니다.
