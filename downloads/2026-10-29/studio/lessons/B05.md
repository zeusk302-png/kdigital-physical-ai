# B05 · KPI·시계열·이력의 의미 맞추기

보기 좋은 그래프보다 무엇을 집계했는지 설명할 수 있어야 합니다.

## 지표를 섞지 않기

속도와 검출 신뢰도, 구역 진입 횟수는 같은 단위가 아닙니다. 장치 ID나 추적 ID를 평균내면
수학 계산은 가능해도 의미 있는 지표가 되지 않습니다. 제공 화면은 같은 장치·같은 종류의
수치만 평균과 한 선으로 표시합니다. 수치가 없는 사건은 시간 구간별 사건 수를 집계할 수
있습니다. 사건 ID의 숫자를 측정값으로 옮기지 않습니다.

## 시간 범위와 최신값

수신 시각과 발생 시각을 구분합니다. 네트워크가 느리면 과거 사건이 늦게 올 수 있습니다.
발생 시각으로 정렬하고 차트의 가로축은 실제 시간 간격을 사용합니다. 입력 간격이 다를
때 각 점을 같은 거리로 놓으면 추세의 속도가 잘못 보입니다.

## 직접 구현

평균 옆에 최고값을 추가하되 null과 빈 목록을 먼저 처리합니다. 장치·종류가 섞이면
필터를 요구하거나 종류별로 나눕니다. 새 지표의 이름·단위·계산 범위를 docs에 적고
손으로 검산할 수 있는 선택 구간을 골라 비교합니다. 실제 수집 전체를 손으로 적은
자료로 대체하지 말고 일부 구간만 검산합니다.

## 표와 그래프를 함께 보기

표에는 최근200건을 표시하고 KPI는 조회한 전체 범위를 사용합니다. 화면에 이 차이를
알려야 표 행 수와 KPI가 다르다고 오해하지 않습니다. 조회 한도5000건이 넘으면
truncated를 표시하고 범위를 좁힙니다. 전체 기간으로 확장하려면 페이지 나눔·집계 API를
별도 설계합니다.

## 새 요구

“최근5분의 주의 사건을 장치별로 비교”를 추가한다면 조회 범위·group 기준·표시 단위를
먼저 적습니다. 차트 라이브러리를 하나 더 설치하는 것보다 무엇을 계산할지가 먼저입니다.

function Trend({rows}){
  // 이 실습은 한 장치·한 종류를 선택했을 때만 한 선을 그립니다.
  const kinds=new Set(rows.map(r=>r.device_id+' / '+r.kind));
  if(kinds.size>1)return <p>여러 종류의 수치를 섞어 선을 그리지 않습니다. 장치·종류를 좁혀 보세요.</p>;
  // 수치가 없는 사건 기록은 분당 사건 수로 집계해 그립니다. 추적 ID를 평균내지 않습니다.
  const numeric=rows.filter(r=>r.value!==null);
  let points;
  if(!numeric.length&&rows.length){
    const buckets=new Map();for(const row of rows){const at=Math.floor(row.occurred_at/60)*60;buckets.set(at,(buckets.get(at)||0)+1);}
    points=[...buckets].sort((a,b)=>a[0]-b[0]).map(([occurred_at,value])=>({occurred_at,value}));
  }else points=numeric.slice().reverse();
  if(points.length<2)return <p>선택 범위에 서로 다른 시점의 기록이 더 쌓이면 추세가 나타납니다.</p>;
  const vals=points.map(r=>r.value),low=Math.min(...vals),high=Math.max(...vals);
  const first=points[0].occurred_at,last=points.at(-1).occurred_at;
  const line=points.map(r=>`${20+((r.occurred_at-first)/(last-first||1))*860},${180-((r.value-low)/(high-low||1))*150}`).join(' ');
  return <><p className="muted">{kinds.values().next().value} · 최솟값 {low} / 최댓값 {high} · 수신 건수 간격이 아닌 실제 시각 간격</p><svg viewBox="0 0 900 210" role="img" aria-label="선택된 기록의 시계열 추세"><line x1="20" x2="880" y1="180" y2="180" stroke="#bccfc2"/><polyline points={line} fill="none" stroke="#087b67" strokeWidth="3"/></svg></>;
}

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
