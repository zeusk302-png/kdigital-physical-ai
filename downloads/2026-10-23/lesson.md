# 2026-10-23 · 전자회로·ESP32

값을 읽는 코드가 실제 세상과 만나려면 전기 신호의 약속이 필요합니다. 오늘은 회로를 종이에서 읽고, 센서 대신 제공 파일을 실행하여 신호·값·판단의 관계를 확인합니다. 실제 연결과 통전은 하지 않습니다.

## 수업의 출발점

물리량의 단위→회로의 경로와 기준→보드와 신호→디지털 기록→검수 순서로 학습합니다. 하드웨어 모델이 정해지지 않았으므로 모든 구체 핀 번호와 배선은 보류하며, 모의 값으로 확인할 수 있는 범위만 실제 실행합니다.

## 읽는 방법

먼저 개념을 읽고 예제의 입력값과 예상 결과를 살펴봅니다. 수업은 50분 × 6교시로 총 300분이며 중식은11:50~13:00입니다. 각 교시에 개념 설명·시연·직접 실습·풀이가 있습니다. 복습·도전 문제는 기본 실습을 마친 뒤 선택하며, 시간이 부족하면 수업 뒤에 이어서 풉니다. 학생 실습에 걸리는 시간은 수업 후 기록합니다.

## A01 · 전압·전류·저항을 구분

<!-- enrichment:2026-10-23:P1 -->

### 1교시 필수 개념 보충 · 전류가 돌아오는 길과 단위 계산

### 실무 상황과 원리

실습 담당자가 3.3V 전원과 330Ω 저항을 종이에 연결합니다. “3.3이 흐른다”라는 말로는 무엇을 측정하는지 알 수 없습니다. 전압은 두 점 사이의 차이이고 단위는 V입니다. 전류는 시간당 이동하는 전하량이며 A, 저항은 전압과 전류의 관계를 나타내며 Ω입니다. 물의 압력 차이와 유량 비유는 역할을 기억하는 출발점으로만 사용합니다.

전류의 통상적인 방향을 전원 + → 저항 → 전원 −로 표시합니다. 돌아오는 길까지 이어져야 닫힌 회로입니다. 중간이 끊어진 이상적인 회로에는 지속적인 전류가 흐르지 않습니다. GND는 이 회로에서 전압 비교의 기준으로 정한 지점이며 언제나 건물의 보호 접지라는 뜻은 아닙니다. 저항 없이 전원 +와 −를 잇는 것은 부하를 통과하는 정상 경로와 다릅니다.

완성 계산의 입력은 저항 양단 전압 3.3V와 저항 330Ω입니다. 옴성 저항의 관계 V=IR에서 I=V/R로 바꿉니다. 3.3÷330=0.010A이고, 1A=1000mA이므로 10mA입니다. 저항을 660Ω으로 바꾸면 0.005A=5mA입니다. 나눗셈 결과에 바로 mA를 붙이면 1000배의 단위 오류가 됩니다. 계산은 이상적인 저항의 관계를 확인한 것이며 부품 발열, 허용 전류, 보드 출력 능력을 승인한 결과는 아닙니다. 실제 연결 전에는 부품과 보드 사양이 필요합니다. 모의 계산의 실행 여부와 실물 측정 여부를 기록 칸에서 나눕니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 저항 양단 5V와 1000Ω이라는 새 종이 조건에서 A와 mA를 각각 계산하고 전류가 돌아오는 경로를 화살표로 그리세요. 가운데 선을 지웠을 때의 이상적 전류도 쓰세요.

### 정답과 오답의 이유

0.005A=5mA이며 + → 저항 → −입니다. 선이 끊어진 이상적 경로는 0A입니다. 5V를 ESP32 신호 입력에 연결해도 된다는 뜻은 아닙니다. 단위 계산과 연결 허용 판단은 별도 문제입니다.

### 확인 질문과 답

1. 전압은 몇 점 사이인가요? → 두 점 사이입니다.
2. 0.002A는? → 2mA입니다.
3. GND는 버리는 구멍인가요? → 전압 기준과 전류가 돌아오는 길의 역할을 읽어야 합니다.

전압은 두 점 사이의 전기적 에너지 차이를 전하량으로 나눈 값이고 단위는 V입니다. 전류는 시간당 흐르는 전하량이며 A, 저항은 전류 흐름을 제한하는 관계를 나타내며 Ω로 씁니다.

단위가 다른 수를 같은 값처럼 연결하면 회로 계산과 부품 선택을 잘못합니다. 수도관의 압력차·유량·흐름 저항 비유는 역할을 기억하는 데만 씁니다.

### 입력에서 살펴볼 예

전압3.3V
전류0.010A=10mA
저항330Ω

전압은 두 점 사이에서 말합니다.
전류는 흐름이며, 저항은 그 흐름과 전압의 관계입니다.

### 구분해야 할 반례

전압 자체가 회로를 흐른다고 말하지 않습니다. 물 비유로 전기 현상의 모든 성질을 설명할 수 없습니다.

## A02 · 닫힌 경로와 GND

회로는 전류가 돌아오는 경로를 포함한 연결입니다. GND는 회로에서 전압의 기준으로 정한 지점입니다. 길을 돌아 출발점에 오는 비유로 닫힌 경로를 읽습니다.

신호의 높고 낮음은 기준에 대한 값입니다. 연결 이름뿐 아니라 돌아오는 경로와 기준 공유 조건을 이해해야 합니다.

### 입력에서 살펴볼 예

종이 회로: 전원+ → 저항 → 전원−
중간 끊김: 열린 경로
기준: 전원−를0V로 정함

완전히 이어진 경로와 끊긴 경로를 구분합니다.
GND는 신호를 비교할 기준입니다.

### 구분해야 할 반례

모든 GND가 건물의 보호접지와 같지는 않습니다. 전원+와GND를 바로 잇는 것은 정상 부하 경로가 아니라 단락 위험입니다.

## A03 · 옴의 법칙을 계산으로 확인

일정 조건에서 옴성 저항은 V=IR 관계를 따릅니다. 전류를 구할 때 I=V/R로 바꾸고 단위를 맞춥니다. LED 같은 비선형 부품 전체에 고정 저항처럼 적용하지 않습니다.

전압이 같을 때 저항을 두 배로 하면 이상적인 계산 전류가 절반이라는 관계를 확인합니다. 계산 결과와 부품의 실제 허용 정격은 별개입니다.

### 입력에서 살펴볼 예

저항 양단3.3V, 저항330Ω
I=3.3/330=0.010A
660Ω로 변경

330Ω 계산은10mA입니다.
660Ω 계산은5mA입니다.
부품 정격과 발열은 따로 확인합니다.

### 구분해야 할 반례

이 계산만으로 ESP32핀에서10mA를 흘려도 된다고 승인할 수 없습니다. 보드·칩·핀·부품의 문서가 더 필요합니다.

스스로 설명할 질문: 계산 전류와 실제 연결 허용 여부는 왜 다른가요?

활동 연결: [입력](examples/course/data/A03_input.md) · [기록 양식](examples/course/work/A03_worksheet.md)

### 01_ohm.py 전체

```python
voltage_v = 3.3
resistance_ohm = 330
if resistance_ohm <= 0:
    raise ValueError("저항은 양수여야 합니다")
current_a = voltage_v / resistance_ohm
current_ma = current_a * 1000
print("current_mA:", round(current_ma, 2))
```

실행 조건: Python 3 표준 라이브러리만 사용합니다. 장치·포트·전원을 연결하지 않습니다.

실행 폴더: examples/course

명령: `python -X utf8 code/01_ohm.py`

결과:

```text
current_mA: 10.0
```

각 줄의 뜻은 [코드 해설](examples/course/code/line-guide.md)에 있습니다.

작은 수정: 저항을 660으로 바꾸면 5.0mA입니다. 전압은 3.3V를 유지합니다.

오류 복구: 저항0은 단락 모사 결과가 아니라 입력 오류입니다. 실제 단락을 만들어 확인하지 않습니다.

## A04 · LED와 저항의 역할

<!-- enrichment:2026-10-23:P2 -->

### 2교시 필수 개념 보충 · LED 직렬 저항과 보드 신호의 전압

### 실무 상황과 원리

알림등을 달고 싶은 담당자는 LED가 밝아지면 성공이라고 생각합니다. 그러나 빛이 보이는 것과 부품이 정격 안에서 동작하는 것은 다릅니다. LED는 방향이 있는 다이오드이며 저항처럼 일정한 V/I 값으로 취급하지 않습니다. 직렬 저항은 같은 가지를 흐르는 전류를 제한합니다.

제작 가정으로 공급 전압 3.3V, LED 전압 강하 2.0V, 직렬 저항 330Ω을 정합니다. 저항에 걸리는 전압은 3.3−2.0=1.3V입니다. 전류는 1.3÷330=0.00394A, 약 3.94mA입니다. 저항 양단에 3.3V 전체가 걸린다고 계산한 10mA와 다릅니다. 목표 전류를 가상으로 5mA라 정하면 필요한 이상적 저항은 1.3÷0.005=260Ω입니다. 실제 선택은 LED 사양, 허용 전류, 저항 정격, 오차와 사용 가능한 표준값을 확인하는 후속 작업입니다. 오늘 숫자는 배선 승인값이 아닙니다.

칩은 계산과 입출력을 수행하는 핵심 부품, 모듈은 칩과 주변 회로 묶음, 개발 보드는 연결과 개발을 돕는 전체 기판입니다. 보드에 5V 전원 단자가 있어도 GPIO 입력이 5V를 허용한다는 결론은 나오지 않습니다. GPIO는 프로그램으로 디지털 신호를 읽거나 출력하는 핀이며 HIGH는 정해진 논리 수준을 뜻합니다. 핀 번호, 부팅 관련 기능, 출력 전류 제한은 정확한 ESP32 계열과 보드 문서로 확인해야 합니다. 모델이 미확정이면 구체 배선 대신 확인할 항목을 작성합니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 공급 3.3V, 가정 LED 강하 1.8V, 저항 500Ω에서 전류를 계산하세요. 보드 전원 입력 표시에 5V가 있다는 이유로 센서의 5V 출력을 GPIO에 연결할 수 있는지도 판단하세요.

### 정답과 오답의 이유

저항 전압은 1.5V, 전류는 3mA입니다. GPIO 허용 전압은 별도 사양으로 확인해야 합니다. LED 강하를 더해 5.1V로 계산하거나 USB 전원과 신호 입력 정격을 같은 것으로 읽으면 오답입니다.

### 확인 질문과 답

1. 직렬 가지의 전류는? → 같은 가지에서 같습니다.
2. 2.0V는 확정 사양인가요? → 여기서는 계산용 가정입니다.
3. 모델 미확정 시 핀 번호는? → 확정하지 않고 확인 항목으로 남깁니다.

### 짧은 완성 코드로 추적하기

제공 참고 파일 [code/05_led_calculation.py](examples/course/code/05_led_calculation.py)은 보존합니다. 예제 `course` 폴더에서 이 파일을 `work/05_led_calculation.py`에 복사하고 학생 수정본은 work에 저장합니다. 아래는 완결된 전체 코드입니다. 파일·폴더·확장자를 확인한 뒤 같은 course 폴더의 터미널에서 `python -X utf8 work/05_led_calculation.py`을 실행합니다. 저장과 실행은 별도 행동입니다.

```python
supply_v = 3.3
led_v = 2.0
resistance_ohm = 330
if resistance_ohm <= 0 or supply_v < led_v:
    raise ValueError("계산 가정을 확인하세요")
current_ma = (supply_v - led_v) / resistance_ohm * 1000
print("assumed_LED_mA:", round(current_ma, 2))
```

예상 출력:

```text
assumed_LED_mA: 3.94
```

1~3행은 공급 전압·가정 LED 강하·저항을 이름에 저장합니다. =는 오른쪽 값을 왼쪽 이름에 붙이는 기호입니다. 4행의 <=는 작거나 같음, <는 작음, or는 둘 중 하나라도 참이라는 뜻입니다. 콜론 뒤 들여쓴 5행은 잘못된 가정을 오류로 알립니다. 6행의 괄호는 뺄셈을 먼저 하게 하며 /는 나눗셈, *는 곱셈입니다. 1000은 A를 mA로 바꾸는 수입니다. 7행은 round로 소수 둘째 자리까지 반올림해 출력합니다. 저항을 660으로 바꾸면 1.97입니다. 저항 0은 오류이므로 330으로 복구합니다. 계산 실행에는 보드와 전원을 연결하지 않습니다.




LED는 전류가 흐를 때 빛을 내는 다이오드이며 방향과 동작 조건이 있습니다. 직렬 저항은 회로 전류를 제한하는 데 사용합니다. LED의 전압 강하는 부품과 전류에 따라 달라집니다.

같은330Ω이라도 저항 양단 전압이 달라지면 전류가 달라집니다. LED가 있는 회로를 저항 하나의 계산과 구분합니다.

### 입력에서 살펴볼 예

종이 가정: 공급3.3V
LED 전압 강하2.0V
저항330Ω
I=(3.3−2.0)/330

가정하에서 약3.94mA입니다.
2.0V는 이번 계산용 가정입니다.
실물 LED 사양은 미확인입니다.

### 구분해야 할 반례

저항 없이 LED를 직접 연결하라는 지시가 아닙니다. LED모델·정격·극성·핀 허용 조건을 확인하기 전에는 통전하지 않습니다.

## A05 · 칩·모듈·개발 보드

마이크로컨트롤러는 프로그램을 실행하며 입출력을 다루는 칩입니다. 모듈은 칩과 주변 부품을 묶고, 개발 보드는 연결과 개발을 돕는 부품을 더합니다. ESP32는 여러 계열을 포함합니다.

같은 ESP32라는 이름만으로 핀 위치·USB·내장LED·전원 경로를 확정할 수 없습니다. 지도 이름과 실제 주소가 다른 것처럼 정확한 모델이 필요합니다.

### 입력에서 살펴볼 예

확인 카드
칩 계열: 미확인
보드 모델/리비전: 미확인
공식 핀맵: 미확인

부품 이름과 보드 이름을 따로 기록합니다.
사진 글자와 공식 문서의 모델을 맞춘 후 계획합니다.

### 구분해야 할 반례

인터넷 예제의 GPIO2가 모든 보드의 내장LED라고 가정하지 않습니다. 보드 외형이 비슷해도 핀 역할은 다를 수 있습니다.

## A07 · 아날로그와 ADC

### 3교시 필수 개념 보충 · 전압 신호를 숫자 기록으로 옮기기

### 실무 상황과 원리

온도 센서 값을 대시보드에 보내려면 전기 신호가 어떤 숫자와 단위를 뜻하는지 약속해야 합니다. 연속적으로 변하는 전압을 아날로그 신호라 부릅니다. ADC는 그 신호를 제한된 개수의 숫자 단계로 바꾸는 변환기입니다. 숫자가 되었다고 바로 섭씨 온도가 되지는 않습니다.

계산 연습용으로 0~3.3V를 코드 0~4095에 대응하는 이상적인 선형 모델을 가정합니다. 값 2048의 전압을 끝점 대응식으로 계산하면 2048÷4095×3.3≈1.6504V입니다. 이는 실물 ESP32 ADC의 교정 결과가 아닙니다. 실제 분해능 설정, 감쇠, 비선형성, 센서 변환식과 오차를 확인해야 합니다. 1.65V를 1.65℃라 적는 것은 단위가 생략된 해석 오류입니다.

이번 파일 실습은 이미 섭씨 단위로 만든 temperature_c를 읽습니다. JSON 한 기록은 sensor_id, seq, temperature_c처럼 이름과 값의 짝으로 표현합니다. { }는 한 기록의 묶음, 콜론은 이름과 값의 연결, 쉼표는 항목 구분입니다. null은 값이 없음을 나타내며 Python으로 읽으면 None이 됩니다. 완성 예의 입력 seq=1, temperature_c=27.8은 숫자 확인 → 28.0 이상 비교 → normal 출력으로 이어집니다. 입력값 "27.8"은 따옴표가 있는 문자열이라 현재 예제에서 invalid입니다. missing, invalid, alert, normal의 출력 이름은 수업용 판단 약속이며 실제 센서 고장 원인을 확정하지 않습니다. 원시 입력과 판정 결과를 함께 남겨야 재검토할 수 있습니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 가상 기록 세 개의 temperature_c가 0, null, "0"일 때 숫자 온도, 미측정, 잘못된 형식을 구분하세요. ADC 코드와 섭씨 값 사이에 필요한 정보 한 가지도 쓰세요.

### 정답과 오답의 이유

0은 숫자, null은 미측정, "0"은 문자열이라 현재 입력 규칙에서는 invalid입니다. 센서 변환식과 교정 조건이 필요합니다. 결측을 0으로 채우면 실제 영도 측정과 구별되지 않는 새 오류가 생깁니다.

### 확인 질문과 답

3. 2048 계산은 실물 교정인가요? → 이상적 모델의 연습입니다.

## A10 · 조건의 경계와 결측

### 4교시 필수 개념 보충 · 경계값과 상태를 기억하는 판단

### 실무 상황과 원리

가상 온도가 27.9와 28.1 사이를 오가면 경보가 켜졌다 꺼졌다 반복될 수 있습니다. 한 문턱만 사용하는 규칙은 현재 값만 봅니다. 서로 다른 켜짐과 꺼짐 문턱을 사용하는 히스테리시스는 이전 상태도 기억합니다. 실제 장비 제어에 적용하려면 별도의 위험과 정격 검토가 필요하며 오늘은 상태 계산만 합니다.

제작 규칙은 28.0 이상이면 alert=True, 27.5 이하이면 False, 사이이면 이전 상태 유지입니다. 초기 상태 False와 입력 [27.8,28.1,27.9,27.4]를 차례로 추적하면 False,True,True,False입니다. 27.9에서 False로 바뀌지 않는 이유는 중간 구간이기 때문입니다. 28.0과 27.5는 각각 켜짐과 꺼짐에 포함됩니다. 초기 상태가 달라지면 첫 중간 값의 출력도 달라지므로 시작 조건을 기록합니다.

None은 온도가 아니라 측정 누락입니다. 예제는 missing과 no command를 출력하고 이전 내부 상태를 유지합니다. 이는 통신 실패 시 실제 부하를 안전하게 제어하는 정책이 완성되었다는 뜻은 아닙니다. 보존한 상태와 현재 유효한 측정이 있다는 사실을 구분합니다. 완성 추적표에는 순번, 원시값, 이전 상태, 적용한 조건, 새 상태, 측정 유효 여부를 둡니다. elif는 앞 조건이 거짓인 경우에만 다음 조건을 확인하고, continue는 이번 반복의 나머지 처리를 건너뜁니다. 결측 행을 지우거나 이전 온도를 새 측정처럼 복사하면 왜 판단이 유지되었는지 알 수 없습니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 초기 False, 새 입력 [28.0,27.7,None,27.5]의 상태와 결측 시 출력 메시지를 순서대로 작성하세요. 중간 27.7이 True인 이유도 설명하세요.

### 정답과 오답의 이유

True,True,상태 True 유지와 no command,False입니다. 27.7은 두 문턱 사이입니다. None을 영도로 바꾸어 꺼짐 조건에 넣는 답은 결측과 수치를 혼동한 오답입니다. 실제 출력 장치의 안전 정책은 아직 시험하지 않았습니다.

3. 결측 출력은 새 온도인가요? → 아닙니다.

## A12 · 원시값과 판단을 함께 보존

## A13 · setup·loop와 직렬 출력

<!-- enrichment:2026-10-23:P5 -->

### 5교시 필수 개념 보충 · 펌웨어 반복과 직렬 통신의 경계

### 실무 상황과 원리

PC 파일에서 한 줄이 출력되는 것을 보고 센서가 연결되었다고 생각하기 쉽습니다. 그러나 Python 파일 재생과 보드 펌웨어는 실행하는 컴퓨터가 다릅니다. 펌웨어는 보드에 넣어 실행하는 프로그램이며 Arduino 방식의 setup은 시작할 때 한 번, loop는 그 뒤 반복되는 함수입니다.

제공 04_serial_mock.ino에서 setup은 Serial.begin(115200)으로 통신 속도를 설정합니다. loop는 고정 JSON 문장을 출력하고 delay(1000)으로 1000밀리초를 기다립니다. 1000밀리초는 1초지만 다른 처리 시간도 있으므로 정확한 1초 주기를 측정한 결과라고 부르지 않습니다. 고정 28.0을 출력하는 코드는 센서 측정 함수가 없습니다. 출력 문자열이 온도처럼 보여도 실제 온도를 읽는 부분은 없습니다.

직렬 통신은 두 장치가 약속한 설정으로 바이트를 주고받는 경로입니다. 보드와 PC의 속도 설정이 맞지 않으면 글자가 깨질 수 있습니다. JSON 문자열 안의 따옴표는 코드 문자열을 끝내지 않도록 역슬래시로 구분합니다. { }는 함수의 문장 묶음, 세미콜론은 C++ 문장의 끝입니다. Python 코드와 기호 약속이 다르므로 파일 확장자 .ino와 .py도 구분합니다. 완성 확인 순서는 정확한 보드 모델 확인 → 개발 환경과 포트 확인 → 컴파일 → 업로드 → 모니터의 같은 속도 설정 → 원문 관찰입니다. 이 과정은 실물 조건이 갖춰진 경우의 후속 경로이며 이번 파일 재생 검증과 나눠 기록합니다. 배선 검토는 전원을 끈 상태의 도면과 사양 확인부터 시작합니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 고정 문장 출력을 센서 측정으로 바꾸려면 어떤 입력 단계가 빠져 있는지 쓰세요. 모니터에 글자가 깨질 때와 포트 자체가 없을 때 확인 순서를 구분하세요.

### 정답과 오답의 이유

실제 센서를 읽고 단위로 변환하는 단계가 빠져 있습니다. 깨진 문자는 양쪽 속도 설정부터, 포트 없음은 데이터 케이블·드라이버·장치 인식부터 확인합니다. Python 출력 성공을 보드 업로드 성공이라고 쓰면 실행 위치를 혼동한 것입니다.

### 확인 질문과 답

1. setup 실행 횟수는? → 시작 때 한 번입니다.
2. 고정 28.0은 측정인가요? → 아닙니다.
3. 115200의 역할은? → 직렬 통신 속도 설정입니다.

<!-- /enrichment:2026-10-23:P5 -->


펌웨어는 장치에서 실행하는 프로그램입니다. Arduino의 setup은 시작 시 한 번,loop는 이어서 반복 실행됩니다. 직렬 출력은 값을 순서대로 보내는 통신 경로입니다.

PC의 Python 파일과 장치 펌웨어는 실행 위치·도구·종료 방법이 다릅니다. 전체 프로그램의 시작과 반복을 먼저 읽습니다.

## A18 · 근거를 남겨 다음 팀에 전달

인수인계는 확인한 사실과 아직 확인하지 못한 조건을 다른 사람이 이어갈 수 있게 적는 일입니다. 결과 숫자만이 아니라 입력·코드·설정·판단에 사용한 값과 조건가 필요합니다.

다음 팀이 장비를 연결하기 전에 어떤 시험을 추가해야 하는지 알 수 있게 합니다. 예제로 확인한 것과 장비에서 더 시험할 것을 함께 설명합니다.

### 입력에서 살펴볼 예

확인한 내용: 파일 판단과 수정·오류경로
추가로 확인할 내용: 실물회로·보드빌드·수신
다음: 모델 확정→문서검토→별도 시험

수치 단위, 0/null, 모의/실물을 구분합니다.
판단에 사용한 값과 조건와 보류 항목을 남깁니다.

### 구분해야 할 반례

실물 미검증을 숨기고 완료라고 적지 않습니다. 반대로 모의 시험 입력과 결과도 버리지 말고 재사용할 수 있게 남깁니다.

스스로 설명할 질문: 검증했다는 문장을 어떤 근거와 함께 쓸 수 있나요?
