# 2026-10-23 · 전자회로·ESP32

값을 읽는 코드가 실제 세상과 만나려면 전기 신호의 약속이 필요합니다. 오늘은 회로를 종이에서 읽고, 센서 대신 제공 파일을 실행하여 신호·값·판단의 관계를 확인합니다. 실제 연결과 통전은 하지 않습니다.

## A01 · 전압·전류·저항을 구분

전압은 두 점 사이의 전기적 에너지 차이를 전하량으로 나눈 값이고 단위는 V입니다. 전류는 시간당 흐르는 전하량이며 A, 저항은 전류 흐름을 제한하는 관계를 나타내며 Ω로 씁니다.

단위가 다른 수를 같은 값처럼 연결하면 회로 계산과 부품 선택을 잘못합니다. 수도관의 압력차·유량·흐름 저항 비유는 역할을 기억하는 데만 씁니다.

### 입력에서 살펴볼 예

전압3.3V
전류0.010A=10mA
저항330Ω

전압은 두 점 사이에서 말합니다.
전류는 흐름이며, 저항은 그 흐름과 전압의 관계입니다.

### 구분해야 할 반례

전압 자체가 회로를 흐른다고 말하지 않습니다. 물 비유로 전기 현상의 모든 성질을 설명할 수 없습니다.

스스로 설명할 질문: 3.3V와10mA를 서로 바꿔 쓸 수 없는 이유는 무엇인가요?

## A02 · 닫힌 경로와 GND

회로는 전류가 돌아오는 경로를 포함한 연결입니다. GND는 회로에서 전압의 기준으로 정한 지점입니다. 길을 돌아 출발점에 오는 비유로 닫힌 경로를 읽습니다.

신호의 높고 낮음은 기준에 대한 값입니다. 연결 이름뿐 아니라 돌아오는 경로와 기준 공유 조건을 이해해야 합니다.

### 입력에서 살펴볼 예

종이 회로: 전원+ → 저항 → 전원−
중간 끊김: 열린 경로
기준: 전원−를0V로 정함

완전히 이어진 경로와 끊긴 경로를 구분합니다.
GND는 신호를 비교할 기준입니다.

### 구분해야 할 반례

모든 GND가 건물의 보호접지와 같지는 않습니다. 전원+와GND를 바로 잇는 것은 정상 부하 경로가 아니라 단락 위험입니다.

스스로 설명할 질문: GND를 모두 안전한 버리는 구멍으로 생각하면 왜 틀리나요?

## A03 · 옴의 법칙을 계산으로 확인

일정 조건에서 옴성 저항은 V=IR 관계를 따릅니다. 전류를 구할 때 I=V/R로 바꾸고 단위를 맞춥니다. LED 같은 비선형 부품 전체에 고정 저항처럼 적용하지 않습니다.

전압이 같을 때 저항을 두 배로 하면 이상적인 계산 전류가 절반이라는 관계를 확인합니다. 계산 결과와 부품의 실제 허용 정격은 별개입니다.

### 입력에서 살펴볼 예

저항 양단3.3V, 저항330Ω
I=3.3/330=0.010A
660Ω로 변경

330Ω 계산은10mA입니다.
660Ω 계산은5mA입니다.
부품 정격과 발열은 따로 확인합니다.

### 구분해야 할 반례

이 계산만으로 ESP32핀에서10mA를 흘려도 된다고 승인할 수 없습니다. 보드·칩·핀·부품의 문서가 더 필요합니다.

스스로 설명할 질문: 계산 전류와 실제 연결 허용 여부는 왜 다른가요?

활동 연결: [입력](examples/course/data/A03_input.md) · [기록 양식](examples/course/work/A03_worksheet.md)

### 01_ohm.py 전체

```python
voltage_v = 3.3
resistance_ohm = 330
if resistance_ohm <= 0:
    raise ValueError("저항은 양수여야 합니다")
current_a = voltage_v / resistance_ohm
current_ma = current_a * 1000
print("current_mA:", round(current_ma, 2))
```

실행 조건: Python 3 표준 라이브러리만 사용합니다. 장치·포트·전원을 연결하지 않습니다.

실행 폴더: examples/course

명령: `python -X utf8 code/01_ohm.py`

결과:

```text
current_mA: 10.0
```

각 줄의 뜻은 [코드 해설](examples/course/code/line-guide.md)에 있습니다.

작은 수정: 저항을 660으로 바꾸면 5.0mA입니다. 전압은 3.3V를 유지합니다.

오류 복구: 저항0은 단락 모사 결과가 아니라 입력 오류입니다. 실제 단락을 만들어 확인하지 않습니다.

## A04 · LED와 저항의 역할

LED는 전류가 흐를 때 빛을 내는 다이오드이며 방향과 동작 조건이 있습니다. 직렬 저항은 회로 전류를 제한하는 데 사용합니다. LED의 전압 강하는 부품과 전류에 따라 달라집니다.

같은330Ω이라도 저항 양단 전압이 달라지면 전류가 달라집니다. LED가 있는 회로를 저항 하나의 계산과 구분합니다.

### 입력에서 살펴볼 예

종이 가정: 공급3.3V
LED 전압 강하2.0V
저항330Ω
I=(3.3−2.0)/330

가정하에서 약3.94mA입니다.
2.0V는 이번 계산용 가정입니다.
실물 LED 사양은 미확인입니다.

### 구분해야 할 반례

저항 없이 LED를 직접 연결하라는 지시가 아닙니다. LED모델·정격·극성·핀 허용 조건을 확인하기 전에는 통전하지 않습니다.

## A05 · 칩·모듈·개발 보드

마이크로컨트롤러는 프로그램을 실행하며 입출력을 다루는 칩입니다. 모듈은 칩과 주변 부품을 묶고, 개발 보드는 연결과 개발을 돕는 부품을 더합니다. ESP32는 여러 계열을 포함합니다.

같은 ESP32라는 이름만으로 핀 위치·USB·내장LED·전원 경로를 확정할 수 없습니다. 지도 이름과 실제 주소가 다른 것처럼 정확한 모델이 필요합니다.

## A06 · GPIO와 논리 수준

GPIO는 프로그램으로 입출력 역할을 정하는 범용 핀입니다. 디지털 입력은 정해진 전압 범위를 LOW/HIGH로 해석합니다. 논리값은 물리 전압의 약속과 연결되지만 같은 단위는 아닙니다.

입력·출력 방향을 혼동하거나 전압 범위를 넘기면 코드가 맞아도 장치 문제가 생깁니다. GPIO와 공급 핀을 먼저 구분합니다.

### 입력에서 살펴볼 예

신호 계획
버튼 상태 → 디지털 입력
표시 상태 → 디지털 출력
구체 GPIO 번호 → 미정

pinMode는 방향을 정하는 API입니다.
digitalRead는 논리 상태를 읽습니다.
번호·허용 전압은 모델 문서로 확인합니다.

### 구분해야 할 반례

HIGH가 모든 보드에서5V라는 뜻은 아닙니다. USB에5V가 들어간다고 GPIO가5V 입력을 허용한다고 추정하지 않습니다.

## A07 · 아날로그와 ADC

아날로그 신호는 범위 안에서 연속적으로 변할 수 있는 물리 신호입니다. ADC는 입력 전압을 정해진 해상도의 디지털 수로 변환합니다. 눈금자로 길이를 읽듯 유한 단계로 기록합니다.

변환 수치에는 해상도·입력 범위·보정 조건이 있습니다. 큰 숫자가 곧 온도라는 뜻은 아닙니다.

원시 수치와mV, 온도°C는 다른 단계입니다.
실제 범위와 해상도는 칩·설정에 따라 확인합니다.

### 구분해야 할 반례

raw/4095×3.3을 모든 ESP32의 정확한 전압 보정식으로 쓰지 않습니다. ADC 감쇠·특성·보정과 센서 변환식이 필요합니다.

## A08 · 센서 기록의 스키마

센서는 물리량을 전기 신호 등으로 바꾸는 장치입니다. 기록 스키마는 식별자·순번·값·단위·상태의 약속입니다. 포장 상자의 라벨처럼 값의 뜻을 같이 보냅니다.

센서에서 온 숫자만 저장하면 어느 장치·어느 순서·어떤 단위인지 잃습니다. 값 없음도 정상0과 구별해야 합니다.

### 02_sensor_replay.py 전체

```python
import json
from pathlib import Path
root = Path(__file__).resolve().parent.parent
source = root / "data" / "sensor_samples.json"
samples = json.loads(source.read_text(encoding="utf-8"))
for sample in samples:
    value = sample["temperature_c"]
    if value is None:
        state = "missing"
    elif type(value) not in (int, float):
        state = "invalid"
    elif value >= 28.0:
        state = "alert"
    else:
        state = "normal"
    print(sample["seq"], value, state)
```

실행 조건: Python 3 표준 라이브러리만 사용합니다. 장치·포트·전원을 연결하지 않습니다.

명령: `python -X utf8 code/02_sensor_replay.py`

결과:

```text
1 27.5 normal
2 28.0 alert
3 None missing
4 0.0 normal
5 29.0 invalid
```

각 줄의 뜻은 [코드 해설](examples/course/code/line-guide.md)에 있습니다.

## A11 · 흔들림과 히스테리시스

히스테리시스는 이전 상태에 따라 현재 판단이 달라지는 특성입니다. 여기서는 켜기28.0,끄기27.5로 기준을 나눠 작은 흔들림에서 반복 전환을 줄입니다.

경계 하나만 쓰면27.9와28.1이 번갈아올 때 상태가 계속 바뀔 수 있습니다. 표시 안정화의 원리를 모의 값으로 살펴봅니다.

### 입력에서 살펴볼 예

27.8 → 28.1 → 27.9
→28.2 →27.4 →null→28.3
켜기≥28.0 / 끄기≤27.5

꺼짐 → 켜짐 → 켜짐
→켜짐 → 꺼짐 → 명령 없음 → 켜짐

### 구분해야 할 반례

이 예의 누락 처리가 모든 장치의 안전 정책은 아닙니다. 실제 제어는 장치 특성에 맞는 별도 실패 안전 정책이 필요합니다.

스스로 설명할 질문: 27.9에서 직전 상태를 왜 기억하나요?

활동 연결: [입력](examples/course/data/A11_input.md) · [기록 양식](examples/course/work/A11_worksheet.md)

### 03_hysteresis.py 전체

```python
values = [27.8, 28.1, 27.9, 28.2, 27.4, None, 28.3]
alert = False
for value in values:
    if value is None:
        print("missing", "no command")
        continue
    if value >= 28.0:
        alert = True
    elif value <= 27.5:
        alert = False
    print(value, alert)
```

실행 조건: Python 3 표준 라이브러리만 사용합니다. 장치·포트·전원을 연결하지 않습니다.

명령: `python -X utf8 code/03_hysteresis.py`

결과:

```text
27.8 False
28.1 True
27.9 True
28.2 True
27.4 False
missing no command
28.3 True
```

각 줄의 뜻은 [코드 해설](examples/course/code/line-guide.md)에 있습니다.

작은 수정: 꺼짐 기준27.5를27.9로 바꾸면 세 번째27.9에서False가 됩니다.

오류 복구: 상태 변수를 반복문 안에서 매번 False로 초기화하면 이력 효과가 사라집니다. 들여쓰기와 초기화 위치를 확인합니다.

## A13 · setup·loop와 직렬 출력

펌웨어는 장치에서 실행하는 프로그램입니다. Arduino의 setup은 시작 시 한 번,loop는 이어서 반복 실행됩니다. 직렬 출력은 값을 순서대로 보내는 통신 경로입니다.

PC의 Python 파일과 장치 펌웨어는 실행 위치·도구·종료 방법이 다릅니다. 전체 프로그램의 시작과 반복을 먼저 읽습니다.

### 입력에서 살펴볼 예

04_serial_mock.ino
setup: Serial.begin(115200)
loop: 고정 JSON 출력, delay(1000)

설정은 한 번, 출력과 기다림은 반복합니다.
고정 문장 전송이며 센서 측정이 아닙니다.

### 구분해야 할 반례

delay1000만으로 정확히 1Hz 측정을 보장하지 않습니다. 실행 시간과 통신 등 지연이 더해지고 실제 센서를 읽는 코드도 없습니다.

스스로 설명할 질문: 이 코드가 센서를 읽었다고 말할 수 없는 근거는 무엇인가요?
