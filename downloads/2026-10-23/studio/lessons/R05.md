# R05. 어댑터로 실제 제조사 주행 코드 연결하기

어댑터는 서로 다른 약속 사이를 번역하는 부품입니다. 휴대전화 충전 단자 변환기처럼 우리 명령을 제조사 함수의 입력으로 바꿉니다. 학생이 적는 forward와 speed의 형식은 유지하고 보드 리비전에 따라 실제 호출만 다르게 만들면 명령·검사·실행기를 전부 다시 쓰지 않아도 됩니다. DryRun 어댑터는 전달 내용을 기록하고, AdeeptDrive 어댑터는 검토한 제조사 move.py의 함수를 부릅니다. 두 경로의 출력이 비슷해도 장치 사용 여부는 mode에서 분명하게 구별합니다.

공식 소스 확인 결과 초록색 경로는 `server/move.py`, 보라색 경로는 `web/move.py`입니다. 두 파일은 setup, move, motorStop, destroy라는 함수를 제공하지만 인자 계약이 다릅니다. 초록색의 직진 방향은 문자열이고 보라색의 직진·후진 방향은 숫자입니다. 보라색 직진 turn에는 mid를 사용합니다. 따라서 파일 이름만 맞추어 한 리비전 코드를 다른 장치에 적용하지 않습니다. 실제 비교 근거와 고정 커밋은 `docs/sources.md`에 남깁니다. GPIO 번호와 채널은 이 교안이 새로 계산하지 않고 선택한 공식 모듈이 관리합니다.

PC에서는 먼저 가짜 제조사 모듈을 쓰는 자동시험으로 번역 인자를 확인합니다. 이것은 GPIO 통신 시험이 아닙니다. 실제 연결은 사전 준비된 Pi에서 강사가 수행하며, 학생은 리비전·파일·해시·준비표가 일치하는지 확인합니다. 제공 실행기는 명시적으로 hardware를 선택하고 board, vendor-file, sha256, confirmed를 모두 주어야 실물 어댑터를 생성합니다. 해시는 강사가 읽고 검토한 파일의 내용이 바뀌지 않았는지 비교하는 값입니다. 출처 자체의 진위를 자동 보증하지 않으므로 아무 파일의 해시를 계산해 넣는 방식으로 검토를 대체하지 않습니다.

실물 첫 시연은 작업 구역을 비우고 궤도가 바닥에 닿지 않는 지지 상태에서, 제조사 지침에 맞는 전원과 전원 분리 방법을 확인한 뒤 짧은 명령 하나로 진행합니다. 웹 제어 서버나 다른 프로그램이 같은 보드를 동시에 조작하지 않게 합니다. 모터 방향·이상음·정지 반응을 관찰하고 기록합니다. 낮은 출력으로 회전하지 않는다고 출력을 무작정 높이지 않습니다. 배선·전원·기구 상태를 먼저 확인합니다. 관찰된 물리 방향이 예상과 다르면 명령 이름을 바꾸어 숨기지 말고 리비전·조립·제조사 방향 설정을 확인합니다.

소프트웨어의 completed는 명령 호출이 끝났다는 뜻입니다. 실제 위치 피드백 없이 명령 호출 결과만으로는 “정확히 10cm 이동 완료”처럼 표시하지 않습니다. state의 feedback은 command-only입니다. 실제 관찰은 학생이 별도 표에 적습니다. 통신 오류, 모듈 import 실패, 보드 초기화 실패가 나면 장치 성공 상태를 만들지 않습니다. 구동 어댑터는 모터 정지를 요청하지만 물리적 전원 차단 장치를 대신하지 않습니다.

필수 활동은 초록색과 보라색 번역표를 코드에서 찾아 채우고, 같은 학생 명령이 다른 제조사 호출로 바뀌는 이유를 설명하는 것입니다. 장비가 준비된 조는 강사 감독 아래 직진·정지 관찰을 기록합니다. 준비되지 않은 조는 같은 입력의 DryRun 결과와 번역 시험 결과를 제출하며 장치 미실행이라고 명시합니다. 추가 도전은 좌회전과 우회전의 제조사 동작이 같은 자리 회전인지 한쪽 궤도 정지인지 소스를 읽고 비교하는 것입니다. 실제 주행 거리와 회전각까지 검증했다고 쓰지 않습니다.
