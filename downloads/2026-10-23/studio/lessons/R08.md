# R08. AI와 파일을 나누어 고치고 증거를 제출하기

오늘 프로젝트는 한 파일에 모든 코드를 몰아 넣지 않습니다. commands.py는 입력 약속과 검사, adapters.py는 장치별 번역, runner.py는 실행 순서와 정리, __main__.py는 터미널 입력을 담당합니다. 이렇게 나누면 speed 검사 규칙을 바꿀 때 GPIO 코드를 함께 건드릴 필요가 줄어듭니다. 파일을 나누는 이유를 “보기 좋기 때문”에서 끝내지 않고 변경의 영향과 시험 범위를 좁히는 관점으로 설명합니다. README는 실행자가 읽는 시작 안내, AGENTS는 코드 에이전트의 수정 경계입니다.

AI에게 “로봇 움직이게 해 줘”라고만 하면 장치 리비전과 API를 추측할 수 있습니다. 먼저 읽을 파일, 고칠 범위, 유지할 규칙, 확인할 결과를 함께 줍니다. 아래 지시문을 학생 상황에 맞게 복사하고 대상 오류를 바꿉니다.

```text
README.md, AGENTS.md, docs/hardware.md와 robotlab/commands.py를 읽어.
seconds가 문자열일 때 거절하는 이유를 초심자에게 설명해.
입력 검사 설명과 관련 시험만 보완해. 실물 명령은 실행하지 마.
기본 dryrun, 전체 사전 검사, finally 정지를 유지해.
공식 근거 없는 GPIO, 서보 채널, 각도 범위를 만들지 마.
수정 파일, 예상 결과, 실제 시험 결과, 남은 미확인을 보고해.
```

강사는 AI 답변에 없는 함수가 나타난 예를 보여 주고 제조사 고정 커밋에서 이름을 찾는 과정을 시연합니다. 답변이 그럴듯해도 소스에 없다면 그대로 복사하지 않습니다. 함께 따라 하기에서는 명령 데이터 한 파일만 고치는 요청을 작성하고 diff를 읽습니다. diff는 전후 차이를 보여 주는 자료입니다. 학생은 추가된 줄이 자기 요청과 연결되는지, 검사와 정지 코드가 지워지지 않았는지 확인합니다. 시험 통과 숫자만 보고 새 실물 동작까지 승인하지 않습니다.

Git에는 소스·시험·예제 명령·README·공개 가능한 근거를 올립니다. .venv는 다시 만들 수 있는 실행 환경이고 __pycache__는 자동 생성 캐시입니다. 실제 Wi-Fi 비밀번호·SSH 키·로컬 보정값·개인정보·장치 누적 로그는 공개하지 않습니다. .gitignore는 추적 시작 전 제외할 패턴을 적는 파일입니다. 이미 추적한 비밀을 .gitignore에 적었다고 과거 커밋에서 사라지는 것은 아닙니다. 학생은 `git status --short`로 올라갈 파일을 읽고 파일명뿐 아니라 내용도 살핍니다.

필수 제출은 자기 시퀀스, 정상·거절·중단 시험 기록, PC와 Pi 실행 위치 설명, 리비전 확인 또는 미확인 기록, AI 수정 요청과 실제 반영 차이입니다. `docs/checks.md` 양식을 복사해 실행한 명령과 실제 결과를 채웁니다. 수행하지 않은 실물 주행·서보 보정은 “미실행”으로 남깁니다. 잘 작성한 실패 기록은 장치 성공 영상 대신 모의 경로의 완성도를 평가하는 근거가 될 수 있습니다. 실제 장비 성공을 요구하는 평가와 모의 코드 평가를 분리합니다.

개별 전이 과제는 “교실 운반 로봇이 짧게 이동한 뒤 정지하고, 입력 시간이 너무 길면 출발하지 않아야 한다”라는 새 요구입니다. 학생은 요구를 명령과 검사 조건으로 바꾸고, 정상·잘못된 입력·중단의 세 시험을 만듭니다. 추가 도전은 10/29 대시보드에 전달할 상태 필드를 설계하는 것입니다. 실제 좌표나 배터리 값이 수집되지 않았다면 빈칸이나 미수집으로 표시하고 임의 값으로 채우지 않습니다. 마무리에서는 다른 학생이 README만 읽고 PC 모의 실행을 재현하도록 교환 검토합니다. 설명을 읽고 실행 위치·파일·성공 기준을 찾을 수 있으면 인계 가능한 산출물에 가까워진 것입니다.
