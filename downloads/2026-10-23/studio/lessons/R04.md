# R04. 명령·인자·검사로 주행을 표현하기

명령은 실행할 행동을 정한 약속입니다. action은 행동 이름, speed는 출력 크기, seconds는 유지 시간입니다. speed가 20이라고 로봇이 초속 20cm로 간다는 뜻은 아닙니다. 이 수업에서는 제조사 함수에 전달하는 출력 크기의 수업용 제한값입니다. 바닥·배터리·기구·부하에 따라 실제 이동은 달라집니다. 안전한 숫자 하나를 찾았다고 모든 상황에 적용하지 않습니다. 이동 거리의 계산과 PWM 계열 출력값을 구별합니다.

```json
{"action": "forward", "speed": 20, "seconds": 0.3}
```

중괄호는 하나의 객체를, 따옴표는 문자열을, 콜론은 이름과 값의 연결을, 쉼표는 다음 항목의 시작을 나타냅니다. 숫자 20에 따옴표를 붙이면 문자열이 되므로 검사에서 거절합니다. `forward`는 프로그램과 약속한 이름이어서 임의로 `앞으로`라고 바꾸면 동작하지 않습니다. 화면에 보여 줄 한국어 설명과 내부 명령 이름을 따로 둘 수 있다는 점을 설명합니다. 실습에서는 먼저 제공 전체 예를 실행하고 작은 조각을 직접 다시 입력합니다.

PC의 kit 폴더에서 sequence.json을 열고 첫 줄부터 끝까지 읽습니다. 대괄호는 여러 명령을 순서대로 모은 목록입니다. 명령 하나만 바꾸어 저장하고 `python -m robotlab sequence.json`으로 실행합니다. 검사기는 action·필드·숫자 범위·시간 합계를 확인한 후 실행기로 넘깁니다. 수업용 제한은 speed 0~30, 한 동작 0.05~2초, 최대 20명령, 합계 15초입니다. 이는 장치의 물리적 안전 인증 범위가 아니라 무제한 입력을 막기 위한 제작 규칙입니다. 실물의 제한은 관찰과 제조사 조건으로 더 좁혀야 합니다.

강사는 먼저 speed를 200으로 바꾸어 오류를 시연하고 다시 20으로 복구합니다. 함께 따라 하기에서는 seconds를 문자열 `"0.3"`으로 바꾸어 타입 오류를 봅니다. 학생의 개별 수행은 `sideways`라는 미정의 명령, 빠진 seconds, 불필요한 pin 필드를 각각 만들어 예상 오류와 실제 오류를 표에 기록하는 것입니다. 실행기에 잘못된 GPIO를 끼워 넣는 일이 불가능하도록 모르는 필드를 거절합니다. “알아서 가능한 값으로 보정”하지 않는 이유는 실수한 학생이 자기 입력이 달라진 사실을 볼 수 없기 때문입니다.

코드의 `if`는 조건에 따라 길을 나누고 `raise ValueError`는 잘못된 입력이라는 이유를 알리며 멈춥니다. `get`은 이름표로 값을 읽고, `copy`는 원본과 별도 사전을 만듭니다. 제공 주석을 읽고 학생은 숫자 검사 한 줄을 자기 말로 설명합니다. 코드 전체를 외우게 하지 않습니다. 필요할 때 함수의 입력·출력·실패 조건을 찾아 읽는 연습을 합니다. 형식 검사에 통과해도 실제 장애물이 없는지까지 알 수 없으므로 소프트웨어 검사와 현장 관찰의 책임을 나눕니다.

필수 제출은 정상 명령 2개, 잘못된 명령 2개, 각 예상과 결과입니다. 추가 도전은 새로운 action을 즉시 추가하는 것이 아니라, 새 행동에 어떤 필드와 시험이 필요할지 설계만 해 보는 것입니다. 장치 없이도 이 단계의 성취를 평가할 수 있습니다. 오류가 나면 괄호·따옴표·쉼표의 JSON 문법 오류인지, 프로그램이 안내한 의미·범위 오류인지 먼저 구분합니다. 파일을 고친 뒤 저장하고 같은 명령으로 다시 실행해 복구를 확인합니다.
