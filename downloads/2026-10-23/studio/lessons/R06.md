# R06. 서보·위치·보정과 동작 경계

서보는 목표 위치를 명령하는 장치지만 코드에 숫자를 쓴 순간 실제 관절 각도가 확인되는 것은 아닙니다. 코드의 각도·펄스 값, 서보축의 방향, 혼의 조립 위치, 링크의 실제 움직임은 서로 연결되어 있습니다. 책상 위에서 분리한 서보가 움직이는 범위와 로봇팔에 연결된 뒤 부딪히지 않는 범위는 다릅니다. 제조사 예제에 큰 왕복 범위가 있어도 조립된 장치에 그대로 적용하지 않습니다. 이번 제작에서 실물 리비전과 보정 상태를 직접 확인하지 못했으므로 학생용 실행기의 실물 servo 명령은 거절합니다.

그 대신 PC에서 팔과 집게의 목표 위치를 명령 데이터로 설계합니다. kit의 servo-dryrun.json을 열고 `python -m robotlab servo-dryrun.json`을 실행합니다. joint는 움직일 부분의 이름이고 position은 수업용으로 0~1 사이에 놓은 모의 위치입니다. 0.4가 40도라는 뜻은 아닙니다. 이 값을 실제 펄스나 각도로 바꾸는 공식은 현재 제공하지 않습니다. 보정 없는 가짜 환산표를 넣으면 장비를 준비한 것처럼 보이지만 실제 충돌 위험과 학습 오류가 생깁니다.

```json
{"action": "servo", "joint": "arm", "position": 0.4, "seconds": 0.2}
```

강사는 0.4를 0.5로 바꾸기 전에 “어떤 이름표가 달라지고 어떤 부분은 그대로인지” 묻습니다. 함께 따라 하기에서는 arm과 gripper 두 명령의 순서를 바꾸고, 출력 이벤트가 입력 순서대로 남는지 확인합니다. 학생 개별 수행은 집게를 나타내는 세 위치와 대기 시간을 표로 설계하는 것입니다. 실제 물체를 집었다고 적지 않고 명령 계획을 만들었다고 적습니다. 추가 도전은 팔을 먼저 이동하고 집게를 닫는 순서와 반대 순서가 물리적으로 다른 결과를 낳을 수 있는 이유를 설명하는 것입니다.

실물 확장 준비는 강사의 `docs/hardware.md` 절차로 진행합니다. 초록색 공식 servo.py는 import 단계부터 제어 장치를 생성하므로 파일을 읽기만 하는 단계와 import하는 단계를 구별합니다. 보라색 공식 examples/03_Servo.py의 직접 실행 구간은 여러 채널을 반복해서 움직이므로 학생용 진단 명령으로 실행하지 않습니다. 제조사 서보 시연 코드가 존재하는 것과 우리 기구에서 보정되었다는 것은 다른 증거입니다. 함수 이름과 파일 경로는 출처 기록에서 확인하고 물리 범위는 실물 측정표에 별도로 남깁니다.

기구 보정이 가능한 장비에서는 혼을 고정하기 전 제조사 초기화 순서를 따른 후 한 관절씩 최소 변화로 움직이고 간섭·이상음·전류 이상 징후를 관찰합니다. 관절 이름, 실제 연결 포트, 제조사 단위, 확인한 최소·중앙·최대, 부하 조건, 담당자와 날짜를 기록합니다. 움직임을 멈추는 정책도 결정해야 합니다. 펄스를 끄면 토크가 풀려 팔이 내려올 수 있고 현재 위치 유지는 발열·부하를 만들 수 있으므로, 모터 정지 함수만 부르고 서보도 안전해졌다고 주장하지 않습니다.

필수 확인 질문은 “position 0.5의 의미는 무엇인가”, “서보 범위를 어떤 근거로 정해야 하는가”, “실물 실행이 막혀 있을 때 어느 자료를 제출할 수 있는가”입니다. 풀이에는 모의 비율, 해당 기구 보정 근거, 설계·모의 로그·미확인 목록이 들어갑니다. 학생이 실물 성공을 얻지 못한 사실을 감추지 않고 다음 연결에 필요한 조건을 명확히 쓰는 것을 평가합니다. 준비된 장치가 있다면 제조사 도구의 감독 시연과 학생의 모의 데이터 설계를 연결하되 자동 구동 어댑터가 서보까지 완성됐다고 보고하지 않습니다.
