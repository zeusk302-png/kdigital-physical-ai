# R03. PC와 Raspberry Pi를 구별하고 OS를 준비하기

PC에서 쓴 파일이 로봇 안에 자동으로 생기지는 않습니다. PC는 편집·모의 실행·자료 보관을 하고, Raspberry Pi는 실제 확장보드와 연결된 환경에서 제어 코드를 실행합니다. PC의 Windows 경로와 Pi의 Linux 경로는 표기가 다릅니다. `D:\robot-class\kit`를 Pi 터미널에 그대로 입력하지 않습니다. 터미널 맨 앞의 사용자·호스트 표시를 보고 지금 어느 컴퓨터에 명령을 보내는지 확인합니다. 같은 Python 명령도 파일과 주변 장치가 준비된 컴퓨터에서 실행해야 의미가 있습니다.

OS는 파일과 프로그램, 장치를 관리하는 기본 소프트웨어입니다. Raspberry Pi는 부팅할 저장 장치가 필요합니다. 일반적인 준비는 PC의 Raspberry Pi Imager에서 대상 Pi 모델·OS·저장 장치를 고르고, 설정을 확인해 쓰는 흐름입니다. [Raspberry Pi 공식 시작 문서](https://www.raspberrypi.com/documentation/computers/getting-started.html)를 참고합니다. 다만 최신 OS가 오래된 초록색 제조사 코드와 반드시 호환되는 것은 아닙니다. 실제 사용할 OS·Python·드라이버 조합은 리비전 설명서에 맞춰 강사가 사전 시험하고 기록합니다. 본 수업에서 특정 OS 버전을 모든 보드에 보장하지 않습니다.

쓰기 전에는 카드 안에 필요한 파일이 없는지 확인하고 대상 저장 장치의 이름과 용량을 다시 봅니다. OS 쓰기는 카드 내용을 바꾸는 작업이므로 학생 개인 자료 카드로 즉흥 시연하지 않습니다. 전원 없이 준비한 카드를 Pi에 꽂고, 모델에 맞는 전원·화면·키보드 또는 준비된 네트워크 경로로 부팅합니다. 원격 접속을 쓸 경우 강사가 장치의 실제 주소와 사용자 이름을 제공하며, 기본 비밀번호를 추측하지 않습니다. Wi-Fi 비밀번호와 SSH 개인키는 수업 ZIP과 GitHub에 넣지 않습니다.

Pi 터미널에서 `pwd`, `python3 --version`, `cat /etc/os-release`로 현재 폴더·Python·OS를 읽습니다. `pwd`는 현재 위치를 보여 주며 파일을 바꾸지 않습니다. `python3 --version`은 설치된 실행기를 확인합니다. `cat`은 파일 내용을 표시합니다. 강사는 비밀값이 섞이지 않는 출력만 공유합니다. PC에서는 `python -m robotlab sequence.json`, Pi에서는 준비된 kit 폴더에서 `python3 -m robotlab sequence.json`을 먼저 실행합니다. 두 경우 모두 아직 dryrun입니다. 접속이 되었다는 사실과 모터가 안전하게 제어된다는 사실을 혼동하지 않습니다.

제조사 저장소를 받은 뒤 README와 설치 스크립트를 먼저 읽습니다. `setup.py`는 단순 Python 패키지 설치 파일이라는 이름만으로 실행해도 되는 것이 아닙니다. OS 설정·서비스·패키지·재부팅에 영향을 줄 수 있으므로 수업용 PC에서 원격 코드를 자동 실행하지 않습니다. 실제 필요한 드라이버 설치와 인터페이스 설정은 강사가 선택 리비전의 공식 지침으로 준비합니다. import 실패가 나면 학생 코드의 action 오타를 고치기 전에 OS·라이브러리·인터페이스 문제인지 분류합니다.

필수 활동은 PC와 Pi 작업을 두 칸에 분류하는 것입니다. 편집, 모의 시험, OS 카드 준비, GPIO 연결, 실제 주행의 실행 위치를 적습니다. 준비된 Pi가 있다면 강사의 화면에서 호스트 이름과 버전을 읽고 기록합니다. 없으면 제공 확인표를 “실물 미실행”으로 채우고 모의 코드를 실행합니다. 한 값 수정에서는 my-sequence의 시간을 바꾸고 PC와 Pi의 파일이 각각 수정되었는지 비교합니다. 추가 도전은 파일을 복사한 후 파일 해시 또는 내용 비교로 같은 버전임을 확인하는 것입니다. 오류 복구에서는 잘못된 폴더에서 난 ModuleNotFoundError를 kit 폴더로 이동해 해결하고, 하드웨어 라이브러리가 없다는 오류와 구별해 설명합니다.
