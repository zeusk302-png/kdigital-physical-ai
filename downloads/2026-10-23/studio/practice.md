# 학생 실습지

## 1. 목적과 준비

RaspTank 명령을 파일로 표현하고, 잘못된 입력과 중단에도 정지 요청이 남는 프로그램을 만듭니다. 준비물은 압축을 푼 kit, Python 3.10 이상, 편집기입니다. PC 모의 경로에는 계정·결제·외부 패키지·로봇이 필요 없습니다. 실물 경로는 강사의 장비 준비표 완료와 감독이 필요합니다.

## 2. 첫 실행과 파일 수정

1. PC 터미널에서 kit 폴더로 이동하고 `python --version`을 적으세요.
2. `python -m robotlab sequence.json`을 실행하고 mode/status/completed/feedback을 설명하세요.
3. sequence.json을 my-sequence.json으로 복사하고 첫 seconds만 0.5로 바꾸세요.
4. 변경 전 예상과 저장 후 실행 결과를 비교하세요. 예상: 처리 명령은 3개이며 첫 대기만 변합니다.
5. 파일을 못 찾으면 폴더와 확장자를, 모듈을 못 찾으면 robotlab과 같은 kit 폴더인지 확인하세요.

## 3. 명령 설계와 거절

앞으로·뒤로·정지 명령 3개를 직접 입력하세요. speed 0~30, seconds 0.05~2의 수업용 제한을 지키세요. 바퀴 이동 거리와 같은 단위라고 설명하지 마세요. speed 200, seconds 문자열, 잘못된 action을 서로 다른 파일로 만들고 예상 오류를 적으세요. 전체 목록을 먼저 검사하므로 마지막 명령이 틀려도 앞부분이 실행되지 않아야 합니다. 단순 JSON 문법 오류와 검사기가 거절한 의미 오류를 나누세요.

## 4. 제조사와 실물 준비

장치가 있으면 전원을 분리한 채 kit/docs/hardware-record.md의 모델·리비전·설명서 항목을 작성하세요. 초록/보라에 해당하는 제조사 move.py 경로와 direction 입력 차이를 적으세요. 장치가 없거나 확인되지 않으면 미확인으로 쓰고 번역 시험을 수행하세요. 실물 주행은 강사가 준비한 Pi에서만 하며 실제 방향·정지 관찰을 프로그램 completed와 별도로 적습니다.

## 5. 서보 명령과 시퀀스

`python -m robotlab servo-dryrun.json`을 실행하세요. position 0.4를 0.5로 바꾸고 출력에서 달라진 필드를 찾으세요. position은 모의 비율이며 각도가 아닙니다. arm→gripper와 gripper→arm 순서를 비교하고 실제 기구에서는 어떤 차이가 날지 설명하세요. 미보정 실물 servo는 거절되는 것이 예상 결과입니다. 제조사 다채널 왕복 예제를 학생 임의로 실행하지 마세요.

## 6. 시험과 제출

`python -m unittest discover -s tests -v`로 시험을 실행하세요. 중단 시험에서 stop 이벤트가 마지막인지, 잘못된 마지막 명령이 앞 명령까지 막는지 설명하세요. 새 요구: “짧게 이동한 뒤 정지, 너무 긴 명령은 출발 전에 거절”. 자기 JSON과 정상·거절·중단 시험, AI 수정 요청·diff, kit/docs/checks.md를 제출하세요. 소스와 공개 가능한 문서만 Git에 포함하고 실제 접속키·보정값·캐시·누적 로그는 제외하세요.

필수 완료 기준은 PC 경로 재현, 명령 작성, 잘못된 입력 설명, 중단 정지 시험, 실물 미확인 구분입니다. 추가 도전은 리비전별 후진 번역 시험 추가와 10/29 상태 전송 필드 설계입니다. 실물 장비가 준비된 조는 감독 주행 관찰을 추가하되 미준비 조의 소프트웨어 성취와 구별해 평가합니다.
