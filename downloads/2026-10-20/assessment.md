# 2026-10-20 확인·평가

공식 수료 기준이 아닌 형성평가입니다. 개인 설치 성공만으로 개념 이해를 판단하지 않습니다. 학생은 직접 수정·예상·대조·설명을 수행합니다.

## 최종 제출

- work의18활동 답칸과 직접 수정한 예제 복사본
- 바꾼 파일·입력·예상·실제 결과를 연결한 검수 기록
- 완료 범위·실제 실행 방식·아직 확인하지 않은 조건의 인수인계

## 판단 방법

스스로 설명함 / 예를 보고 설명함 / 다시 연습 필요를 각 구간에 기록합니다. 결과가 틀렸더라도 근거를 찾아 수정하고 다시 확인한 과정을 남깁니다. 관찰하지 않은 출력을 실제 실행으로 쓰지 않습니다. 빠른 학생의 확장은 필수 기준에 포함하지 않습니다.




## 개념 보충 전이 문제 · 독립 추가 복습

교시별 필수 설명을 다른 상황에 적용하는 추가 복습입니다. 50분 필수 경로에 모두 포함되어 완수된 것으로 처리하지 않습니다. 답안은 먼저 학생이 작성하고 이후 아래 해설을 대조합니다. 설치·계정 성공 여부와 판단 근거를 분리합니다.

### 전이 1 · 작업 요청과 공유 자료

**문제:** 온도 경계 오류를 맡길 때 고객 연락처, 실제 API 키, 현재 함수, 가상 검사 입력, 실패 로그 중 무엇을 제공하나요? 다섯 줄 요청을 작성하세요.

**해설·확인 기준:** 현재 함수·가상 검사 입력·비밀을 제거한 실패 로그를 제공합니다. 목적·대상·유지 조건·허용 행동·검증을 씁니다. 실제 키와 고객 연락처는 이번 문제의 근거에 필요하지 않습니다. 자료를 많이 보내는 것이 목표라는 답은 부족합니다.

### 전이 2 · 새 경계 규칙

**문제:** 업무 규칙은 5 초과 점검입니다. 4.9·5·5.1과 None의 기대를 쓰고 28 이상 주의 규칙과 비교 기호 차이를 설명하세요.

**해설·확인 기준:** 정상·정상·점검이며 누락은 별도 미측정입니다. 초과는 >, 이상은 >=입니다. 함수 출력 문자열은 새로운 업무 계약에 맞게 명시합니다. 기준과 기호를 함께 설명하면 충족입니다.

### 전이 3 · 주장과 근거

**문제:** 응답은 “수정·검사·실제 운영 모두 완료”라고 합니다. 제공 근거는 코드 diff와 로컬 가상 검사 출력뿐입니다. 보고할 수 있는 범위와 남은 질문을 쓰세요.

**해설·확인 기준:** 실제 변경과 해당 로컬 검사 결과까지 보고하고 실제 장비·서비스 운영은 미확인으로 남깁니다. 대상 파일·명령·입력이 필요합니다. 증거 부족을 자동 실패라고 단정하지 않습니다.

### 전이 4 · 잘못된 입력의 해석

**문제:** 0·None·True·문자 "28"·50·51을 현재 분류 계약으로 판단하고 종류 검사를 비교보다 먼저 해야 하는 이유를 쓰세요.

**해설·확인 기준:** 정상·미측정·입력 오류·입력 오류·주의·입력 오류입니다. 문자나 불리언은 허용한 정확한 숫자 종류가 아니며 문자 비교는 예외를 낼 수 있습니다. None을 0으로 바꾸면 측정과 누락을 합칩니다.

### 전이 5 · 재현 가능한 보고

**문제:** 입력 문자 "뜨거움"에서 TypeError가 관찰되었습니다. 다른 사람이 재현할 수 있는 보고와 수정 뒤 회귀 확인 두 사례를 쓰세요.

**해설·확인 기준:** 파일·현재 위치·명령·입력·기대 입력 오류·실제 TypeError·관찰 방식을 씁니다. 종류 검사 누락은 코드 확인 전 가설입니다. 기존 28 경계와 None 등을 다시 확인하여 이전 계약을 보존합니다.

### 전이 6 · 기본값과 특정 호출

**문제:** 특정 장소만 기준 30입니다. classify(28)과 classify(29.9,threshold=30)의 기대를 쓰고 인계에 남길 미확인 범위 두 개를 제시하세요.

**해설·확인 기준:** 기본 호출은 주의, 기준 30 호출은 정상입니다. 기본값 28을 유지하고 특정 호출 인수를 지정합니다. 실제 AI 서비스 연결과 실제 센서 운영은 미확인입니다. 기본 전체 변경은 별도 요구라는 점을 설명하면 충족입니다.
