# E10 · README와 설계·작업 기록의 역할

다른 사람과 에이전트가 같은 기준으로 작업할 수 있게 기록합니다.

## 파일 구조

```text
starter/
├─ README.md              # 실행과 사용 방법
├─ AGENTS.md              # 지원 도구의 작업 지침
├─ app.py                 # 창과 버튼
├─ inventory.py           # 대여·반납·저장
├─ data/equipment.json    # 장비 자료
└─ docs/
   ├─ requirements.md     # 무엇이 되어야 하나
   ├─ design.md           # 어떤 구조로 만들까
   ├─ tasks.md            # 어떤 순서로 구현할까
   └─ progress.md         # 지금 어디까지 했나
```

`docs` 안의 파일 이름은 이 수업의 정리 방법입니다. 파일명만으로 모든 에이전트가 자동으로 읽는 특별한 기능은 아닙니다. 요청이나 프로젝트 지침에서 읽을 파일을 지정합니다.

## 문서를 나누는 이유

README에 모든 대화와 설계 고민을 붙이면 실행 방법을 찾기 어렵습니다. 실행자는 README, 다음 기능 구현자는 요구사항과 설계, 이어받는 사람은 진행 기록을 먼저 봅니다.

## 실행 안내 작성 예

```markdown
# 실습실 장비 대여
Python 표준 라이브러리로 실행한다.

## 실행
starter 폴더에서 `py app.py`를 실행한다.

## 자료
data/equipment.json의 장비를 표시한다.
대여·반납 이후 저장하고 다음 실행에서 복원한다.
```

## 작업 목록 작성 예

```markdown
- [ ] R02: checkout 구현 — 정상·재고0·없는 번호 시험
- [ ] R04: 반납 구현 — 전체 수량 초과 방지
- [ ] R05: JSON 저장·복원 — 재실행 후 수량 유지
```

## 직접 해 보기

README만 보고 옆 사람이 실행할 수 있게 운영체제, 실행 폴더, 명령, 데이터 위치를 적습니다. 이어서 tasks에 한 작업의 완료 기준을 붙입니다.

## 에이전트에게 검토 맡기기

```text
README.md만 보고 처음 실행할 때 빠진 단계가 있는지 검토해.
실제 폴더 구조와 실행 명령을 대조해.
docs/tasks.md의 각 항목에 완료를 확인할 방법이 있는지도 봐 줘.
문서를 수정하기 전에 발견한 문제와 근거를 보고해.
```

## 확인

“완료” 표시는 코드 작성뿐 아니라 실행 결과를 근거로 합니다. 시험을 하지 못했다면 이유와 다음 확인 방법을 progress에 남깁니다.

[Markdown 기본 문법](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)
