# E15 · diff·테스트·오류 재현으로 검토하기

완료 보고를 실제 코드와 실행 결과로 확인합니다.

## 세 가지를 나눠 확인

**코드가 바뀜 → 실행됨 → 요구사항을 만족함**은 서로 다른 단계입니다. 창이 열려도 재고가 음수가 되면 실패입니다. 테스트가 있어도 실행하지 않았다면 통과 여부를 모릅니다.

## 변경 사항 보기

Git 저장소에서는 소스 제어의 변경 파일을 누르거나 터미널에서 확인합니다. Git 저장소가 아니라면 수정 전 파일을 따로 보존하고 비교하세요.

```powershell
git status
git diff -- inventory.py app.py
```

`status`는 바뀐 파일, `diff`는 실제 변경 줄을 보여 줍니다. 프로젝트와 관계없는 파일 삭제·새 의존성·JSON 필드 변경이 생겼는지 확인합니다. diff만으로 동작을 증명할 수는 없습니다.

## 시험 실행

비교용 완성본인 `reference` 폴더에서 실행하면 제공한 기준 동작을 확인할 수 있습니다. `starter`에서는 구현을 완성한 뒤 같은 시험으로 확인합니다. 연결 전 함수에 대한 실패는 구현할 부분을 보여 줍니다.

```powershell
py -m unittest -v
py app.py
```

첫 명령은 자동 시험, 둘째는 화면 확인입니다. 자동 시험은 계산과 파일 처리를 확인하며 실제 버튼·글자 크기·선택 상태는 화면에서 별도로 확인합니다.

## 시험 사례

| 입력 상태 | 행동 | 예상 |
|---|---|---|
| 전체2·남은1 | 대여 | 남은0 |
| 전체2·남은0 | 대여 | 안내,0 유지 |
| 전체2·남은2 | 반납 | 안내,2 유지 |
| 없는 번호 | 대여 | 안내,모든 자료 유지 |
| 정상 대여 후 종료 | 재실행 | 저장된 수량 복원 |
| 잘못된 JSON·잘못된 수량 | 읽기 | 오류 안내,원본을 임의 초기화하지 않음 |

## 검토 요청

```text
docs/requirements.md의 R01~R05와 현재 diff를 대조해.
정상 동작뿐 아니라 재고0·전체 반납·잘못된 JSON을 확인해.
문제가 있으면 파일·위치·재현 입력·예상과 실제를 보고해.
먼저 검토만 하고 코드 수정은 하지 마.
실행한 시험과 실행하지 못한 화면 확인을 나눠 줘.
```

## 직접 오류 만들기

개인 연습 복사본에서 재고0 검사를 제거하고 시험을 실행하세요. 음수가 되는 사례를 잡는지 확인한 후 복구합니다. 원본 수업 자료를 덮어쓰지 않습니다.
