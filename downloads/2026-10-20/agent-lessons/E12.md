# E12 · Skill로 반복 작업 절차 만들기

매번 길게 쓰던 검토 절차를 이름 붙여 재사용합니다.

## Skill이 필요한 때

프로젝트 규칙은 늘 적용할 원칙입니다. Skill은 특정 작업을 할 때 꺼내 쓰는 절차입니다. 예를 들어 “Python 코드 검토”에는 입력 검사, 경계값, 저장 실패, 시험 결과를 보는 순서를 담을 수 있습니다.

Codex 예시에서는 프로젝트의 `.agents/skills/review-inventory/SKILL.md`를 사용합니다. 지원 도구와 버전에 따라 탐색 위치·호출 방법이 다릅니다. 예제 폴더를 만들었다는 사실과 실제 발견·실행됐다는 사실을 구분합니다.

## SKILL.md 예시

```markdown
---
name: review-inventory
description: 장비 대여 코드의 수량 조건과 저장 동작을 검토한다.
---

# 검토 순서
1. docs/requirements.md의 완료 조건을 읽는다.
2. 대여·반납 전후의 수량을 추적한다.
3. 재고0, 전체 반납, 없는 번호, 잘못된 자료를 확인한다.
4. 기존 시험을 실행하고 누락된 사례를 제안한다.
5. 문제 위치·재현 입력·예상과 실제 결과를 보고한다.
코드 수정은 별도 요청이 있을 때 수행한다.
```

위쪽 `---` 사이에는 이름과 용도를 적습니다. 아래에는 실제 절차를 적습니다. 도구는 Skill 설명을 통해 관련성을 판단할 수 있으며, 모든 Skill 본문을 항상 대화에 넣는 방식과는 다를 수 있습니다.

## 사용해 보기

```text
review-inventory Skill을 사용할 수 있는지 확인해.
가능하면 이 Skill로 inventory.py를 검토하고 수정은 하지 마.
읽은 요구사항, 실행한 시험, 발견한 문제를 나눠 보고해.
발견되지 않으면 지원 경로를 확인하고 임의로 실행했다고 하지 마.
```

Skill이 지원되지 않으면 같은 본문을 요청문에 붙여 넣어 절차 자체를 연습할 수 있습니다. 이때는 Skill 자동 발견을 확인한 것으로 기록하지 않습니다.

## 직접 확장

CSV 내보내기 검토 절차를 만들어 보세요. 열 이름, 한글 인코딩, 빈 목록, 원본 JSON 유지, 실제 출력 파일 확인을 포함합니다.

## 확인

검토 결과가 “좋습니다”로 끝나지 않고 요구사항·재현 입력·파일 위치에 연결돼야 합니다. 검토 도구를 추가해도 실행 결과 확인은 필요합니다.
