# E09 · 컨텍스트를 고르고 작업을 이어 가기

대화 전체를 믿고 맡기기보다 다음 작업에 필요한 근거를 전달합니다.

## 컨텍스트란

현재 요청을 이해할 때 참고하는 자료입니다. 대화, 파일, 코드 선택 영역, 프로젝트 지침, 오류 출력, 도구 결과가 포함될 수 있습니다. 토큰은 모델이 문장을 처리하는 단위이며, 한 번에 다룰 수 있는 양에는 한도가 있습니다.

파일 이름을 말했다고 파일 전체가 읽혔다고 가정하지 마세요. `@` 파일 참조·선택 영역·폴더 참조 방식은 도구별로 다릅니다. 실제 참조 목록과 도구 기록에서 무엇을 읽었는지 확인합니다.

## 무엇을 넣고 뺄까

| 작업 | 필요한 것 | 보통 먼저 뺄 것 |
|---|---|---|
| 수량 오류 수정 | 요구사항, 관련 함수, 재현 입력, 전후 결과 | 다른 날짜 수업 전체 |
| 화면 개선 | 현재 화면, 크기 조건, app.py | 무관한 설치 로그 |
| 저장 복원 | JSON 예시, 읽기·쓰기 함수, 오류 전문 | 옛 설계의 중복 사본 |

오류는 마지막 줄만 남기기보다 원인을 찾을 수 있는 호출 경로와 함께 전달합니다. 개인정보나 인증값은 제거합니다.

## 작업이 길어졌을 때

```text
다음 대화에서 이어갈 수 있도록 docs/progress.md를 갱신해.
확정한 결정, 완료한 변경, 실행한 시험, 미해결 문제,
재현 명령과 다음 작업 하나를 구분해.
추정과 확인된 사실을 섞지 마.
```

새 대화에서는 이렇게 시작합니다.

```text
AGENTS.md와 docs/requirements.md, docs/progress.md를 읽어.
지난 결정을 요약하고 실제 코드와 다른 점이 있는지 확인해.
아직 구현하지 말고 다음 작업 한 개의 계획을 작성해.
```

## 직접 비교

기록 없이 “아까 하던 거 계속해”라고 요청한 답과 위 요청을 비교하세요. 이어갈 작업·파일·완료 조건이 구체적인지 봅니다. 일부러 새 대화를 열어 보되 기존 대화는 삭제할 필요가 없습니다.

## 흔한 오해

자동 요약·압축이 모든 세부 사항을 보존하지는 않습니다. 중요한 요구사항과 결정은 파일에 남기고 최신 코드를 기준으로 다시 확인합니다. 프로젝트 문서도 낡을 수 있으므로 문서와 코드가 다르면 차이를 해소합니다.
