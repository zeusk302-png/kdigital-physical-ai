# E11 · AGENTS.md와 도구별 지침 파일

프로젝트 전체 규칙과 역할별 에이전트 설정을 구별합니다.

## 이름이 비슷해도 다릅니다

| 파일 | 읽는 대상과 역할 |
|---|---|
| AGENTS.md | Codex 등 지원 도구의 작업 지침. 복수형 이름 사용 |
| CLAUDE.md | Claude Code의 지속적인 프로젝트 지침 |
| .github/copilot-instructions.md | Copilot의 저장소 지침 |
| .cursor/rules/*.mdc | Cursor의 범위별 규칙 |
| GEMINI.md | Gemini CLI의 문맥·지침 |
| .github/agents/reviewer.agent.md | 지원되는 VS Code 환경의 특정 역할 에이전트 정의 |

`agent.md`라는 파일을 아무 폴더에 넣으면 모든 도구가 같은 방식으로 읽는 것은 아닙니다. `AGENTS.md`는 프로젝트 규칙, `reviewer.agent.md`는 검토자 같은 역할 정의로 구분하세요. 적용 위치와 우선순위는 사용 도구의 문서에서 확인합니다.

## 프로젝트 지침 예시

```markdown
# 작업 지침
## 먼저 읽기
README.md, docs/requirements.md, docs/design.md를 읽는다.

## 구현 규칙
Python 표준 라이브러리를 사용한다.
화면은 app.py, 수량 계산과 저장은 inventory.py에서 처리한다.
equipment.json의 id/name/total/available 필드 이름은 유지한다.
현재 요청과 관계없는 파일은 수정하지 않는다.

## 완료 확인
정상·잘못된 입력·경계값을 확인한다.
실행 명령과 결과를 보고하고, 실행하지 못한 것은 구분한다.
```

## 어디에 두나

실습은 `starter/AGENTS.md`를 기준으로 합니다. 다른 도구를 사용한다면 지원 파일로 필요한 규칙을 옮기고 중복 지침의 충돌을 피합니다. Codex는 프로젝트·하위 폴더 지침 등을 조합하므로 적용된 규칙을 확인하세요. 모든 세부 우선순위를 외우기보다 현재 작업 위치와 범위를 먼저 봅니다.

## 직접 해 보기

“JSON 필드 이름 유지” 규칙이 없는 상태에서 설계 제안을 받고, 규칙을 읽게 한 뒤 다시 제안받습니다. 최종 판단은 계획과 diff에서 합니다. 지침을 읽었다는 답변만으로 준수를 판정하지 않습니다.

## 보안 설정과 구분

지침은 행동을 안내하는 텍스트입니다. 파일 접근·명령 실행·외부 전송의 실제 허용 범위는 도구 권한 설정에서 정합니다. “비밀을 보내지 마” 한 줄로 접근 제어가 완성되지는 않습니다.
