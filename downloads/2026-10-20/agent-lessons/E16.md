# E16 · 변경 요청을 나누고 다음 작업 전달하기

작동하는 작은 결과를 유지하면서 기능을 늘립니다.

## 변경 요청 예

기본 대여·반납이 동작한 뒤 “장비명 검색과 CSV 내보내기를 추가해 주세요”라는 요청이 왔다고 가정합니다. 두 기능을 한꺼번에 바꾸기보다 서로 독립적으로 확인할 작업으로 나눕니다.

| 작업 | 유지할 것 | 완료 조건 |
|---|---|---|
| 검색 | 원본 목록·장비 번호·수량 | 검색어와 일치하는 이름만 표시,빈 검색이면 전체 |
| CSV 내보내기 | 원본 JSON·현재 수량 | 정해진 열,한글 표시,빈 목록 처리 |

검색된 목록만 JSON에 저장하면 나머지 장비가 사라질 수 있습니다. 화면에서 보이는 목록과 저장 원본을 구분하는 설계가 필요한 이유입니다.

## 작은 작업으로 나누는 요청

```text
검색과 CSV 내보내기를 추가하려고 해.
현재 요구사항과 파일 구조를 먼저 확인해.
두 기능을 독립적으로 구현·시험할 작업으로 나눠 줘.
각 작업에 수정 파일·완료 조건·회귀 시험을 적어.
우선 검색 계획만 세우고 구현은 하지 마.
```

회귀 시험은 기능을 추가한 뒤 기존 대여·반납이 망가지지 않았는지 다시 확인하는 것입니다. 새 버튼만 확인하고 끝내지 않습니다.

## 인수인계 문서 예

```markdown
# 진행 기록
## 확정 결정
- 장비는 id로 구분하고 원본 JSON 필드 이름을 유지한다.
## 완료
- 재고가 있는 장비 대여, 재고0 거부, 반납 상한 검사.
## 확인 근거
- 실제 실행 명령과 결과를 여기에 적는다.
## 미완료
- 장비명 검색과 CSV 내보내기.
## 다음 작업
- 검색어가 빈 경우 전체 목록 표시부터 구현한다.
## 주의
- 검색 결과만 원본 JSON에 저장하지 않는다.
```

위 문서의 시험 결과를 복사해 채우지 마세요. 본인이 실행한 결과를 적습니다.

## 마지막 실습

요구사항·설계·지침·작업 요청·변경 diff·시험 기록을 묶습니다. 새 대화에서 문서만 읽게 한 뒤 다음 작업을 정확히 이어 갈 수 있는지 확인합니다.

## 마무리 질문

1. 에이전트가 만든 코드 중 실제로 확인한 부분은 어디인가요?
2. 재고0 조건은 어느 문서에 있고 어느 시험으로 확인하나요?
3. 다음 사람이 같은 폴더에서 실행하려면 무엇이 필요한가요?

이 세 질문에 파일과 실행 결과를 근거로 답할 수 있으면 이번 실습의 흐름을 설명할 수 있습니다.
