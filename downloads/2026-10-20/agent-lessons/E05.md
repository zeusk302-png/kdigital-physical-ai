# E05 · 설명·계획·수정·실행·검토를 나누기

한 번에 전부 맡기기 전에 지금 어떤 작업을 하는지 구분합니다.

## 다섯 가지 작업

| 작업 | 요청 예 | 눈으로 확인할 결과 |
|---|---|---|
| 설명 | 대여 버튼이 호출하는 함수를 찾아 줘 | 실제 파일·함수와 설명의 일치 |
| 계획 | 수량 검사 구현 순서를 적어 줘 | 수정 파일·조건·시험 목록 |
| 수정 | checkout 함수만 구현해 줘 | 해당 함수의 diff |
| 실행 | 테스트를 실행해 줘 | 명령·종료 상태·출력 |
| 검토 | 재고 0일 때 잘못된 처리가 있는지 찾아 줘 | 재현 입력·문제 위치·영향 |

`diff`는 바꾸기 전과 후의 차이입니다. 삭제와 추가가 보이는 화면에서 의도한 부분만 변경됐는지 살펴봅니다. 실행 요청을 했더라도 에이전트가 실행할 권한이나 도구가 없다면 방법 설명만 받을 수 있습니다.

## 계획부터 받기

```text
inventory.py의 checkout 함수를 완성하려고 해.
지금은 수정하지 말고 다음을 작성해.
1. 현재 구현 상태
2. 수정할 함수와 유지할 입력·출력 형식
3. 정상·재고0·없는 장비 번호의 예상 동작
4. 이 동작을 확인할 명령
```

## 구현을 맡기기

```text
방금 계획에서 checkout 함수만 구현해.
app.py의 화면 배치와 장비 데이터의 필드 이름은 유지해.
바뀐 부분을 보여 주고, 직접 실행한 시험과 미실행 시험을 구분해.
```

## 권한과 완료는 다릅니다

설명만 허용, 파일 수정 허용, 명령 실행 허용, 외부 접근 허용은 서로 다른 범위입니다. 화면에 표시되는 승인·권한 옵션을 확인합니다. 지침 파일에 “안전하게 해”라고 적는 것으로 실제 권한이 제한되지는 않습니다.

## 직접 해 보기

계획에서 수정 파일이 너무 많으면 “왜 필요한가?”를 질문하세요. 이번 기능과 관계없는 폴더 정리나 새 프레임워크 설치가 끼어 있으면 범위를 다시 좁힙니다.

## 확인 질문

“테스트 코드를 작성했다”와 “테스트를 실행해 통과했다”는 무엇이 다른가요? 답변에서 실행 명령과 출력이 없는 경우 실제 실행 여부를 다시 확인합니다.
