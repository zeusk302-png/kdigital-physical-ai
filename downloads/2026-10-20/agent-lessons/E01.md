# E01 · 채팅과 코드 에이전트는 어떻게 다른가

답변을 받는 것과 프로젝트 파일을 수정하고 실행하는 것은 다른 작업입니다.

## 먼저 구분할 네 가지

| 말 | 쉬운 설명 | 이번 수업에서 보는 것 |
|---|---|---|
| 모델 | 질문을 해석하고 답을 만드는 바탕 | 도구 안에서 선택하는 모델 |
| 채팅 | 사람이 메시지를 주고받는 창 | 설명이나 계획을 요청하는 화면 |
| 개발 도구·IDE | 파일을 열고 코드를 작성·실행하는 작업실 | VS Code |
| 에이전트 | 허용된 도구로 자료를 읽고 작업을 이어 가는 기능 | 파일 검색·수정·터미널 실행 |

에이전트가 “고쳤습니다”라고 답해도 실제 파일이 바뀌었는지, 실행 결과가 맞는지는 따로 확인해야 합니다. 반대로 일반 채팅도 연결된 도구에 따라 파일을 다룰 수 있습니다. 제품 이름보다 **현재 사용할 수 있는 도구와 권한**을 봅니다.

## 같은 요구를 다르게 해 보기

첫 요청은 설명만 받습니다. 프로젝트 폴더를 연 뒤 에이전트 입력창에 붙여 넣으세요.

```text
이 폴더의 프로그램이 하는 일을 처음 배우는 사람에게 설명해 줘.
아직 파일을 수정하거나 명령을 실행하지 마.
실행 시작 파일과 데이터 파일을 찾아 설명하고,
실제로 읽은 파일 이름을 함께 알려 줘.
```

다음에는 작업 계획을 받습니다.

```text
장비를 선택하고 대여 버튼을 누르면 재고가 1 줄어들게 하려면
어디를 바꿔야 하는지 조사해 줘. 이번에는 계획만 작성해.
화면 처리와 수량 계산을 나눠 설명해 줘.
```

## 예상 결과와 확인

답변에 `app.py`, `inventory.py` 같은 실제 파일 이름과 역할이 있어야 합니다. 파일을 열어 답변과 대조하세요. 설명 요청만 했는데 파일 수정이 나타났다면 변경 내용을 먼저 검토하고 유지 여부를 정합니다.

## 직접 바꿔 보기

두 번째 요청에서 “계획만 작성해”를 “대여 기능만 구현해”로 바꾸면 어떤 작업이 추가될지 먼저 예상하세요. 바로 실행하기 전에 파일 수정과 터미널 실행이 각각 허용되는 상태인지 확인합니다.

## 막혔을 때

프로젝트가 안 보인다는 답이면 VS Code의 파일 → 폴더 열기로 압축을 푼 폴더를 여세요. 웹 채팅에 파일 이름만 적는 것으로 로컬 파일을 읽게 되지는 않습니다.
