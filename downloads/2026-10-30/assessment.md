# 평가 · 프로젝트 기획

이 평가는 멋진 기능 목록의 길이보다 **누가 겪는 어떤 문제를, 어떤 근거로, 어디까지 해결하고, 어떻게 확인할지** 설명할 수 있는지 확인합니다. 오늘 완성할 결과는 검토 가능한 기획서입니다. 기획서 작성만으로 제품 구현이나 현장 검증을 마쳤다고 표시하지 않습니다.

## 준비와 제출 방법

1. 예제 ZIP을 푼 폴더의 `work/project-charter.md`를 엽니다. 기획서는 프로젝트의 목적·범위·확인 방법을 함께 적는 문서입니다.
2. 활동 기록에서 문제 근거, 요구사항, 데이터와 처리 흐름, 시험 계획, 작업과 위험을 가져와 기획서를 채웁니다. 복사한 내용도 서로 같은 대상과 범위를 말하는지 확인하세요.
3. `work/A17_worksheet.md`에 2분 발표문과 동료 질문·답변을 기록합니다. 혼자 수행한다면 예상 검토 질문과 자신의 답변을 적고 “자체 검토”라고 표시합니다.
4. `work/A18_worksheet.md`에는 수정 전후 내용, 수정 이유, 남은 질문과 다음 작업을 적습니다.

제출 묶음은 **기획서 + 요구사항·시험 연결표 + 데이터·흐름 설명 + 작업·위험 계획 + 2분 발표문 + 질문·수정 기록**입니다. 기획서 안에 모두 포함되어 있다면 같은 내용을 별도 파일로 중복 작성할 필요는 없습니다.

## 반드시 연결할 내용

- **문제와 근거:** 사용할 사람과 구체적인 상황을 적고, 제공된 가상 사례의 근거 ID를 연결하세요. 관찰한 사실, 그에 대한 해석, 아직 확인하지 않은 가정을 나눕니다.
- **범위와 요구사항:** 이번에 포함할 일과 제외할 일을 적습니다. R01~R04처럼 번호가 있는 요구사항은 결과를 보고 충족 여부를 판단할 수 있게 씁니다.
- **데이터와 흐름:** 식별에 쓸 키, 허용하는 값, 빈값과 중복 처리, 입력 → 처리 → 출력 흐름을 적습니다. 오류가 생겼을 때 사용자에게 보여 줄 내용도 포함합니다.
- **검증:** 각 요구사항에 T01~T04처럼 시험 번호를 연결하고, 시험 입력·기대 결과·실행 여부·관찰 결과를 구분합니다. 실행하지 않은 시험은 “미실행”입니다.
- **실행 계획:** 작업의 순서, 먼저 끝나야 하는 일, 담당 또는 필요한 역할, 위험과 대안, 다음 사람이 받을 파일을 적습니다. 팀과 일정이 정해지지 않았다면 가정과 확정할 질문을 표시합니다.

## 채점 기준 · 100점

| 관점 | 배점 | 충분한 근거의 기준 |
|---|---:|---|
| 문제와 사용자 | 20 | 사용 상황·문제·근거 ID가 연결되고 관찰과 가정을 구분한다. |
| 범위와 요구 | 20 | 포함·제외 범위와 관찰 가능한 요구사항이 일치한다. |
| 데이터와 흐름 | 20 | 키·허용값·누락·중복·실패 경로를 입력과 출력에 연결한다. |
| 검증과 경계 | 20 | 요구사항마다 시험 입력과 기대 결과가 있고 통과·실패·미실행을 구분한다. |
| 실행 계획 | 20 | 작업 순서·선행 조건·담당·위험·인수인계가 기획 범위에 맞는다. |

각 관점은 **0점: 근거나 결정이 없음 / 10점: 일부 연결되지만 핵심 내용이 빠짐 / 20점: 근거·결정·확인 방법이 일치**로 채점합니다. 자세한 판단 예시는 [기획 평가표](examples/course/data/rubric.md)에 있습니다. 70점 이상이고 가상·실제 근거와 통과·미실행을 구분하면 기본 목표에 도달한 것으로 봅니다.

## 설명으로 확인하는 질문

1. 해결할 “문제”와 만들 “기능”은 어떻게 다른가요? 자신의 기획서에서 한 문장씩 골라 설명하세요.
2. 제공 사례에서 직접 확인한 내용과 자신의 가정을 하나씩 찾을 수 있나요?
3. 같은 식별 키를 가진 기록이 두 개 들어오면 어떤 문제가 생기며, 기획서에는 어떤 처리 규칙이 필요한가요?
4. 아직 실행하지 않은 시험을 “통과”로 적을 수 없는 이유는 무엇인가요?
5. 포함 범위를 바꾸면 요구사항·데이터·시험·작업 계획 중 어떤 문서를 함께 바꿔야 하나요? 실제 수정한 항목을 연결하세요.

## 최종 점검과 보완

기획서만 읽은 다른 사람이 입력과 결과, 완료 조건, 다음 작업을 설명할 수 있는지 확인합니다. 가장 약한 항목 하나를 고르고 “무엇이 빠졌고, 어떤 근거를 더해, 어떻게 고쳤는지”를 A18에 적으세요. 실제 개발 기간·장비·기관 조사는 미확정이면 그대로 표시합니다. 정답 예시와 강사 채점 설명은 별도의 강사용 자료에 있습니다.


## 새 상황으로 옮겨 보는 전이 문제 · 복습·도전

교시당 한 문제이며 기존 필수 평가 후 필요에 따라 선택합니다. 독립 작성 또는 판단을 먼저 기록한 뒤 해설을 확인합니다. 설치 실패나 장비 부재는 개념 오답과 구분합니다.

### 전이 1 · 1교시

창고 직원이 재고 확인에 오래 걸립니다. 관찰·문제·가설·기능을 분리해 쓰세요.

<details><summary>정답과 해설</summary>

관찰은 확인 시간 기록, 문제는 찾기 지연, 가설은 부족 목록이 시간을 줄인다는 주장, 기능은 목록 표시입니다. 미측정 효과를 사실로 쓰지 않습니다.

</details>

### 전이 2 · 2교시

필요성·실현·시험 점수 3,4,4에 가중치 .4,.35,.25를 적용하고 관찰 가능한 요구를 하나 쓰세요.

<details><summary>정답과 해설</summary>

1.2+1.4+1=3.6입니다. 예: 누락 행 입력 시 검토 필요 문구 표시. 점수는 성공 확률이 아닙니다.

</details>

### 전이 3 · 3교시

loan_id가 A,B,A이고 item_id가 X,X,Y인 새 파일의 충돌과 실패 화면을 설계하세요.

<details><summary>정답과 해설</summary>

첫째·셋째 기록 키 A가 충돌합니다. 중복 ID와 이유를 오류로 표시하고 두 X는 별도 대여일 수 있으므로 자동 거절하지 않습니다.

</details>

### 전이 4 · 4교시

시험 5개 중 통과2·실패1·미실행2입니다. 계획 대비와 실행 대비 통과를 설명하세요.

<details><summary>정답과 해설</summary>

계획 대비 2/5, 실행 비교 대비 2/3입니다. 분모를 명시하며 실제 제품 완성도나 사용성으로 해석하지 않습니다.

</details>

### 전이 5 · 5교시

10시간·가정 시급2만원·여유10%의 견적과 추가 기능의 영향을 쓰세요.

<details><summary>정답과 해설</summary>

기본20만원+여유2만원=22만원입니다. 추가 기능은 데이터·오류·시험·문서 작업을 포함해 재산정하고 별도 비용 포함 여부를 적습니다.

</details>

### 전이 6 · 6교시

CSV 기획에 자동 잠금 요청이 추가됐습니다. 같이 갱신할 문서와 보류 근거를 쓰세요.

<details><summary>정답과 해설</summary>

범위·요구·데이터·위험·시험·작업·견적을 검토합니다. 장비와 안전 조건이 없으면 확인 질문과 대안으로 남기며 현장 통과라고 쓰지 않습니다.

</details>
