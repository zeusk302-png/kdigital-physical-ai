# 2026-10-30 · 프로젝트 기획

좋은 기획은 기술 이름을 많이 적은 문서가 아니라, 누구의 어떤 문제를 어떤 입력과 결과로 확인할지 합의하는 자료입니다. 오늘은 가상 실습실 반납 기록을 바탕으로 작은 범위와 검증 가능한 요구를 정합니다.

## 수업의 출발점

10/8부터 익힌 데이터·코드·웹·영상·센서의 개념을 선택 가능한 수단으로 사용합니다. 이번 기획은 실물 장비가 없어도 검토할 수 있으며 실제 구현·현장 효과와 기획서 완성을 구분합니다.

## 읽는 방법

개념의 뜻을 먼저 읽고 가상 입력에서 근거를 찾습니다. 최신 운영은 50분 수업 × 6교시이며 순수 수업 300분, 중식 11:50~13:00입니다. 기존 활동은 한 교시의 개념 보충·시연·필수 적용·풀이를 위한 자료 묶음입니다. 복습·도전 문제는 진도에 따라 선택합니다. 모든 활동을 50분 안에 모두 완수한다고 가정하지 않습니다. 실제 학생 수행시간은 아직 측정하지 않았습니다.

### 1교시 필수 개념 보충 · 사용자·문제·가설을 서로 다른 문장으로 쓰기

### 실무 상황과 원리

실습실 담당자는 마감 때 대여 장부를 여러 번 확인합니다. 학생은 물건을 반납했는데 담당자는 기록을 찾지 못합니다. 여기서 “AI 카메라 만들기”를 문제라고 쓰면 왜 필요한지 알 수 없습니다. 문제는 특정 사용자가 특정 상황에서 겪는 어려움이고 기능은 그 어려움을 줄이기 위해 선택한 수단입니다.

직접 사용자는 마감 전에 미확인 기록을 찾는 담당자로 정합니다. 학생은 기록에 영향을 주는 참여자, 시설 담당자는 설치 조건을 결정하는 이해관계자입니다. 모든 역할의 요구를 한 화면에 넣기 전에 누구의 어떤 결정을 먼저 돕는지 정합니다. 결과물은 검토 가능한 기획서이고, 반납 확인 시간 감소는 구현 후 현장에서 측정할 효과입니다. 문서 작성으로 효과가 발생했다고 보고하지 않습니다.

가상 근거 E01은 20건 중 기록 지연 4건, E02는 미확인 목록이 필요하다는 문장입니다. 4÷20×100=20%는 그 가상 표본의 비율입니다. 관찰은 자료에 적힌 4건, 해석은 기록 확인이 어려울 수 있다는 설명, 가설은 미확인 목록을 만들면 확인 시간이 줄어든다는 시험할 주장입니다. 원인이 장비 부족인지 기록 습관인지 이 표만으로 알 수 없습니다. 완성 문제 문장은 “담당자가 마감 때 미확인 대여를 찾으려고 전체 기록을 다시 읽는다”입니다. 가설 문장은 “미확인만 모아 보여 주면 찾는 시간이 줄어든다”입니다. 확인 질문은 현재 확인 절차, 지연 원인, 필요한 필드와 측정 방법을 묻습니다. 가상 인터뷰를 실제 기관 요구로 인용하지 않습니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 식당 재고 담당자가 품절 목록을 늦게 확인하는 새 상황에서 사용자, 문제, 기능 후보, 시험할 가설을 서로 다른 네 문장으로 직접 작성하세요.

### 정답과 오답의 이유

사용자는 재고 담당자, 문제는 확인 지연, 기능 후보는 부족 항목 목록, 가설은 목록이 확인 시간을 줄인다는 주장입니다. “AI를 안 쓰는 것이 문제”라고 쓰거나 아직 측정하지 않은 시간 감소를 관찰 사실로 쓰면 오답입니다.

### 확인 질문과 답

1. 관찰과 가설의 차이는? → 적힌 사실과 시험할 주장입니다.
2. 20%의 범위는? → 제공된 가상 표본입니다.
3. 기획서 완료가 효과 검증인가요? → 아닙니다.

## A04 · 후보를 같은 기준으로 비교

<!-- enrichment:2026-10-30:P2 -->

### 2교시 필수 개념 보충 · 후보 비교에서 최소 범위와 요구로 이어가기

### 실무 상황과 원리

같은 문제에 목록 화면, 카메라 인식, 자동 잠금이라는 후보가 나왔습니다. 가장 화려한 기능부터 고르면 장비와 검증 조건이 없어 시작하지 못할 수 있습니다. 후보 비교는 같은 기준으로 장단점을 읽는 일입니다. 가중치는 중요도이고 점수는 근거를 갖춘 판단이며 성공 확률이 아닙니다.

완성 가상 계산에서 필요성 0.40, 실현 가능성 0.35, 시험 가능성 0.25를 사용합니다. 후보 A의 점수 5,4,5를 각각 곱하면 2.00+1.40+1.25=4.65입니다. 가중치 합은 1입니다. 점수는 실제 조사로 확정한 수가 아니라 제공 교육 사례의 판단입니다. 장비나 기간 조건이 달라지면 점수 근거와 선택을 다시 검토합니다. 소수 둘째 자리 숫자가 사람의 판단을 없애 주지 않습니다.

선택 뒤에는 최소 범위를 정합니다. 이번 포함은 로컬 CSV 한 개 읽기, 기록 검수, 미확인 목록 표시이며 제외는 카메라 인식, 자동 잠금, 외부 메시지입니다. 작은 범위도 정상과 실패 경로를 다뤄야 합니다. 요구 R1은 “제공 CSV를 읽고 각 행의 대여 ID와 상태를 표시한다”, R2는 “갱신 시각이 없는 행을 review로 표시하고 원문을 유지한다”입니다. “쉽고 빠르게 보여 준다”는 문장은 입력과 기대 결과가 없으므로 아직 시험 가능한 요구가 아닙니다. 성능 목표를 넣으려면 PC 조건, 파일 크기, 측정 시작과 끝을 함께 합의해야 합니다. 추가 카메라 요청은 기존 범위에 자동으로 포함하지 말고 데이터와 시험·일정 영향을 검토합니다.

### 새로운 입력에 직접 적용 · 복습 또는 도전

복습 문제: 새 후보 D의 점수 4,5,3에 같은 가중치를 적용하세요. “편한 화면”을 관찰 가능한 요구 하나로 다시 쓰고 현재 제외 범위 한 가지를 함께 적으세요.

### 정답과 오답의 이유

점수는 1.60+1.75+0.75=4.10입니다. 예: “시간 누락 행을 넣으면 ID와 검토 필요 문구를 표시한다.” 취향 표현만 반복하거나 점수 4.10을 성공 확률 41%로 바꾸면 오답입니다.

### 확인 질문과 답

1. 가중치 합은? → 이 예는 1입니다.
2. 최소 범위도 오류 경로가 필요한가요? → 필요합니다.
3. 제외는 가치 없다는 뜻인가요? → 현재 약속 밖이라는 뜻입니다.

의사결정표는 여러 대안을 같은 기준으로 비교하는 도구입니다. 가중치는 기준의 중요도이며 점수는 근거를 가진 판단입니다. 수치가 그 자체로 정답이나 성공 확률이 되지는 않습니다.

기술이 멋있다는 이유만으로 후보를 정하지 않고 필요성·실현 가능성·검증 가능성을 함께 봅니다.

이 조건에서는 A를 우선 검토합니다.
점수의 이유를 반드시 남깁니다.

### 구분해야 할 반례

가중합의 소수 둘째 자리 차이가 과학적 정밀도를 뜻하지 않습니다. 보드나 데이터가 확보되면 점수와 결정을 다시 검토합니다.

### 01_compare_options.py 전체

```python
import json
from pathlib import Path
root = Path(__file__).resolve().parent.parent
plan = json.loads((root / "data" / "options.json").read_text(encoding="utf-8"))
weights = plan["weights"]
for option in plan["options"]:
    score = 0
    for criterion, weight in weights.items():
        score = score + option[criterion] * weight
    print(option["id"], round(score, 2))
```

### 02_check_evidence.py 전체

```python
import json
from pathlib import Path
root = Path(__file__).resolve().parent.parent
cases = json.loads((root / "data" / "test_observations.json").read_text(encoding="utf-8"))
passed = 0
for case in cases:
    actual = case["actual"]
    if actual is None:
        result = "NOT_RUN"
    elif actual == case["expected"]:
        result = "PASS"
        passed = passed + 1
    else:
        result = "FAIL"
    print(case["id"], result)
print("passed:", passed, "/", len(cases))
```

### 5교시 필수 개념 보충 · 결과물로 작업을 나누고 견적을 계산하기

### 실무 상황과 원리

의뢰자가 “며칠이면 되나요?”라고 묻습니다. 화면 한 장만 보고 기간을 정하면 데이터 계약, 오류 처리와 시험 시간이 빠집니다. 작업은 손댈 기술 이름보다 전달할 결과물로 나눕니다. 선행 관계는 다른 작업이 시작되기 전에 합의하거나 완료해야 할 조건입니다.

완성 제작 가정은 W1 데이터 계약과 샘플 2시간, W2 검수 처리 4시간, W3 화면 3시간, W4 통합·시험·안내 3시간입니다. 한 사람이 순서대로 한다면 작업량 합은 12시간입니다. W1 뒤 W2와 W3를 나눠 진행할 수 있어도 인원이 실제로 정해지지 않았으면 달력 기간이 자동으로 줄지 않습니다. 검수 기준은 W1 샘플 승인, W2 정상과 오류 출력, W3 세 상태 화면, W4 요구별 시험과 재실행 안내로 붙입니다. 시간이 지났다는 이유만으로 결과물을 통과 처리하지 않습니다.

견적 연습은 가정 시급 30000원과 작업 12시간을 곱해 360000원입니다. 여유 20%를 계산하면 72000원, 합계 432000원입니다. 이는 교육용 계산이며 실제 계약 가격이나 시장 평균이 아닙니다. 장비·유료 API·서버·세금·수정 범위의 포함 여부는 따로 명시합니다. 새 기능을 넣으면 필요한 입력, 실패 경로, 시험과 운영 문서 작업까지 추가해 다시 계산합니다. “카메라 추가”라는 한 줄의 시간만 더하면 통합과 장비 확인이 빠질 수 있습니다. 범위가 줄었다면 무엇을 제외했는지 결과물과 시험표에도 반영합니다. 위험에 대한 여유를 넣어도 미확인 요구를 확정할 수 없으므로 확인 질문과 결정 시점을 함께 남깁니다.

### 정답과 오답의 이유

기본 200000원, 여유 30000원, 합계 230000원입니다. 장비와 서버 등 포함 여부를 표시합니다. 선행 관계와 분담, 통합 조건이 없으므로 자동 4시간은 아닙니다. 여유를 확정 수익이나 실제 리허설 시간으로 쓰면 오답입니다.

### 확인 질문과 답

### 짧은 완성 코드로 추적하기

제공 참고 파일 [code/03_estimate.py](examples/course/code/03_estimate.py)은 보존합니다. 예제 `course` 폴더에서 이 파일을 `work/03_estimate.py`에 복사하고 학생 수정본은 work에 저장합니다. 아래는 완결된 전체 코드입니다. 파일·폴더·확장자를 확인한 뒤 같은 course 폴더의 터미널에서 `python -X utf8 work/03_estimate.py`을 실행합니다. 저장과 실행은 별도 행동입니다.

```python
hours = 12
rate_won = 30000
reserve_rate = 0.20
base_won = hours * rate_won
reserve_won = base_won * reserve_rate
total_won = base_won + reserve_won
print("assumed_total_won:", round(total_won))
```

예상 출력:

```text

```

1~3행은 작업 시간·가정 시급·여유 비율을 이름에 저장합니다. 밑줄은 이름 안 단어를 연결하며 계산 기호가 아닙니다. =는 값 저장, 0.20은 20%의 소수 표현입니다. 4행의 *는 시간과 시급을 곱해 기본 비용을 계산합니다. 5행은 기본 비용에 여유 비율을 곱합니다. 6행의 +는 둘을 합합니다. 7행의 print는 터미널 출력, round는 반올림입니다. 작업 시간을 8로 바꾸면 288000원입니다. 여유 비율에 20을 넣으면 20배가 더해지므로 0.20으로 복구합니다. 이 계산은 교육용 가정이며 장비·서버·세금 포함 여부가 확정된 견적이 아닙니다.

## A17 · 짧은 발표와 동료 질문

기획 발표는 청자가 무엇을 결정하거나 질문해야 할지 알게 하는 설명입니다. 문제 근거→작은 해결 흐름→시험→미확정을 짧게 전달합니다. 학생 수 미확인이라 개인 기록 또는 짝 역할로 진행합니다.

기술 목록을 모두 읽기보다 핵심 판단과 근거를 보여 주고 빠진 조건을 질문받습니다. 설명을 통해 요구의 모호함이 드러납니다.

### 입력에서 살펴볼 예

2분 발표
30초 문제·근거
40초 입력→결과
30초 시험
20초 미확정 질문

질문자는 장점 한 개와 확인 질문 한 개를 남깁니다.
답을 모르면 확인할 자료와 담당을 적습니다.

### 구분해야 할 반례

확인하지 않은 효과나 장비 성능을 자신 있게 말한다고 좋은 발표가 되지 않습니다. 가정은 가정이라고 말합니다.

스스로 설명할 질문: 질문을 받았을 때 모르는 조건을 어떻게 기록하나요?

## A18 · 수정 이력과 인수인계

수정 이력은무엇을 왜 바꿨고 어떤 항목에 영향이 있는지 남기는 기록입니다. 인수인계는 다음 사람이같은 입력과 판정 기준으로 일을 이어갈 수 있게 하는 자료입니다.

좋은 피드백을 받고도 기획서·시험표가 따로 남으면 오래된 요구로개발할 수 있습니다. 한 결정을 관련 문서에 반영합니다.

### 입력에서 살펴볼 예

변경예: 실시간 카메라 요청 보류
이유: 모델·성능 근거 없음
영향: 범위·위험·시험
유지: 파일 입력 기본 흐름

변경 전후와 이유를 남깁니다.
최신 기획·시험·입력을 묶습니다.
미실행 항목을 마지막으로 확인합니다.

### 구분해야 할 반례

보고서에 완료라고 썼다고 제품이 구현된 것은 아닙니다. 오늘 완료 범위는 기획 자료와 제공 비교 코드의 검증입니다.

스스로 설명할 질문: 다음 팀에게 바로 넘길 수 있는 최소 묶음은 무엇인가요?
