## A01 · 프로젝트는 문제와 결과의 약속

프로젝트는 정해진 범위와 자원 안에서 특정 결과를 만드는 활동입니다. 기능은 그 결과를 만드는 수단입니다. 이사할 집의 문제를 먼저 정하고 가구를 고르듯, 기술 이름보다 해결할 일을 먼저 적습니다.

카메라나 AI를 쓰는 것 자체를 목표로 삼으면 누구에게 어떤 변화가 필요한지 확인하기 어렵습니다.

### 입력에서 살펴볼 예

가상 실습실: 반납 기록 확인이 늦음

## A02 · 사용자와 이해관계자

사용자는 결과를 직접 사용하는 사람이며 이해관계자는 영향을 받거나 조건을 결정하는 사람입니다. 같은 실습실에서도 담당자·학생·시설관리자의 관점이 다릅니다.

누구의 어떤 순간을 돕는지 정해야 화면과 데이터의 우선순위를 정할 수 있습니다. 모든 사람의 모든 요구를 한 번에 넣지 않습니다.

## A03 · 관찰·해석·가정을 나누기

관찰은 자료에 직접 적힌 내용, 해석은 관찰에서 끌어낸 설명, 가정은 아직 확인하지 않은 전제입니다. 추리에서 단서와 결론을 분리하는 것과 같습니다.

작은 표본과 가상 자료로 원인이나 개선 효과를 단정하지 않도록 근거의 강도를 구분합니다.

## A04 · 후보를 같은 기준으로 비교

의사결정표는 여러 대안을 같은 기준으로 비교하는 도구입니다. 가중치는 기준의 중요도이며 점수는 근거를 가진 판단입니다. 수치가 그 자체로 정답이나 성공 확률이 되지는 않습니다.

기술이 멋있다는 이유만으로 후보를 정하지 않고 필요성·실현 가능성·검증 가능성을 함께 봅니다.

### 입력에서 살펴볼 예

A 반납 기록 확인
B 카메라 빈칸 검출
C 온도 상태 표시
중요도: 0.40 /0.35 /0.25

제작 가정 점수: A 4.65, B 3.45, C 3.85
이 조건에서는 A를 우선 검토합니다.
점수의 이유를 반드시 남깁니다.

### 구분해야 할 반례

가중합의 소수 둘째 자리 차이가 과학적 정밀도를 뜻하지 않습니다. 보드나 데이터가 확보되면 점수와 결정을 다시 검토합니다.

스스로 설명할 질문: A가 높다는 결론은 어떤 가정에 의존하나요?

활동 연결: [입력](examples/course/data/A04_input.md) · [기록 양식](examples/course/work/A04_worksheet.md)

### 01_compare_options.py 전체

```python
import json
from pathlib import Path
root = Path(__file__).resolve().parent.parent
plan = json.loads((root / "data" / "options.json").read_text(encoding="utf-8"))
weights = plan["weights"]
for option in plan["options"]:
    score = 0
    for criterion, weight in weights.items():
        score = score + option[criterion] * weight
    print(option["id"], round(score, 2))
```

실행 조건: Python3 표준 라이브러리만 사용합니다. 네트워크·계정은 필요 없습니다.

실행 폴더: examples/course

명령: `python -X utf8 code/01_compare_options.py`

결과:

```text
A 4.65
B 3.45
C 3.85
```

각 줄의 뜻은 [코드 해설](examples/course/code/line-guide.md)에 있습니다.

작은 수정: work에 복사한 코드에서 options.json을 options_equal.json으로 바꾸면 세 기준의 같은 가중치 결과4.67·3.33·4.00입니다.

오류 복구: JSON 필드 이름과 큰따옴표를 확인합니다. 점수는 교육용 판단이며 수치가 객관적 확률이라는 뜻은 아닙니다.

상태 의미나 키가 달라지면 화면이 떠도 잘못된 대여를 갱신할 수 있습니다. 사람 이름 없이 가상대여 ID와 물품 ID로 과제를 구성합니다.

## A11 · 통과·실패·미실행을 구분

검증 결과는 기대값과 관찰값을 비교한 판단입니다. 관찰하지 않은 항목은 통과도 실패도 아닌 미실행으로 남깁니다. 아직 보지 않은 시험지를 맞았다고 채점하지 않는 것과 같습니다.

기획 단계에서 코드를 실행했다는 말의 범위를 정확히 씁니다. 제공 코드는 가상 관찰표를 비교하며 기획 제품을 구현하지 않습니다.

### 입력에서 살펴볼 예

### 구분해야 할 반례

입력표의 actual을 고쳤다고 제품 결함이 수정된 것은 아닙니다. 재시험 파일은 교육용 새 가상 기록이며 현장 증거로 사용하지 않습니다.

스스로 설명할 질문: 이 Python 실행으로 실제 확인한 것은 무엇인가요?

### 02_check_evidence.py 전체

```python
import json
from pathlib import Path
root = Path(__file__).resolve().parent.parent
cases = json.loads((root / "data" / "test_observations.json").read_text(encoding="utf-8"))
passed = 0
for case in cases:
    actual = case["actual"]
    if actual is None:
        result = "NOT_RUN"
    elif actual == case["expected"]:
        result = "PASS"
        passed = passed + 1
    else:
        result = "FAIL"
    print(case["id"], result)
print("passed:", passed, "/", len(cases))
```

실행 조건: Python3만 사용하며 제공된 가상 관찰 기록을 비교합니다. 기획한 대시보드를 구현·실행하는 코드가 아닙니다.

실행 폴더: examples/course

명령: `python -X utf8 code/02_check_evidence.py`

결과:

```text

T02 FAIL
T03 NOT_RUN
T04 PASS
passed: 2 / 4
```

각 줄의 뜻은 [코드 해설](examples/course/code/line-guide.md)에 있습니다.

작은 수정: 입력을 test_observations_retest.json으로 바꾸면4건PASS입니다. 새 파일은 재시험했다고 가정한 별도 교육 사례이며 실제 제품 통과 증거가 아닙니다.

오류 복구: None을0이나빈문자와 같게 취급하지 않습니다. expected를 actual에 맞춰 고치지 말고 관찰과 결함 원인을 남깁니다.
