# 개인 프로젝트의 실무 연결 만들기

## 준비

전체ZIP을 모두 풀고 kit/project-practice/README.md를 엽니다. templates의 필요한 파일을 개인 폴더에 복사하고,examples의 같은 이름과 비교합니다. .md는 글 파일이며 편집기에서 [작성]을 자신의 내용으로 바꿉니다.

## 직접 할 순서

1. 사용자·문제·범위·제약·판단 권한을 정합니다. 사실·가정·미확인을 나눕니다.
2. 실무 역할을 확인하고 오늘 개인 작업의 작성·검토·결정 관점을 적습니다.
3. 선택한 표준 세 가지의 적용 대상·산출물·확인 방법을 적습니다.
4. 요구 두 개 이상에 수용 기준을 쓰고 화면·구조·계약으로 연결합니다.
5. 요구 한 개의 작업·시험과 변경 영향을 같은 ID로 연결합니다.
6. 준비된 환경에서 위험한 연결 하나를 확인합니다. 실제·연습·소스 검토·미실행을 구별합니다.
7. 자기 리뷰에서 불일치 하나를 찾아 수정하고 원본·실행·미해결·첫 작업을 인계합니다.

## 최소 결과와 확인

문제·범위 / 역할·결정 / 요구 / 설계·계약 / 작업·위험 / 시험 / 연결표 / 실행·인계의 여덟 묶음입니다. 문서는 합쳐도 됩니다. 실제 장치가 막혀도 계획과 화면 작업을 진행하고 시험은 BLOCKED 또는 NOT_RUN으로 남깁니다. 실제 받은 피드백만 기록하며 짝·팀 리뷰를 했다고 가정하지 않습니다.

추가 도전은 두 번째 기능의 변경·재시험 연결,다른 관점의 구조 설명,데이터·AI 확장의 평가 카드입니다. 새 계정·유료 서비스·원격 배포는 완료 조건으로 강제하지 않습니다.
