# 프로젝트 기획 평가표

평가표는 결과물을 어떤 기준으로 볼지 미리 정한 안내입니다. 각 관점을 0·10·20점으로 평가하며 합계는 100점입니다. 표현을 길게 쓰는 것보다 서로 연결되는 근거를 남기는 것이 중요합니다.

| 관점 | 0점 | 10점 | 20점 |
|---|---|---|---|
| 문제와 사용자 | 사용자나 문제의 근거가 없다. | 사용자와 문제는 있지만 사용 상황·근거 ID·가정 구분 중 핵심이 빠졌다. | 사용 상황과 문제가 근거 ID에 연결되고 관찰·해석·가정을 구별한다. |
| 범위와 요구 | 무엇을 만들고 어디까지 할지 알 수 없다. | 포함 기능은 있지만 제외 범위나 관찰 가능한 완료 조건이 부족하다. | 포함·제외 범위가 분명하고 R01~R04 요구사항으로 충족 여부를 판단할 수 있다. |
| 데이터와 흐름 | 필요한 입력과 출력이 연결되지 않는다. | 정상 흐름은 있지만 키·허용값·누락·중복·실패 처리 중 핵심이 빠졌다. | 데이터 규칙과 입력→처리→출력 흐름이 맞고 잘못된 입력 처리도 설명한다. |
| 검증과 경계 | 시험 방법이 없거나 미실행을 통과로 적었다. | 시험은 있으나 요구사항 연결·입력·기대·실제 결과 중 핵심이 빠졌다. | 요구사항과 시험 번호가 연결되고 시험 입력·기대 결과·관찰 결과·미실행을 구분한다. |
| 실행 계획 | 다음에 누가 무엇을 할지 판단할 수 없다. | 작업 목록은 있지만 순서·선행 조건·담당·위험·인수인계 중 핵심이 빠졌다. | 기획 범위에 맞는 작업·선행 조건·역할·위험 대응·인수인계가 연결된다. |

## 평가 순서

1. 기획서와 활동 기록을 옆에 놓습니다. 위 표의 관점을 하나씩 읽습니다.
2. 각 관점의 근거가 있는 파일 이름과 문단 또는 요구사항·시험 번호를 적습니다.
3. 빠진 핵심 정보가 있는지 확인한 뒤 0·10·20점 중 하나를 고릅니다. 근거 없이 중간 점수를 주지 않습니다.
4. 가장 먼저 고칠 항목 하나와 이유를 정합니다. 수정 뒤 점수만 바꾸지 말고 실제로 바뀐 내용도 기록합니다.
