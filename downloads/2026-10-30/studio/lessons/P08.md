# P08 · 최종 리뷰·Git·개발 인수인계

기획의 모양이 아니라 다음 개발이 가능한 연결 상태를 확인합니다.

## 리뷰 순서

문제 근거 → MVP → 사용자 행동 → 화면/구조 → 시험 → 작업 순서로 설명합니다.
기술 검증의 실제 출력이나 시제품을 보여 주고 확인하지 못한 조건도 구분합니다. 기능을
많이 적었다는 이유로 완성도를 높게 판단하지 않습니다.

## 자동 점검의 범위

kit의 plan_check.py는 필수 파일, 작성 표시, 요구·시험·작업 번호 연결을 확인합니다.
통과해도 사용자의 문제가 실제라는 사실, 기술이 가능하다는 사실을 검증한 것은 아닙니다.
자동 점검은 문서 사이의 빠진 연결을 찾는 보조 도구입니다.

## 직접 수행

요구 R01을 하나 골라 관련 시험 T01과 작업 W01까지 따라 설명합니다. 연결이 없으면
문서를 보완합니다. 옆 학생이 “어느 파일부터 읽고 무엇을 구현해야 하는가”를 답할 수
있게 README와 첫 개발 요청을 고칩니다.

## Git에 올릴 것

현재 기획·출처 URL·설계·시제품 소스·시험·실행 안내·결정 기록을 올립니다. 인터뷰
개인정보·비공개 고객 원문·인증키·의존성 폴더·임시 산출물은 제외합니다. 오래된 기획
복사본을 여러 파일로 쌓기보다 Git 이력으로 변경을 남깁니다. 실제 기획과 공개 자료의
범위가 다르면 비공개 자료 위치만 설명하고 내용을 섞지 않습니다.

## 최종 제출

기획서, 화면·구조·자료 설계, 짧은 기술 검증, WBS·일정·위험, 첫 개발 지시를 묶습니다.
전체 제품이 완성되지 않았어도 무엇이 검증됐고 다음에 무엇을 해야 할지 분명해야 합니다.

## 실제 파일과 연결해서 읽기

[전체 파일 받기](../kit/tools/plan_check.py)

아래는 파일 앞부분입니다. 실행은 전체 파일로 합니다. 생략한 코드를 그대로 실행하지 마세요.

```python
"""기획의 문서 연결을 보조 점검합니다. 사업성·근거의 진실성을 자동 판정하지 않습니다."""
from pathlib import Path
import argparse,re

REQUIRED=('problem','research','requirements','user-flow','data-design','architecture','validation','roadmap','risks')
def inspect(root):
    root=Path(root);issues=[];texts={}
    for name in REQUIRED:
        file=root/'docs'/f'{name}.md'
        if not file.is_file():issues.append(f'빠진 문서: {file.name}');continue
        text=file.read_text(encoding='utf-8');texts[name]=text
        if '[작성]' in text:issues.append(f'미작성 표시: {file.name}')
        if len(text.strip())<40:issues.append(f'내용 확인 필요: {file.name}')
    reqs=re.findall(r'^\|\s*(R\d+)\s*\|',texts.get('requirements',''),re.M)
    if not reqs:issues.append('요구번호가 없습니다: R01 형식')
    if len(reqs)!=len(set(reqs)):issues.append('중복 요구번호')
    for name,code in [('validation','시험'),('roadmap','작업')]:
        refs=set(re.findall(r'\bR\d+\b',texts.get(name,'')))
        for missing in sorted(set(reqs)-refs):issues.append(f'{code} 연결 없음: {missing}')
        for unknown in sorted(refs-set(reqs)):issues.append(f'{code}에 없는 요구 참조: {unknown}')
    return issues

def main():
    p=argparse.ArgumentParser();p.add_argument('root',nargs='?',default='.')
    issues=inspect(p.parse_args().root)
    print('\n'.join(issues) if issues else '문서 연결 점검 통과. 근거·설계·실행은 별도로 검토하세요.')
    return 1 if issues else 0
if __name__=='__main__':raise SystemExit(main())
```

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
