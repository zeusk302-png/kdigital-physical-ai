# P04 · 사용자 흐름·화면·데이터 설계

화면의 버튼과 데이터의 필드가 같은 요구를 설명하게 만듭니다.

## 사용자 흐름

어디서 시작해 무엇을 선택하고 어떤 결과를 확인하는지 그립니다. 정상 경로뿐 아니라
빈 자료·잘못된 입력·취소·오류 후 복구를 포함합니다. 기능이 화면에 보인다는 사실과
사용자가 행동을 완료할 수 있다는 사실은 다릅니다.

## 화면 설계

주요 화면을 종이 또는 편집기로 그리고 제목·중요 정보·주요 행동·오류 메시지를 표시합니다.
사용자가 기술 용어를 알아야만 사용할 수 있게 만들지 않습니다. 디바이스 화면이라면
조작 상태·대기·실패·마지막 성공이 구별되는지 봅니다. 디자인 도구 이름을 배우는 것이
이 단계의 목표는 아닙니다.

## 데이터 설계

필드 이름, 뜻, 자료형, 단위, 없는 값, 식별자, 출처를 적습니다. 장치에서 측정한 값과
프로그램에서 판단한 결과를 구분합니다. 번호를 수량으로 계산하거나 검출 신뢰도를
실제 안전 확률로 표시하지 않습니다. 데이터를 모으는 방법·권한·보관 범위도 적습니다.

## 직접 수행

docs/user-flow.md와 design/wireframes에 화면을 만들고 docs/data-design.md에 필드를
정합니다. 요구 R01을 화면·필드·T01 시험과 연결해 한 줄씩 추적합니다. 사용하는 말이
문서마다 다르면 용어를 정하고 같이 수정합니다.

## 검토 질문

버튼을 눌렀을 때 무엇이 바뀌는지, 그 값은 어디에서 오는지, 실패하면 무엇을 보여 주는지
설명하세요. 구현 전에 정하지 못한 연결은 질문으로 남기고 시제품에서 확인할 대상으로
올립니다.

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
