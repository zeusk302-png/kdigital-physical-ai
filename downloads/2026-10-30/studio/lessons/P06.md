# P06 · WBS·일정·비용·위험 계획

큰 기능 이름을 실제 완료를 확인할 수 있는 작업으로 나눕니다.

## 작업 분해

“프런트 만들기”는 너무 큽니다. 목록 표시, 입력 검사, 오류 표시, 저장 조회처럼 결과를
확인할 수 있는 단위로 나눕니다. 작업번호 W01, 관련 요구 R01, 결과 파일, 담당 역할,
완료 기준, 먼저 필요한 작업을 적습니다. 한 사람이 여러 역할을 맡아도 됩니다.

## 선행 관계

UI와 서버가 함께 작업하려면 필드 계약을 먼저 맞춥니다. 장치 영상이 필요한 기능이라면
영상 입력 확인이 모델 통합보다 앞섭니다. 마지막 날에 처음 전체 연결하지 말고 가장
작은 경로를 먼저 붙여 시험할 시점을 정합니다.

## 기간과 비용

처음 해 보는 작업은 불확실성을 표시하고 실측·짧은 검증으로 조정합니다. AI가 제안한
일정을 실제 수행시간이라고 적지 않습니다. 장비·계정·유료 서비스·데이터 준비의
필요 항목과 근거를 남기며 확인하지 않은 가격을 채워 넣지 않습니다. 비용이 없어도
설치·권한·운영 시간이 필요할 수 있습니다.

## 위험과 대체 경로

위험마다 언제 확인할지, 누가 판단할지, 안 되면 무엇을 줄이거나 바꿀지 적습니다.
“잘 준비한다” 대신 “카메라 입력 실패 시 제공 영상으로 UI와 사건 처리를 검증하고
실물 영상 경로는 미완료로 남긴다”처럼 행동으로 씁니다.

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
