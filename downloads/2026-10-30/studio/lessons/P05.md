# P05 · 아키텍처와 위험한 기술 가설 검증

전체 제품을 만들기 전에 실패하면 계획이 달라질 연결 하나를 실제로 확인합니다.

## 필요한 부분만 선택

프런트·API·DB·AI·장치가 항상 모두 필요한 것은 아닙니다. 한 사용자 행동을 처리할 때
어떤 프로그램이 어느 순서로 값을 받고 보내는지 그립니다. 자동으로 연결된다고 쓰지
말고 호출·파일·통신의 실제 경계를 적습니다. 실행 위치·계정·네트워크·버전 조건을
함께 남깁니다.

## 위험한 가설 고르기

장치에서 영상을 얻을 수 있는가, 선택한 모델이 필요한 클래스를 검출하는가, 현재 PC에서
필요한 속도가 나오는가, 서버가 재시작 후 자료를 복원하는가 중 중요한 조건 하나를
고릅니다. 예쁘게 보이는 표지보다 이 조건의 실패가 계획에 미치는 영향이 큽니다.

## 짧은 검증

이전 수업 코드를 재사용하거나 prototype에 작은 실행을 만듭니다. 입력·명령·환경·예상·실제
결과를 적고 성공·실패·미실행을 나눕니다. 제공 latency_probe.py는 실제 HTTP 응답을
반복 측정하는 도구입니다. 웹 요청이 필요 없는 프로젝트는 이 도구를 쓸 필요가 없습니다.
응답200이 사용자의 과업 성공을 증명하지는 않습니다.

## 직접 작성

아키텍처 그림과 docs/validation.md에 검증할 가설·통과 기준·실패 때 변경할 범위를
적습니다. 실행 후 기준을 조용히 바꾸지 말고 왜 바꿨는지 기록합니다. 장비가 없는 부분은
미실행으로 남기고 대신 확인 가능한 코드·자료 경로를 설명합니다.

## 인수인계

시제품은 전체 제품 완성본이 아닙니다. 다음 개발자가 어떤 위험은 줄었고 어떤 위험은
남았는지 알 수 있어야 합니다.

## 실제 파일과 연결해서 읽기

[전체 파일 받기](../kit/prototype/latency_probe.py)

아래는 파일 앞부분입니다. 실행은 전체 파일로 합니다. 생략한 코드를 그대로 실행하지 마세요.

```python
"""실제 HTTP 요청의 응답 시간과 실패를 기록합니다. 결과를 미리 채우지 않습니다."""
import argparse,time,statistics,math
from urllib.request import urlopen
from urllib.error import URLError

def main():
    p=argparse.ArgumentParser();p.add_argument('url');p.add_argument('--count',type=int,default=10)
    a=p.parse_args()
    if not 1<=a.count<=50:p.error('count는1~50입니다.')
    times=[];failures=[]
    for i in range(a.count):
        start=time.perf_counter()
        try:
            with urlopen(a.url,timeout=5) as response:
                response.read();status=response.status
            elapsed=(time.perf_counter()-start)*1000
            times.append(elapsed);print(i+1,status,f'{elapsed:.2f}ms')
        except (URLError,OSError) as error:failures.append(str(error));print(i+1,'실패',error)
        time.sleep(.1)
    print('성공',len(times),'실패',len(failures))
    if times:
        print('중앙값(ms)',round(statistics.median(times),2))
        print('표본 p95(ms)',round(sorted(times)[math.ceil(.95*len(times))-1],2))
    print('HTTP 성공과 실제 사용자 과업 성공은 별도로 확인합니다.')
if __name__=='__main__':main()
```

## 실습을 끝내기 전에

먼저 실행 위치와 파일 이름을 확인합니다. 코드를 바꾸기 전 출력이나 화면을 예상하고,
실행 후 실제 결과를 비교합니다. 에이전트가 수정했다면 git diff에서 이번 요구와 무관한
변경이 섞이지 않았는지 봅니다. 다음 단계가 막힐 때는 현재 작업을 보존하고 실행 가능한
기준본과 비교하되, 기준본을 실행한 결과와 내가 구현한 결과를 구분합니다.

결과 기록에는 내가 바꾼 파일, 입력과 조건, 실제 결과, 실패한 것과 다음 확인을 적습니다.
설명문을 길게 쓰는 대신 코드·실행 명령·짧은 화면 또는 출력으로 확인할 수 있게 남깁니다.
