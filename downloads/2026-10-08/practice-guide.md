# 데이터 기초 실습 워크북 · 의미와 종류에서 CSV·JSON까지

코딩을 처음 배우는 학생을 위한 데이터 기초 수업입니다. **50분씩 6교시로 운영하며 중식은 11:50~13:00입니다.** 각 활동에서 설명을 듣고 예를 비교한 뒤 직접 해 보고 풀이를 확인합니다.



첫 세 시간은 데이터의 의미, 구조의 정도, 값의 의미와 저장 자료형, 행·키·스키마·목록과 계층을 배웁니다. CSV와 JSON은 이 개념을 파일로 표현하는 후반 적용입니다. **구조의 정도 / 통계적 의미 / 컴퓨터 저장 자료형은 서로 다른 분류 축**입니다.

- 입력은 `examples/foundations/data`, 작업 양식은 `examples/foundations/work`, 완성 코드는 `examples/foundations/code`에 있습니다. 학생은 분류의 이유와 원문을 직접 씁니다.
- 원본을 보존하고 작업 복사본을 수정합니다. 텍스트 편집기나 웹 CSV·JSON 편집기에서 직접 작성하고 UTF-8로 저장하거나 지정한 파일명으로 내려받습니다. PC 미준비 시 같은 원문과 기호, 분류·검수 기록을 종이에 씁니다.
- 웹 실습 화면은 CSV·JSON을 편집하고 형식을 확인합니다. **Python을 실행하는 화면은 아닙니다.** Python은 준비된 PC의 개인 실행 또는 강사의 실제 실행 결과와 비교합니다. [전체 코드·모든 줄 해설·실행 출력](examples/foundations/code/line-guide.md)을 함께 봅니다.
- 숫자처럼 보이는 식별자, 순서 등급의 간격, 사진 속 표, 엄격한 스키마의 JSON을 반례로 확인합니다. 확장자만으로 자료 형태를 단정하지 않습니다.
- 모든 자료는 합성 예시입니다. 사진·음성은 설명 카드이며 실제 미디어를 분석한 것은 아닙니다. 모르는 온도는 추정해서 채우지 않습니다.

## A01 · 데이터와 정보: 숫자에 맥락 붙이기


### 목적

기록된 값과 그 값을 해석해 얻는 정보를 구분하고, 판단에 필요한 맥락을 찾습니다.

### 준비

세 카드를 나란히 봅니다. 알고 있는 사실과 추정한 내용을 다른 표시로 구분합니다.

입력 파일: [A01_context_cards.md](examples/foundations/data/A01_context_cards.md)

작업 양식: [A01_notes.md](examples/foundations/work/A01_notes.md)

### 실제 입력

가: 22.5. 나: S01이 입구에서 2026-10-08 10:00에 기록한 22.5℃. 다: 근거 없이 적힌 “입구는 안전하다.”

### 단계

1. 숫자 22.5만 보고 확실히 알 수 있는 것과 알 수 없는 것을 두 가지씩 적습니다.
2. 카드 나에서 누가 또는 무엇이, 어디서, 언제, 어떤 단위로 기록했는지 표시합니다.
3. 카드 나를 근거로 말할 수 있는 사실 한 문장을 씁니다.
4. 카드 다의 결론을 내리려면 필요한 추가 근거 두 개를 적습니다.
5. 짝에게 데이터가 기록되어 있다는 사실만으로 모든 결론이 참은 아닌 이유를 설명합니다.

### 예상 결과

값 하나에 맥락 네 가지를 붙이고, 관찰 사실과 근거가 부족한 판단을 나눕니다.

### 확인 방법

온도 한 번의 기록을 공간 전체의 안전 확인으로 바꾸어 말하지 않았는지 확인합니다.

결과 파일: `work/A01_notes.md`

### 오류 해결

아는 것과 모르는 것이 섞이면 카드에 실제로 적힌 문구에만 밑줄을 긋고 나머지를 질문으로 바꿉니다.

### 힌트

무엇·어디·언제·단위가 해석을 돕습니다.

### 빠르게 마친 학생의 확장

같은 22.5가 가격이나 길이일 수도 있는 예를 만들어 맥락이 달라지는 모습을 설명합니다.

### 학생 답칸

- 숫자만으로 아는 것 / 모르는 것: _____
- 카드 나의 맥락 네 가지: _____
- 근거가 있는 사실 한 문장: _____
- 안전 판단에 더 필요한 근거: _____

## A02 · 수집 방법과 출처·맥락·메타데이터


### 목적

주문·설문·센서·사진 설명·자유 메모가 무엇을 어떻게 기록했는지 비교합니다.

### 준비

다섯 카드의 원문과 수집 상황을 읽습니다. 메타데이터는 다른 자료의 출처나 조건을 설명하는 데이터라는 뜻부터 확인합니다.

입력 파일: [A02_collection_cards.md](examples/foundations/data/A02_collection_cards.md)

작업 양식: [A02_notes.md](examples/foundations/work/A02_notes.md)

### 실제 입력

공책 3권 주문, 보통이라는 설문 응답, S01 22.5℃ 기록, 창고 사진 설명, “오후에 더웠음” 메모를 비교합니다.

### 단계

1. 각 카드에서 기록 대상과 수집 방법을 한 가지씩 적습니다.
2. 수량·온도·시각에 단위나 기준이 있는지 표시합니다.
3. 빠진 정보 한 개씩을 찾아 정확한 질문으로 바꿉니다.
4. 다섯 자료 중 수집 시각과 출처를 덧붙이면 도움이 되는 예 두 개를 고릅니다.
5. 설문 미응답과 사진 밖의 상황처럼 원문에서 알 수 없는 한계를 짝에게 설명합니다.

### 예상 결과

다섯 자료에 수집 방법·출처·빠진 정보가 대응된 비교표가 남습니다.

### 확인 방법

사진 설명 카드만 읽고 실제 물건 수를 세었다고 쓰지 않았는지 확인합니다.

결과 파일: `work/A02_notes.md`

### 오류 해결

자료 자체와 자료를 설명하는 정보를 섞었다면 “무엇을 기록했나”와 “어떻게 얻었나”로 칸을 나눕니다.

### 힌트

원문에 없는 시각이나 단위는 지어내지 말고 확인 질문으로 남깁니다.

### 빠르게 마친 학생의 확장

설문 응답이 전체 수강생의 의견을 대표한다고 말하려면 무엇을 더 알아야 할지 설명합니다.

### 학생 답칸

- 카드 1의 기록 대상 / 수집 방법 / 빠진 정보: _____
- 카드 2의 기록 대상 / 수집 방법 / 빠진 정보: _____
- 카드 3의 기록 대상 / 수집 방법 / 빠진 정보: _____
- 카드 4의 기록 대상 / 수집 방법 / 빠진 정보: _____
- 카드 5의 기록 대상 / 수집 방법 / 빠진 정보: _____
- 메타데이터 예 두 개: _____
- 원문만으로 알 수 없는 것: _____

## A03 · 정형·반정형·비정형을 근거로 구분하기


### 목적

고정된 항목, 키와 계층, 자유로운 내용이라는 구조의 차이로 자료를 분류합니다.

### 준비

카드 여덟 개를 읽고 정형·반정형·비정형의 뜻을 비교합니다. 확장자는 보조 단서이며 절대 기준이 아닙니다.

입력 파일: [A03_structure_cards.md](examples/foundations/data/A03_structure_cards.md)

작업 양식: [A03_notes.md](examples/foundations/work/A03_notes.md)

### 실제 입력

고정 주문 표, 유연한 JSON, 엄격한 스키마의 JSON, 자유 메모, 표 사진, 선택 태그 XML, 고정 CSV, 음성을 분류합니다.

### 단계

1. 각 카드에서 고정 항목·계층·자유 내용 중 어떤 특징이 있는지 표시합니다.
2. 여덟 카드에 구조 분류와 한 줄 근거를 씁니다.
3. 2번과 3번 JSON이 같은 확장자여도 규칙이 다른 이유를 설명합니다.
4. 5번 표 사진에서 보이는 표와 분석 도구가 읽는 셀 값의 차이를 씁니다.
5. 짝과 판단이 다른 카드는 어떤 관점이나 조건이 다른지 비교합니다.

### 예상 결과

여덟 분류에 이유가 있고, 스키마가 엄격한 JSON과 표 사진의 조건을 설명합니다.

### 확인 방법

“JSON이라 반정형”, “사진에 표가 있으니 셀 데이터”처럼 확장자나 외관만으로 끝내지 않았는지 봅니다.

결과 파일: `work/A03_notes.md`

### 오류 해결

경계 사례에서는 현재 제공 형태와 적용 중인 규칙을 다시 읽고 조건을 덧붙입니다.

### 힌트

무엇으로 끝나는 파일인가보다 항목과 관계를 어떤 규칙으로 읽을 수 있는가를 묻습니다.

### 빠르게 마친 학생의 확장

자유 메모를 일정한 항목으로 옮기면 얻는 것과 잃는 것을 한 가지씩 예상합니다.

### 학생 답칸

- 카드 1의 분류 / 근거 / 필요한 조건: _____
- 카드 2의 분류 / 근거 / 필요한 조건: _____

## A04 · 같은 관찰을 메모·표·키와 값으로 표현하기


### 목적

표현을 바꾸면서 유지할 내용과 표에 들어가지 않는 맥락을 함께 찾습니다.

### 준비

원문 한 문단과 빈 다섯 열 표를 준비합니다. 이 활동의 키·값은 개념 표현이며 JSON 문법 검사는 아직 하지 않습니다.

입력 파일: [A04_same_event.md](examples/foundations/data/A04_same_event.md)

작업 양식: [A04_table.md](examples/foundations/work/A04_table.md), [A04_notes.md](examples/foundations/work/A04_notes.md)

### 실제 입력

S01, 입구, 22.5℃, 2026-10-08 10:00, 가동 중이라는 관찰과 문이 잠깐 열렸다는 메모입니다.

### 단계

1. 다섯 공통 항목에 해당하는 원문 조각을 각각 표시합니다.
2. 다섯 열의 표 한 행을 직접 채웁니다.
3. 같은 내용을 항목 이름: 값의 다섯 쌍으로 적습니다.
4. 표에 들어가지 않은 문 열림 메모를 찾아 별도 보관 방법을 씁니다.
5. 표로 바꾸면 비교하기 쉬워지는 점과 잃을 수 있는 맥락을 하나씩 설명합니다.

### 예상 결과

한 관찰의 표 한 행과 키·값 다섯 쌍, 별도 맥락 메모를 만듭니다.

### 확인 방법

문이 열렸다는 관찰을 온도가 달라진 원인으로 단정하지 않았는지 확인합니다.

결과 파일: `work/A04_table.md; work/A04_notes.md`

### 오류 해결

어느 칸에 넣을지 모르면 열 이름이 묻는 질문을 먼저 말해 봅니다.

### 힌트

정형화는 항목을 일정하게 만드는 일이며 원문의 모든 뜻을 자동으로 보존하지는 않습니다.

### 빠르게 마친 학생의 확장

별도 메모 열을 추가하면 어떤 비교가 쉬워지고 어떤 어려움이 남는지 설명합니다.

### 학생 답칸

- 표 한 행: A04_table.md
- 키와 값 다섯 쌍: _____
- 보존할 추가 맥락: _____
- 정형화의 이점 / 한계: _____

## A05 · 범주형과 수치형: 값의 업무상 뜻


### 목적

값이 종류를 구별하는지, 양을 나타내는지 의미로 판단합니다.

### 준비

여덟 항목을 읽고 파일의 저장 방법과 업무상 뜻을 별개의 질문으로 생각합니다.

입력 파일: [A05_meaning_cards.md](examples/foundations/data/A05_meaning_cards.md)

작업 양식: [A05_notes.md](examples/foundations/work/A05_notes.md)

### 실제 입력

부서, 상태, 상자 개수, 온도, 사번 001, 만족도, 제품 색, 대기 시간을 비교합니다.

### 단계

1. 각 항목을 범주형 또는 수치형으로 분류하고 이유를 씁니다.
2. 더하거나 크기 차이를 계산하는 것이 의미 있는 항목 두 개를 고릅니다.
3. 사번 001과 002를 더하는 것이 왜 업무상 수량 계산이 아닌지 설명합니다.
4. 상태 true가 프로그램에서 불리언이어도 업무상 종류를 구별하는 항목임을 말해 봅니다.
5. 짝과 같은 값에 다른 분류를 붙였다면 어떤 의미를 가정했는지 확인합니다.

### 예상 결과

여덟 항목의 의미 분류와 계산 가능성에 대한 근거가 남습니다.

### 확인 방법

숫자 기호로 적었다는 이유만으로 식별자를 수치형 의미로 분류하지 않았는지 봅니다.

결과 파일: `work/A05_notes.md`

### 오류 해결

값의 생김새보다 담당자가 그 항목으로 어떤 질문에 답하려는지 생각합니다.

### 힌트

이름표를 더한다고 새로운 수량이 생기지는 않습니다.

### 빠르게 마친 학생의 확장

우편번호나 버스 번호처럼 숫자로 보이는 범주 예를 하나 더 만듭니다.

### 학생 답칸

- 부서의 범주형 또는 수치형 / 이유: _____
- 장치 상태의 범주형 또는 수치형 / 이유: _____
- 상자 개수의 범주형 또는 수치형 / 이유: _____
- 온도의 범주형 또는 수치형 / 이유: _____
- 사번 001의 범주형 또는 수치형 / 이유: _____
- 만족도의 범주형 또는 수치형 / 이유: _____

## A06 · 명목·순서·이산·연속의 차이


### 목적

범주의 순서 여부와 수량의 세기·측정 차이를 구별합니다.

### 준비

먼저 범주형과 수치형으로 나눈 뒤 각각을 두 종류로 더 살펴봅니다. 평균 계산은 하지 않습니다.

입력 파일: [A06_subtypes_cards.md](examples/foundations/data/A06_subtypes_cards.md)

작업 양식: [A06_notes.md](examples/foundations/work/A06_notes.md)

### 실제 입력

색, 만족도, 상자 수, 소수 첫째 자리 온도, 사번, 숫자 코드 점검 등급, 고장 횟수, 반올림한 거리를 봅니다.

### 단계

1. 각 항목을 명목·순서·이산·연속으로 나누고 짧은 이유를 씁니다.
2. 만족도에 순서가 있어도 낮음에서 보통의 간격과 보통에서 높음의 간격을 같다고 할 근거가 있는지 표시합니다.
3. 점검 등급 1·2·3이 수량인지 순서 범주의 코드인지 설명합니다.
4. 온도와 거리는 제한된 자리까지 기록해도 원래 무엇을 측정하는지 씁니다.
5. 짝에게 이산 개수 한 예와 연속 측정량 한 예를 들어 구별하게 합니다.

### 예상 결과

여덟 세부 분류와 숫자 등급·측정 정밀도의 반례를 설명합니다.

### 확인 방법

소수점을 한 자리로 적었다는 이유만으로 온도를 셀 수 있는 개수로 분류하지 않았는지 확인합니다.

결과 파일: `work/A06_notes.md`

### 오류 해결

수치형이면 먼저 “몇 개인가”와 “얼마나 되는가” 중 어떤 질문인지 생각합니다.

### 힌트

순서는 앞뒤를 알려 주지만 간격까지 자동으로 알려 주지는 않습니다.

### 빠르게 마친 학생의 확장

순서 범주를 숫자 코드로 저장할 때 데이터 사전에 적어야 할 뜻을 제안합니다.

### 학생 답칸

- 사례 1의 명목·순서·이산·연속 / 이유: _____
- 사례 2의 명목·순서·이산·연속 / 이유: _____

## A07 · 문자열·정수·실수·불리언 관찰하기


### 목적

업무상 뜻과 별개로 컴퓨터가 값을 어떤 자료형으로 저장하는지 완성 코드에서 관찰합니다.

### 준비

전체 코드와 모든 줄 해설을 읽습니다. 브라우저 자료 화면은 Python을 실행하지 않습니다. 준비된 PC의 개인 실행 또는 강사 실행과 비교합니다.

입력 파일: [A07_types.py](examples/foundations/code/A07_types.py), [line-guide.md](examples/foundations/code/line-guide.md)

작업 양식: [A07_types.py](examples/foundations/work/A07_types.py), [A07_notes.md](examples/foundations/work/A07_notes.md)

### 실제 입력

문자열 001, 실수 22.5, 불리언 True, 날짜 글자, 정수 22, 숫자처럼 보이는 글자 22.5를 출력합니다.

### 단계

1. 출력 여섯 줄에서 값과 자료형 이름을 각각 예상해 적습니다.
2. type은 종류를 확인하고 __name__은 종류 이름을 보여 준다는 해설을 읽습니다. 이 표현을 외워 새로 만들 필요는 없습니다.
3. 실제 실행 출력과 예상한 여섯 종류를 대조합니다.
4. 작업 복사본의 employee_id만 "002"로 바꾸고 달라질 출력 한 줄을 예상합니다.
5. 숫자 22.5와 문자열 "22.5"의 출력 생김새가 같아도 자료형이 다른 이유를 설명합니다.

### 예상 결과

여섯 값의 Python 자료형을 구별하고 문자열 식별자 한 값을 수정한 결과를 설명합니다.

### 확인 방법

날짜 의미가 있다는 이유로 이 코드의 문자열을 별도 날짜 자료형이라고 적지 않았는지 봅니다.

결과 파일: `work/A07_types.py; work/A07_notes.md`

### 오류 해결

따옴표를 지웠다면 원본과 비교합니다. Python에 001이라는 정수 표기를 쓰는 과제는 아닙니다.

### 힌트

값의 뜻, 화면에 보이는 모양, 저장된 종류를 각각 따로 적습니다.

### 빠르게 마친 학생의 확장

동일한 22를 "22"로 감쌌을 때 type 결과가 어떻게 달라질지 예상합니다.

### 학생 답칸

- 여섯 출력의 값 / 종류 / 의미: _____
- 002로 수정하면 달라지는 줄: _____
- 날짜 글자를 저장한 자료형: _____
- 실제 확인 방법: _____

## A08 · 값 없음·0·False·문자 0을 구분하기


### 목적

겉으로 비어 있거나 꺼져 보이는 값을 같은 뜻으로 합치지 않습니다.

### 준비

### 단계

1. 각 카드의 저장 표현과 원문에서 확인한 뜻을 적습니다.

### 확인 방법

### 힌트

### 빠르게 마친 학생의 확장

필드 자체가 없는 기록을 받았을 때 null과 같다고 단정하기 전에 할 질문을 씁니다.

### 학생 답칸

- 카드 1의 표현 / 자료형 / 업무상 뜻: _____
- 카드 2의 표현 / 자료형 / 업무상 뜻: _____

## A09 · 표 한 줄에는 무엇을 기록할까요?


### 목적

표의 한 행이 무엇을 나타내는지 정하고 장치 수와 관찰 수를 구별합니다.

### 준비

원문 여섯 메모와 같은 기록의 표를 나란히 봅니다. 아직 CSV를 직접 작성할 필요는 없습니다.

입력 파일: [base_readings.csv](examples/foundations/data/base_readings.csv), [base_notes.md](examples/foundations/data/base_notes.md)

작업 양식: [A09_notes.md](examples/foundations/work/A09_notes.md)

### 실제 입력

공통 다섯 열과 데이터 여섯 행입니다. S01과 S02는 서로 다른 시각에 두 번씩 나타납니다.

### 단계

1. 헤더와 데이터 행을 구분하고 다섯 열의 이름을 읽습니다.
2. 한 행이 장치 하나인지, 장치의 한 시점 관찰 하나인지 한 문장으로 정의합니다.
3. 원문 1번과 5번에서 같거나 다른 항목을 표시합니다.
4. 서로 다른 장치의 수와 관찰의 수를 따로 셉니다.
5. 온도 빈칸 한 개가 있어도 해당 관찰 전체가 사라지는 것은 아닌 이유를 설명합니다.

### 예상 결과

관찰 여섯 건과 장치 네 개를 구분하고 각 셀을 행과 열로 찾습니다.

### 확인 방법

장치 이름이 반복된다는 이유만으로 행을 지우지 않았는지 봅니다.

결과 파일: `work/A09_notes.md`

### 오류 해결

헷갈리면 한 행을 “어느 장치의 언제 관찰”로 읽어 봅니다.

### 힌트

관찰 단위가 정해져야 무엇이 중복인지 판단할 수 있습니다.

### 빠르게 마친 학생의 확장

한 행을 하루 평균으로 바꾸면 현재 여섯 행과 어떤 정보가 달라지는지 설명합니다.

### 학생 답칸

- 한 행이 뜻하는 것: _____
- 열 수 / 관찰 수 / 장치 수: _____
- 1번과 5번의 공통점 / 차이: _____
- 빈칸이 있는 행의 알려진 정보: _____

## A10 · 기록을 구별하고 항목 설명을 적어 봅시다


### 목적

다섯 필드 규칙과 빈 데이터 사전을 준비합니다. 스키마는 어떤 항목과 구조를 따를지 정한 약속으로 설명합니다.

규칙과 예를 구분하기 어렵다면 먼저 규칙 문장을 쓰고 예시 하나를 괄호에 붙입니다.

### 힌트

### 빠르게 마친 학생의 확장
