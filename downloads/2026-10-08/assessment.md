# 데이터 기초 · 적용과 설명 평가 초안

자료를 분류한 이유와 표현을 고른 근거를 설명해 보세요. 이 확인 기준은 학습을 돕기 위한 것이며 공식 수료·채용 평가 기준과는 별개입니다.

학생은 용어를 맞추는 데 그치지 않고 자료의 근거를 보고 분류 이유와 표현 선택을 설명합니다. 개인 Python 설치·실행 여부만으로 이해도를 판단하지 않습니다. 실행 환경이 없으면 출력 예측과 실제 강사 실행 비교를 기록합니다. 데이터 작성·수정·검수는 학생이 직접 수행하며, PC 미준비 시 같은 원문과 기호를 종이에 씁니다.

## 확인할 핵심 기준

| 기준 | 확인 자료 | 최소 충족의 모습 | 다시 도울 부분 |
| --- | --- | --- | --- |
| 데이터와 해석 | A01~A02 | 관찰 사실·맥락·모르는 것을 나누고 출처나 수집 조건을 질문한다. | 기록 하나를 근거 없이 최종 결론으로 바꾸는 경우 |
| 구조의 정도 | A03~A04 | 고정 항목·계층·자유 내용이라는 근거를 쓰며 JSON과 표 사진의 조건을 설명한다. | 확장자나 겉모양만으로 분류하는 경우 |

| CSV·JSON 표현 | A13~A20 | 표 원문을 직접 쓰고 헤더·구분자·키·값·괄호·자료형을 확인한다. 전체 코드의 입력과 출력도 읽는다. | 파싱 성공만으로 내용까지 맞다고 판단하는 경우 |
| 종합 설계와 검수 | A21~A23 | 세 분류 축과 한계를 설명한 뒤 사전·CSV6건·JSON2건을 만들고 네 관점으로 근거 있는 수정을 한다. | 원문 없이 값을 추정하거나 검수 근거를 남기지 않는 경우 |
| 개념 전이와 설명 | A24 | 처음 보는 네 상황에 이유를 대고 결과·검수·보류를 세 문장으로 인계한다. | 외운 용어만 나열하고 선택 이유를 말하지 못하는 경우 |

## 과정 중 제출 흔적

- A01~A04: 맥락 질문, 수집 상황 비교, 구조 카드 여덟 분류와 근거, 한 관찰의 표·키값 표현과 빠진 맥락.
- A05~A08: 의미 카드 여덟 분류, 세부 사례 여덟 분류, 여섯 값의 자료형 관찰, 여섯 상태 비교.
- A09~A12: 관찰 단위 설명, 다섯 항목 사전, 리스트·딕셔너리 출력 해석, 두 시점 표와 계층 경로.
- A13~A16: CSV 세 행과 다섯 행 작성본, 세 비교 사례의 설명, CSV 전체 읽기 코드의 출력 해석.
- A17~A20: JSON 한 객체, 안쪽 값 네 개, CSV 두 행 변환과 오류 두 개 복구, JSON 전체 읽기 코드의 출력 해석.
- A21~A24: 새 자료의 형태·한계, 필드 설계, 새 CSV 여섯 행·지정 JSON 두 객체·이슈, 검수 수정 두 건, 전이 질문과 인계.

## 스스로 설명하는 질문

1. 같은 001을 왜 사번이라는 의미와 문자열이라는 저장 종류로 따로 설명하나요?
2. JSON과 사진이라는 이름만으로 구조를 단정하면 어떤 예외를 놓치나요?
3. 표의 한 행을 무엇으로 정했나요? 그 기준으로 무엇을 함께 비교해야 기록을 구별하나요?
4. 데이터가 읽힌다는 확인과 업무 내용이 맞다는 확인은 어떻게 다른가요?
5. 무엇을 직접 확인했고 어떤 실제값은 아직 모른 채 남겼나요?

## 학습 상태 기록

각 기준에 **스스로 설명함 / 예를 보고 설명함 / 다시 연습 필요** 중 하나를 표시합니다. 초기 답이 틀렸어도 원문·규칙을 보고 이유를 고쳐 설명한 과정을 남깁니다. 명칭이 조금 달라도 관점과 근거가 맞는 경계 사례는 설명을 듣고 판단합니다.

다음 연습은 막힌 개념 한 가지에 맞춥니다. 분류가 어려우면 두 사례 비교, 자료형이 어려우면 같은 값의 따옴표 유무, 구조가 어려우면 한 행과 키·값, 구문이 어려우면 한 기록의 기호부터 다시 확인합니다. 빠른 학생의 확장 과제는 필수 제출 기준에 넣지 않습니다.
