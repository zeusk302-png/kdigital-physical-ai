<h2>피지컬 AI를 쉬운 말로 설명하면</h2>
<p>AI가 글이나 그림을 만드는 것에서 더 나아가, 센서로 실제 세계의 상태를 받아들이고 그 정보를 바탕으로 판단하거나 행동하는 것을 피지컬 AI라고 부릅니다. 여기서 physical은 ‘물리적 세계’라는 뜻입니다. 카메라로 상자의 위치를 읽고 로봇 팔이 잡는 위치를 바꾸는 장면을 떠올려 보세요.</p>
<table><thead><tr><th>입력: 무엇을 읽나?</th><th>판단: 무엇을 정하나?</th><th>출력·다시 확인</th></tr></thead><tbody>
<tr><td>카메라의 상자 사진, 거리, 힘</td><td>상자는 어디 있고 어떻게 잡을까?</td><td>팔을 움직이고 잡혔는지 확인</td></tr>

</tbody></table>
<p>센서는 상태를 기록하는 장치입니다. 카메라는 빛을 이미지로, 온도 센서는 온도를 숫자로 기록합니다. 액추에이터는 모터·밸브처럼 실제 움직임이나 작용을 만드는 장치입니다. 모델은 데이터에서 학습한 관계를 이용해 결과를 추정하는 부분입니다. 사람이 적은 조건문과 학습한 모델은 서로 다른 방법이며, 한 시스템 안에서 함께 쓰일 수 있습니다.</p>
<p>자동문이 사람이 오면 열리는 것처럼 정해진 규칙만 수행하는 자동화도 중요합니다. 그렇다고 센서나 모터가 있는 장치를 모두 피지컬 AI라고 부르지는 않습니다. 이 과정의 온도 기준 비교 예제는 데이터와 제어 흐름을 배우는 작은 규칙 기반 연습입니다. 실제 AI 모델 학습·로봇 제어를 했다는 증거로 사용하지 않습니다.</p>
<h3>완성 예: 센서 기록에서 현장 질문으로</h3>
<p>‘S01, 22.5, 10:00’만 보면 단위·장소·측정 상태를 모릅니다. ‘입구 센서 S01이 10:00에 기록한 온도 22.5℃, 정상 측정’처럼 뜻을 붙여야 비교할 수 있습니다. 사진 속 로봇을 이해하는 데도 무엇을 읽었는지, 시간과 단위가 무엇인지, 판단의 근거가 무엇인지가 먼저 필요합니다. 그래서 오늘은 데이터부터 시작합니다.</p>
<h2>사례 영상 1 · 부품을 옮기는 Atlas</h2>
<p>Boston Dynamics 공식 YouTube, <a href="https://www.youtube.com/watch?v=F_7IPm7f1vI">Atlas Goes Hands On</a> (2024-10-30). 앞부분과 설명에 표시된 0:36의 인식 장면, 1:24의 실패 대응 장면을 짧게 비교합니다. 수업 권장 시청량은 약 2분이며 실제 재생 길이는 수업 전에 확인합니다.</p>
<p>제작사 설명에 따르면 엔진 커버를 보관함과 이동 장치 사이에 옮기며 시각 모델로 환경과 보관함 위치를 찾습니다. 동작 실패와 환경 변화에도 대응한다고 설명합니다. 이것은 제작사 시연의 설명이며 어느 공장·모든 부품에서도 같은 성공률을 보장한다는 뜻은 아닙니다.</p>
<h3>보면서 적기</h3>
<ol><li>카메라·힘 등 입력에 해당하는 것을 한 가지 적습니다.</li><li>팔이 움직인 결과와 다음에 확인해야 할 것을 나눠 적습니다.</li><li>성공률·작업 속도·사람과의 안전거리는 영상만으로 확인되는지 표시합니다.</li></ol>
<p>풀이 예: ‘물체 위치를 읽고 잡는 동작을 정한다’는 연결은 설명과 장면으로 살펴볼 수 있습니다. ‘모든 현장에서 사람보다 안전하다’는 결론에는 시험 조건·실패 횟수·안전 검증이 추가로 필요합니다. 로봇의 모양보다 입력→판단→행동→다시 확인의 연결을 설명하는 것이 이 활동의 목표입니다.</p>
<h2>사례 영상 2 · 사람이 확인할 설비를 대신 살펴보는 Spot</h2>
<p>Boston Dynamics 공식 YouTube, <a href="https://www.youtube.com/watch?v=iubgWPHsuWM">High Voltage Spot Inspections at National Grid</a>. 회사 설명은 확대 카메라와 열화상 카메라를 이용한 설비 점검 사례를 소개합니다. 수업에서는 처음 2분 또는 점검 장면을 선택해 봅니다. 선택 구간은 제작 제안이며 온라인 재생·자막은 강의실에서 확인해야 합니다.</p>
<p>설비를 돌아다니는 로봇, 값을 기록하는 센서, 이상 징후를 해석하는 처리, 담당자의 최종 판단은 서로 다른 역할입니다. 이 영상의 모든 판단이 AI 모델로 자동 처리됐다고 추정하지 않습니다. 자동 이동·측정과 AI 분석을 구분해 질문하는 사례로 사용합니다.</p>
<p>질문: 사람이 직접 들어가기 어려운 곳에서 무엇을 대신 기록할 수 있을까요? 기록을 받아 본 담당자는 어떤 확인을 해야 할까요? 풀이 예: 측정 위치와 시간, 정상 때의 값, 카메라 상태를 확인하고 이상 징후를 다른 자료와 대조합니다. 반복 점검의 기록 품질이 중요하므로 센서 데이터·파일·대시보드 학습과 연결됩니다.</p>

## 22.5만 보고 무엇을 알 수 있을까요?

종이에 **22.5**가 적혀 있습니다. 온도인가요, 길이인가요, 금액인가요? 누구를 언제 측정했을까요? 이 숫자만으로는 알 수 없습니다.

**2026년 10월 8일 10:00, 입구 센서 S01이 기록한 섭씨 온도 22.5**라고 설명을 붙이면 대상·시각·단위를 알 수 있습니다. 이런 맥락을 사용하면 다른 시각의 값과 비교할 수 있습니다. 그래도 센서가 제대로 작동했는지까지 숫자 하나가 보장하지는 않습니다.

데이터는 관찰·측정·기록한 내용입니다. 정보를 얻으려면 그 내용의 뜻과 맥락을 이해하고 목적에 맞게 정리하거나 해석해야 합니다. 오늘은 “파일이 열렸다”뿐 아니라 **이 값이 무엇을 뜻하는지, 어떤 판단까지 가능한지**를 계속 묻습니다.

## 첫 번째 관점: 자료 전체가 어떤 구조인가요?

| 종류 | 쉬운 설명 | 살펴볼 예 | 판단 근거 |
| --- | --- | --- | --- |
| 정형 데이터 | 미리 정한 항목과 구조에 맞춰 기록 | 주문번호·상품·수량 열이 정해진 주문 표 | 각 기록에서 같은 항목을 같은 뜻으로 찾음 |
| 반정형 데이터 | 이름표·계층 등의 구조가 있지만 기록 구성이 유연함 | 항목과 중첩 구성이 다른 여러 JSON 기록 | 키와 묶음으로 찾을 수 있으나 항상 같은 표는 아님 |
| 비정형 데이터 | 분석하려는 내용이 미리 정한 레코드·필드에 맞춰 정리되어 있지 않음 | 사진의 장면, 음성의 대화, 자유롭게 쓴 후기 | 내용을 해석하고 필요한 항목을 추출해야 함 |

비정형은 “쓸모없다”거나 “파일 형식에 아무 규칙이 없다”는 뜻이 아닙니다. 예를 들어 사진 파일에도 정해진 저장 규칙이 있지만, 사진 속 장면의 뜻이 곧바로 주문 표의 셀 값으로 주어지지는 않습니다.

**확장자만 외우지 않습니다.** JSON은 반정형 데이터를 표현할 때 자주 사용하지만, 항목과 자료형을 엄격히 정해 사용할 수도 있습니다. 표를 찍은 사진과 실제 행·열 값이 있는 표 파일도 구별해야 합니다. 무엇을 분석하려는지와 실제 구조를 보고 판단합니다. [구조에 따른 구분 참고](https://aws.amazon.com/what-is/structured-data/)

## 두 번째 관점: 한 값은 무엇을 뜻하나요?

값을 **분류를 나타내는 범주형**과 **수량을 나타내는 수치형**으로 나누어 봅니다.

| 큰 구분 | 작은 구분 | 예 | 해 볼 질문 |
| --- | --- | --- | --- |
| 범주형 | 명목: 이름으로 구별 | 부서, 색, 센서 식별자 | 자연스러운 크기 순서가 있나요? |
| 범주형 | 순서: 앞뒤·높낮이 구분 | 낮음·보통·높음, 만족 등급 | 순서는 있지만 간격도 같다고 말할 수 있나요? |
| 수치형 | 이산: 개수를 셈 | 주문 수량, 불량 개수 | 이 상황에서 2.5개가 가능한가요? |
| 수치형 | 연속: 양을 측정 | 길이, 시간, 온도 | 측정 도구의 정밀도를 더 높이면 더 자세히 기록할 수 있나요? |

**사번 001과 수량 1은 다릅니다.** 사번은 사람을 구별하는 이름표이고 수량은 개수입니다. 숫자로 적혀 있다는 이유로 사번을 더하거나 평균 내는 것은 업무 의미와 맞지 않습니다. 만족도를 1·2·3으로 적었다고 각 단계의 차이가 같다고 자동으로 정할 수도 없습니다. [값의 의미에 따른 분류 참고](https://www.abs.gov.au/statistics/understanding-statistics/statistical-terms-and-concepts/variables)

## 세 번째 관점: 컴퓨터는 어떤 자료형으로 저장하나요?

| 표현 | 쉬운 뜻 | 예와 주의 |
| --- | --- | --- |
| 문자열 | 글자로 다루는 값 | 사번 "001"은 앞의 0을 보존 |
| 정수 | 소수 부분 없이 다루는 숫자 | 수량 3 |
| 실수 | 소수점이 있는 값 등을 다루는 숫자형 | 온도 22.5 |
| 불리언 | 참·거짓의 두 상태 | Python True/False, JSON true/false |
| 값 없음 | 값이 없는 상태를 나타내는 표현 | 이 수업에서는 Python None, JSON null |
| 날짜·시간 | 시점을 나타내는 의미 | 파일에는 "2026-10-08 10:00" 같은 문자열로 적을 수 있음 |

**값의 의미와 저장 자료형은 같은 분류가 아닙니다.** 온도는 의미상 측정량인데 CSV에서 처음 읽은 값은 글자일 수 있습니다. 반대로 범주를 나타내는 등급을 컴퓨터 숫자로 저장할 수도 있습니다. 저장된 모양만 보고 계산 방법을 정하지 않습니다.

0은 실제 숫자이고, False는 거짓 상태이며, null은 이 수업에서 값 없음 표현입니다. 빈 온도를 0으로 바꾸면 “미측정”을 “0도를 측정함”으로 바꾸게 됩니다. [Python 자료형 참고](https://docs.python.org/3/library/stdtypes.html)

## 파일을 다룰 때 필요한 최소 준비

파일은 저장한 내용 한 묶음, 폴더는 파일을 모아 두는 곳입니다. 확장자 .csv·.json·.py는 형식을 알려 주는 이름 끝부분입니다. 원문은 보관하고 작업 사본을 수정합니다. **열기→수정→저장**과 **프로그램 실행**은 서로 다른 행동입니다.

학생 자료는 예제 ZIP을 푼 뒤 **foundations/README.md**부터 봅니다. data에는 원문, work에는 학생 작성 양식, code에는 완성 코드와 줄별 설명이 있습니다. 코드를 복사했다고 실행된 것은 아닙니다. Python은 준비된 PC에서 강사와 실행하며, 웹 화면은 Python 실행기가 아닙니다.

CSV·JSON을 작성할 단계가 되면 [작업 화면](#/data-lab)을 엽니다. 형식을 확인한 뒤 저장하고 원문과 비교합니다. 내려받기가 지원되지 않으면 입력 복사 후 편집기에 붙여넣어 UTF-8로 저장합니다. 웹이 문법을 읽었다는 사실은 데이터의 의미까지 맞다는 판정이 아닙니다.
